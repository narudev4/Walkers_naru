## ⛔ 絶対 NG

抵触したら**即停止して naru に報告**。自走中（/goal）でも例外なく止まる。

1. **本見積もりの先方合意前に、本開発フェーズの作業へ着手しない** — 契約根拠なき工数消化。案件の現フェーズは L3 で管理し、それを超える作業を始めない
2. **要件定義フェーズで詳細設計（DB 論理設計・API 一覧）まで踏み込まない** — 稼働超過の原因。詳細設計は本開発フェーズ
3. **見積もりに影響するスコープ追加・仕様変更を、記録・合意なしで進めない** — 分業案件は営業担当に共有、一人案件でも確認事項/decisions に記録し先方合意を残す
4. **稼働上限の超過を黙って続けない** — 気づいた時点でエスカレーション or 打診（スコープ縮小／稼働追加）
5. **`vercel --prod --yes` や `.vercel/project.json` 無しの CLI デプロイをしない** — 別チームへの新規プロジェクト作成事故。デプロイは GitHub 連携の自動デプロイ or 正規手順（`.claude/refs/vercel-deploy.md` を必ず Read）
6. **Claude が publish / メール送信 / 本番反映 / 課金契約を独断実行しない** — 必ず naru の承認を取る
7. **UUID 形式の MCP（`mcp__<UUID>__*`）で Google 操作をしない** — 第三者アカウント事故。Google 系は `mcp__google-workspace__*` のみ。見つからなければ naru に報告
8. **credentials/ をコミットしない・シークレットを push しない・.mcp.json をリモートに上げない**

## フェーズゲート（受託開発）

受託開発は次の順で進む。**各フェーズは前フェーズのゲート条件が満たされて初めて開始できる**。Claude は作業着手前に L3 の「現フェーズ」を確認し、それを超える作業を求められたら停止して確認する（絶対 NG #1・#2 の実装）。

| # | フェーズ | 開始ゲート条件 | 主成果物 |
|---|---|---|---|
| ① | 営業 | 問い合わせ受領 | モックアップ・提案書（概算見積）・準委任契約 |
| ② | PM アサイン | 準委任契約締結 | 引き継ぎ完了（スコープ・やらないこと・金額前提） |
| ③ | 要件定義 | ②完了 | 要件定義書（画面一覧/機能一覧/非機能要件）・技術検証 |
| ④ | 本見積もり | 要件定義書の先方合意 | 本見積もり（先方合意済み） |
| ⑤ | 本開発契約 | 本見積もり合意 | 締結済み本開発契約書 |
| ⑥ | 本開発 | 本開発契約締結 | 本番リリース・検収シート・先方検収合意 |

## 案件ライフサイクル

```
新規案件  → /project-init     L3 ディレクトリ + CLAUDE.md を雛形から生成（CONTEXT.md・議事録から穴埋め）
進行      → スプシ駆動         作業一覧スプシを真理源に、確認事項を起票しながら進める
開発自走  → /goal-check → /goal  発射前自己検査 → 完了条件まで自走（停止条件は下記）
クローズ  → /project-close    distill（学びを memories+インシデント記録へ）→ 検収確認 → 軽量化 → archive/ へ
```

## スプシ駆動 = 業務 OS（CRITICAL）

**「頭の中を一度ぜんぶスプシに書いて、頭をクリアにしてから動く」が全業務の標準形。** 開発に限らず調査・制作・補助金でも同じループを回す。

- **真理源はスプシ**。ローカル md は途中の作業メモ。**確定したことだけスプシに昇格**する（未確認・憶測は書かない＝事実の扱い〔L1〕と一体）
- 各案件の真理源スプシ ID は L3（clients/{案件}/CLAUDE.md）に記録する。L2 に案件固有 ID は書かない
- **作業一覧**（親シート）: `ID / フェーズ / タスク / 作業内容 / ステータス / 担当 / naru確認`。naru確認列は人間専用
- **ステータス 5 値**: `未確認`（AI 未精査）/ `未着手` / `着手可能` / `対応中` / `✅完了`。✅完了にできるのは検証が PASS した時のみ
- **確認事項シート**: 仕様の空白・矛盾・未確認はここに起票する。`ID / カテゴリ / 内容 / ステータス / 備考`
- **検収シート**: 対象（画面/機能/DB/API）ごとに発行。AI 記入列と人力確認列を分離（実装者 ≠ 検証者 ≠ 判定者）

## 自走（/goal）の停止条件

- **層 A（起票して続行）**: 仕様の空白・矛盾・判断の迷いは確認事項シートに起票し、そのタスクをブロックにして次へ進む。全タスクがブロックされたときだけ停止
- **層 B（即時停止）**: 上の「⛔ 絶対 NG」に抵触する操作、不可逆操作（DB マイグレーション・データ削除・本番書き込み・force push）、同一エラー 3 回ループ、シークレット境界 — これらは止まって naru の承認を待つ
- 再開は /loop が確認事項シート/承認待ち行を巡回して行う（naru がスプシに回答／「承認」と記入 → 次のループが拾って再開）
