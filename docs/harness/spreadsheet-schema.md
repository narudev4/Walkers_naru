# スプシ標準スキーマ定義（業務OS の真理源フォーマット）

Walkers の調査・開発・制作を貫く「頭の中を全部スプシに書いてから動く」運用の標準スキーマ。
各案件の真理源スプレッドシートはこの定義に従う。スプシ操作は **`mcp__google-workspace__*`** のみ（UUID コネクター禁止）。

## 0. 派生モデル（最重要思想）

固定シートセットではない。**「作業一覧」を作ると必要なタブが派生して生えてくる**（古谷さん談）。

```
作業一覧（親・全工程）
  ├─ 確認事項        ← 作業中に出た不明点・未確認・受領待ち
  ├─ 環境情報        ← URL・接続・アカウント・資料リンク
  ├─ 検収シート×N     ← 対象（画面/機能/DB/API）ごとに発行
  └─ 要件定義書系     ← 画面一覧/機能一覧/非機能要件/技術検証（要件定義フェーズ）
       └─ 詳細設計系  ← API設計/DB設計（本開発フェーズ）
```

**運用原則**: 確定したことだけスプシに昇格する。未確認・憶測は書かない（事実の扱い〔L1〕と一体）。ローカル md は途中メモ、確定したらスプシが正。

## 1. 作業一覧（親シート・必須）

| 列 | 内容 | 記入者 |
|---|---|---|
| ID | `{Phase}-{連番}`（例 3-2）。フェーズ見出し行は `▶` | AI |
| フェーズ | Phase 名（見出し行のみ） | AI |
| タスク | タスク名 | AI |
| 作業内容 | 具体的な作業・対象ファイル | AI |
| ステータス | 下記5値 | AI（✅完了は検証PASS後のみ） |
| 担当 | Walkers / naru / 古谷 / 先方名 | AI |
| naru確認 | 人間の最終確認欄（✓/コメント） | **naru 専用・AI禁止** |

### ステータス5値（PTJ 条件付き書式を全案件標準）

| 値 | 意味 | 背景色 |
|---|---|---|
| `未確認` | AI がまだ行を精査していない | #FCE5CD |
| `未着手` | 精査済みだが未開始 | #EFEFEF |
| `着手可能` | 前提が揃い開始できる | #CFE2F3 |
| `対応中` | 作業中 | #FFF2CC |
| `✅完了` | **検証 PASS 済み**のみ | #D9EAD3 |

## 2. 確認事項（必須）

仕様の空白・矛盾・未確認・受領待ちはすべてここに起票（/goal 層A の起票先）。

| 列 | 内容 |
|---|---|
| ID | 連番 |
| カテゴリ | アクセス権 / 環境 / 既存システム調査 / 要件と実態の矛盾 / 受領物 / 決定事項 / 技術リスク |
| 内容 | 不明点・確認したいこと（一次情報・対象を具体的に） |
| ステータス | 未確認 / 確認待ち / ✅解決 / ⚠️要対応 / 承認待ち |
| 備考・メモ | 回答・対応方針・根拠 |

> `承認待ち` 行は /goal 層B（不可逆・課金等）の停止地点。naru が「承認」と書くまで /loop は再開しない。

## 3. 環境情報（必須）

デモURL・本番URL・ステージング・ローカル開発手順・接続情報の所在（実値は credentials/）・関連資料リンク。

## 4. 検収シート（テスト・デプロイ時／対象ごとに発行）

要件定義書の各シート（画面一覧・機能一覧・DB・API/関数一覧）に1つずつ発行。**AI 記入と人力確認を列で分離**（実装者 ≠ 検証者 ≠ 判定者）。

| 列 | 内容 | 記入者 |
|---|---|---|
| # | 検証ID | AI |
| テスト項目 | 何を確認するか | AI |
| 対象 | 画面/機能/エンドポイント | AI |
| テスト可否 | テスト可 / テスト不可（理由） | AI |
| AI結果 | PASS / FAIL / 確認中 | **verifier（実装者と別）** |
| エビデンス | スクショ・ログ・レビューコメント | verifier |
| naru確認 | 人力確認の合否 | **naru 専用** |

> /goal 完了条件の標準形 = 「対象 Phase の検収シート AI結果が全行 PASS またはテスト不可」。

## 5. オプションタブ（案件に応じて派生）

| タブ | フェーズ | 各行の項目 |
|---|---|---|
| 画面一覧 | 要件定義 | 画面ID / 画面名 / URL / 概要 / 主な機能 / アクセス権限 |
| 機能一覧 | 要件定義 | 機能ID / 関連画面 / 機能名 / 概要 / 入力 / 出力 / 備考 |
| 非機能要件 | 要件定義 | カテゴリ / 要件内容 / 優先度 / 備考 |
| 技術検証 | 要件定義 | 検証項目 / 検証方法 / 結果 / 本開発での扱い |
| API設計 | 本開発 | メソッド / パス / パラメータ / レスポンス / 認証要否 |
| DB設計 | 本開発 | テーブル / カラム / 型 / 制約 / 説明 |
| デモvs要件定義 | 要件定義 | 項目 / デモ挙動 / 要件定義 / 差分 / 採用 |
| 見積もり | 本見積もり | 機能 / 工数 / 単価 / 金額 / 備考 |
| バックログ | 随時 | ID / 内容 / 優先度 / 状態 |
