# プロジェクト管理スキル

プロジェクトの作成・クローズ・マージ・一覧表示を行う。

## 操作一覧

ユーザーの指示に応じて以下のいずれかを実行する:

### 1. 一覧表示（デフォルト）
`03_projects/` 配下のプロジェクトを一覧化し、各プロジェクトの状態を表示。
- README.md があればそこからステータスを読み取る
- 最終更新日（git log または ファイル更新日）
- `_archive/` 配下にあるものは「アーカイブ済み」と表示

### 2. 新規作成
```
03_projects/{プロジェクト名}/
  README.md    # プロジェクト概要・ステータス・担当者
  documents/   # ドキュメント格納
  notes/       # メモ・議事録
```
README.md テンプレート:
```markdown
# {プロジェクト名}
- ステータス: active
- 作成日: {日付}
- 担当: 古谷
- 概要: {ユーザーから聞いた概要}
- 親プロジェクト: （なし or 営業 etc）
```

### 3. クローズ
プロジェクトを閉じる。2パターン:

**a) アーカイブ（ヒストリーとして保存）**
- `03_projects/{名前}/` → `03_projects/_archive/{名前}/` に移動
- README.md のステータスを `archived` に変更
- 完了日・完了理由を追記
- 今後の参考になる知見があれば `_archive/{名前}/lessons.md` に記録

**b) トラッシュ（不要なので削除）**
- `03_projects/{名前}/` を削除（git で復元可能）
- 削除前に確認プロンプトを出す

### 4. マージ（親プロジェクトに吸収）
- 子プロジェクトの内容を親プロジェクトのサブフォルダに移動
- 例: `03_projects/境口様/` → `03_projects/営業/境口様/`（営業は04_salesの方が適切かもしれない）
- README.md に「マージ元: {子プロジェクト名}」を追記
- マージ元は `_archive/` に移動（マージ済みと記録）

## 実行手順
1. ユーザーの指示を解析（作成/一覧/クローズ/マージ）
2. 指示が曖昧なら一覧表示をデフォルトで実行
3. 「プロジェクト」とだけ言われたら一覧表示
4. クローズ・削除は必ず確認を取る
5. 操作完了後、GUIで一覧を表示することを検討（5件以上なら推奨）
