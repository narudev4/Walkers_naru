# セッションチェックポイント

セッションの作業状態をローカルファイルに保存/復元する。セッションが「Prompt is too long」で飛んだ場合の復旧に使う。

## トリガー

### 自動保存（AIが自律的に実行）
以下のタイミングで **ユーザーに確認せず自動で** チェックポイントを更新する:
- 大きなタスクが1つ完了したとき
- ツール呼び出し累計15回に達したとき
- ユーザーが「覚えておいて」「セーブ」「チェックポイント」と言ったとき
- `/compact` を推奨するタイミング（コンテキスト管理と連動）

### 手動保存
ユーザーが「セーブして」「チェックポイント」と言ったら即座に実行する。

## 保存先

`.claude/session-checkpoint.md`

## 保存フォーマット

以下のフォーマットで **上書き保存** する（追記ではない）:

```markdown
# Session Checkpoint

> このファイルはAIが自動更新する。セッションが飛んだ場合、新セッションで「前回の続きから」と言えば復旧に使われる。

Updated: {YYYY-MM-DD HH:MM}

## Current Task
{今やっている作業を1〜2行で}

## Progress
- [x] {完了済みのステップ}
- [ ] {未完了のステップ}

## Files Modified
- {変更したファイルパス}

## Key Context
- {案件名、クライアント名、重要な数値、URL等}
- {この作業で取得した重要データのサマリ}

## Next Steps
- {次にやるべきこと}
- {ユーザーへの確認事項（あれば）}
```

## 復元手順

新セッションでユーザーが以下のいずれかを言ったら復元する:
- 「前回の続きから」
- 「復旧して」
- 「チェックポイント読んで」

復元時の手順:
1. `.claude/session-checkpoint.md` を Read で読む
2. 内容をユーザーに要約して見せる
3. 「この状態から再開しますか？」と確認する
4. 必要なファイルを読み込んで作業を再開する

## 注意
- チェックポイントに **機密情報（APIキー・パスワード）は書かない**
- 大量のデータそのものではなく **サマリ** を書く（チェックポイント自体が肥大化しない）
- 1セッションにつき1チェックポイント（履歴は持たない、上書きのみ）
