# YouTube AI動画 スライド生成

`/yt-script` の台本からWalkersブランドのPPTXスライドを生成する。
JSONを単一ソースとし、エンジン（`yt_slide_engine.py`）でPPTXに変換する。

```
台本(script.md) → slides.json生成 → エンジンでPPTX生成
```

## 入力

$ARGUMENTS に台本ファイルパスまたはスラッグが渡される。

- パスの場合: そのファイルを読み込む
- スラッグの場合: `projects/{slug}/script.md` を読み込む
- 引数なしの場合: `projects/` 内の最新プロジェクトを使用

## スライド3部構成

### Part 1: 冒頭（5枚・固定構成）

| # | type | 内容 | 生成方式 |
|---|------|------|---------|
| 1 | title | タイトルのみ + 会社紹介（タグ/サブタイトル廃止） | テンプレートXMLコピー → テキスト差し替え |
| 2 | text | 問題提起（hero: 32pt Bold） | テンプレートSlide2 XMLコピー → テキスト差し替え |
| 3 | text | 動画の趣旨（hero: 32pt Bold） | テンプレートSlide2 XMLコピー → テキスト差し替え |
| 4 | intro | 自己紹介（固定） | テンプレートXMLコピー |
| 5 | subscribe | チャンネル登録（固定） | テンプレートXMLコピー |

**冒頭3枚の品質ルール（CRITICAL — 視聴継続率に直結）:**
- スライド1: **タグ・サブタイトル禁止**。タイトル本体のみ・3行構成で大胆に
- スライド2: **セリフ抽出型**。ナレーション内の独白セリフを「」で囲んで表示（32pt Bold 中央配置）
- スライド3: **内容リスト型**。「キャッチ + 【本動画の内容】 + ① ② ③」の固定構造（32pt Bold）
- 詳細は `.claude/skills/yt-script/SKILL.md` の「冒頭1〜3枚の質的ルール」を参照

**スライド2 の複数セリフ表示形式（CRITICAL・2026-05-08 追記）:**
ナレーションを 2 文に分割した場合、slides.json では **`\n\n` 区切り** で `lines` フィールドに書く:

```json
{
  "type": "text",
  "lines": "「セリフ1…」\n\n「セリフ2…」",
  "top_in": 1.5
}
```

- 連結 (`"「セリフ1」「セリフ2」"`) で書くと 1 鉤括弧の詰まった表示になり NG
- 改行 1 つ (`\n`) では間隔が足りず詰まる
- 改行 2 つ (`\n\n`) で適切な間隔
- 縦位置が下にずれて見える場合は `top_in: 1.5` (inch) を併用 (`yt_slide_engine.py` の既存対応)

### Part 2: 本編（N枚・台本に応じて変動）

| type | 用途 |
|------|------|
| section | セクションタイトル（全面CHARCOAL + 番号 + タイトル） |
| cards | カード2〜3枚横並び（最も使用頻度高い） |
| table | テーブル（比較表・一覧） |
| comparison | 左右対比カード |
| flow | ステップ横並びフロー |

### Part 3: CTA（8枚・固定）

テンプレートPPTXの末尾8枚をそのままXMLコピー。内容変更不可。

| type | 内容 |
|------|------|
| cta-text | 費用削減実績 |
| cta-image | 実績紹介画像 x3 |
| cta-text | お問い合わせ誘導 |
| cta-image | お問い合わせ導線画像 |
| cta-text | シミュレーター誘導 |
| cta-image | エンディング画像 |

## JSONスキーマ

Claudeが台本から生成するJSONの構造。`projects/{slug}/slides.json` に出力する。

```json
{
  "meta": {
    "slug": "video-slug",
    "title": "動画タイトル",
    "footer": "動画タイトル短縮版 | アプリ開発研究所"
  },
  "slides": [
    { "type": "title", "title": "Claude Codeで\n作ったアプリを収益化する方法\n11選",
      "company": "AI・ノーコード専門の開発会社Walkersで事業企画を担当。\n累計100万PV以上のノーコード・AI専門メディアを運営。" },
    // 注: tag/subtitle フィールドは廃止。タイトル本体に \n で改行した3行構成で書く。
    { "type": "text", "lines": "1行目\n2行目\n..." },
    { "type": "intro" },
    { "type": "subscribe" },
    { "type": "section", "num": "01", "title": "セクション名" },
    { "type": "cards", "num": "①", "header": "ヘッダー",
      "cards": [{ "label": "ラベル", "items": ["項目1", "項目2"], "color": "" }] },
    { "type": "table", "num": "01", "header": "ヘッダー",
      "columns": ["#", "項目", "判定"], "rows": [["1", "...", "yes"]] },
    { "type": "comparison", "num": "01", "header": "ヘッダー",
      "left": { "label": "...", "items": ["..."], "color": "" },
      "right": { "label": "...", "items": ["..."], "color": "alt1" } },
    { "type": "flow", "num": "01", "header": "ヘッダー",
      "steps": [{ "label": "STEP 1", "items": ["..."], "color": "" }] },
    { "type": "cta-text", "text": "..." },
    { "type": "cta-image", "src": "cta-images/cta-slide31-img1.png", "label": "..." }
  ]
}
```

**カードカラー**: `""` (orange), `"alt1"` (blue), `"alt2"` (green), `"alt3"` (purple), `"negative"` (red)

**textスライド**: 1行20文字前後、4〜5行以内。

### `num` フィールドの値域（CRITICAL — 厳守・違反するとスライドが破綻する）

`num` フィールドは **以下の値しか許容されない**。漢字・ひらがな・カタカナ・絵文字・独自ラベルを入れるのは絶対禁止。

| type | 許容値 | NG 例 |
|------|--------|-------|
| `section` | `"01"`, `"02"`, ... `"99"` の2桁ゼロ埋め | ❌ `"結"`, `"序"`, `"破"`, `"急"`, `"01."`, `"1"`, `"第1章"` |
| `cards` / `comparison` / `table` / `flow` | `"①"`, `"②"`, `"③"`, ... `"⑨"` の丸数字、または `""`（空文字 = バッジ非表示） | ❌ `"結"`, `"1"`, `"○"`, `"01"` |

**禁止理由**: エンジンの num バッジは「番号系」を前提にレイアウトされており、漢字や独自ラベルを入れると意図しない見栄えになる（「序破急結」のような独自演出は過去プロジェクトにも実績なし）。**`"結"` は過去のサブエージェントが暴走した実例**。

**まとめスライド等で num を出したくない場合**: `num: ""`（空文字）にする。漢字を入れて装飾するのではなく、num 自体を出さない選択を取る。

### `section` スライド title の行数制約（CRITICAL — 視認性を守る鉄則）

エンジンの section title 描画は **textbox 高さが 1 inch 固定**で、**36pt フォントで 2 行までしか綺麗に収まらない**。3 行入れると押し込まれて密集する＝視覚的に「文字が被って」見える。

| ルール | 基準 | NG 例 |
|--------|------|-------|
| `section.title` の行数 | **必ず 2 行以下**（1行 or 2行） | ❌ `"事例①\nドキュメント要約時の\n隠れた指示による情報流出"` (3行) |
| 1行目に独立カテゴリラベル | **禁止**。「事例①」「ポイント①」のような副題化はしない | ❌ 1行目「事例①」+ 本文 → ✅ 「ドキュメント要約時の\n隠れた指示による情報流出」のみ |

**過去プロジェクト準拠の正解パターン**:
- 「なぜ今ClaudeCode×起業が\n注目されるのか」（2行）
- 「アプリ開発で起業する\n2つの手法」（2行）
- 「失敗を防ぐ\n7つのポイント」（2行）

### サブエージェントへの強制要件

このスキルを実行するエージェント（人間でも AI でも）は **必ず以下を行うこと**:

1. **過去プロジェクトの slides.json を Read して構造を確認**（`projects/claudecode-entrepreneur/slides.json` 等）
2. **過去プロジェクトと違う独自構造（独自バッジ、独自ラベル、3 行 title 等）を絶対に作らない**
3. 上記 2 つの CRITICAL ルール（num 値域・section title 行数）を `slides.json` 出力前にセルフチェックする
4. エンジン実行 (`yt_slide_engine.py --verify`) が PASS しても、JSON の num 値や title 行数が CRITICAL ルールに違反していたら **手で直して再実行**する（`--verify` は画像 blob 健全性しか見ない）

### カードの文字量ルール（CRITICAL — 視認性を守る鉄則）

エンジンはカード内の文字数に応じてフォントを自動縮小するが、限界がある。
**文字が多いと読めないスライドになる。** 以下を厳守すること。

| ルール | 基準 | NG例 |
|--------|------|------|
| 1アイテムの文字数 | **最大15文字**（改行含めず） | ❌「Excel・Googleスプレッドシートをデータベースとして利用」(24文字) |
| アイテム内の`\n`改行 | **禁止** | ❌「社内に蓄積したデータを\n活用して即開発開始」 |
| 1カードあたりアイテム数 | **最大3個** | ❌ 4個以上のリスト |
| 1カードの合計文字数 | **最大40文字** | ❌ 50文字超のカード |
| カード枚数 | **2〜3枚**（エンジン制約） | ❌ 4枚以上（描画崩壊） |

**正しい書き方（キーワード型）:**
```json
{
  "label": "特徴",
  "items": ["環境構築がほぼ不要", "公式ツールチェーン", "TS環境まで自動構築"],
  "color": ""
}
```

**間違った書き方（文章型）:**
```json
{
  "label": "使い慣れたツールをそのまま活用",
  "items": [
    "Excel・Googleスプレッドシートを\nデータベースとして利用",
    "シートを接続するだけで\nアプリに内容が反映",
    "特別なDB知識不要で\n迅速にアプリ開発を開始できる"
  ],
  "color": ""
}
```

**原則: スライドは「読む」ものではなく「見る」もの。キーワードだけ載せ、詳細はナレーションで伝える。**

## 処理フロー

1. 台本を読み、`slides.json` を生成 → `projects/{slug}/slides.json`
2. エンジンでPPTX生成:

```bash
python3 _shared/yt_slide_engine.py \
  --json projects/{slug}/slides.json \
  --verify --open
```

3. `--verify` が PASS であることを確認
4. ユーザーにPPTXを確認してもらう

### エンジンオプション

- `--verify`: 生成後に画像blobの健全性を自動検証
- `--open`: 検証OK後にPPTXを開く
- `--output`: 出力パス指定（省略時: `projects/{slug}/slides.pptx`）
- `--template`: テンプレート指定（省略時: `_shared/template-slides.pptx`）
