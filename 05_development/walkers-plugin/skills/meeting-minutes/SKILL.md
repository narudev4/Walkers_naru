# 議事録作成

トリガー: 「議事録作って」「議事録」「MTGまとめて」「ミーティングメモ」

## 実行手順

### Step 1: ヒアリング

ユーザーに以下を確認する（わかる範囲でOK）:

1. **会議名・案件名**: どのクライアント・プロジェクトのMTGか
2. **日時**: いつのMTGか（Google Calendarから候補を提示してもよい）
3. **参加者**: 誰が参加したか
4. **Geminiメモの有無**: Google MeetのGeminiが自動生成したメモがあるか
   - ある場合 → `google_drive_search` で検索 → `google_docs_get` で取得して活用する
   - ない場合 → ユーザーからの口頭説明・メモ・音声文字起こしテキストをベースにする
5. **追加のメモ・補足**: ユーザーが手元に持っているメモや補足事項

### Step 2: 情報収集

1. **Google Calendar** から該当MTGの情報（タイトル、参加者、説明文）を取得する
2. **Geminiメモ**がある場合、`google_docs_get` でGoogle Docsから本文を取得する
3. **既存の関連ドキュメント**がある場合（過去の議事録・提案書など）、コンテキストとして参照する
4. ユーザーから提供された追加情報を統合する

### Step 3: 議事録ドラフト作成

収集した情報をもとに、以下のテンプレートで議事録を構成する。
ドラフトをユーザーに提示し、修正点がないか確認する。

### Step 4: Google Docsに保存

1. `google_docs_create` で **Google Docs** に議事録を作成し、`google_docs_append` で本文を書き込む
   - タイトル: `【{クライアント名}】議事録_{YYYY-MM-DD}_{会議名}`
   - 既存の議事録フォルダがあればそこに保存
2. ローカルにもバックアップを保存する
   - 保存先: `03_projects/{プロジェクト名}/minutes/YYYY-MM-DD_{会議名}.md`
   - プロジェクトフォルダがない場合は `output/minutes/YYYY-MM-DD_{会議名}.md`

### Step 5: ネクストアクション整理

1. 議事録から抽出したネクストアクションをユーザーに確認する
2. 必要に応じて `/issue-triage` でGitHub Issue / Notionタスクに登録する
3. 次回MTGの日程が決まっていれば、Google Calendarへの登録を提案する

## Geminiメモ活用のルール

Google MeetのGeminiメモが提供された場合:
- 「まとめ」セクション → 議事録の全体サマリーとして活用
- 「詳細」セクション → 各議題の議事内容に再構成
- 「推奨される次のステップ」→ ネクストアクションに反映
- Geminiメモの内容はそのままコピーせず、構造化して再編集する
- 明らかに不正確・不自然な記述があれば、ユーザーに確認する

## ルール
- ドラフト段階でユーザーの確認を必ず取る（推測で確定しない）
- 既存のクライアント情報（memories/や過去のドキュメント）がある場合は参照する
- 機密性の高い内容（金額・契約条件等）はローカル保存を優先する
- 決定事項とネクストアクションは必ず明確に分離する
- 次回MTGが決まっている場合は必ず記載する
