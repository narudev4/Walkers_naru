# distill（学びの蒸留）

トリガー: 「蒸留して」「distill」「学びをまとめて」「振り返って記録」（project-close からも呼ばれる）

セッション・案件で得た知見を、再利用可能な形で memories に昇格する。**次の goal-check が Step 0 で consult する**ことで、同じ地雷を二度踏まない学習ループを閉じる。

## 蒸留先

| 先 | 内容 |
|---|---|
| `context/memories/decisions.md` | 意思決定とその理由（既存フォーマット踏襲） |
| `context/memories/incidents.md` | フェーズ逸脱・稼働超過・検収トラブル・技術的地雷（無ければ新規作成） |
| `context/memories/facts.md` | 確定した事実・データ（必要時） |
| 受託開発マニュアル スプシ `📋 インシデント記録` | 全社共有すべき教訓（任意・naru 承認の上で） |

## 実行手順

### Step 1: 対象の収集

対象セッション/案件の経緯を、スプシ（確認事項の解決履歴・作業一覧）・DAILY.md・議事録から拾う。

### Step 2: 蒸留候補の抽出

次の観点で「次回に効く知見」だけを抜く（雑多なログは入れない）:
- **地雷**: 想定外に詰まった点・原因・回避策（例: lib/claude.ts のローカルCLI前提で Vercel 落ち）
- **判断**: 分岐でどちらを選び、なぜか
- **再利用パターン**: 効いた手順・確立したパイプライン

### Step 3: incidents.md へ起票

各インシデントを `事象 / 原因 / 教訓（次回のチェック観点）` の3点で記録。goal-check が読みやすいよう、教訓は「〜を着手前に確認する」の形にする。

### Step 4: decisions.md へ追記

重要な意思決定を既存フォーマット（日付見出し + 決定 + 理由）で追記。

## 完了報告

蒸留した件数と、incidents.md に追加した「次回チェック観点」を naru に提示する。
