# goal-check（/goal 発射前検査）

トリガー: 「goal-check」「発射前チェック」「自走していい？」「ガチガチに固まった？」

**目的**: 「どこまでやればいいか」の判定を naru でなく AI が担う。スプシを精査し、足りない情報を具体的な質問に変換して確認事項へ起票し、naru には**不足リストだけ**返す。不足ゼロで「発射可能」を宣言する。

## 実行手順

### Step 0: 過去のインシデントを consult

`context/memories/incidents.md` と decisions.md を読み、過去に踏んだ地雷（同種の見落とし）を今回のチェック観点に加える。

### Step 1: スプシ全体を読む

L3 から真理源スプシ ID を取得し、作業一覧・確認事項・環境情報・（あれば）検収シートを `read_sheet_values` で読む。

### Step 2: 7項目の機械検査

| # | 項目 | 不合格条件 |
|---|---|---|
| 1 | フェーズ整合 | L3 の現フェーズと作業一覧の対象 Phase が一致しない |
| 2 | ステータス健全性 | 対象 Phase に `未確認` が残っている |
| 3 | 確認事項の解消 | 対象 Phase に依存する確認事項が `未解決/要対応/承認待ち` |
| 4 | 完了条件の明示 | /goal に渡す完了条件文（作業一覧基準）が一意に書けない |
| 5 | 環境情報 | デプロイ先・接続情報・ローカル手順が未記載 |
| 6 | 検収準備 | 対象に検収シートが未発行（テストフェーズの場合） |
| 7 | 絶対NG/ゲート | L2 フェーズゲートを越える作業が混じっていないか |

### Step 3: 行単位の精査（最重要）

作業一覧の対象行を1行ずつ見て、「**この行を AI が独力で実装するのに必要な情報が揃っているか**」を自己評価する。足りない行は:

- 何が不足か（仕様・値・判断・受領物）を**具体的な質問文**にする
- 確認事項タブに `append_table_rows` で起票（カテゴリ付き）
- 作業一覧の当該行を `未確認` に戻す

### Step 4: 不足リストを naru に提示

```
■ 発射前検査結果（Phase {N}）
不足 {件数}件 → 確認事項に起票済み:
  - {3-2}: {決済プロバイダ未確定で着手不可}（確認事項#{12}）
  - ...
これらに回答いただければ発射可能です。
（回答はスプシ確認事項に直接記入 → /loop が拾って再開、でもOK）
```

不足ゼロなら:
```
✅ 発射可能。完了条件文の案:
「作業一覧 Phase {N} の全行が ✅完了（検収シート全PASS）」
/goal "{この条件文}" で自走を開始できます。
```

## 禁止

- naru に「ガチガチに固まりましたか？」と丸投げしない。**判定は AI が行い、具体的な質問だけ出す**
- 不足を握りつぶして「発射可能」と言わない（事実の扱い・L1）
