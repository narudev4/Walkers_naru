# タスク登録（重複チェック付き）

トリガー: 「タスク登録」「タスク追加」「TaskGodに登録」

## 目的
TaskGodへのタスク登録時に、既存タスクとの重複を防止する。
登録前に必ず既存タスクを全件確認し、類似タスクがないことを担保してから登録する。

## 実行手順

### Phase 1: 登録内容のヒアリング
ユーザーから以下を確認する:
- **タスク名**（必須）
- **説明**（任意）
- **タイプ**: quick / deep（デフォルト: quick）
- **プロジェクト**: 既存プロジェクトに紐づけるか（任意）
- **期限**: due_at（任意）
- **見積時間**: estimate_minutes（任意）

### Phase 2: 重複チェック（必須・省略不可）
登録前に以下の3ステップを**すべて**実行し、重複がないことを確認する。

#### Step 2-1: 全タスク一覧を取得
```
TaskGod MCP: list_tasks
```
- 返却された全タスク（todo / doing / done すべて）のタイトルと説明を確認する

#### Step 2-2: キーワード検索
```
TaskGod MCP: search_tasks
  query: "<登録予定のタスク名から抽出したキーワード>"
```
- タスク名から主要キーワードを2〜3語抽出して検索する
- 例: 「国永紙業 モックアップ作成」→ 「国永」で検索、「モックアップ」で検索

#### Step 2-3: 重複判定
以下のいずれかに該当する場合、**重複の可能性あり**と判定する:
- タスク名が完全一致する
- タスク名の主要キーワードが70%以上一致する
- 同じ案件名 + 同じ作業内容の組み合わせが存在する
- 説明文の内容が実質的に同一である

### Phase 3: ユーザーへの報告と確認

#### 重複なしの場合
「既存タスク○件を確認しました。重複なしのため登録します。」と報告し、Phase 4へ進む。

#### 重複の可能性がある場合
類似タスクを一覧で提示し、ユーザーに判断を仰ぐ:
```
⚠️ 以下の類似タスクが見つかりました:

1. [タスク名] (ステータス: doing, ID: xxx)
   説明: ...

登録予定のタスク: [新タスク名]

→ 以下のどれにしますか？
  A) 重複ではないので新規登録する
  B) 既存タスクを更新する（タスクIDを指定）
  C) 登録をキャンセルする
```

### Phase 4: タスク登録
重複なし or ユーザーが新規登録を選択した場合のみ実行する。

```
TaskGod MCP: create_task
  title: "<タスク名>"
  description: "<説明>"
  type: "quick" or "deep"
  project_id: "<プロジェクトID>"（指定がある場合）
```

必要に応じて追加設定:
```
TaskGod MCP: update_task
  task_id: "<作成されたタスクID>"
  due_at: "<期限 ISO 8601>"
  estimate_minutes: <見積時間>
```

### Phase 5: 登録結果の報告
以下を報告する:
- タスクID
- タスク名
- ステータス
- 紐づけたプロジェクト（あれば）
- 期限・見積時間（設定した場合）

## 複数タスク一括登録の場合
複数タスクを登録する場合は、Phase 2の重複チェックを**タスクごとに**実施する。
一括で全タスクを登録してから確認するのではなく、1件ずつチェック→登録のサイクルを回す。

## 注意事項
- **Phase 2 は絶対に省略しない**: どんなに明らかに新規と思えるタスクでも必ず実行する
- **done ステータスのタスクも確認対象**: 完了済みタスクの再登録を防ぐ
- **プロジェクト一覧も必要に応じて確認**: `list_projects` で既存プロジェクトを確認し、適切なプロジェクトに紐づける
