# スプシ駆動（業務OS）

トリガー: 「スプシに展開して」「作業一覧作って」「工程表に書いて」「確認事項に起票」「ステータス更新して」「真理源スプシ」

スプシ操作は **`mcp__google-workspace__*`** のみ（UUID コネクター禁止＝第三者アカウント事故）。
標準スキーマは `docs/harness/spreadsheet-schema.md` を**必ず Read してから**着手する。

## 前提の確認

1. 案件の真理源スプシ ID を L3（`clients/{案件}/CLAUDE.md`）から取得する。無ければ naru に確認
2. まだスプシが無い新規案件なら、`create_spreadsheet` で作成し ID を L3 に記録するところから

## 実行手順

### Step 1: スキーマ Read

`docs/harness/spreadsheet-schema.md` を読み、列定義・ステータス5値・派生モデルを確認する。

### Step 2: 現状読み込み

`list_sheet_tables` / `read_sheet_values` で既存タブと作業一覧を読む。**既存の確定事項を消さない**。

### Step 3: 作業一覧へ展開

naru から受けた作業内容を、Phase 見出し（`▶`）+ タスク行（`{Phase}-{連番}`）に分解して `append_table_rows` / `modify_sheet_values` で記入する。

- **全工程から派生する項目を漏れなく出す**: 技術検証 / 未確定事項 / 機能要件 / 非機能要件 / 仕様 / 質問・確認事項
- 各行の初期ステータスは `未確認`（AI 未精査）。精査して前提が揃ったら `着手可能`
- **確定したことだけ書く**。未確認・憶測は作業一覧でなく確認事項へ

### Step 4: 確認事項の起票

精査中に出た不明点・矛盾・受領待ちを確認事項タブに起票する（カテゴリは schema 参照）。対応する作業一覧の行は該当タスクを `未確認` のまま据え置き、依存を明記。

### Step 5: 派生タブの生成

案件フェーズに応じて必要タブを `ensure_tab` で用意（要件定義なら画面一覧/機能一覧/非機能要件、本開発なら API設計/DB設計、テストなら検収シート）。

### Step 6: ステータス更新（作業セッション中）

- 着手したら `対応中`、検証 PASS したら `✅完了`（**✅完了は検証者の PASS 後のみ**。自己採点禁止 → verifier に委ねる）
- `naru確認` 列には**書き込まない**（人間専用）
- 条件付き書式が無いスプシには schema の5色を `manage_conditional_formatting` で設定

## 完了報告

更新したタブ・行範囲・残確認事項の件数を naru に報告する。確定していないことをスプシに書いていないか最後に自己チェックする。
