# コンサル道場（Consul Dojo）要件 v2

自習用トレーニングアプリ。スキマ時間に、コンサルとしての「引き出し（breadth）」と「瞬時の振り分け（routing）」を反復で鍛える。**打倒古谷**が目標。

> 経緯: 2026-06-26 wi2案件2回目MTGで、古谷の「想定外の悩みを即座に解決カテゴリへ振り分け、打ち手＋根拠＋概算で即答する」力に圧倒された。naru の課題は引き出しの数＋振り分けの瞬発力。これを反復訓練で埋めるためのアプリ。

---

## 1. 鍛える対象（筋肉）
- **主筋: routing力** — 先方発言 → 解決カテゴリ → 打ち手＋根拠＋概算 を、白紙から即答する
- **副筋: breadth** — 引き出しの数
- コミュ力は naru の既存強みのため対象外（一旦クリア扱い）

## 2. モード
- **ドリル（breadth・速さ）**: 選択式/一問一答で高速回転。スキマ時間向け。
- **壁打ち（routing・本命）**: リアルな状況が提示 → 白紙に開放回答 → AI採点＋模範解答（◯◯流）＋見落とした引き出しを提示。

## 3. トラック（学習領域＝データで拡張）★スコープ: 全般
エンジンは共通。トラックは `{コンピテンシーマップ, 採点ルーブリック, 模範解答の根拠ソース}` のデータで足していく。
- **T1. 技術提案routing**（インフラ/DB・ストレージ/分析・計測/認証・権限/移行/外部連携/保守運用/コスト・課金モデル/セキュリティ/ベンダーロックイン/AI活用・役割分担/**スコープ判断＝あえて削る**）← **MVPはここ**
- **T2. 補助金**（対象判定/要件/申請書の書き方/採択ロジック/スケジュール感）
- **T3. ビジネス思考フレームワーク**（SWOT、ユニットエコノミクス、3C、PL感覚、価格設計 など）
- **T4. サービス知識**（自社/Walkersのサービス、主要SaaS・競合の特徴と使いどころ）
- （将来）T5以降を随時追加

## 4. コンテンツ＝「逆算コンピテンシーマップ × 動的生成」★方式確定
固定の問題バンクは手作りしない。以下の2層で動的に出題する。
1. **コンピテンシーマップ（逆算の設計図）**: 「一流コンサル/古谷ならできること」を頂点に、各トラックで**習得すべき項目を逆算してツリー化**。項目ごとに到達基準（何を即答できればOKか）を定義。議事録＋Claudeで設計。
2. **動的生成（winnaru Claude）**: マップの各ノードに対し、**実コーパスに接地**して問題＋模範解答を都度生成。naru の弱点ノードを狙って無限に出題。
- **一次ソース（コーパス）**: 過去のHP問い合わせ / 古谷さんの Gemini議事録 / 古谷さん同席の naru の tl;dv / 案件 `minutes/`・提案書
- 効果: 「模範解答が古谷流そのもの」＋固定バンク枯渇なし＋弱点特化。

## 5. アーキテクチャ ★確定
- **採点・生成エンジン = winnaru（常時起動Windows・SSH済）上の Claude Code headless（`claude -p`）**
- **構成**: スマホ/PC のフロント(Next.js/Vercel) → API → winnaru の Claude headless → 問題生成・採点JSON返却
- **接続経路（要設計）**: Vercel/スマホ → 自宅Windows を安全に繋ぐ（Cloudflare Tunnel もしくは Tailscale）＋認証必須
- **論点/リスク**: 常時起動の信頼性（落ちたら不可）／レイテンシ／並行リクエストのキュー処理
- **進捗保存**: winnaru 側に保持（スマホ前提のため端末をまたいで参照）

## 6. 記憶定着
- コンピテンシーノード単位で弱点を記録 → **spaced repetition** で再出題（弱いノードを動的生成が優先的に突く）
- 連続日数など軽いゲーミフィケーション（任意）

## 7. プラットフォーム ★確定: モバイルファースト
- Next.js + Vercel（モックと同じ流儀／naru が手書きできる）
- **スマホ前提のレスポンシブ**（空き時間用、まずはスマホで快適に）
- 進捗は winnaru 側（サーバ）保存。複数端末から同じ進捗。

## 8. フェーズ設計 ★順序確定: 学習点ファースト
**アプリより先にカリキュラムを固める。** 学ぶべき点（コンピテンシー）が真の資産で、アプリは配信シェルに過ぎない。先にエンジンを作るとぶれる。

### Phase 1: カリキュラム設計（今ここ）
- 学ぶべき点を**網羅的に洗い出す**（全ドメインのコンピテンシーマップ）
- 採点は当面 **Claude chat に貼って手動**で回す（インフラ不要・即訓練開始できる）
- これで「何を・どの順で身につけるか」を確定させる

### Phase 2: アプリ化（カリキュラム確定後）
- winnaru headless で問題の動的生成＋AI採点を自動化
- Next.js/Vercel フロント（壁打ち画面・採点表示・弱点ダッシュボード）
- 接続経路（Cloudflare Tunnel / Tailscale）＋認証、進捗はサーバ保存

## 9. 次にやること（Phase 1）
1. **全ドメインの学習点インベントリ（マスターシラバス）を作る** ← 次の成果物
2. ドメインごとにコンピテンシーマップを詳細化（T1=技術提案routing は設計済）
3. 各ノードを実コーパス（tl;dv/Gemini議事録/問い合わせ/提案書）に接地
4. Claude chat 用の「壁打ちプロンプト」を用意して訓練開始
→ ここまで固めてから Phase 2（アプリ化）に着手
