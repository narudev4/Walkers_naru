# T1 コンピテンシーマップ：技術提案 routing

**頂点（できるようになりたい姿）**
> 先方の業務課題・不安を聞いた瞬間に、適切な技術カテゴリへ振り分け、**打ち手＋根拠（なぜそれ）＋概算コスト**を白紙から即答できる。さらに「あえて削る」等の上級ムーブで信頼を取りにいける。

**マップの読み方**
- `ノード` = 習得単位。`到達基準` = それが即答できればクリア。`実トリガー` = 動的生成のタネにする現実の先方発言（wi2コーパス由来）。
- winnaru の Claude が各ノードに対し、実トリガーを変形して問題＋模範解答を生成する。

---

## C1. インフラ / サーバー配置
- **N1 データ配置の判断（同居/分離/ローカル物理）**
  - 到達基準: セキュリティ要件 × データ重量 から配置を即答し、根拠（例: KDDI子会社の社内審査）を添えられる
  - 実トリガー: 「KDDI完全子会社でセキュリティ要件が厳しい」「社外流出を防ぎたい」
- **N2 サーバー契約名義の選択**
  - 到達基準: 自社名義（手数料が乗る）vs 直接契約＋保守依頼（コスパ良）のトレードオフを説明できる

## C2. DB / ストレージ
- **N3 専用ストレージの要否判断**
  - 到達基準: 「動画等の大容量がなければ内部DBで足り、専用サーバー不要」と即答。重いデータが出た時のみ専用サーバーを足す筋を示せる
  - 実トリガー: 「PDF等のドキュメントをアップしたい」

## C3. 分析 / 計測
- **N4 利用状況計測の打ち手**
  - 到達基準: 「画面の閲覧計測なら GA / ヒートマップ＝追加予算なし」と振り分け、個別実装は『誰がどの画面まで』必要な時だけ、と線引き。管理者IP除外などの実務Tipsも添える
  - 実トリガー: 「どの画面が社員にどれだけ見られているか知りたい」「PV/UU的な数字をダッシュボードで」

## C4. 認証 / 権限
- **N5 ロール別権限設計**
  - 到達基準: 参照のみ/新規作成不可 等を Salesforce 同様に設計でき、サンドボックス（エージェントの操作制限）まで言及できる
  - 実トリガー: 「ユーザーによって参照のみにしたい」

## C5. データ移行 / 連携
- **N6 移行 vs 連携の切り分け**
  - 到達基準: 「引っ越して持ってくるデータ」と「Salesforceを残して連携するデータ」を要件定義で仕分ける枠組みを即提示できる
  - 実トリガー: 「Salesforceの既存データはどうなる？」

## C6. 外部連携
- **N7 定番連携先の即提示**
  - 到達基準: 契約書＝クラウドサイン、請求＝会計ツール、等の定番をユースケースで即答できる
  - 実トリガー: 「契約は紙とJust」「請求書は取引先様式で目視転記している」

## C7. 保守運用
- **N8 保守の価値の具体化**
  - 到達基準: 「サーバー監視・外部API仕様変更対応・瑕疵担保との切り分け」を具体ユースケースで語り、月額の妥当性を腹落ちさせられる
  - 実トリガー: 「運用保守には何が含まれる？」

## C8. コスト / 課金モデル
- **N9 課金構造の翻訳**
  - 到達基準: アカウント課金（SF）vs サーバー利用料ベースの差で「SFより安くなる」を説明、ランニング目標（月2万〜5万）を提示できる
- **N10 契約形態の比較**
  - 到達基準: 要件定義の時給制（早く終われば安い）vs 請負（一定額で割高になり得る）を、顧客に有利な側から正直に提示できる

## C9. セキュリティ / 監査
- **N11 グループ審査・AI特有リスク**
  - 到達基準: グループ内審査プロセスへの伴走、プロンプトインジェクション等 AI 特有の視点に触れられる

## C10. ベンダーロックイン
- **N12 不安解消トークへの翻訳**
  - 到達基準: 「Next.js＝開発者人口多・一般言語＝他社/フリーランスへ引き継ぎ可」を、顧客の『逃げられたら詰む』不安を潰す言葉に変換できる
  - 実トリガー: 「特定ベンダーに縛られたくない」

## C11. AI活用 / 役割分担
- **N13 AI利用体制の設計**
  - 到達基準: 全員付与の課題（スキル差・従量課金増）→ 担当者集約体制（簡単な活用は全員/画面構築は担当者）を提案できる
- **N14 活動管理の自動化**
  - 到達基準: メール・Googleカレンダーから活動情報を自動吸い上げ→記録レコメンド、という AI 活用を要件として出せる

## C12. スコープ判断（あえて削る）★上級
- **N15 リスク領域を自ら外す**
  - 到達基準: 在庫管理・AP管理を「組み込むのは危険」と判断し、自ら受注範囲から外して信頼を得るムーブを再現できる
  - 実トリガー: 「在庫やアクセスポイントの管理も入れられる？」

## 採点ルーブリック（壁打ち共通・初期版）
各回答を以下4観点でスコア（各0〜25点）：
1. **振り分けの妥当性** — 正しい技術カテゴリへ routing できたか
2. **打ち手の具体性** — 抽象論でなく具体ツール/構成まで出せたか
3. **根拠（なぜそれ）** — 顧客のリスク/コストの言葉で説明できたか
4. **上級ムーブ** — あえて削る/弱点先出し/無料案提示/不安翻訳 等を織り込めたか

模範解答は、該当ノードの実トリガー由来のコーパス（古谷の実発言）を根拠に生成する。
