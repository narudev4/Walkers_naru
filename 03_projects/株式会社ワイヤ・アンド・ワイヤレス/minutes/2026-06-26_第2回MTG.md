## 1. 概要

Salesforce 利用中の営業部門システムを **AI駆動開発によるスクラッチ**でリプレイスし、利便性向上とランニングコスト削減を実現する提案。要件定義→開発→テスト→段階移行まで、段階的アプローチで進める計画を提示。

## 2. システム構成と技術仕様

- AI駆動開発によるスクラッチ開発。Salesforce 月額利用料を削減できる可能性
- フロントエンドは **Next.js**。開発者人口が多く、ベンダーロックインが起きない
- ブラウザベースの Web アプリ。PC / スマホ両対応
- コードベースは GitHub 等に上げ、接続された AI により、ユーザーが**自然言語でシステム修正を指示**できる
- AI チューニングは、特定ディレクトリに指示ドキュメントを配置し AI が最初に読む方式で実現
- Salesforce 公式 API ドキュメント等、最新情報を参照させることで API 仕様変更に対応

## 3. データストレージとセキュリティ

- サーバー + DB 構成。セキュリティ要件に応じてローカル/クラウドに配置可
- 現状は PDF 等のドキュメント中心で重いデータなし → 要件なければシステムと同一サーバーで可
- セキュリティ要件が厳しい場合、データとシステムを別サーバーに分離推奨
- 重いデータ管理が必要になればストレージ専用サーバーを借りる選択肢
- サーバー契約名義: 保守運用を任せるなら弊社名義も可だが手数料が乗る → 直接契約 + 保守依頼の方がコスパ良
- AWS 等の著名サーバーへのデータ配置は許容されるケースが多い
- 要件が厳しければ社内ローカルサーバーへの物理配置も可

## 4. 機能要件と画面設計

- 主要機能の柱: 商談管理 / 顧客管理 / 在庫管理 / ダッシュボード / ユーザー権限管理
- **見積書発行**: 現状 Salesforce 標準機能で作っており営業ユーザーに非常に使いづらい → 改善必要
- 見積書・請求書は取引先指定の様式で出力が必要。現状は目視で転記作業が発生
- 現状は Freeform で様式に落とし PDF 出力 → 本システムで見積データを作成し販売価格・原価を管理する仕組みへ
- 契約関連: 紙と Just で管理、承認プロセスは別システム → 一元管理の検討余地
- **在庫管理・AP管理は本システムに組み込むのは非常に危険 → 別で実施推奨**（スコープ外）
- 項目の**履歴管理**が必要（誰がいつどのステータスを変更したか、Salesforce の編集履歴同様）。レポートで確認できることが望ましい
- ダッシュボードは、ユーザーが自然言語で AI に指示し**カスタマイズダッシュボードを作成**できる機能を提案
- 仕様書・注文書・見積書等のドキュメントを分けて管理可能

## 5. 分析・レポート機能

- どの画面がどれだけ見られているか計測したい（社員の利用状況把握）
- Web サービスの PV / UU のような数字をダッシュボードで見たい
- **Google Analytics や Microsoft のヒートマップ導入で追加予算なしで対応できる可能性**
- システム管理者の IP を除外して GA 計測 → 実ユーザー利用頻度を把握
- 「誰がどの画面を見たか」レベルの詳細計測が必要ならシステム機能として実装

## 6. セキュリティと権限管理

- ユーザーごとに参照のみ／新規作成不可等の制限を Salesforce 同様に設定したい
- サンドボックス: エージェントで特定操作を防止する形で対応
- AI 関連機能はプロンプトインジェクション等、AI 特有のセキュリティ視点を考慮
- グループ内に明確なセキュリティ要件がある場合、社内審査プロセスを通す必要 → 弊社がサポート

## 7. 内製化と保守運用

- 初期構築はサポートを受けたいが、その後は内製運用へ移行したい
- 自分で修正・拡張したい場合は AI 経由で指示
- 当初は自分で壊す可能性があるためサポートが必要
- 壊した場合、保守運用契約があればバージョンロールバックで復旧可
- 保守運用契約に内製化支援を含め、稼働上限を決めてコンサルサポート提供可
- Salesforce 導入時のような細かなサポートは不要（AI が指示に応じて修正するため）

## 8. 保守運用とサポート内容

- 対応範囲: サーバー監視 / バグ修正 / 外部API連携の仕様変更対応
- 納品後半年以内のバグは保守ではなく**瑕疵担保**として修正対応
- 外部API（例: Salesforce API）の仕様変更対応が保守の主要な役割
- サーバー監視: 利用量の異常上昇を検知 → 外部攻撃か利用者増かを判断しプラン変更を提案

## 9. 要件定義と開発スケジュール

- 要件定義: 約1ヶ月（業務フロー設計 + 画面設計）
- 要件定義の稼働: 40〜60時間想定（1ヶ月で終われば40時間台）
- 開発: 1〜1.5ヶ月、その後テスト 0.5〜1ヶ月
- DX系のため段階移行・ユーザー研修が必要
- 一度に全員切替ではなく段階導入が重要（Salesforce 導入時と同様）

## 10. 費用見積もり

- 要件定義費用: **60万〜90万円**
- 開発費用: 設計含め 150〜180時間、合計予算 **200万円後半〜300万円前半**
- 要件定義完了タイミングで、その費用請求 + 残り開発の本見積もりを提示
- 要件定義は**実稼働時間ベース**請求 → 早く終われば安くなる
- 請負契約だと早く終わっても一定額のため若干割高になり得る
- 要件定義が伸びても、業務量が増えなければ請求額は増えない

## 11. ランニングコストと保守運用費

- ランニング: 月額 **2万円程度**で収まる見込み、従業員増でも月額5万円程度に抑えたい
- 営業部門のみ（最大40名）でヘビーに使っても月2万円は超えない見込み
- Salesforce より安くなる可能性が高い（アカウント数削減でコストメリット）
- 保守運用費: 月額 **2.5万〜3.5万円**（コンサルサポート含む）
- 当初はコンサル含め月3〜5万円、ある程度内製できたタイミングで減額可
- AI 従量課金が含まれる → 全員が AI で修正すると増加する可能性、担当者を決めて対応推奨

## 12. 現状分析と改善方針

- Salesforce は約10年前導入、活用は徐々に上がるもまだスプレッドシートで済むレベル
- 顧客情報も本当はもっとやりたいことがある
- 最終的に3事業部すべてに導入したいが、まず営業部門から段階導入し効果確認後に横展開
- 単なるリプレイスではなく**使いやすさの向上**が重要

## 13. 既存システムとの連携

- Salesforce 既存データの活用 / 連携 / 移行が可能
- 「引っ越して持ってくるデータ」と「Salesforce を残して連携するデータ」を要件定義で確認
- 契約書管理: Cloud Sign 等との連携を検討
- 請求書管理: 会計ツールとの連携を推奨

## 14. AI活用と自動化の可能性

- メール・Google カレンダーから活動情報を自動登録し、活動レコメンドを出す AI 活用を検討
- 活動管理は AI で効率化することが望ましい

## 15. 提案内容の特徴

- AI駆動スクラッチで Salesforce 月額利用料を削減
- コード編集可能 → Salesforce より詳細で理想的な UI
- Next.js で開発者人口が多く保守運用が容易
- ベンダーロックインなし → 他開発会社/フリーランスへ引き継ぎ可

## 16. 実装方法とユーザー体験

- **モックアップを見ながら要件定義を進める**。その場で修正 or 次回までに反映
- スピーディーかつ正確な要件定義が可能
- 想定パターンに応じてテンプレートを作成・割当可
- 細かいカスタマイズは AI を使ったアプローチも利用可

## 17. 対応デバイスとシステム構成

- ブラウザベース Web アプリ。PC / スマホ両対応
- 管理者は PC、現場はスマホ想定
- 画面によってはスマホメイン対応も可
- ネイティブアプリ化・アプリストア配布は不要

## 18. 実装の課題と検討事項

- 全員が AI で修正すると AI 従量課金が増加 → 担当者を決めて対応推奨
- ダッシュボード作成等の複雑操作は得意な人が AI で行う方が効率的
- 請求書・資料作成等の簡単な AI 活用は全員が使用可

## 19. 契約と支払い方法

- 要件定義費用を着手金で支払うことも可
- 一度に契約し毎月の支払い額を分けることが可能
- 契約を丸ごとまとめたいという要望にも対応可
- 官公庁やエンタープライズは予算を決めて一度に契約することが多い
