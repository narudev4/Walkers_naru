### iOS ビルドで判明した環境問題と対処（重要）

ビルドには「日本語パス（`オーケーウェブ`）× ASCII 前提ツール」起因の問題が3つあり、すべて対処済み:

1. **CocoaPods が locale 未設定で落ちる** → `pod` 系コマンドは必ず `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` を付けて実行（恒久化するなら ~/.zshrc に export）
2. **app.plugin.js の post_install 重複** → CocoaPods は post_install を1つしか許さないため、
   既存 post_install ブロック内へ追記する方式に**コード修正済み（未コミット**、`frontend/modules/expo-trustdock/app.plugin.js`）
3. **RN 0.85 の prebuilt 取得が非ASCIIパスで失敗**（`URI::File.build` / encoding）→ `node_modules` に**ローカルパッチ済み（yarn install で消える**。再発時は下記3ファイルの `PATCHED (local-only, 2026-06-11 eKYC)` コメント箇所を参照）:
   - `node_modules/react-native/scripts/cocoapods/rndependencies.rb`（2箇所）
   - `node_modules/react-native/scripts/cocoapods/rncore.rb`（2箇所）
   - `node_modules/react-native/sdks/hermes-engine/hermes-engine.podspec`（2箇所）

## 0. いま何をテストするのか（全体像）

今回作った eKYC は3つの部品でできています:

| 部品 | 何をするか | 今回テストする？ |
|---|---|---|
| ① 画面フロー（Web） | マイページ→方式選択→書類選択→本人情報入力→完了 | **✅ 今回これ**（モックで動く） |
| ② iPhone 実機（Native SDK） | IC読み取り・撮影の本物のTRUSTDOCK画面 | 次回（dev build が必要） |
| ③ サーバ（PHP） | TRUSTDOCK API 呼び出し・審査結果の受信 | 次回（Docker 起動が必要） |

①は「**モック**」モードで動きます。モック＝本物の TRUSTDOCK には繋がず、ダミーの応答で
画面の流れだけ確認できる仕組みです。テスト環境（aikata-auth-test）でやっていた
`USE_MOCK=true` と同じ考え方です。
