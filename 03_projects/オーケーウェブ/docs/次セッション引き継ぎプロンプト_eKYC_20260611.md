### 外出中に自走で完了させるタスク（上から順に）

1. **環境復旧確認**: Docker（worktreeから `docker compose up -d`）と Expo（実APIモード、下記コマンド）を起動し、`curl localhost:8080/member/api/rn/auth/ping` と `curl localhost:8083` が通ることを確認
2. **Webhook 反映の検証（curlシミュレート）**:
   - testlogin でログイン→submit を API 直叩き（または既存の user_verifications 行を利用）して trustdock_verification_id を取得
   - `verification.verified` を webhook に POST → DB の result=2 / confirm_timestamp 更新を確認 → `GET /api/rn/identity/status` が verified を返すことを確認
   - 別 verification で `denied` → result=3 → status が rejected になり、**再提出（同フロー再走）が通る**ことまで確認
   - 不正系: 未知の verification_id（404）、verification_id 無し（422）、GET メソッド（405）
3. **API バリデーション網羅（curl）**: submit の personal_info 欠落/生年月日形式不正/gender不正（422）、document_type 不正（422）、未ログイン（401）、Already verified（agelimit=1 に一時変更して 200 "Already verified"、確認後 0 に戻す）
4. **リグレッション一式**: `npx tsc --noEmit` / `npm test`（657+件）/ `npx expo lint`（identity関連にエラーが無いこと）/ Docker 内 `php -l`（Identity_api.php / Trustdock_gateway.php）
5. **iOS ビルド検証（シミュレータ）**: SDKバイナリを `aikata-auth-test/modules/expo-trustdock/ios/Frameworks/` から worktree 側へコピー → `npx expo prebuild -p ios` → `npx expo run:ios`（シミュレータ）。**目的は Swift ブリッジ（再実装）のコンパイル通過とアプリ起動**。シミュレータはカメラ/NFC が無いので SDK 起動が canceled で返るのは想定内。Podfile linkage workaround が効いているか（APIKit/RxSwift の dynamic_framework 化）をビルドログで確認
