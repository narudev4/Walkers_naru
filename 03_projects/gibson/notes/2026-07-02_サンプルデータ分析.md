## ファイル別の構造

### 1. Sample PSI.xlsx（帳票サンプル）
- **帳票の正式呼称は「PSI」**（初回MTG文字起こしの「BSI」は誤記と確定）
- 列: SKU / 製品名 Model / Business Unit / 数量(Qty) / 仕入値単価(NET) / 数量×仕入値 / 売価単価(GROSS・任意) / 数量×売価 / 参考価格 / 粗利額 / 粗利率 / 店舗(任意) / 備考
- 毎月200〜500行×11ディーラー×約5年分が存在
- 含意: スキーマは明確でクリーン。分析ダッシュボードは取込パイプラインさえ作れば実現容易。粗利まで載っているので収益分析も可能

### 2. ハードケース適合表 例データ.xlsx
- 1ファイルに複数タブ（Japan-Dealers / 1 / 2 …）。875行×235列など極端に横長
- 実データはヘッダーが9行目付近から始まり、B列=MODEL品名、C列=INSTRUMENT CODE、J列=CASE CODE。セクション見出し行（コレクション名）やフラグ列（NEW/C=価格変更）が混在
- MSRP・DLR NET等の価格列も同居。「CONFIDENTIAL」表記あり
- 含意: **完全に人間の目視用レイアウト**。AI参照の前に正規化・マスターデータ化の工数が必須 → 見積の主要根拠

### 3. パーツ BOM numberダミーデータ.docx
- Word文書。`BOM: <SKU>` の下に `部品番号 / カテゴリ / 品名` の箇条書きが階層で連なる（o=部品、§=キット内訳）
- 実際は1 BOM(SKU)あたり約80行×数百SKU
- **部品番号は偽造を可能にする高機密データ**（先方明言）
- 想定Q&A: 「モデル XXYY123456 の弦は？」→「146727 / KIT: STRING SET, 10-46 PURE NICKEL のセットが使われています」
- 含意: 提案書でアクセス制御・データの取り扱い設計（ローカル/閉域運用の選択肢）に言及すべき

### 4. mail問い合わせCSV例データ.xlsx
- メール対応ログ。列: フォルダ(分類) / 日時 / 返信日時 / 状況 / 件名 / 差出人 / 宛先 / CC / 本文 / **返信メールの本文** / コメント / メール番号
- 数百行規模。本文にHTMLスタイル混入あり（前処理必要）
- 含意: **過去の質問→実際の回答ペアがそのまま存在**。回答テンプレ生成・RAGの品質評価データとして極めて有用
