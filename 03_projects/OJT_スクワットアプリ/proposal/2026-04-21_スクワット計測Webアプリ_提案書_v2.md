## スクワット計測Webアプリ 開発のご提案

カメラ姿勢推定でスクワットを客観計測し、目標未達時に自動課金する習慣化Webアプリ

## 1. 提案概要

**本提案の目的**
デスクワーカーのスクワット習慣化を、カメラ姿勢推定（MediaPipe／MoveNet）による客観計測と、目標未達時のStripe自動課金を組み合わせたWebアプリで実現します。「StickK型没収モデル × 客観計測」で競合と明確に差別化し、自己申告不正を排除した上で高い継続率を担保します。

- **ターゲット**: 運動習慣をつけたいデスクワーカー（20〜40代）。自己申告型の習慣化アプリで三日坊主を経験し「強制力」を求めている層。
- **特徴**: ① カメラ姿勢推定によるスクワットの客観自動カウント ② 目標未達時のStripe自動課金 ③ PWAによるPC・スマホ両対応とネイティブ不要の初期コスト抑制
- **ローンチ目標**: 2026年10月末MVP β公開→同年12月有償ローンチ
- **期待効果**: 「客観性 × 強制力」の組み合わせにより、競合サービスと明確に差別化し、習慣化アプリ市場で独自のポジションを獲得。

## 2. 現状整理

自己申告型の習慣化アプリ（みんチャレ、Habitica等）やスクワット専用アプリは基本的にユーザー自身の報告に依存しています。海外ではStickKが「没収」による強制力で市場を確立していますが、日本国内で「客観計測 × 目標未達自動課金」を実装したサービスはホワイトスペースです。

| 課題 | 詳細・現状 |
|------|----------|
| 自己申告型アプリは虚偽申告を排除できない | みんチャレ等の既存サービスは「やった／やっていない」がユーザー申告に依存 |
| ペナルティ型サービスは国内に実用的な選択肢がない | StickKは日本語UI・国内決済が不十分 |
| ネイティブアプリ開発は初期コストとスピードが見合わない | 審査・二重メンテ負担が大、PWAで代替 |

## 3. 提案ソリューション

**支援名称（仮称）**: スクワット計測Webアプリ（プロダクトコード：StickK Squat）

ブラウザ上で動作する姿勢推定AI（MediaPipe Pose / TensorFlow.js MoveNet）でスクワット回数を自動カウントし、目標未達時にStripeで事前登録済みのクレジットカードから自動決済する習慣化Webアプリです。

### 主要機能
- カメラ姿勢推定スクワットカウント
- 目標設定・進捗可視化ダッシュボード
- ペナルティ自動課金（Stripe SetupIntent + 動的PaymentIntent）
- ランキング・ソーシャル機能
- PWA通知（iOS制約回避のためメール/LINE併用）

## 4. 利用フロー
1. WebサイトまたはPWA起動
2. アカウント登録 + Stripeカード情報登録（SetupIntent）
3. 目標回数・期間・没収額を設定
4. 毎日カメラでスクワット、姿勢推定が自動カウント
5. ダッシュボードで進捗確認、メール/LINEリマインダー
6. 目標期間末に達成自動判定、未達時PaymentIntent発動
7. 運営管理画面で利用者・成功率・稼働状況モニタリング

## 5. システム構成
- **フロントエンド**: Next.js 15 + React 19 + Tailwind CSS + TypeScript
- **バックエンド**: Next.js Route Handlers + Vercel Fluid Compute (Node 24 LTS)
- **データベース**: Neon Postgres
- **決済**: Stripe (SetupIntent / PaymentIntent)
- **インフラ**: Vercel + Neon
- **認証**: NextAuth (メールマジックリンク + LINE連携)
