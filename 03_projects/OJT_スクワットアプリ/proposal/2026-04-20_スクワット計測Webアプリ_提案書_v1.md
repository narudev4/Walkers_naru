## 1. 提案概要（エグゼクティブサマリー）

### 1-1. 本提案の目的
デスクワーカー向けに、**スクワット習慣を「客観的な計測」と「目標未達時の自動課金」で確実に継続させる** Webアプリ（PWA）を開発します。目覚ましアプリがアラームで起床を強制するのと同じ発想で、「身体活動を行動経済学的な仕組みで習慣化する」ことがコアです。

### 1-2. 想定ターゲット
- 一次ターゲット: 運動不足を自覚しているデスクワーカー（30〜50代、PC前滞在時間が長い層）
- 二次ターゲット: 家トレ・習慣化アプリを試したが継続できなかった経験のあるユーザー

### 1-3. 本提案の特徴（3つの差別化軸）
| 差別化軸 | 内容 |
|---------|------|
| **客観的計測 × 行動経済学** | 既存の習慣化サービス（StickK等）は「自己申告」がほとんど。カメラ姿勢推定で**不正の効かない計測**を実現し、「自己申告ベースの甘さ」を排除 |
| **Webアプリ（PWA）完結** | ストア審査・手数料なし。PC（仕事中）とスマホ（休日）の両方で使える。iOS/Androidの分離開発不要 |
| **AI駆動開発による短期リリース** | Claude Code等のAI開発手法を前提に、**100万円レンジで MVP まで到達** |

### 1-4. ローンチ目標
- 要件定義完了: 契約締結後 2〜3週間
- MVP公開（クローズドβ）: 契約締結後 約2ヶ月
- 本ローンチ: 契約締結後 約3ヶ月

## 4. 利用フロー

```
[初回登録]
  ├ アカウント作成
  ├ カメラ許可
  ├ 目標設定（例: 1日30回 × 週5日）
  └ クレカ登録（SetupIntent：即時課金なし、ペナルティ時のみ発動）

[日次ループ]
  ├ リマインド通知（朝 / 夕方など任意時刻）
  ├ カメラ起動 → スクワット → 自動カウント
  └ 達成 or 未達を記録

[週次判定]
  ├ 達成日数 ≥ 目標 → ペナルティなし
  └ 達成日数 < 目標 → 設定金額を自動課金 + 履歴記録
```

## 5. システム構成・技術スタック

### 5-1. 開発形態
- **Webアプリ（PWA）**: PC（Chrome/Edge/Safari）・スマホ（iOS Safari / Android Chrome）両対応
- ストア審査・手数料を回避。ホーム画面追加でネイティブアプリ相当の体験を提供

### 5-2. 技術構成（想定）
| レイヤ | 採用候補 | 選定理由 |
|-------|---------|---------|
| フロントエンド | Next.js（App Router） + TypeScript | AI駆動開発との親和性が高く、PWA 実装が容易 |
| 姿勢推定 | MediaPipe Pose（33点） または TensorFlow.js MoveNet Lightning（17点） | ブラウザ完結・スマホで30〜50fps 動作実績あり。スクワット検出には膝・股関節の角度取得で十分 |
| バックエンド | Next.js Route Handlers / Vercel Functions | フロントと一体管理でシンプル |
| 認証 | Supabase Auth または Auth0 | メール＋ソーシャルログインを短期間で構築可能 |
| DB | Supabase（PostgreSQL） | 認証と密結合、スケーラブル |
| 決済 | Stripe（SetupIntent + 動的 PaymentIntent） | 「未達時のみ課金」はSubscription標準機能外のためカスタム実装 |
| 通知 | Web Push（VAPID）＋ SendGrid（メール） | iOS の PWA 通知制約を**メール通知で冗長化** |
| ホスティング | Vercel | PWA・Next.js との親和性 |

### 5-3. 技術リスクと対応方針
| リスク | 対応方針 |
|-------|---------|
| iOS PWA プッシュ通知の制約（16.4+・ホーム画面追加必須・APNs 必要） | リマインドは **PWA プッシュ通知＋メール**の二重化で担保。iOS 非対応環境でもメールで欠落なく届く |
| 姿勢推定精度（照明・背景の影響） | MVP ではスクワット1種目のみ対応。膝角度の閾値ベース State Machine で検出。初期モニターの実測で閾値チューニング |
| ペナルティ課金の法務リスク | 利用規約で「未達判定 → 自動課金」の同意を明示。消費者契約法・特商法の観点で**法務レビューが必須** |

### 5-4. セキュリティ
- カメラ映像は **端末内処理のみ**、サーバーに送信しない（プライバシー保護）
- 決済情報は Stripe 側で保管（PCI DSS 準拠）、Wokarz 側でカード番号を保持しない
- 通信は全て HTTPS、Supabase の Row Level Security でユーザーデータを分離
