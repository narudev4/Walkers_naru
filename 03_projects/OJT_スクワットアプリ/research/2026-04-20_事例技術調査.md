# スクワット計測アプリ 事例・技術調査レポート

調査日: 2026-04-20
用途: OJTロールプレイ用 提案書作成の下地資料（4/21 MTG向け）

---

## サマリー
- **スクワット計測アプリ**はiOSネイティブ中心に既存ジャンル（例:「家トレ」）。Web完結の競合はほぼ空白 → **差別化余地あり**
- **姿勢推定**はブラウザで MediaPipe Pose / TensorFlow.js MoveNet がリアルタイム動作可能（スマホで30〜50fps）
- **ペナルティ課金**は既存サービスあり（StickK が代表例）。Stripe標準機能ではなく**カスタム実装**が必要
- **PWAプッシュ通知**は iOS 16.4+ で対応。ただし **ホーム画面追加必須 + APNs証明書が必要** という強い制約
- **100万円スコープ**: AI駆動開発前提で **MVP（姿勢推定+回数カウント+目標設定+Stripe定期課金+基本ランキング）** 程度が現実的

### 1-2. 習慣化＋ペナルティ課金・コミットメント系
| サービス | 課金モデル | 仕組み | URL |
|---------|----------|--------|-----|
| **StickK** | コミットメント契約型（金銭デポジット→未達時に没収） | Yale大学行動経済学者開発。目標未達なら預託金が他者 or 慈善団体へ | https://www.stickk.com/ |
| **みんチャレ** | サブスク型（月500円/3か月1,480円/年4,700円） | 5人1組チームでチャット励まし合い | https://minchalle.com/ |
| **Habitica** | 基本無料+サブスク$4.99/月 | RPGゲーミフィケーション | https://habitica.com/ |

**気づき**: **「行動未達で自動引き落とし」= StickKモデル**が最も近い。ただしStickKは自己申告ベース。
本件は「カメラ計測で客観的エビデンス→自動課金」という**StickK + 姿勢推定の融合**が差別化の肝。

## 2. 技術的実現性

### 2-1. ブラウザ姿勢推定ライブラリ
| ライブラリ | キーポイント数 | 速度（スマホ） | 特徴 |
|----------|-----------|-------------|------|
| **MoveNet Lightning**（TF.js） | 17点 | 192×256で**7ms以下/推論**、50fps+ | 超軽量・低レイテンシ優先 |
| **MoveNet Thunder**（TF.js） | 17点 | 256×256で約20ms/推論 | 精度優先 |
| **MediaPipe BlazePose** | 33点（顔・手・足含む） | WebAssembly+GPU対応 | 詳細な関節取得可能 |

**結論**: スクワット検出（股関節・膝の角度）なら **MoveNet Lightning で十分**。精度が欲しければ BlazePose。
2026年時点でどちらも成熟しておりブラウザ完結で動く。

### 2-2. PWAプッシュ通知（iOS対応）
- **iOS 16.4+**（2023〜）で Web Push API が使える
- **前提条件**: ユーザーが**手動で「ホーム画面に追加」した場合のみ**通知可能（Safariタブ上では不可）
- **実装コスト**: Chrome/Firefox は VAPID Key のみで済むが、**Safariは APNs 証明書が必要** → Apple Developer Program 加入($99/年) 必須
- ペイロードサイズ・ボタン数もSafariは制限あり

**提案書への反映**: 「PWAプッシュ通知はiOSで制約があり、重要通知はメール/LINE Notify等との併用を推奨」と明記する。

### 2-3. ペナルティ課金の決済手段
- **Stripe Subscription は標準機能としてはサポート外**
- 実装アーキテクチャ（案）:
  1. 通常は Stripe Customer に**カード情報のみ保存**（定期課金ではなくSetupIntent）
  2. 目標未達を検出したタイミングで `PaymentIntent` を動的に発行 → 自動決済
  3. 実装工数目安: Stripe側 3〜5人日（Webhook含む）
- 既存比較対象: **StickKの没収モデル**（Escrow的）も検討余地。ただし日本法制・税務の複雑化リスク → 初期は**普通の任意決済**寄りが安全

**提案書への反映**: 「ペナルティ発動ロジックと決済発火はカスタム実装。**利用規約でユーザー同意を明確化する法務観点**が必要」と付記する。

## 3. UI/画面構成の参考
既存アプリからの構成要素：
- **目標設定画面**（1日XX回/週XX日）
- **計測画面**（カメラプレビュー+骨格オーバーレイ+カウンター大表示）
- **ダッシュボード**（日次/週次の達成率グラフ、連続記録）

- **通知設定**（時刻、頻度、PWA通知 or メール）
- **課金履歴**

## 4. 100万円スコープの目安感（AI駆動開発前提）

### 前提
- AI（Claude Code等）を使った高速開発前提 → **30〜50人日相当のスコープ**を想定
- 単価換算: 100万円 ÷ 20,000〜33,000円/日 ≒ 30〜50日

### MVPに含める機能（100万円内で実現可）
| カテゴリ | 機能 |
|---------|------|
| 認証 | メール or ソーシャルログイン（Auth0/Supabase Auth） |
| 姿勢推定 | MediaPipe/MoveNet をブラウザ統合、スクワット1種対応 |
| カウント | 角度ベースState Machineで自動カウント |
| 目標設定 | 日次回数・達成期間 |
| 決済 | Stripe SetupIntent でカード登録＋未達時課金 |
| 通知 | PWA Web Push（対応ブラウザのみ）+ メール（SendGrid） |
| ランキング | 全体ランキング（基本のみ） |
| ダッシュボード | 達成率・連続記録表示 |
| 管理 | 最小限の管理画面（ユーザー一覧・課金履歴） |

### 100万円外（Phase 2 以降）
- 複数種目（腕立て・腹筋）対応
- チーム機能・招待制ランキング
- 動画保存・フォーム診断AI
- ネイティブアプリ化
- iOS APNs証明書まわりのプッシュ最適化

### 「松竹梅」提示案
| プラン | 金額 | スコープ |
|-------|-----|---------|
| **梅** | 70万円 | 認証＋姿勢推定＋目標設定＋基本ダッシュボード（課金・ランキングなし） |
| **竹** | 100万円 | 梅＋Stripe決済（ペナルティ課金）＋基本ランキング＋PWA通知 |
| **松** | 150万円 | 竹＋複数種目＋管理画面強化＋運用保守1ヶ月 |
