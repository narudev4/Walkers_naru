## 1. 結論 — SEO 最適なドメイン構成

**3 者一致で「案C = ドメイン構成は現状のまま変えない」が最適。代替案（Cloudflare O2O・Hydrogen 移行・フルヘッドレス化）はいずれも劣後。**

| ホスト | 役割 | 公開時の扱い |
|---|---|---|
| `kaketoco.com`（Vercel / Next.js） | アプリ＝SEO の主戦場。農薬詳細 3,248 ページ + 将来の `/magazine` | robots 開放（実装済みフラグ）・インデックス対象 |
| `shop.kaketoco.com`（Shopify） | 決済・商品管理・ブログ編集画面 | 全ページ `noindex,follow`・検索から隠す |

ただし 3 者とも**条件付き**支持で、共通の主張は次の 1 文に集約される。

> **ドメイン構成（トポロジー）は既に正解。勝負は「ドメインの中身」＝内部リンク構造とクロール制御であり、ここに公開前に塞ぐべき穴が実在する。**

### 8/5 調査から覆った点（重要）

1. **「robots.txt 開放が投下工数あたり最大の効果」は不成立**。農薬詳細 3,248 ページへのサーバー描画リンクが 1 本も無い「孤児ページ」状態のため、robots を開けても sitemap 単独発見となり、インデックスは遅く部分的になる。真のボトルネックは**サーバー描画のハブ/一覧ページが存在しないこと**（反証・SEO 両レビュアーが独立に特定。重要度: 高）
2. **手順の順序が逆**。8/5 調査は「①robots 開放 → ③shop noindex」だが、正しくは **shop noindex が先**。未公開・流入ゼロの今なら、指名検索で shop が出続ける窓を作らずに済む
3. **スラッグ化「今が最も安い」は過大**。後日移行しても UUID→スラッグは DB で引ける計算可能な対応で、動的 301 ルート 1 本で済む（件数比例のコストではない）
4. **soft-404（不正 ID で 200）は現コードでは修正済み**（`page.tsx` が `UUID_RE` 検査で `notFound()`）。チェックリストは「本番再測定」へ格下げ
5. **`unauthenticated_read_content` スコープは `shopify.app.toml:21` に宣言済み**。野呂さん宛質問 4 は「本番トークンへの反映確認」のみに縮小

## 3. 公開前に塞ぐべき穴（3 者の指摘を統合。優先度順）

### P1 — robots 開放より前に必須

1. **`/pesticides/by-*` 4 ページ（by-ingredient / by-rac / by-feature / by-composition）に `noindex,follow`**
   - 農薬詳細からサーバー描画リンクで発見される（`page.tsx:242,261,311,331,379`）のに、受け側は `use client`・canonical なし・title ほぼ重複・sitemap 外。パラメータ空間は事実上無限（by-composition?id= だけで約 3,000 URL）
   - トップの絞り込み URL には faceted navigation 対策が実装済み（`src/proxy.ts:16-28`）なのに、by-* には proxy の matcher が届いていない（`src/proxy.ts:128`）
2. **`robots.ts` の Disallow 修正**: 末尾スラッシュ付き（`/cart/` 等）は実ルート `/cart` にマッチしない（前方一致仕様）。加えて `/fields` `/agent` `/alerts` `/calendar` `/subscription` `/login` `/survey` が未掲載
3. **shop 側 `noindex,follow` を theme.liquid に追加**（robots.txt では塞がない）— これを robots 開放より先に反映

### P2 — 公開前に強く推奨

4. **サーバー描画ハブページを最低 1 系統新設**（作物別 or 有効成分別 or 五十音別。一覧→詳細の `<a>` を初期 HTML に含める）。孤児ページ問題の根本対策で、案C の工数見積りの外側にある唯一のまとまった新規実装
5. **WebSite JSON-LD 併記**（`name: カケトコ` + `alternateName` 表記ゆれ）
6. **重複農薬の処理**: `canonical_pesticide_id` を持つ従属 ID が 200 + 自己 canonical で開いている（`detail.ts:275` にフィルタなし。過去に手作業修正スクリプトが存在 = 漏れの実在証拠）。canonical を代表へ向けるか 301
7. **sitemap 改善**: `lastModified` 追加（Google は priority/changefreq を無視し lastmod のみ参照）+ 静的ページ収録
8. **公開フリップは事前生成の成功確認と別デプロイに分離**（フリップと同一ビルドで DB 不調だと「robots は開いたが sitemap が空」が本番に出る）

### P3 — 判断事項（8/19 で決める）

9. **非農薬商品（園芸資材）の受け皿**: shop 全面 noindex は園芸資材の商品系クエリを検索から完全に消す決定。8/5 調査ではこのコストが伏せられていた。→ **まず shop 全商品のうち農薬に紐付かない点数を数える**（`pesticide_products` 約 3,835 件はほぼ農薬）。数点なら放棄と明文化、主力級ならフェーズ2 で受け皿ページを設計
   - 安価な手当: `/products/:handle` のリダイレクト先を、農薬対応がある handle は shop でなく `/pesticides/{id}` へ向ける
10. **UUID→スラッグ**: 3 者で唯一割れた論点（下記 §4）
11. **レジの同一タブ化**: 意図的な設計（外部遷移の明示）なので UX 合意が必要。推奨は「レジ（checkoutUrl）だけダイアログなし・同一タブ、第三者リンクは現行維持」の出し分け

### フェーズ2（リリース後）

- by-* をサーバー描画 + `generateMetadata` + canonical + パスセグメント化（`/pesticides/ingredient/[name]`）した本物の SEO ハブへ昇格（有効成分名・RAC は検索需要のあるクエリ）
- 混用チェックの**説明ページ**（ツール本体はログイン必須のまま、紹介ページをサーバー描画で）
- 園芸資材の受け皿（必要なら）

### /magazine 実装時の注意（実装フェーズ向け）

- Storefront API バージョンが `2024-01` 固定（`client.ts:47`）で 2026-08 時点サポート外。記事取得の前にバージョン更新 + 既存クエリの回帰確認が必要
- CSP `frame-src` に YouTube が無い → 記事内の動画 iframe が**無言で消える**（マーケ計画は YouTube 埋め込み前提なので要対応）
- `contentHtml` を `dangerouslySetInnerHTML` で流すなら**サニタイズ必須**（`script-src 'unsafe-inline'` のため、Shopify 管理画面の編集権限がそのまま kaketoco.com 上の XSS になる）
- `offers.url` が noindex 予定の shop URL を指す（`page.tsx:129`）→ `pageUrl` に揃える

## 4. 意見が割れた論点: UUID→農薬名スラッグ

| レビュアー | 判定 | 要旨 |
|---|---|---|
| Codex | 公開前に決定すべき・効果は中位 | やるなら `名前+登録番号` 複合。robots 開放・内部リンクより優先度は下 |
| 反証 | **実施すべきでない** | `name` に UNIQUE 制約なし・ローマ字化手段なし・`regroup-canonical` 再実行で代表が入れ替わり URL 集合が動く。UUID の不変性が勝る |
| SEO | 実施推奨・ただし非ブロッカー | 日本語のまま percent-encode + 登録番号接尾なら安全。順位への寄与は小さく、価値は共有可読性・AIO 引用・パンくず。後日移行は動的 301 ルート 1 本で安い |

**裁定（Walkers としての推奨）**: **リリースをブロックしない。UUID のまま公開してよい。** 実施する場合の唯一の安全形は「日本語スラッグ + 登録番号」（登録番号は不変・`registrationNo` は取得済み）だが、ISR 全件事前生成というアプリで最も慎重に設計された部分を触るため、公開日程と引き換えにする価値はない。順位効果は Google 自身が「ごく小さい」としており、後日移行のコストも低いことが確認できたため。

## 5. 8/19 定例への提示ストーリー

1. **構成の結論**: 現状構成が正解。リバースプロキシ統合は不要（Shopify 非サポート + 現構成に Cloudflare 不在）。**開発チームは既に正しい方向で作り込み済み**（robots フラグ・canonical・sitemap の公開フリップ設計は高品質）— 野呂さんチームの設計を立てる形で提示
2. **公開時にやることの確定**: §3 の P1（3 件）→ P2（5 件）を「公開前チェックリスト」として合意。順序は shop noindex → robots 開放
3. **判断をもらうこと**: 園芸資材の SEO を捨てるか / スラッグは UUID のままか / レジ同一タブ化
4. **工数観**: 8/5 調査の「小〜中」は下方修正。フラグ類は済んでいる一方、ハブページ新設・by-* 対策・robots 修正・/magazine（API バージョン更新 + サニタイズ込み）で**中規模**。ただし全て 1 リポジトリ内で完結
