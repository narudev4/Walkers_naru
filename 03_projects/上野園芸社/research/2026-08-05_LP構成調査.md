## 1. 結論サマリー

1. **調査の過程で、ドメインが `kaketoko.com` ではなく `kaketoco.com`（"toco" 綴り）であることが判明した。** 議事録の表記は tl;dv 文字起こし由来の誤りである。詳細は第 2 章。
2. **`kaketoco.com` の robots.txt が現在 `User-Agent: * / Disallow: /` になっている。** 全ページがクロール拒否である。sitemap.xml には農薬詳細ページ 3,246 件が登録済みなので、公開時にこれを外し忘れると SEO 施策がすべて無効になる。LP 議論以前の最優先の技術論点である。
3. **LP のファーストビューには「説明」ではなく「検索窓そのもの」を置くことを推奨する。** 調査した農薬検索系サービスは 4 件すべてがトップに検索 UI を直置きしており、かけとこの最大の売り（同一ページ内で検索⇄詳細を往復できる UX）は説明文より 1 回触らせたほうが速く伝わる。
4. **サブスクは「プレミアムプラン」として既に実装されており、特典は「マイ畑・防除計画の管理」「AI 相談」「広告非表示」の 3 点、月額のみである**（アプリの公開 JS から確認。第 3-4 章）。この設計は「記録・管理に課金する」という競合の相場と方向性が一致しており妥当である。一方で**年額プランがなく、競合が課金対象にしている「提出用 PDF 出力」も見当たらない**。LP を書く前にこの 2 点を詰める価値がある。直接競合の農薬混用チェッカーは月 550 円 / 年 5,500 円で散布記録・PDF 出力（JA 提出用）・全履歴・広告非表示を提供している。
5. **B2B 動線は離脱防止だけでなく、被リンク獲得の入口として設計する。** 古谷が定例で述べた「B2B の人のほうがドメインが強いのでリンクをもらいやすい」という狙い（transcript [19:32]）を活かすなら、問い合わせボタン 1 個ではなく「事業者向けの独立ページ 1 枚」まで作るのが合理的である。
6. **指名検索「かけとこ」には既存語との競合リスクがある。** 「かけとこ」で検索すると特殊詐欺の「かけ子」関連ページが上位を占める（第 8 章）。覚えやすい名前である一方、ブランド確立前は「かけとこ 農薬」の複合語を主戦場に据える想定が要る。
7. **アプリ側には「カケトコスコア」という独自指標が既に実装されている。** 検索結果をおすすめ順に並べる指標であり（meta description と JSON-LD の featureList に明記）、公的な農薬登録情報提供システムにも既存の無料 DB にも無い、かけとこ固有の資産である。**LP の機能訴求はここを軸に立てるべきである。**
8. **社会的証明の素材が現時点でほぼ無い**（会員数・導入事例・レビュー）。代替として使えるのは「収録農薬 3,246 件」「有限会社上野園芸社の実店舗・販売実績」であり、ここは上野様への素材ヒアリングが必要である（第 10 章）。
9. 流入経路別の訴求差分は、**別 LP を 4 本作るのではなく「1 本の LP ＋ アンカーリンクとパラメータによる出し分け」から始める**ことを推奨する。PR 経由だけは B2B 比率が高いため、事業者向けページを着地点にするパターンを別途用意する。

> **議論の前提について 1 点訂正がある。** 定例では「freee はルートを白紙にして `/lp` へリダイレクトしている」という前提で話が進んだが、実測するとこれは事実と異なる。`www.freee.co.jp/` は HTTP 200 でサービス紹介トップを返しており、アプリ本体は `secure.freee.co.jp` という別サブドメインにある。この構成を根拠にすると「ルート＝LP、アプリ＝サブドメイン」という、上野様の要望と正反対の結論が導かれる。8/19 でこの例を引く場合は要注意である（第 4-8 章）。

## 2. 前提の訂正: ドメインは `kaketoco.com`

【事実】議事録（`minutes/2026-08-05_上野園芸社定例/minutes.md`）および transcript には `kaketoko.com` と記載されているが、この綴りのドメインは存在しない。**この点は本調査での指摘後、メインセッション側でも検証され、`kaketoco.com` が正であることが確定している。**

```
$ whois -h whois.verisign-grs.com kaketoko.com
No match for domain "KAKETOKO.COM".
$ dig @8.8.8.8 +short kaketoko.com A      # 応答なし
$ dig @1.1.1.1 +short kaketoko.com NS     # 応答なし
```

一方、`kaketoco.com` は稼働している。

| ホスト | A レコード | 実体 |
|---|---|---|
| `kaketoco.com` | 216.150.1.1 | Vercel（自社システム＝検索アプリ） |
| `www.kaketoco.com` | `24de5ca7b50153fd.vercel-dns-016.com.` ほか | Vercel |
| `shop.kaketoco.com` | 23.227.38.69 | Shopify |

NS は `ns-cloud-b{1..4}.googledomains.com`（Google Cloud DNS）である。「ルート＝自社システム／shop サブドメイン＝Shopify」という議事録の記述は、`kaketoco.com` 上で実際にそのとおりになっている。

> ドメイン構成の是非は並行して別途調査中のため本書では扱わない。ただし**社内資料・スプレッドシート・提案書に `kaketoko.com` と書かれている箇所はすべて `kaketoco.com` に修正が必要**である。この綴り違いは、後述する指名検索・URL 共有・名刺印刷などで実害が出る。

## 3. 現状のかけとこ（2026-08-05 実地確認）

【事実】以下はすべて実際にアクセスして確認した内容である。

### 3-1. アプリ（`kaketoco.com`）

- 技術構成: Next.js（App Router）を Vercel でホスティング。
- `<title>`: 「カケトコ - AI農薬検索アプリ｜作物・病害虫から最適な農薬を検索」
- `<meta name="description">`: 「農家・園芸事業者向けのAI農薬検索アプリ。作物・病害虫・使用方法から登録農薬を検索し、**カケトコスコア**でおすすめ順に表示します。有効成分や系統（RACコード）が一致する農薬、希釈倍率・使用回数・収穫前日数などの適用情報も確認できます。」
- `<meta name="author">` および JSON-LD の `publisher`: **有限会社上野園芸社**（正式社名の確認材料になる）
- JSON-LD の `audienceType`: **農家・園芸事業者**
- グローバルナビと実際のパス: 検索（`/`）／ マイ畑（`/fields`）／ 相談（`/agent`）／ アラート（`/alerts`）／ マイページ（`/mypage`）／ ログイン（`/login`）
- ルート直下が検索アプリの画面になっている（LP ではない）。
- `sitemap.xml` に登録された URL は計 **3,247 件**。うち **3,246 件が `/pesticides/{UUID}` 形式の農薬詳細ページ**、残り 1 件がルートである。LP・マガジン・料金ページは sitemap に存在しない。
- `/subscription` は実在する（後述）。`/lp`、`/magazine`、`/pricing`、`/about`、`/contact` は存在しない。
- **`robots.txt` の内容は `User-Agent: *` / `Disallow: /`**（全面クロール拒否）。

#### JSON-LD に記載された実装済み機能（featureList）

【事実】トップページの構造化データに、開発チームが定義した機能一覧がそのまま入っている。**LP の機能セクションを書く際の一次資料として最も信頼できる。**

1. 作物・病害虫・使用方法からの農薬検索
2. **カケトコスコアによるおすすめ順の表示**
3. 有効成分の種類・濃度・剤型が一致する農薬の表示
4. 同じ系統（RAC コード）の農薬の表示
5. 登録番号・希釈倍率・使用回数・収穫前日数などの適用情報の表示
6. AI を活用した農薬検索

【推奨】「カケトコスコア」は、公的な農薬登録情報提供システム（FAMIC）にも農家 web にも農薬インデックスにも存在しない、**かけとこだけが持つ指標**である。既存の無料 DB との差別化は、この 1 点に集約して訴求するのが最も効率がよい。ただしスコアの算出根拠は【要確認】であり、根拠を説明できないまま LP の目玉にすると、農家という「なぜその薬なのか」を問う層に対して逆効果になりうる。

### 3-2. 農薬詳細ページの中身（サンプル 1 件を確認）

`/pesticides/17432e1a-...`（2,4-D「石原」アミン塩）で確認できた掲載項目は次のとおり。

- 基本情報: 登録年月日、登録番号、有効成分と含有量、剤型、毒性区分（普通物）
- 性能データ: 登録作物数、適用病害虫数、速効性の 5 段階指標、特性タグ（非選択性・茎葉処理・広葉・一年生／多年生 など）
- 適用表: 作物ごとの使用量・使用時期・使用回数・散布方法
- 解説文: 2 段落程度
- 有効成分・RAC コードへの内部リンク（回遊導線として機能している）
- 購入導線: **「現在この商品の購入導線は準備中です」と表示され、購入不可**

【推奨】「速効性 3/5」「特性タグ」といった**独自の構造化データは、公的な農薬登録情報提供システム（FAMIC / 農林水産省）や農家 web にはない付加価値**である。LP の機能訴求はここを軸に立てるべきである。ただし、この指標の算出根拠は【要確認】であり、根拠が説明できないまま LP の目玉にすると信頼性リスクになる。

### 3-3. Shopify ストア（`shop.kaketoco.com`）

- ストア名: 「カケトコ｜農薬・園芸資材検索サイト/通販サイト」
- ナビ: 農薬検索 / 商品一覧 / お問い合わせ
- トップに 12 商品を表示（アクタラ、プレバソン、アニキ 等の殺虫剤・殺ダニ剤）
- サブスク商品の掲載は確認できない。単発購入のみ。
- 会社情報（企業名・住所）の表示はフッターの「© 2026, カケトコ」のみで、特定商取引法に基づく表記へのリンクは存在する。
- Shopify 標準の robots.txt が返っており、商品ページはクロール可能な状態にある（議事録の「Shopify 商品ページは noindex 方向」はまだ未適用）。

### 3-4. サブスク（プレミアムプラン）の実装状況 ★LP の中核に直結

【事実】`/subscription` は実在するが、中身はクライアントサイドで描画され、未ログインでは表示されない。ただし**アプリが公開している JavaScript から、実装済みの UI 文言を確認できた**。以下はその文言そのものである。

- プラン名: **「プレミアムプラン」**
- 特典として画面に列挙されている 3 項目:
  1. **マイ畑・防除計画の管理**
  2. **AI 相談**
  3. **広告非表示**
- 料金ラベル: **「月額料金（税込）」**（金額は Stripe から動的に取得しているため HTML/JS 上では確認できず）
- 申込フロー: 「プレミアムプラン お申し込み」→「お申し込み前のご確認事項」→「同意して決済へ進む」
- 注意書き: 「本プランは毎月自動更新されます（解約されるまで …）」「・いつでも解約可能」
- 状態表示: 「すでにプレミアムをご利用中です」「認証が必要です」（＝申込には**ログインが必須**）
- アプリ内から Shopify への導線として「商品一覧（Shopify ストア）」というラベルが存在する。

【推奨】ここから 4 つのことが言える。

1. **課金対象の設計は妥当である。** 「マイ畑・防除計画の管理」に課金する設計は、競合の農薬混用チェッカーが散布記録・PDF 出力に課金しているのと同じ方向であり、「検索そのものは無料」という相場も守れている。LP もこの前提で書けばよい。
2. **年額プランがない。** 現在は月額のみである。YAMAP が年割を主軸に「月額換算」と「差額」を見せて転換率を取っている（第 4-4 章）のに対し、月額のみだと解約が容易で LTV が読みにくい。**年額プランの追加を提案する価値がある**（サブスクで利益を積み上げるという上野様の方針 transcript [32:03] とも整合する）。
3. **「提出用の PDF 出力」が特典に見当たらない。** 競合が課金対象にしている最も実務的な価値である。「防除計画の管理」があるなら、そこから防除記録を PDF 出力できるかは【要確認】。**これが無いなら、competitor に対して弱い**。
4. **「広告非表示」が特典にあるということは、無料版に広告を出す前提である。** LP では触れないのが自然だが、比較表に「広告非表示」を載せると「無料だと広告が出るのか」と初見に伝わる。広告を実際に出すのか、出すならいつからかは【要確認】であり、**出さないなら比較表からこの項目を落とすべきである**（3 項目のうち 1 つが消えると特典が手薄に見えるため、その場合は別の特典の追加が要る）。

## 4. 参考事例の分析

### 4-1. 農薬混用チェッカー（直接競合）— https://nouyaku-checker.com/

【事実】かけとこの「混用可否チェック」と正面から競合する国内サービスである。構成は次のとおり。

- トップ最上部が**いきなり機能 UI**（「🌱 農薬を選択」→ 作物タブ → 農薬選択 →「混用チェック」ボタン）。サービス説明のヒーローセクションが存在しない。
- PWA インストールを促すバナーを最上部に配置。
- 料金: **無料 + プレミアム 月額 550 円（税込）／年額 5,500 円（税込、2 ヶ月分割引）**。ライトプランも用意（金額未定表示）。
- **有料で解禁される機能: 散布記録、PDF 出力、全期間の履歴閲覧、広告非表示。**
  - 履歴は無料だと直近 10 件まで。「過去 3 ヶ月・全履歴はプレミアムで」という施錠表示。
  - 散布記録の PDF 出力は「個人農家 / 特別栽培 / JA 提出用」の様式を選べる設計。
- 収益源が 3 本立て: プレミアム課金、農薬・肥料メーカー向けスポンサー枠、マーケットプレイス（農家の出品機能）。
- 「チームチャレンジ」（チェック回数を貯めると紹介プラン 1 ヶ月付与）というゲーミフィケーション。
- プロフィール登録で「利用用途（農家・メーカー・自治体等）」を取得している。

【推奨】ここから読み取るべき示唆は 2 つある。第一に、**混用チェック機能そのものは無料が相場**であり、かけとこがここに課金の壁を置くと価格競争で不利になる。第二に、**この競合が課金対象にしているのは「記録・帳票・提出」である**。農家にとって金を払う価値があるのは、判断の補助ではなく事務作業の代行だという仮説がここに現れている。かけとこのサブスク設計はこの前提を踏まえて組むべきである。

### 4-2. AGRIHUB（隣接競合・フリーミアムの完成形）— https://www.agrihub-solution.com/agrihub

【事実】「農家が作った農家のためのアプリ」。農薬管理・農業日誌・売上管理を無料提供し、有料プランを上に載せる構造である。LP のセクション順は次のとおり。

1. ヒーロー（「無料で使える農業日誌・農薬管理アプリ」＋ CTA「無料で始める」）
2. **実績（会員登録 50,000 人突破 / App レビュー No.1 / 豊富な無料機能）＋ ストアバッジ**
3. メディア掲載実績（日経・NHK・フジテレビ等 11 社のロゴ）
4. 受賞歴（JA ACCELERATOR 優秀賞、マイナビ農業 3 冠）
5. キャンペーン告知（システム移行費 0 円）
6. 「個人農家も法人農家もアグリハブが使いやすい理由」（3 点。うち 1 つが「登録料・利用料・解約料 0 円」）
7. 「なにができるの？」（利用シーン 5 つをイラストで）
8. 機能一覧（アイコン 9 個）
9. 機能詳細 01〜05（各機能にデモ GIF）
10. 「農業アプリ利用者数 No.1 の理由」＋ CTA
11. 利用者の声（コメント 6 件＋インタビューカード 2 件）
12. **法人向けサービス（AGRIHUB CLOUD）の紹介 → 導入事例**
13. 最終 CTA「今すぐ無料で始める - 5万人が選んだアプリ」

【推奨】注目すべきは**セクション 2 と 3 の位置**である。ヒーロー直下に実績とメディアロゴを置き、機能説明より先に信頼を取りに行っている。無料サービスで「怪しくないか」という疑念を先に潰す構成であり、農薬という規制商材を扱うかけとこはこれを踏襲すべきである。またセクション 12 は、B2C アプリの LP に B2B（JA・直売所向け）の導線を自然に埋め込んだ実例として、かけとこの B2B 動線設計の直接の参考になる。

| ルーラル電子図書館（農文協） | https://lib.ruralnet.or.jp/ | 有料会員制。「はじめての方へ」「入会申込み」をヘッダーに配置。混用事例の参照が可能 | 有料会員 |

【事実】4 件中 3 件（農薬インデックス、農家 web、混用チェッカー）が、トップページの最上部に説明ではなく**検索 UI そのもの**を置いている。

【推奨】この領域のユーザーは「サービス紹介を読みに来る」のではなく「調べに来る」。かけとこ LP も、FV に検索窓を置いて 1 回触らせる構成にすべきである。ただし LP には「なぜ既存の無料 DB ではなくかけとこなのか」を answering するセクションが不可欠であり、これは**「探す → 確かめる → そのまま買える」が 1 か所で完結する**という点に尽きる（既存の無料 DB はいずれも購入導線を持たない）。

【推奨】競合比較表を LP に載せる場合、公的機関（FAMIC）を比較対象として貶める書き方は避けるべきである。一次情報源への敬意を保ちつつ「登録情報はここ、選ぶ・買うはかけとこ」という補完関係として提示するのが安全である。

### 4-4. YAMAP プレミアム（無料の検索・地図 → サブスクの完成形）— https://yamap.com/premium

【事実】無料で使える地図アプリに有料プランを載せる、かけとこと同型の構造。ページ構成は次のとおり。

1. 価値提案「豊かな山体験を支える安全登山のパートナー」
2. **信頼指標「山を歩くユーザーの 2 人に 1 人が利用」**
3. 3 つの特長（安全 / 地図 / 記録）
4. 料金プラン（**年割プランを主軸に「¥475/月・¥5,700/年」と月額換算で提示、「月額プランより約 4 ヶ月分（¥3,660）お得」と削減額を明示**）
5. ユーザー証言（実体験ベース。遭難経験に触れた切実な声）
6. 追加特典（STORE 送料無料）
7. **無料 vs 有料の機能比較表**（「ダウンロードできる地図の数：無制限 / 1 枚まで」のように制限数を並置）
8. CEO メッセージ
9. 学生無料・ふるさと納税
10. 注意点（自動更新の明示、解約手順へのリンク）

CTA は「年割プランで 1 ヶ月無料体験する」、注記に「いつでもキャンセルできます」。

【推奨】かけとこのサブスクセクションで真似すべき点は 4 つある。(a) 年額を主軸に置き月額換算と差額を明記する、(b) 無料 / 有料の比較表で「制限の数字」を並べる、(c) CTA を「登録する」ではなく「◯日無料で試す」にする、(d) 自動更新と解約導線を同じセクション内に書いて不安を先回りで潰す。特に (d) は、農家という「解約手続きが面倒そう」という懸念を持ちやすい層に効く。

【推奨】さらに「STORE 送料無料」を有料特典に組み込んでいる点は、**物販とサブスクを両建てするかけとこにそのまま適用できる**。平均単価 4,000〜4,400 円・利益率約 14% という条件下では送料無料の常設は難しいが、「有料会員は送料 ◯ 円引き」なら、サブスク料金の中で送料原価を吸収する設計が成り立つ。年 5,500 円のサブスクで送料 800 円 ×3 回分を還元しても、粗利は残る計算になる（具体的な数値は送料確定後に要試算）。

### 4-5. クックパッド プレミアム（検索結果を課金対象にした例）— https://cookpad.com/jp/premium

【事実】無料の「さがす」機能に対し、プレミアムで解禁されるものを 6 つのカードで列挙している。

1. プレミアムレシピ（30 万回以上作られた人気作者の限定レシピ）
2. 殿堂入りレシピ（1,000 人以上が絶賛）
3. 話題のレシピ（つくれぽ 100 人以上）
4. 専門家厳選（悩み別）
5. 献立提案（毎週更新）
6. ランキング（毎日更新）

比較表は提示せず、**プレミアム機能の希少性（限定性・人気実績）のみを強調**する手法である。価格はこのページに掲載されていない。

【推奨】かけとこが「一部の情報をサブスク会員のみ閲覧可にする」構想（議事録 7、transcript [16:37]）を実装する場合の参考になる。ただしクックパッドが課金対象にしているのは「他のユーザーの行動データで絞り込んだ結果」であり、レシピそのものではない。かけとこに置き換えるなら、農薬の登録情報（公的な一次情報）ではなく、**「同じ作物・同じ病害虫で他の農家が実際に選んでいる農薬」「上野園芸社の販売実績に基づく売れ筋」といった、かけとこにしかないデータ**が課金対象の候補になる。公的登録情報そのものをペイウォールに入れるのは、価値・心証の両面で推奨しない。

### 4-6. 食べチョク（B2C LP に B2B 導線を併設した実例）— https://www.tabechoku.com/

【事実】B2C の EC トップに、供給側（生産者・飲食店）の導線をどう同居させているかの実例である。

- ヘッダー内に「**生産者さん・法人の方**」というセクションを設け、その中に 2 本の導線を格納している。
  - 「出品希望の方はこちら」→ `/lp/farmer/`
  - 「飲食店の方はこちら」→ `pro.tabechoku.com`
- B2C の主導線（商品 / 生産者 / 産地 / 特集 / カテゴリー / ふるさと納税）とは階層を分け、B2C の閲覧を邪魔しない位置に置いている。
- ページ内にもバナー形式で「出品希望の方はこちら」を複数箇所に配置。

【事実】着地先の生産者向け LP（`/lp/farmer/`）は独立した 1 枚もので、構成は「ヒーロー（135 万人以上のユーザー・9 つの No.1）→ 食べチョクって？→ 特徴 → **料金体系（手数料 8〜18%、初期費用・月額無料）** → 出品は簡単 3 ステップ → 生産者事例（動画 3 本）→ 食べチョク基準 → 3 つの約束 → 代表メッセージ → メディア掲載 → 運営チーム紹介 → 最終 CTA」。CTA「出品の申請はこちら」を 3 箇所に配置している。

【推奨】かけとこの B2B 動線はこの構造をそのまま縮小して適用できる。すなわち、**(1) ヘッダーの階層を分けた位置に「農薬メーカー・事業者の方へ」を置き、(2) 着地先は独立した 1 枚のページにする**。B2B 事業は現時点でやらないため中身は「かけとことは / 取り組みたい事業者の例 / 問い合わせフォーム」の 3 セクションで十分だが、独立ページにしておくと業界メディアや取引先からの被リンク対象になり、古谷が指摘した SEO 上の狙い（transcript [19:32]）が成立する。ボタン 1 個だけではリンクの受け皿にならない。

### 4-7. 日本農業システム（農業資材 EC の B2B/B2C 切り分け）— https://www.nou.co.jp/shop/

【事実】農業資材 15,000 点規模の EC。参考になる点は次の 2 つである。

- 「**初めての方へ（個人の方）**」と「**初めての方へ（法人屋号の方）**」で入口を切り分けている。専業農家から一般消費者まで同一サイトで扱う際の定石である。
- トップに「譲受書受付の変更告知」を掲示している。毒物・劇物農薬の販売実務が UI に現れている実例である（第 9 章参照）。

### 4-8. freee（対象別の入口切り分け）— https://www.freee.co.jp/

【事実】ヘッダーで「個人事業主向け」「法人向け」に分岐させ、以降のセクション・CTA を対象別に出し分けている。CTA は「無料ではじめる」（クレジットカード不要を強調）と「資料をダウンロード」の 2 系統。トップページに具体的な料金表示はなく、「30 日間無料でお試し可能」「登録はメールアドレスのみ」で参入障壁の低さを訴求している。

【事実・要注意】**定例で「freee はルートを白紙にして `/lp` へリダイレクトしている」という前提で議論が進んだが、これは事実と異なる。** 実測すると次のとおりである（2026-08-05 確認。並行して調査していた domain-research の指摘を受け、本調査でも独立に検証した）。

- `https://www.freee.co.jp/` は **HTTP 200 でサービス紹介トップを返す**（リダイレクトしていない）。
- アプリ本体は **`secure.freee.co.jp`** にあり、アクセスすると 302 で `/users/login` へ遷移する。

つまり freee の実態は「**ルート＝サービス紹介ページ、アプリ＝別サブドメイン**」である。この構成を根拠にすると「ルートは LP、アプリはサブドメイン」という結論になり、**上野様の「かけとこドットコムはこのページ（＝アプリ）であってほしい」という要望とは正反対になる**。8/19 の議論で freee を引き合いに出す場合は、この点を訂正したうえで扱う必要がある。

【推奨】かけとこは対象が「新規就農・就農検討層」と「クロート農家」に割れるが、**freee のように入口を二分するのは推奨しない**。理由は 2 つある。第一に、ユーザーが自分を「新規就農者」と自認して分岐を選ぶとは限らない。第二に、分岐させると LP が 2 本になり運用負荷が倍になる。代わりに、**1 本の LP の中で「上から順に読むと初心者向け、飛ばして検索窓を触るとクロート向け」という構成**にするのが現実的である（後述の第 6 章はこの方針で設計している）。

## 5. LP 構成のベストプラクティスとかけとこ固有のねじれ

### 5-1. 定番の構成要素

【事実】国内の LP 制作各社が公開している構成テンプレートは、おおむね次の 8〜10 要素に収束している（出典: digrart、トライハッチ、CANVAS）。

| 順 | 要素 | 役割 |
|---|---|---|
| 1 | ファーストビュー | 3 秒以内に「自分に関係がある」と判断させる。キャッチコピー・メインビジュアル・権威付け・CTA |
| 2 | 問題提起 | ユーザーの悩み・現状の不利益を言語化する |
| 3 | 共感 | 心理的距離を縮める |
| 4 | 解決策 | 商品がどう課題を解決するかの道筋 |
| 5 | 商品説明 | 機能・特徴と、得られる変化（理想の未来） |
| 6 | 実績・お客様の声 | 社会的証明。導入社数、データ、メディア掲載 |
| 7 | 比較表 | 競合や他手段との違い |
| 8 | オファー・緊急性 | 期間・数量限定、返金保証 |
| 9 | FAQ | 申込み直前の不安を潰す |
| 10 | CTA | 行動喚起。**3〜5 箇所に分散配置**するのが定石 |

フレームワークは、悩み解決型に**新 PASONA**（Problem → Affinity → Solution → Offer → Narrow down → Action）、認知度の低い新ジャンルに**QUEST**（Qualify → Understand → Educate → Stimulate → Transition）、既知の商品や比較検討層に **BEAF**（Benefit → Evidence → Advantage → Feature）が推奨されている。

【推奨】かけとこは「農薬を EC で買う」という行動自体は既存だが、「検索から混用チェックを経てそのまま買う」という体験は新しい。指名検索のベース LP は **QUEST 寄り**（教育・啓蒙）、記事や商品ページから来た比較検討層向けの出し分けは **BEAF 寄り**（結論ファースト）に振るのが噛み合う。

【事実】動画埋め込みについては、LP に動画を配置すると滞在時間が伸び、理解度が上がり離脱率が下がるという二重の効果があるとされ、CVR が 120〜200% に改善した事例が報告されている（出典: Kaizen Platform、ECのミカタ）。ただしこれらはベンダー側の公表事例であり、業種・実装条件が異なる点は割り引いて読む必要がある。

### 5-2. かけとこ固有の 4 つのねじれ

定番テンプレートをそのまま当てると破綻する箇所が 4 つある。

**ねじれ 1: 主機能が無料で、しかも競合も無料である。**
LP の定番は「この商品を買うと解決します」だが、かけとこの検索・混用チェックは無料で提供され、しかも農薬インデックス・農家 web・FAMIC・混用チェッカーという無料の代替が既にある。したがって LP の役割は「買わせる」ではなく、**(a) まず触らせて手放せなくする、(b) そのうえで買う場所としても選ばせる、(c) 記録が必要になった人だけサブスクに引き上げる**の 3 段構えになる。CTA も 1 種類ではなく、この 3 つに対応した 3 系統が必要である。

**ねじれ 2: 収益の主戦場（サブスク）が、ユーザーの来訪動機（検索）と一致しない。**
上野様が定例で述べたとおり「サブスクで利益を積み上げないと」（transcript [32:03]）だが、ユーザーは農薬を調べに来る。古谷の指摘「単純に農薬が売れればいいっていうビジネスではない」「LP をただ検索機能だけ押して農薬売れればいいやにしちゃうと、広告が回らなくなる」（transcript [50:08]）はこのねじれを指している。
【推奨】LP でサブスクを最上部に出すと、来訪動機とずれて離脱する。逆に最下部だけだと読まれない。**「機能紹介の直後、社会的証明の前」**にサブスクセクションを置き、機能を理解した直後の熱量で比較表を見せるのが妥当である。

**ねじれ 3: ターゲットが「読む層」と「読まない層」に割れている。**
古谷の指摘「クロートって全然ページ滞在しない」「クロートだと絶対（動画を）見ない」「新規就農系の人たちをイメージするんだったら動画はあった方がいい」（transcript [54:09] [55:15]）。
【推奨】この 2 層は LP を 2 本に分けるのではなく、**同一 LP 内で「上部＝クロート向けに 1 秒で検索窓、中盤以降＝新規就農層向けに読み物と動画」**という縦の配置で吸収する。クロートは FV で離脱（＝アプリへ遷移）してくれてよく、それは失敗ではなく成功である。

**ねじれ 4: 農薬は規制商材であり、書ける表現に制約がある。**
効果効能の訴求、価格の安さの強調、購入者の資格などに実務上の制約がかかる（第 9 章）。定番テンプレートの「オファー・緊急性」（限定割引・返金保証）はそのまま使えない可能性が高い。

### 6-1. セクション 0: ヘッダー（追従）

- **目的**: どのセクションを読んでいても 1 タップで検索に入れる状態を保つ。
- **載せる要素**:
  - ロゴ（かけとこ）

### 6-6. セクション 5: 機能 02「確かめる（混用可否チェック）」

- **目的**: 差別化の核を提示しつつ、安全性への配慮を示す。
- **載せる要素**:
  - 混用チェックの操作イメージ（2 剤以上を選んで判定するまで）
  - 判定結果の見え方（可否とその根拠、注意事項の表示）
  - **免責の明示**: 「最終的な判断は必ず製品ラベルをご確認ください」
- **コピーの方向【推奨】**: 見出し「その組み合わせ、混ぜて大丈夫か。」／本文「使いたい農薬を選ぶだけで、混用の可否をチェックできます。」
- **CTA**: ［混用チェックを試す］
- 【推奨・重要】AI 判定を「安全です」と断定するコピーは避ける。農薬の混用は農林水産省が推奨しておらず、誤判定時のリスクが事業に跳ね返る。「確認の手間を減らす補助」という位置づけを崩さないことを強く推奨する。免責の文言は法務確認が望ましい（【要確認】）。
- 【推奨】競合の農薬混用チェッカーが同機能を無料提供しているため、**この機能を有料化しない**。ここは集客の入口として無料に据える。
- 【要確認】混用可否チェックは議事録のネクストアクション（NA-20260805-008「AI 機能の仕上げ・混用可否チェックの荒解消」）にあるとおり実装途上であり、公開状態のアプリからは確認できなかった。一方でプレミアム特典には「**AI 相談**」（`/agent`）が存在する。**混用チェックと AI 相談が同じ機能なのか別物なのか**で LP の書き方が変わる。別物なら、無料の混用チェックと有料の AI 相談の線引きを LP 上で明示する必要がある（無料だと思って使ったら課金要求、が最も心証を損なう）。

### 6-9. セクション 8: プレミアムプラン（サブスク）★最重要

- **目的**: 有料転換。LP でここだけは「読ませる」設計にする。
- **載せる要素**:
  - **無料 / 有料の機能比較表**（YAMAP 方式で制限の数字を並置）
  - 価格（年額主軸、月額換算と差額を併記）
  - 無料お試し期間の表示
  - 自動更新の明示と解約手順へのリンク
  - 「いつでも解約できます」の注記
- **比較表の設計案【推奨】**
  実装済みのプレミアム特典は「マイ畑・防除計画の管理」「AI 相談」「広告非表示」の 3 点である（第 3-4 章）。これをそのまま 3 行の表にすると訴求が薄いため、**無料側に「できること」を厚く並べて対比させる**構成を推奨する。無料でここまでできると示すこと自体が、LP 全体の信頼と利用開始のハードル低下に効く。

| | 無料 | プレミアムプラン |
|---|---|---|
| 農薬検索（作物・病害虫・使用方法から） | ◯ | ◯ |
| カケトコスコアによるおすすめ順表示 | ◯ | ◯ |
| 適用情報の確認（希釈倍率・使用回数・収穫前日数） | ◯ | ◯ |
| 同じ有効成分・同じ系統（RAC）の農薬表示 | ◯ | ◯ |
| 商品の購入 | ◯ | ◯ |
| **マイ畑・防除計画の管理** | — | ◯ |
| **AI 相談** | — | ◯ |
| **広告非表示** | — | ◯ |
| （提案）防除記録の PDF 出力 | — | ◯ |
| （提案）送料の優遇 | — | ◯ |

  下 2 行は未実装の提案である。**LP に載せるのは実装済みの機能だけ**とし、提案分は実装判断後に追加する。
- **コピーの方向【推奨】**: 見出し「調べるのは、ずっと無料です。」／サブ「畑ごとに記録して、相談したくなったらプレミアムへ。」
  - この立て方の意図は、無料機能を人質に取らないことで心証を守りつつ、**課金対象を「継続利用者だけが必要になるもの」に寄せる**ことである。競合の農薬混用チェッカーが月 550 円 / 年 5,500 円で散布記録・PDF 出力・全履歴を提供している以上、かけとこが検索そのものに課金すると比較で不利になる（第 4-1 章）。実装済みの設計はこの条件を満たしている。
- **CTA**: ［プレミアムプランを見る］（主）／［まずは無料で検索する］（副）
  - 現在の実装では申込にログインが必須である（「認証が必要です」）。LP から決済まで一直線には行けないため、**CTA の文言を「今すぐ申し込む」にすると期待とずれる**。「見る」「詳しく知る」に留め、ログインが挟まることを織り込むほうが離脱が少ない。
- 【推奨】自動更新と解約について、LP のこのセクション内に明記する。アプリ側には既に「本プランは毎月自動更新されます」「いつでも解約可能」という文言があるため、**LP でも同じ文言を使って表記を揃える**。YAMAP が注意点と解約導線を同一ページに置いているのと同じ理由で、先回りの明示は転換率を下げるより不安を減らす効果のほうが大きい。
- 【要確認・最重要】**月額の金額が未確認である。** Stripe から動的取得しているため外部からは読めない。議事録にも「MTG 中に具体額の言及なし」と記載がある。ここが決まらないと LP の中核が書けない。競合ベンチマークは月 550 円 / 年 5,500 円。
- 【要確認】**年額プランの追加と、無料お試し期間の有無。** 現在は月額のみで、お試し期間を示す文言も見当たらない。

## 8. SEO 観点の論点整理

ドメイン構成そのものは並行調査中のため、ここでは LP に固有の論点のみ整理する。

### 論点 1: robots.txt の全面ブロック（最優先・即対応）

【事実】`https://kaketoco.com/robots.txt` は現在次の内容である。

```
User-Agent: *
Disallow: /
```

一方で `sitemap.xml` には農薬詳細ページ 3,246 件が登録されている。開発中の措置と思われるが、**公開時にこれを外さないと、古谷が SEO の主戦場と位置づけた商品詳細ページ（transcript [15:20]）が 1 ページもインデックスされない**。LP の議論以前の前提条件として、リリースチェックリストに入れるべきである。

### 論点 2: 指名検索「かけとこ」の SERP 競合

【事実】2026-08-05 に「かけとこ」で検索した結果、上位は特殊詐欺の実行役を指す「かけ子」に関する法律事務所のページと辞書サイトで占められており、サービス名として認識されている形跡はない。「かけとこ 農薬 検索」で検索すると、農薬登録情報提供システム、ルーラル電子図書館、農薬インデックス等が並び、かけとこは現れない（robots.txt でブロック中なので当然である）。

【推奨】上野様の「かけとこって覚えやすい名前なんで、かけとこで検索する人は結構いると思う」（transcript [14:33]）という期待は妥当だが、**「かけとこ」単体は同音の既存語（かけ子）と競合する**。当面は「かけとこ 農薬」を指名検索の主戦場と置き、title・meta・見出しに「かけとこ」と「農薬」を必ず併記して、Google に「かけとこ＝農薬のサービス」という関連付けを学習させることを推奨する。ブランド認知が進めば単体でも取れるようになる。

### 論点 3: ルートに LP を置くか、アプリを置くか

【事実】定例では 2 つの立場が出た。

- 上野様: 「かけとこドットコムはこのページ（＝アプリ／検索画面）であってほしい」「かけとこドットコムで調べる人はいないので、かけとこで調べたときにこのページが（出てほしい）」（transcript [11:48] [12:09]）
- 古谷: 「かけとこドットコムのインデックスは真っ白にしといて、リダイレクトかけて `/なんちゃら` に。LP は LP でホスティングして、ルートには何もページがない」（transcript [12:59]）
- 現状: ルートは検索アプリになっている（第 3 章）。

【推奨】この論点は**「ルートに何を置くか」ではなく「指名検索で 1 位に出したいのはどちらか」に翻訳して議論すべき**である。整理すると次のようになる。

| 案 | ルート | 指名検索で出るもの | 利点 | 欠点 |
|---|---|---|---|---|
| A. ルート＝アプリ（現状） | 検索画面 | 検索画面 | 上野様の希望どおり。既知ユーザーが最短で目的に着く | 初見に何のサービスか伝わらない。LP が別 URL になり指名検索で埋もれる |
| B. ルート＝LP | LP | LP | 初見に伝わる。B2B・PR 流入も受けられる | 既知ユーザーに 1 クリック余計に踏ませる |
| C. ルート白紙＋`/lp` リダイレクト（古谷案） | 空 → `/lp` | LP | ルートを中立に保てる | リダイレクト分の遅延。SEO 上の利点は B と大差ない。**根拠とされた freee の構成は事実と異なる（第 4-8 章）** |
| D. **ルート＝1 枚で兼ねる（上部が検索、下部が説明）**【推奨】 | 検索＋説明 | そのページ | 初見に伝わり、かつ既知ユーザーも最上部で即検索できる | 実装がやや重くなる |

【推奨】**案 D を推す。** 第 6-2 章の FV 設計は案 D を前提にしている。上野様の懸念（既知ユーザーが目的に着けない）は、ページ最上部に実際に動く検索窓を置くことで解消できる。「LP かアプリか」の二者択一ではなく、**同じ 1 枚が上から順に「検索 → サービス説明」になっている**という第三案である。クロート層は最上部で離脱（＝検索に入る）してよく、それは失敗ではない（第 5-2 章 ねじれ 3）。

【事実】並行調査していた domain-research の推奨は「ルート＝アプリ画面＋下部にサービス説明セクション。営業用の独立 LP が要るなら `/lp` や `/about` に別置きし、ルートからはリダイレクトしない」であり、**呼び方（アプリに説明を足すか、LP に検索を埋めるか）が違うだけで、出来上がるページは案 D と実質同じ**である。両調査が独立に同じ形へ収束した点は、この案を採る根拠として補強になる。

【推奨】ただし B2B 動線の置き場所については整理が要る。domain-research は「ルートは B2C 導線だけに保ち、B2B は `/lp` 側に寄せる」としており、本書は LP 内にセクションを設ける前提で書いている。**両立させるなら、B2B 動線はルート最上部の検索 UI には置かず、下部のサービス説明セクション内に置く**のが解になる。検索体験を邪魔せず、かつ PR 経由でルートに着地した B2B 層も拾える。PR のリンク先自体は `/business` を直接指定して、ルートを経由させない運用にする（第 7 章）。

なお、これはドメイン構成（Shopify とシステムのどちらをルートに置くか）の結論とも連動する。`2026-08-05_ドメイン構成調査.md` と突き合わせて最終決定すべきである。

### 論点 4: LP のインデックス方針とカニバリ

【推奨】LP とアプリのトップが同じドメインの別 URL に並ぶ場合、「かけとこ」クエリでどちらが出るかは Google の判断になる。意図した側を出すために、次を推奨する。

- LP の `<title>`: 「かけとこ｜農薬の検索・混用チェック・購入がひとつに」のように**ブランド名を先頭**に置く。
- アプリ側検索画面の `<title>`: 「農薬を検索する｜かけとこ」のように**機能を先頭**に置き、指名クエリでの競合を避ける。
- LP からアプリへ、アプリから LP へ相互リンクを張り、どちらに着地しても回遊できるようにする。
- LP を sitemap.xml に追加する（現在の sitemap にはルートと農薬詳細ページしかない）。
- **LP（またはルートページ）に `WebSite` 型の構造化データを入れる。** 現在トップが宣言しているのは `WebApplication` 型で、これは `SoftwareApplication` の下位型であり `WebSite` の下位型ではない。Google が検索結果のサイト名表示（Site Names in Google Search）で参照するのは `WebSite` 型なので、指名検索「かけとこ」で意図したサイト名を出したいなら併記が要る。この指摘は domain-research の調査で判明したもので、詳細は `2026-08-05_ドメイン構成調査.md` を参照。

### 論点 5: 農薬詳細ページの URL スラッグ

【事実】農薬詳細ページの `<title>`・`<meta description>`・`canonical` は、**ページごとに個別生成されており品質も高い**。たとえば「2,4-D「石原」アミン塩 | カケトコ」、description は「2,4-D「石原」アミン塩は石原産業株式会社が登録する除草剤（液剤）です。有効成分は 2,4-PA ジメチルアミン（49.5%）です。7 作物・5 雑草に登録があります（主な対象：一年生及び多年生広葉雑草 …）」という具合に、メーカー・剤型・有効成分・登録作物数・主な対象が自動で入る。**ここは既によくできており、robots.txt を外しさえすれば戦える状態にある。**

【事実】一方、URL は `/pesticides/{UUID}` 形式である（例: `/pesticides/17432e1a-2df6-4a9c-84fa-51ed2f8632fc`）。

【推奨】古谷が「SEO の評価をもらいに行くのは、かけとこのシステムの検索結果の商品ページになりそう」（transcript [15:20]）と述べているとおり、3,246 ページの詳細ページが SEO の主力である。UUID スラッグは URL に検索語を含められず、共有時にも内容が分からない。**農薬名のローマ字またはメーカー＋製品名を含むスラッグへの変更を検討する価値がある**（例: `/pesticides/24d-ishihara-aminen`）。ただしリリース後の変更はリダイレクト管理が発生するため、**リリース前に決めるのが最も安い**。これは LP の範囲外だが、開発チームに早めに共有すべき論点である。

### 論点 6: B2B ページによる被リンク獲得

【事実】古谷の狙い: 「B2B 向けに本当に簡単なやつでいいんでサービスとか作っておくと、B2B の事業のほうが SEO って上げやすい。B2B の B の人のほうが基本的にドメインが強いので、その人たちからリンクをもらいやすい」（transcript [19:32]）。

【推奨】この狙いを成立させるには、リンク先になりうる**実体のあるページ**が必要である。LP 内のボタンだけでは被リンクの受け皿にならない。第 6-14 章で `/business` を独立ページとして推奨したのはこの理由による。

### 論点 7: `/pesticides/` 配下の soft 404（優先度・中）

> **訂正**: 本書の初版では「`/consult`、`/alert` など存在しないパスが HTTP 200 を返している」と記載したが、**これは誤りだった**。レスポンスサイズの一致だけを見てステータスコードを確認していなかったことによる。並行調査の domain-research から指摘を受け、再測定して訂正する。

【事実】ステータスコードを直接測定した結果は次のとおりである（2026-08-05 再測定）。

| パス | ステータス | サイズ |
|---|---|---|
| `/consult`、`/alert`、`/magazine`、`/pricing`、`/zzz-not-exist-9x8y7z` | **404** | 46,856 バイト |
| `/subscription` | 200 | 86,542 バイト |
| `/pesticides/{実在 ID}` | 200 | 153,577 バイト |
| **`/pesticides/does-not-exist`** | **200** | 88,055 バイト |
| **`/pesticides/00000000-0000-0000-0000-000000000000`** | **200** | 88,191 バイト |

つまり存在しないトップレベルのパスは正しく 404 を返している。46,856 バイトで一致していたのは共通の 404 ページ本文であり、サイズの一致は soft 404 の証拠にならない。

【事実】一方、**`/pesticides/` 配下は存在しない ID でも HTTP 200 を返す**。この場合の `<title>` は「農薬が見つかりません | カケトコ」であり、実体がないのに 200 を返す真の soft 404 である。3,246 ページを抱える名前空間なので、影響範囲としてはこちらのほうが大きい。

【事実】ただし、このページには **`<meta name="robots" content="noindex">` が設定されている**。インデックスされる事故は防がれている。

【推奨】インデックス事故が防がれている以上、残るコストはクロールバジェットのみである。**リリースブロッカーではなく、優先度は中**とする。robots.txt を解除する際に、`/pesticides/` 配下の存在しない ID は 404 を返すよう合わせて直せば十分である。第 8 章の最優先事項は論点 1（robots.txt の全面ブロック）のままで変わらない。

### 論点 8: LP を作る前に、詳細ページの内部リンクを設計する

【事実】農薬詳細ページには「同じ有効成分の農薬」「同じ系統（RAC コード）の農薬」への内部リンクが既にある。3,246 ページが相互に繋がる構造である。

【推奨】LP の役割は入口だが、SEO の実質は 3,246 ページの詳細ページ群が担う。**LP から詳細ページへ、詳細ページから LP へのリンクを双方向に張る**ことで、LP に集まった被リンクの評価を詳細ページ群へ流せる。具体的には、LP の機能セクションに「よく検索される農薬」として実際の詳細ページへのリンクを数件置き、詳細ページのヘッダーロゴのリンク先を LP にする、という設計を推奨する。

## 9. 法規制・表現上の留意点

【事実】以下は公的情報に基づく。LP のコピーと機能設計に直接影響する。

- **販売者の届出義務**: 農薬を販売する者は、農薬取締法第 17 条第 1 項に基づき、販売所ごとに氏名・住所・販売所を都道府県知事に届け出る義務がある。事務所を構えずインターネットで販売する場合は、販売者の住所地を管轄する都道府県知事に届け出る。違反した場合は 6 ヶ月以下の懲役または 30 万円以下の罰金、またはその併科の対象となる（出典: 農林水産省「農薬の販売」）。
- **毒物・劇物**: 毒物または劇物に指定された農薬を販売する場合は、別途「毒物劇物販売業者」の登録が必要である。譲受書の交付が必要で 5 年間保存する。帳簿は 3 年間保存（出典: 岐阜県病害虫防除所「農薬販売者の手引き」、栃木県資料）。
- **表示義務**: 登録農薬には農薬取締法第 16 条により、登録番号・農薬の種類・名称・有効成分の種類と含有量・適用病害虫の範囲・使用方法・最終有効年月等の表示が義務づけられている。容器・包装に登録番号等の表示がない農薬（特定農薬を除く）の販売は禁止されている（出典: 農林水産省）。
- **混用について**: 農林水産省は農薬の混用を推奨していない（出典: ルーラル電子図書館の記載）。

【推奨】LP のコピーに次の制約をかける。

1. **効果を断定しない。** 「必ず効く」「病気が治る」等の表現は避け、適用表に基づく事実の提示に留める。
2. **混用チェックを「安全のお墨付き」として提示しない。** 「確認の手間を減らす」という位置づけを守り、ラベル確認を促す注記を機能セクションと FAQ の両方に置く。
3. **価格の安さを主訴求にしない。** 薄利構造とサブスク主軸の戦略に照らして不利であるうえ、規制商材で価格を煽ると心証も悪い。
4. **購入資格・毒劇物の手続きを FAQ で明示する。** 日本農業システムがトップに譲受書受付の告知を出しているのは、この手続きが実際に購入体験に影響するためである。「買えると思ったら買えなかった」体験は離脱と不信につながる。
5. **販売届出済である旨を運営者セクションに明記する。** 規制遵守の明示は、この領域では信頼の獲得手段になる。

なお、上記はいずれも公開情報に基づく整理であり、**LP の最終文言については専門家（行政書士・所管の都道府県担当部署）の確認を経ることを推奨する**。

## 10. 上野様・古谷に確認が必要な事項

LP を確定させるために、次回定例（8/19）までに埋めたい項目である。重要度順に並べた。

### 最優先（これが決まらないと LP の中核が書けない）

1. **プレミアムプランの月額（税込）はいくらか。** プラン名と特典 3 点（マイ畑・防除計画の管理／AI 相談／広告非表示）は実装から確認できたが、金額だけは Stripe から動的取得のため外部から読めなかった。（競合ベンチマーク: 農薬混用チェッカーが月 550 円 / 年 5,500 円）
2. **年額プランを用意するか。無料お試し期間を設けるか。** 現在は月額のみ。年額は LTV と解約率の両面で効く（第 4-4 章の YAMAP 事例）。
3. **無料版に広告を出すのか。出すならいつからか。** 特典に「広告非表示」がある以上、出す前提の実装になっている。出さないなら比較表からこの項目を落とす必要があり、特典が 2 点になるため別の特典追加を検討したい。
4. **防除記録・防除計画を PDF 等で出力できるか。** 出荷先や JA への提出は農家にとって実務価値が最も高く、競合が課金対象にしている機能である。「マイ畑・防除計画の管理」に含まれるかを確認したい。
5. **「AI 相談」と「混用可否チェック」は同じ機能か、別機能か。** 別なら、どちらが無料でどちらが有料かを LP で明示する必要がある。
6. **「カケトコスコア」の算出根拠。** LP の目玉に据える価値がある指標だが、根拠を説明できないと逆効果になりうる。何を評価して順位づけしているのかを一言で説明できる形にしたい。
7. **LP をルートに置くか、アプリをルートに置くか。**（第 8 章 論点 3。ドメイン構成の並行調査と合わせて決定）

### 素材（あるかないかで構成が変わる）

8. **使える写真素材。** 上野園芸社の店舗・倉庫・スタッフ・上野様の顔写真。圃場や農家の写真。ない場合はストック写真の購入予算が必要になる。
9. **社会的証明として出せるもの。** ベータ利用者の声、店頭常連客のコメント、取引農家数、創業年、年間出荷件数など。掲載許諾が取れるものはどれか。
10. **YouTube チャンネルの有無と動画本数。** LP に埋め込む 1 本目をいつまでに用意できるか。誰が撮るか。
11. **取扱商品の点数とメーカー。** Shopify に何点登録予定か。ロゴ掲載の許諾が取れるメーカーはあるか。

### 事業・運用

12. **B2B 問い合わせの受け皿。** 誰が受信し、誰が返信するか。返信のテンプレートは用意するか。（フォームだけ作って放置すると心証を損なう）
13. **農薬販売届出の届出先都道府県と、毒物劇物販売業登録の有無。** LP・フッターに表記するため。
14. **「卸不可・小売のみ」という制約を LP でどう表現するか。** B2B 動線から来た事業者に「仕入れたい」と言われた場合の返し方を含む。
15. **家庭菜園・個人への販売可否。** アプリの JSON-LD では対象を「農家・園芸事業者」と定義しているが、新規就農検討層より手前の「家庭菜園層」を含めるかで LP のコピーが変わる。
16. **上野様が店頭でよく受ける質問トップ 5。** 課題共感セクションと FAQ の一次素材として最も価値が高い。

### ブランド・表記

17. **表記ルールの統一。** 現在、アプリ内の表示名と `application-name` は「**カケトコ**」（カタカナ）、ドメインは `kaketoco`、議事録と社内の口頭表記は「かけとこ」（ひらがな）で揺れている。LP の見出し・title・PR 原稿で表記が割れると指名検索が分散するため、**正式表記を 1 つに決める必要がある**。
18. **ロゴデータとブランドカラー。**
19. **「かけとこ／カケトコ」の名前の由来。** 由来が語れるなら FV や運営者セクションのコピーに使える。
20. **マガジンの正式名称。**（議事録に「かけとこジャーナル」という呼称が一度出たが未確定との記載あり）
21. **社名の正式表記。** アプリの JSON-LD では「**有限会社上野園芸社**」となっている。LP のフッター・特商法表記もこれで統一してよいか。
22. **社内資料の `kaketoko.com` 表記の一括修正。** 正しくは `kaketoco.com`（第 2 章）。
