1. **ドメイン構成は現状のサブドメイン分離を維持する**（kaketoco.com＝自社システム／shop.kaketoco.com＝Shopify）。リバースプロキシでサブディレクトリに統合する案は両方向とも見送る。
   - **① Shopify を自社システム配下に入れる案**: 不可。前回時点で結論済みとして扱われた（[02:30]「前回のミーティングでも話してた」）。本会議で理由の説明はない。
   - **② 自社システム（Vercel）を Shopify 配下に入れる案**: 間に Cloudflare を挟んでルーティングする必要があるが、Shopify 自身も Cloudflare を使っているため Cloudflare 経由 Cloudflare の構成になり、リスクが高い（[02:30]〜[03:39] 古谷）。
   - 野呂さんから「SEO が取れる環境であれば手段は問わない、技術的に不可能なら別のやり方を考える」と方針への同意（[04:16]）。
   - ※ Walkers 側の事前調査（`research/2026-08-05_ドメイン構成調査.md`）では、**①は決済画面を Shopify ドメインから出せないため技術的に不可能**、**②は Cloudflare プロキシを Shopify が公式に非サポートと明言している**、という整理。会議での説明は②の理由を要約したもので、①の根拠には触れられていない。実装判断の際は調査資料側を参照すること。
2. **SEO 評価は自社システム側（kaketoco.com）に集約する**。Shopify 側は noindex にして重複コンテンツを避け、顧客に見える Shopify の画面は決済画面のみとする。Shopify は決済と商品・在庫管理を担うバックエンドという位置づけ（[07:15]）。
   - ※ noindex の適用範囲がブログのみか shop 全体かは発言上明示されていない（要確認表参照）。
3. **ブログは Shopify を執筆基盤として使い、API でシステム側にミラーする**。ゼロからブログ機能を作る案は、追加開発コストに加えて運営が見る画面が 2 つに増えるため見送った。執筆 UI は Shopify 側に残す。
4. **ブログの URL は /blog とする**。Shopify 側は「blog」固定だが、システム側の URL は自由に決められる。マガジン等の名称案も出たが上野様は「名前は何でもいい」との意向。
5. **ブログのレイアウト実装の追加費用は、デポジットから消化する**。記事一覧ページと記事単体ページの最低 2 種類が必要で、単体ページは WordPress テーマの UI を模倣する方向。別途請求ではなく、マーケティング用に預かっている金額から充当する形で上野様の了承を得た。
6. **ブログ記事の執筆は初期は上野様が担当する**。AI を使って書き、手が回らなくなった段階でライター起用を再検討する。ただし着手は先で、**まず商品詳細ページの登録を優先する**（現状 5% 未満、20% 程度まで進んだらブログに着手する意向）。
7. **AI による記事の自動リライトには人間の承認を挟む**。かけとこスコアの変動に応じて記事が自動更新される理想像は共有しつつ、自社名義の発信である以上は丸投げを避ける。管理画面に作り込むのではなく、上野様が Claude Code / Codex を使える前提でローカル側で解決する方がコストを抑えられるという方針。
8. **LP とトップページは分けて両方作る**。LP はサービスの説明と利点を伝える役割、トップページは即座に検索を使える役割。**LP を優先し、トップページの改善は運用フェーズに回す**（[33:41]）。
9. **トップページはファーストビューを検索窓だけにしない**。他プロジェクト NGSS のスタイルを参考に、横長バナー枠（3 枚程度・スクロール可能）を置きキャンペーン等の PR に使う。バナーは管理画面から画像と URL を設定できるようにする。
10. **システム側データの取り出し口を用意する**。農薬の使い方など Shopify 側にない情報はシステム側の DB にあるため、AI が参照できるよう API エンドポイントの公開または MCP サーバーの構築を行う。野呂さん「システム側は開ければ開く、そこまで工数はかからない」。
11. **散布日は「間隔の選択 → 日付の自動算出」の方向で実装する**。現状の日付入力方式は実運用で調整が難しい。上野様「何日おきにかけるかは農家さん次第なので、それを選択できれば勝手に日付まで入る方が親切」。
12. **作物ごとの病害虫情報は農薬データベースから逆算して生成する**。現状は農薬基準の情報しかなく「この作物にどの病害虫が発生しうるか」の情報がない。ただし**生育ステージごとの日数情報（定植後 30 日・40 日など）は DB に存在しないため別途登録が必要**。
13. **在庫は当面手動で入力する**。初期は正確な数字ではなく少なめ（3 本など）に入れ、店頭販売との重複を避ける。会計上は「店頭部門からの買い取り」として処理する。
14. **リリースは今月中、9 月に補助金報告**。LP 作成 → 上野様による機能確認 → リリース → 研修フェーズ・納品 → 運用フェーズ、の流れ。報告期限は 10 月 20 日頃。
15. **初期ターゲット設定は次回に持ち越した**（時間切れ）。
