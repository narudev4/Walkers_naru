## 1. 提案概要

### 本提案の目的

既存スーパーマーケット会員アプリの会員向けに、地域の加盟店企業と連携したクーポン配布 Web アプリケーションを新規構築いたします。既存会員アプリとは別システムとして開発し、会員番号 API 連携によるログイン認証を実現いたします。

- **ターゲット:** 既存会員アプリのユーザー（スーパーマーケット会員）
- **特徴:** ① 既存アプリとは独立した別システムとして構築（既存システムへの影響を最小化） ② 加盟店企業が自社クーポンを登録・管理できるマルチテナント構成 ③ 管理画面による一元的なクーポン配布管理・使用状況分析
- **ローンチ目標:** 要件定義完了後 1〜1.5 ヶ月で開発完了を目指します
- **期待効果:** 加盟店企業が配布するクーポンを会員が Web 上で受け取り・使用でき、使用状況データを一元管理できるシステムの実現

## 2. 現状整理

### プロジェクトの前提条件

初回 MTG にて共有された現状・前提条件を以下に整理いたします。

| 課題 | 詳細・現状 |
|---|---|
| 既存会員アプリ | クライアント企業はスーパーマーケットの会員アプリを保有しております。会員番号 API 連携によりクーポンシステムへのログインを実現する方針です |
| 別システムとしての構築 | クーポン配布システムは既存アプリとは独立した Web アプリとして構築いたします。既存システムの保守運用は Toppan 様が継続されます |
| レジ連携・使用方式 | 加盟店ごとにレジ・決済システムが異なるため個別連携は困難 → 運用でカバーする方向です。クーポン使用方式（バーコード／ボタン押下／スタッフ手動）は要件定義にて確定いたします |

## 3. 提案ソリューション

### 支援コンセプト

**支援内容：クーポン配布 Web アプリケーション開発**

既存会員アプリの会員基盤を活用し、地域の加盟店企業が参加できるクーポン配布プラットフォームを構築いたします。ユーザー向け・管理者向け・加盟店向けの 3 面構成とし、クーポンの配布から使用・データ管理までを一気通貫で実現いたします。

### 主要機能一覧

| 機能カテゴリ | 概要 |
|---|---|
| ログイン認証 | 既存アプリの会員番号で API 認証。セッション引き継ぎは初期フェーズでは不要です |
| クーポン一覧・使用 | 配布中クーポンの閲覧、使用（方式は要件定義にて確定いたします）、使用履歴管理 |
| 管理者ダッシュボード | 期間指定でのクーポン使用数確認、クーポン作成・編集・配布設定（回数制限・有効期限等）、加盟店管理 |
| データ分析・出力 | CSV エクスポートで提携企業にデータ提供、AI サマリー作成、PDF レポート出力 |
| 加盟店ポータル | 加盟店が自社クーポンの使用データを確認できます。クーポンコード使用履歴で重複使用を防止いたします |

## 4. 利用フロー

1. **会員ログイン:** 既存アプリの会員番号でクーポン Web アプリにログインします（API 認証）
2. **クーポン閲覧:** 加盟店から配布されているクーポン一覧を閲覧、条件・有効期限を確認します
3. **クーポン取得:** 利用したいクーポンを取得します（取得済みクーポンは「マイクーポン」に保存されます）
4. **店舗でクーポン提示:** 加盟店舗にてクーポン画面を提示します（バーコード表示等、使用方式は要件定義にて確定いたします）
5. **使用確認・値引き:** 店舗スタッフがクーポンの有効性を確認し、値引きを適用します。使用済みとしてシステムに記録されます

## 5. システム構成

### 開発形態

- **プラットフォーム:** ブラウザベースのWebアプリケーション
- **対応デバイス:** PC・スマートフォン・タブレット（レスポンシブデザイン）
- **モバイルアプリ:** 初期フェーズでは不要です（Webで完結）

### 推奨技術スタック

- **フロントエンド:** React / Next.js（モックアップで採用済み。レスポンシブ対応）
- **バックエンド:** Node.js API サーバー（既存会員アプリとの API 連携基盤）
- **データベース:** RDB（PostgreSQL 等。クーポン・使用履歴・加盟店データを管理）
- **インフラ:** 既存サーバーの空き領域活用を第一候補とし、要件に応じてクラウドも検討いたします

### セキュリティ対策

- 会員番号 API 認証により、不正アクセスを防止いたします
- クーポンコード定期更新により、スクリーンショットの不正利用を防止いたします（長期運用決定後に実装検討）
- 使用履歴 DB 管理により、重複使用を防止いたします

## 6. 開発スケジュール

要件定義フェーズで仕様を確定した後、開発フェーズに移行する段階的アプローチを採用いたします。AI 駆動開発の特性上、要件定義書の精度が開発速度に直結するため、要件定義の品質を最優先といたします。

| フェーズ | 期間 | 主な作業内容 |
|---|---|---|
| Phase 1 | 約2〜4週間 | 要件定義・基本設計（画面一覧・機能一覧・API仕様を策定いたします） |
| Phase 2 | 約1〜1.5ヶ月 | 開発（フロントエンド・バックエンド・管理画面・加盟店ポータル） |
| Phase 3 | 約2週間 | テスト・品質検証（結合テスト・ユーザー受入テスト） |
| Phase 4 | 約1〜2週間 | リリース・初期運用支援 |
