# モックアップ設計判断メモ

作成日: 2026-06-18
作成者: Claude（naru 不在時の自律作成）

---

## 1. 成果物タイプ: A（業務システム）

**理由**: クーポン配布・管理は業務ツール。スーパーの30万会員が日常的に使う実用アプリであり、LP・ブランドサイトではない。
**影響**: ヒーロー見出し・宣伝コピー・派手なCTAは排除。情報密度を上げ、定型・予測可能なレイアウトを採用。

## 2. カラースキーム

| 用途 | カラー | 理由 |
|------|--------|------|
| Primary | Emerald (#059669) | スーパー・食品・フレッシュ感。信頼感のあるグリーン |
| Accent | Amber (#F59E0B) | クーポン・お得感・注目を引く暖色 |
| Admin Primary | Slate (#334155) | 管理画面のプロフェッショナルな基調 |
| Danger | Red (#DC2626) | エラー・警告 |
| Background | #F8FAFC | User面の軽い背景。真っ白より目に優しい |

**意図**: スーパーのブランドカラーは未確認（未確定事項#1）。汎用的で食品小売と相性の良いグリーン+アンバーを選定。次回MTGでクライアントのブランドガイドラインを確認し調整可能。

## 3. フォント

| 用途 | フォント | 理由 |
|------|----------|------|
| Heading | Zen Maru Gothic | 丸ゴシック。消費者向けの親しみやすさ + 日本語の美しい可読性 |
| Body | BIZ UDPGothic | UD（ユニバーサルデザイン）対応。幅広い年齢層が利用するスーパー会員向け |

**意図**: スーパーの会員は年齢層が広い（20代〜70代）。UDフォントで視認性を担保しつつ、丸ゴシックで堅すぎない印象に。

## 4. レイアウト方針

### User面（モバイル: 375px基準）
- ボトムナビゲーション（ホーム/履歴/マイページ）
- カード型クーポン一覧
- スマホ端末フレーム内で表示（テストハブから遷移時）
- **理由**: 既存スーパーアプリの会員がスマホで使う前提。ボトムナビは片手操作に最適

### Admin面（デスクトップ: 1280px基準）
- 左サイドバー + トップバー
- テーブル・グリッド中心の情報密度の高いレイアウト
- **理由**: 管理者はPCで操作。一覧性と操作性を重視

### 加盟店面（デスクトップ: 1280px基準）
- シンプルなヘッダー + メインコンテンツ
- Admin面より簡素（加盟店は自社データのみ確認）
- **理由**: 加盟店スタッフはITリテラシーが様々。シンプルさ優先

## 5. テーマ: ライトモード

**理由**: スーパーの会員アプリとして明るく親しみやすい印象が適切。ダークモードは業務上不要。

## 6. クーポン使用方式: 3パターン全て実装

MTGで「バーコード / ボタン押下 / スタッフ手動」の3方式が検討対象とされた。
モックアップでは3パターン全てをタブ切り替えで見せる。
**意図**: 次回MTGで「どの方式を採用するか」の議論材料にする。1つに絞るよりも、全パターンを見せた方が意思決定が早い。

## 7. ダミーデータの設計

- クーポン: 5種類（ガソリンスタンド割引、ドラッグストアポイント、飲食店セットメニュー、家電量販店値引き、美容室割引）
- 加盟店: 5社（上記に対応）
- 会員: テスト用1名（会員番号: 1234567890）
- **意図**: MTGの議事録に「ガソリンスタンド等の地元企業」とあるため、リアルな業種構成で作成

## 8. 画面遷移構造

```
User面:
  ログイン → ホーム(一覧) → 詳細 → 使用画面
                            → 履歴

Admin面:
  ログイン → ダッシュボード → クーポン管理
                            → 加盟店管理
                            → データエクスポート

加盟店面:
  ログイン → ダッシュボード → 使用確認
```

## 9. モーション・アニメーション

業務システム（タイプA）のため、派手なアニメーションは抑制。
- ページ遷移: なし（Next.js標準）
- ホバー: ボタン・カードに控えめなscale/shadow変化
- ローディング: スケルトンスクリーンは実装しない（モックアップのため）
- **意図**: 操作フィードバックに留め、業務の邪魔にならないUI

## 10. Admin面ダッシュボードの構成

KPIカード（4枚）+ 週次棒グラフ + 利用ランキング + AIサマリーの4セクション構成。
- **KPIカード**: 総クーポン数・配布中・今月利用数・加盟店数 → 管理者が一目で把握すべき指標
- **週次チャート**: CSSのみの棒グラフ（Chart.jsなしでモックアップの軽量性を維持）
- **AIサマリー**: 「自動生成」バッジ付き。提案書で「AI活用」をアピールする布石。PDF出力/再生成ボタンで実運用イメージを提示
- **理由**: CONTEXT.mdの要件「ダッシュボード（集計・AIサマリー）」をそのまま具現化

## 11. クーポン管理テーブル + モーダルCRUD

一覧はテーブル形式（業務システムの標準）、新規作成はモーダル。
- テーブルカラム: 名前・加盟店・割引・期間・上限・利用数・状態・操作
- モーダル: 全フィールドを1画面に収めて入力ステップを最小化
- **理由**: 管理者が日常的に行うCRUD操作。テーブル+モーダルが最も低学習コストで効率的

## 12. 加盟店の使用確認（4桁コード入力UI）

スタッフ確認方式の対になる画面。4つの大きな入力ボックスで1桁ずつ入力。
- 自動フォーカス移動（1桁入力 → 次のボックスへ）
- Backspace で前のボックスに戻る
- 確認完了後にクーポン情報・会員番号（マスク済み）を表示
- **理由**: ガソリンスタンドのスタッフなど、ITリテラシーが様々な人が使う。大きなボタン + シンプルなフローで誤操作を防止

## 13. データ出力画面の設計

左: 設定パネル（形式・データ種別・期間）、右: プレビュー+実行ボタンのサイドバイサイド。
- CSV / PDF のトグル選択
- 4種のデータ（利用履歴・クーポン一覧・加盟店情報・月次サマリー）
- 期間指定 + 推定件数表示
- **理由**: 「CSV出力・PDF出力」はCONTEXT.mdの要件。プレビューで確認してからエクスポートする安全なUX
