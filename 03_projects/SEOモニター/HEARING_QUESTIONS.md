## §K. コード読解で新たに浮上した論点

### K-1. Google CSE 依存の代替（重要）
現状トレンド分析は Google Custom Search API（1日100クエリ無料、超過は失敗）依存。  
超過時はサーキットOPENで **「AI の知識ベース分析」というプレースホルダにサイレント劣化** する。

- SerpAPI / Tavily / Bing 等の代替検索を切替可能にするか
- サーキットOPEN を UI に表示する設計を入れるか

### K-2. Cron スケールアウト戦略
現在の `/api/cron/trend-check` は全テナントの全メディアを1リクエストで処理。メディア数が増えると1メディア当たり 30s しか取れず、エージェンティック処理が回らなくなる。

- Vercel Queues / Workflow 採用判断
- 「メディアID毎に1ジョブにファンアウト」アーキへの移行可否

### K-3. 招待メール送信
現状は招待トークンURLを **UIに表示してユーザーに手動コピペ送信** させる方式。

- Resend / SendGrid / SES 連携の優先度
- 招待時に「歓迎メール本文」をテンプレ化するか

### K-4. LLM プロバイダの固定化 vs 切り替え
現在 `LLM_PROVIDER` 環境変数で claude/openai/gemini を切り替え。ただしプロンプトは1種類で、プロバイダ固有最適化（プロンプトキャッシュ等）はゼロ。

- AI Gateway 採用でフェイルオーバーする方針か
- Anthropic直叩きで固定するか
- 既定モデル `claude-sonnet-4-20250514`（2026年現在やや古い）の更新方針

### K-5. customAnalysisPrompt / customRewritePrompt の UI 追加
API・型・テンプレ変数処理（`{{currentDate}}` 等）は完備されているが、**設定画面に編集 textarea が無い**。30行作業で追加可能。

- 優先度（次に着手するか、後回しか）

### K-6. 一括記事生成（古谷スプシ空白の論点）
既存の「一括インポート」は **既存 URL を取り込む** 機能で、KW→記事の **新規一括生成** は未実装。

- KWリスト or トピッククラスター → 記事一括生成 の仕様
- 並列実行上限、品質保証（差別化 / 重複防止）
