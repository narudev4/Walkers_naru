# SEO記事運用フロー 全細分化マップ

> 出典: 鳳汰共有 https://seo-workflow-gules.vercel.app/
> 取得日: 2026-05-27
> サイト記載のサマリ: **11フェーズ × 92工程 / 1記事あたり 約2〜3週間 / 運用サイクル 月次レビュー**

このフローを **SEOモニター** に実装することが鳳汰からの依頼。

---

## フェーズ1: 戦略策定フェーズ

- **目的**: 何のために、誰に、どんな記事を届けるかを定義する
- **所要時間**: 初回 5〜10時間 / 四半期見直し 2時間
- **工程数**: 11工程
- **成果物**: SEO戦略書・KPI定義書・トピッククラスターマップ・本数計画表
- **落とし穴**: KPIをPV数だけに設定するとCVに繋がらないKWを量産しがち。必ずCV近接KPIを混ぜる

### 1-A. 事業・メディア目的の定義
- 事業ゴール → SEOのKGI/KPIへの分解（ツール: Notion / スプレッドシート）
- 売上 / リード / 商談 / 認知のうちどれを獲るか
- 目標CV種別の決定
- 資料DL・問い合わせ・無料相談・ウェビナー登録など
- 月次の目標流入数・CV数の数値化
- 投資予算と回収期間の決定
- 記事単価 × 本数 ÷ 想定CVRで回収シミュレーション

### 1-B. ターゲット設計
- ペルソナ作成（職種 / 役職 / 課題 / 情報源）
- カスタマージャーニーマップ作成
- 認知→興味→比較→決定→継続の5段階
- 各ステージの検索行動の言語化

### 1-C. メディア戦略
- トピッククラスター設計
- ピラー（柱）記事と関連記事の階層を決める
- 競合メディアの選定（3〜5社、ツール: Ahrefs / Ubersuggest）
- 差別化軸の決定（独自データ / 体験 / 監修 / 速報性）
- 年間 / 四半期 / 月次の本数計画

## フェーズ2: キーワード調査フェーズ

- **目的**: 勝てる&CVに繋がるKWを発掘し、優先順位をつける
- **所要時間**: 記事1本あたり 1〜2時間 / 月次の棚卸し 半日
- **工程数**: 14工程
- **成果物**: KWマップ（クラスター単位の一覧）・優先順位付きKWリスト
- **落とし穴**: ビッグKWだけ狙うと勝率0。ロングテール+商業KWを混ぜる

### 2-A. KWの洗い出し
- シードキーワードの列挙（事業ドメイン・商品名・サービスカテゴリから50〜100語）
- サジェスト・関連語の収集（Ahrefs / Ubersuggest / ラッコKW / GSC）
- 競合上位ページからのKW逆引き（Ahrefs Organic Keywords）
- 質問系KW（Know系）の収集（AlsoAsked / Yahoo知恵袋）
- PAA（People Also Ask）の収集

### 2-B. 指標の取得
- 検索ボリューム取得
- KD（キーワード難易度）取得
- CPC / 商業性（広告出稿の有無）
- トレンド推移確認（Googleトレンド）

### 2-C. 分類・優先順位
- 検索意図の分類（Know / Do / Buy / Go の4分類）
- ファネル位置のタグ付け（TOFU / MOFU / BOFU）
- 自社で勝てるKWの絞り込み（DR・既存記事との関連）
- KWマップ作成（クラスター化）
- 優先順位スコアリング（CV近接性 × ボリューム ÷ 難易度）

## フェーズ3: SERP・競合分析フェーズ

- **目的**: 上位を取るために必要な情報量・角度を見極める
- **所要時間**: 記事1本あたり 1〜2時間
- **工程数**: 13工程
- **成果物**: SERP分析シート・差別化方針メモ
- **落とし穴**: 上位記事の見出しコピペで構成を作ると、独自性ゼロで上位に上がらない

### 3-A. SERP構造分析
- 検索結果TOP10のURLリスト化
- SERPフィーチャー確認（強調スニペット / PAA / 画像 / 動画 / マップ / ナレッジパネル）
- 広告枠の数（商業性の判断）
- 上位ドメインの傾向（大手メディア寡占 or 個人ブログ混在）

### 3-B. 上位記事の構造抽出
- H2/H3見出しの全抽出（ラッコ見出し抽出 / SimilarContent）
- 文字数・画像数・表の数の測定
- 共通して扱われているトピックの抽出
- 独自で扱われているトピックの抽出
- 出典・引用の傾向確認

### 3-C. 自社・競合状況
- 自社の現状順位確認（GSC / Ahrefs）
- カニバリ記事の有無確認
- 競合の被リンク数・DR確認
- 差別化ポイントの抽出（独自データ / 体験談 / 監修者 / 速報 / 図解）

## フェーズ4: 記事構成設計フェーズ

- **目的**: 執筆前に勝負を決める。構成で7割が決まる
- **所要時間**: 記事1本あたり 2〜4時間
- **工程数**: 15工程
- **成果物**: 記事構成書（タイトル・見出し・各セクションの要点・図解計画）
- **落とし穴**: 見出しを「ですます調」「体言止め」など揺らすと回遊性が下がる。記事内で統一

### 4-A. タイトル・メタ情報
- タイトル案5パターン以上（ツール: `/title-gen`）
- KW前方配置・数字・年号・ベネフィット明示
- meta description作成（120字前後）
- OGP用タイトル・説明文
- スラッグ（URL）案

### 4-B. 見出し構成
- H2/H3階層設計
- 検索意図への最短回答→深掘り→比較→行動の流れ
- 各H2の目的・含めるべき要素を明記
- 想定読了時間・文字数目安の決定
- FAQセクションの設計（PAAの質問を取り込む）

### 4-C. ビジュアル・構造化
- 図解・画像・表の配置計画
- アイキャッチのトーン決定
- 構造化データの種類選定（Article / FAQ / HowTo / BreadcrumbList）

### 4-D. 導線・信頼性
- 内部リンク先の決定（既存記事 / 他クラスター）
- CTAの配置設計（中段 / 末尾 / 追従）
- 監修者・著者プロフィールの決定
- 出典・一次情報の事前リストアップ

## フェーズ5: 執筆フェーズ

- **目的**: 構成書に従い、ファクトと独自性を盛り込んで書く
- **所要時間**: 記事1本あたり 4〜10時間（文字数による）
- **工程数**: 18工程
- **成果物**: 記事Markdown / Googleドキュメント・画像素材一式
- **落とし穴**: AI生成のまま入稿すると一次情報ゼロ・体験ゼロで上位は無理。必ず固有名詞と数値を実例で埋める

### 5-A. 情報収集・準備
- 一次情報・統計データの収集
- 出典URL・引用元の事前整理
- 監修者からのコメント・チェック依頼
- 事例・体験談・スクショ素材の準備

### 5-B. 本文ライティング
- 導入文（リード）執筆（H2見出しを入れず、結論先出し・読者の悩みを言語化）
- H2ごとに本文執筆
- 1見出し1主張ルール（H3も同様）
- 2〜3文ごとに改行（スマホ可読性）
- 太字は1見出し1箇所まで
- ダッシュ記号「—」「ー」連発を避ける
- 出典は『»出典：...』形式で記載

### 5-C. ビジュアル制作
- アイキャッチ作成（Canva / Figma）
- 記事内図解作成（ツール: `/create-diagrams`）
- 表のHTML化
- スクリーンショット撮影・加工

### 5-D. CV要素
- CTAコピー作成
- 資料DLバナー・問い合わせ導線の設置
- 関連記事リンクの内部リンク文作成

## フェーズ6: 校正・編集フェーズ

- **目的**: 公開後に直すコストは事前チェックの10倍
- **所要時間**: 記事1本あたり 1〜2時間
- **工程数**: 19工程
- **成果物**: 校了原稿（入稿可能版）
- **落とし穴**: レビュー往復が多いと公開が遅れる。構成書段階で編集長承認を取っておく

### 6-A. 表記・文章チェック
- 表記ゆれチェック（Just Right! / ChatGPT）
- 誤字脱字チェック
- 一文の長さ確認（80文字以内推奨）
- 難語・専門用語の補足確認
- 敬体/常体の統一

### 6-B. 事実・出典確認
- 数値・統計の出典再確認（ツール: `/fact-check`）
- 固有名詞のスペル・社名確認
- 引用元の最新性確認（古い情報の差し替え）
- 画像の権利確認

### 6-C. SEO要件
- KW出現箇所の確認（タイトル・H1・導入・H2）
- 見出し階層の崩れ確認
- alt属性の記入確認
- 内部リンクのアンカーテキスト適正化

### 6-D. 法務・コンプライアンス
- 薬機法・景表法・金商法チェック（該当業種）
- 著作権・引用ルールの確認
- NG表現リストとの照合

### 6-E. レビュー
- 編集長レビュー
- 修正反映 → 再レビュー
- 監修者の最終承認取得

## フェーズ7: 入稿・公開フェーズ

- **目的**: CMSに入れて、検索エンジンが読める形に整える
- **所要時間**: 記事1本あたり 30分〜1時間
- **工程数**: 19工程
- **成果物**: 公開済み記事URL
- **落とし穴**: 既存記事からの内部リンクを忘れる→クロール促進が遅れる。必ず2〜5本貼る

### 7-A. CMS入稿
- WordPress等への本文ペースト
- 段落・引用・コード・リスト等のブロック整形
- 画像アップロード・alt記入
- 表組み・カスタムブロックの調整

### 7-B. メタ情報
- パーマリンク（slug）設定
- meta title / meta description設定
- OGP画像・OGP説明文設定
- カテゴリー・タグ設定
- アイキャッチ画像設定

### 7-C. 構造化・SEO設定
- 構造化データ埋め込み（Article / FAQ / HowTo / BreadcrumbList）
- canonical設定
- noindex/index設定確認
- パンくずリスト確認

### 7-D. リンク・公開前確認
- 内部リンク貼り込み（新規記事→既存記事）
- 既存記事からの逆向き内部リンク追加
- プレビュー確認（PC）
- プレビュー確認（SP）
- 表示速度確認（PageSpeed Insights）
- 公開ボタン押下

## フェーズ8: 公開後の初動対応フェーズ

- **目的**: 24〜72時間以内の初動で順位が決まる
- **所要時間**: 記事1本あたり 30分 + 24h後の確認10分
- **工程数**: 12工程
- **成果物**: 初動レポート（インデックス状況・初動順位）
- **落とし穴**: 公開して放置→インデックスされず1週間ロス。必ず手動でGSC送信する

### 8-A. インデックス促進
- GSCにURL送信（インデックス登録リクエスト、ツール: GSC）
- sitemap.xml更新の確認
- 内部リンク経由のクロール導線確認

### 8-B. 告知・拡散
- X（Twitter）告知投稿
- LinkedIn / Facebook告知
- メルマガで紹介
- 社内チャットで共有
- 関連note記事への転載検討（ツール: `/repost-note`）

### 8-C. 初動モニタリング
- 24時間後のインデックス確認（site:検索 / GSC URL検査）
- 初動順位の記録（公開3日目）
- 初動の表示回数・CTR確認
- 記事内の不具合（表崩れ等）チェック

## フェーズ9: 効果測定・モニタリングフェーズ

- **目的**: 数字を見ないSEOはギャンブル
- **所要時間**: 週次30分 / 月次2時間
- **工程数**: 18工程
- **成果物**: 月次SEOレポート・Quick Winsリスト
- **落とし穴**: 順位だけ追ってCVを見ない→PVは出るが売上ゼロのメディアになる

### 9-A. GSC（Search Console）
- 表示回数・クリック数・CTR・平均掲載順位の週次取得
- Quick Wins検出（10〜20位の改善余地、ツール: `mcp__gsc__detect_quick_wins`）
- CTRが低いクエリの特定
- 検索クエリの新規発見

### 9-B. GA4（Analytics）
- セッション数・新規ユーザー・滞在時間
- 離脱率・直帰率
- CV数・CVR・CV経路
- ランディングページ別のパフォーマンス

### 9-C. ユーザー行動
- ヒートマップ確認（Microsoft Clarity）
- スクロール率（記事末尾まで読まれているか）
- セッション録画でCTAクリックの観察
- フラストレーションクリック検出

### 9-D. 順位計測
- ターゲットKWの順位推移（Ahrefs Rank Tracker）
- 競合の順位変動監視
- アルゴリズムアップデートの影響確認

### 9-E. レポーティング
- 月次レポート作成（経営層向け1枚サマリー）
- クラスター別 / 記事別の貢献度算出
- ROI試算（流入価値 ÷ 制作コスト）

## フェーズ10: リライト・改善フェーズ

- **目的**: 新規執筆より、リライトのほうがROIが高い
- **所要時間**: 記事1本あたり 1〜3時間
- **工程数**: 18工程
- **成果物**: リライト済み記事・前後比較レポート
- **落とし穴**: リライトしたのに更新日を変えない→検索エンジンに「鮮度更新」が伝わらない

### 10-A. 対象選定
- リライト対象の優先順位付け（10〜20位 / CTR低 / 離脱率高 / 公開6ヶ月以上経過）
- カニバリ記事の統廃合判断
- アーカイブ（noindex）判断（ツール: `/article-monitor`）

### 10-B. 再分析
- 競合の最新構成を再取得
- 検索意図の変化確認
- PAA・サジェストの最新化
- GSCでのクエリ実態確認

### 10-C. 改修作業
- 見出し追加・順序変更
- 古い情報・数値のアップデート
- E-E-A-T強化（著者情報・監修者・引用追加）
- 画像・図解の差し替え
- 内部リンク再設計
- CTA文言・配置の最適化
- タイトル・metaのABテスト

### 10-D. 再公開・再計測
- 更新日変更
- GSC再インデックス申請
- リライト前後の指標比較（30日 / 90日）
- 効果が出なければ再リライト or 統廃合

## フェーズ11: ナレッジ蓄積・型化フェーズ

- **目的**: 再現性のある勝ちパターンを資産化する
- **所要時間**: 月次2時間 / 四半期半日
- **工程数**: 14工程
- **成果物**: 更新されたSEO運用マニュアル・テンプレート・KWマップ
- **落とし穴**: 型化を怠ると、担当者が変わるたびに品質がリセットされる

### 11-A. パターン抽出
- 勝ち記事の共通要素を言語化
- 負け記事の共通要素を言語化
- 勝ちタイトル・勝ちCTAのパターン集約

### 11-B. 資産化
- 構成テンプレートの更新
- スタイルガイド・編集ガイドの改訂
- NG表現リスト・推奨表現リストの更新
- プロンプト・Skillの改善（ツール: `/seo-article` / CLAUDE.md）

### 11-C. 計画への反映
- KWマップの月次アップデート
- 次月の本数計画・優先順位再設定
- 四半期の振り返りMTG実施
- 次期戦略への反映

### 11-D. 組織化
- ライター・編集者のオンボーディング資料更新
- 外注ライターへのフィードバック反映
- 教育コンテンツ化（社内勉強会等）
