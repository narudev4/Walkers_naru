**Re:Story（リストーリー）／ 開発のご提案**

査定を起点に、一度の撮影・入力でEC出品・店頭接客・商品DBまで一気通貫。一点物リユースの属人化と二重入力を解消する業務支援システム

クライアント: 株式会社ナンバー 鈴木 様 ／ 提案: 株式会社Walkers

## 1. 提案概要
- **目的**: リユース店の買取（査定）から店頭接客までを一本のデータで貫く。査定時の撮影・記録が、EC出品文・接客トーク・商品DBへ再入力ゼロで自動連携。属人化と二重・三重入力を解消。
- **ターゲット**: 高単価のヴィンテージ家具・ブランド古着を扱うリユース企業（買取〜販売を自社で行い複数店舗を展開）。現場の買取担当・店頭スタッフ（アルバイト含む）。
- **特徴**: ①査定起点のワンパス統合（再入力ゼロ）②一点物・高級ヴィンテージに特化（既存相場・出品ツールが苦手な領域）③査定は"参考値"で提示・最終判断は担当者（責任/精度リスク回避）
- **ローンチ目標**: 要件定義→MVP 約2〜3ヶ月。実機デモ公開済み（https://restory-mockup.vercel.app）
- **期待効果**: 浅いスタッフでも安定査定・接客。二重入力削減で多チャネルへ早く送り出し販売機会最大化。

## 2. 現状整理
属人化した商品知識・相場観、一点物ゆえの毎回ゼロからの作業、買取〜店頭の情報分断、相場/EC/接客での二重・三重入力。
| 課題 | 詳細 |
|---|---|
| 接客・査定の属人化 | ベテラン依存。新人即戦力化が困難、退職でノウハウ喪失 |
| 買取〜店頭の情報分断 | 仕入時のストーリーが店頭へ渡らず、相場以上の販売ができない |
| 二重・三重入力の負担 | 相場/EC/接客で同じ情報を繰返し入力。出品が追いつかず機会損失 |

## 3. 提案ソリューション — 査定起点のワンパス統合
買取（査定）時にスマホ複数枚撮影＋エピソード記録。この1キャプチャがEC出品文・接客トーク・商品DBへ再入力ゼロで自動連携。相場は複数ソース（ヤフオク/オークファン/メルカリ/各社EC/eBay）から"参考値"集約、金額は断定せず最終判断は担当者。型番のない一点物・高級ヴィンテージに特化（既存の相場ツール/クロスリスターが苦手な領域）。

| 機能 | 概要 |
|---|---|
| 査定補助（相場の参考集約） | 複数ソースの類似品価格を横断集約→相場レンジ・参考買取レンジ提示。断定せず最終判断は担当者 |
| エピソード音声入力 | 背景・来歴を話すだけ→AIが来歴/エピソード/タグへ構造化（手入力負担なし） |
| ハイブリッドRAG引き出し | 過去取引/EC/ストーリー/Webを統合検索。出典明示・社内優先で誤情報抑制 |
| EC出品文の自動生成 | 査定情報からタイトル/説明/タグのたたきを生成。多チャネル展開を効率化 |
| 接客トーク生成＆簡単UI | 店頭スキャンで物語を引き出し接客トーク提示。アルバイトでも使えるUI |

## 4. 利用フロー（査定起点の一気通貫）
査定・撮影 → 相場の参考集約 → エピソード録音 → AI構造化・DB蓄積 → EC出品文自動生成 →（店頭）スキャン → 接客トーク提示

## 5. システム構成
- フロント: Next.js（App Router）＋PWA / バック: マルチモーダルLLM（Vision）API＋複数相場ソース連携（独自モデル学習回避） / DB: ベクトルDB＋テナント別分離 / インフラ: Vercel / 決済: 対象外（将来EC構築時）
- セキュリティ: テナント別データ完全分離、SSL・権限管理、出典明示・社内優先でハルシネーション抑制

## 6. 開発スケジュール（段階的開発）
