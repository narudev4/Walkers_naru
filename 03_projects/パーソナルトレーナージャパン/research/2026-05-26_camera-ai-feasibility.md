動作検知AIで何を自動化できて、何ができないかを切り分ける

## 結論を3行で

1. **シートの質問の大半は「主観感覚（痛み・しびれ・突っ張り）」で、カメラAIでは原理的に判定できない** → ユーザー自己申告が必須
2. **「可動域・左右差」は MediaPipe Pose 等で客観測定でき、ユーザー回答と併用すれば診断精度が上がる**
3. **「ふらつき・バランス」はカメラだけで自動判定可能** → 唯一カメラAIが完全代替できる領域

## 質問のタイプ別分類

枝光シートの質問を、判定主体の観点で3種類に分類した。

### A. 主観感覚（カメラAIで判定不可・**永久にユーザー自己申告必須**）

**理由**: 痛み・しびれ・突っ張り感などの内的感覚は、身体の外からは見えない。
MediaPipe / Sency / Vision LLM / EMG（筋電センサー）でも検出できない領域。

| シート質問 | 含まれるテスト |
|----------|---------------|
| 「太もも裏が突っ張りましたか？」 | 前屈 |
| 「腰の真ん中が痛みましたか？」 | 前屈・後屈 |
| 「腰の左右どちらかの側が痛みましたか？」 | 前屈・側屈 |
| 「お尻〜太もも裏に痛みやしびれが走りましたか？」 | 前屈・回旋 |
| 「前ももが突っ張って反らせませんでしたか？」 | 後屈 |
| 「腰の片側だけ詰まる感じがありましたか？」 | 後屈 |
| 「お尻〜足にしびれが走りましたか？」 | 後屈 |
| 「倒した反対側の腰・脇腹が突っ張りましたか？」 | 側屈 |
| 「倒した側の腰がピリッと痛みましたか？」 | 側屈 |
| 「腰のあたりが詰まって回りませんでしたか？」 | 回旋 |
| 「腰の片側がピリッと痛みましたか？」 | 回旋 |
| 「支えている側の腰の外側が痛む・張りましたか？」 | 片足立ち |

→ シート全質問の **約 60〜70%** がこれに該当。**カメラAI導入の有無に関わらず、ユーザータップ回答のUIは必要**

---

### B. 動きにくさ・可動域・左右差（カメラAIで客観測定可・**ユーザー回答とのハイブリッドが理想**）

**理由**: 関節角度・到達度・左右差は MediaPipe Pose で 33 ランドマークから定量的に計算できる。
ただし「主観的な動きにくさ」と「客観的な可動域不足」は必ずしも一致しないので、ユーザー回答も並行で取った方が情報量が増える。

| シート質問 | カメラAIでの測定方法 |
|----------|------------------|
| 「胸〜背中が固くて反らせませんでしたか？」 | 胸椎の伸展角度を測定。一定閾値未満なら可動域低下と推定 |
| 「左右で倒しやすさが違いましたか？」 | 左右の側屈角度を測定して差分を出す（例: 左30°/右22° = 左右差大） |
| 「左右でひねりやすさが違いましたか？」 | 左右の体幹回旋角度を測定 |
| 「上げた足側の股関節が硬くて足が上がりにくいですか？」 | 股関節屈曲角度を測定 |
| 「足が上がりにくいですか？」全般 | 関節可動域（ROM）を骨格データから計算 |

→ シート全質問の **約 20〜25%** に該当。**ユーザー回答 + カメラ補強**で「気づいてない左右差」も拾える

---

### C. ふらつき・バランス（カメラAIで完全自動化可能）

**理由**: 重心動揺・支持基底面・体軸の傾きはカメラから完全に客観測定できる。
これだけはユーザーの主観に頼らなくてもOK。

| シート質問 | カメラAIでの測定方法 |
|----------|------------------|
| 「ふらついて、すぐ足をついてしまいましたか？」 | 片足立ち中の重心移動の大きさ・足を着いた瞬間の検出 |
| 「左右で明らかに安定度が違いましたか？」 | 左右それぞれで重心動揺の大きさを測定して比較 |

→ シート全質問の **約 5〜10%**。**ここはカメラAIが代替可能、むしろ自動測定の方が客観性が高い**

## だから何が言えるか

### 1. シートのUI実装はユーザー自己申告（はい/いいえ）が**主軸でなければならない**
- 質問の半数以上がA分類（主観感覚）で、カメラAIで代替不能
- なので「シート全部をカメラAIで自動判定」は技術的に不可能、議事録の方針通り

### 2. カメラAIの本当の役割は「補強」と「気づき」
- B分類: ユーザーが「動きにくさ無し」と答えても、カメラで左右差を検出 → 「実は左右差があります」と提示
- C分類: 片足立ちのふらつきは数値化して可視化（「左足支持時の重心動揺は標準より40%大きい」など）
- これにより**客観性 + ユーザー視点 + 専門家の判定ロジック**の三層で診断精度が上がる

### 3. 「枝光さんが見て筋肉判定できる」をAIで再現する筋道
- カメラから「動作 → 関節角度・左右差・ふらつき」を計測する（B+C）
- ユーザーから「痛み・しびれ・突っ張り」を取る（A）
- **両方のデータを枝光さんが作った条件分岐ロジック（シート）に流す**
- 必要なら最終判定の自然言語化だけ LLM（Claude/GPT）に任せる
- これが「枝光さんの目」のシステム化に最も近い

### 4. 枝光さん発言「これを動作検知できるなら」の解釈
- シート全部の代替ではなく、**B/C（客観測定可能領域）の自動化**を意図していると解釈するのが整合的
- 全部を動作検知で代替したいなら、痛み・しびれの主観質問は不要になるはずだから

## 動作検知でカバーできる範囲の数値感

| カバー領域 | 自動判定の比率（シート上） | 実装難度 | 投資対効果 |
|---------|:----:|:---:|:---:|
| A: 主観感覚 | 0%（不可） | — | — |
| B: 可動域・左右差 | 約 25%（補強用） | 中 | 高（ユーザー気づきに繋がる） |
| C: ふらつき | 約 10%（完全代替可） | 低 | 中（質問1つ削れる） |
| 合計 | 約 35%が補強・代替可能 | — | — |

**つまり、動作検知をフル投資しても「ユーザー回答が完全に不要になる」のは1問だけ。残りは補強用途**。
これがフェーズ1で「動作検知を入れる前にまずシートで実装する」べき技術的な根拠。
