**不動産業務のAI活用支援**

**導入・伴走のご提案**

販売図面の作成と営業数値の集計を、検算まで含めて自動化します。

## 1. 提案概要

**本提案の目的**

弊社では、御社の販売図面の作成と営業数値の集計を自動化するご提案をいたします。目的は、作業を速くすることではありません。出来上がった図面と数値に、誤りが残らない状態をつくることです。進め方は初回MTGでお伝えした通りです。1〜2週間で1つの業務を自動化し、実際に動くものをご確認いただきながら積み上げます。

**ターゲット：**

- 販売図面を作成される営業のご担当者
- 媒体別・担当者別の数値をご確認になる経営層の皆様

**特徴：**

- 販売図面の生成と検算をセットでご提供します。
- 営業数値の3つのファイルを1つに統合し、月をまたいだ比較を可能にします。
- 最初のサンプルは無料でご確認いただき、そのうえで月額契約へ移行します。

**ローンチ目標：** 2026年8月5日のMTGでサンプルをご確認いただきます。ご契約後1〜2週間で、最初の自動化を実運用に載せます。

## 2. 現状整理

**受領データの確認結果**

NDA締結後にご提供いただいた販売図面のExcelと、営業数値の3ファイルを弊社にて確認いたしました。以下は、そこで実際に見つかった事実です。販売図面のExcelは2007年に作成されたもので、更新を重ねながら現在もお使いです（最終更新は2026年7月14日）。ブック全体で、数式が入ったセルは0件でした。面積の合計も坪換算も、すべて手で計算して入力されています。収録されている4物件を弊社で検算したところ、4物件すべてで転記または計算の不整合が見つかりました。これはご担当者の注意不足によるものではありません。作成した数値をあとから突き合わせる仕組みがないため、誤りが残っても気づけない構造になっています。

| 課題 | 詳細・現状 |
| --- | --- |
| 販売図面の数値に検算の仕組みがない | ブック全体で数式セルが0件のため、面積の合計と坪換算はすべて手入力です。塚越の土地は37.04坪と記載されていますが、122.64㎡から計算すると37.10坪です。中山の建物床面積の合計は80㎡と記載されていますが、1階48.84㎡と2階31.46㎡の合計は80.30㎡です。 |
| 前の物件の記載や更新前の表記が次の図面に残る | 女影の交通欄はJR八高線「東飯能」駅と記載されていますが、同じ図面の最寄駅欄は「武蔵高萩」です。日高市高萩の接道状況は「42粂2項」となっています（正しくは42条2項）。宅建業免許番号は、4シートのうち2シートが更新前の（1）のままです。 |
| 営業の数値が3つのファイルに分かれ、月をまたいだ比較ができない | 購入反響数・査定対応数・業者訪問一覧が別々のExcelで、さらに月ごとに別シートで管理されています。期中にご担当者が交代され、1〜4月と5〜7月では列に並ぶ顔ぶれが変わっています。成約数の表記も全角括弧・半角括弧・記入なしが混在し、そのままでは集計できません。 |
| 業者訪問の優先度がセルの塗り色で管理されている | 一覧表には「黄色は月に1度は必ず訪問する」と注記があり、対象はセルの塗り色で指定されています。10市町村103社のうち重点先は62社です。このうち訪問日の記録がある50社は、すべて30日以上更新されていません。経過日数の中央値は76日です（2026年7月29日時点）。残る12社は訪問日の記録自体がありません。 |

## 3. 提案ソリューション

**支援コンセプト**

**支援内容：販売図面の自動生成・自動検算と、営業数値の統合**

初回MTGで新島様より、ChatGPT等で見栄えの良い図面は作れるものの、ミスやエラーが解消できないとお伺いしました。弊社が受領データを確認したところ、原因は生成の精度ではないと判断しました。元のExcelの運用に検算の仕組みがないことが原因です。したがって、生成だけを自動化しても誤りは残ります。弊社では、図面を組み立てる機能と、組み上がった図面を機械的に検算する機能を必ずセットでご提供します。営業数値についても同様です。集計するだけでなく、ご担当者の交代や表記の揺れを吸収したうえで、比較できる形に整えます。

**主要機能一覧**

| 機能カテゴリ | 概要 |
| --- | --- |
| 販売図面の自動生成 | 住所・面積・構造・接道などの物件情報を入力すると、現在お使いのレイアウトの販売図面をPDFで出力します。謄本や物件調査メモからの読み取りにも対応します。 |
| 販売図面の自動検算 | 出力の前に、面積の合計・坪換算・建ぺい率・容積率を計算し直して照合します。最寄駅と交通欄の不一致、宅建業免許番号の版ずれ、法令用語の誤字も検出し、該当箇所を一覧で表示します。 |
| 営業数値の統合 | 購入反響数・査定対応数・業者訪問一覧の3ファイルを、1つのデータに統合します。月ごとに分かれたシートと、期中に変わったご担当者の列を突き合わせ、月をまたいで比較できる形に揃えます。 |
| 媒体別・担当者別の集計 | 統合したデータから、媒体別の反響数、ご担当者別の成約率、査定から専任媒介までの推移を自動で集計します。数値の入力は現在の運用のまま、集計だけを自動化します。 |
| 業者訪問のフォロー管理 | 重点先の最終訪問日からの経過日数を自動で計算し、訪問の間隔が空いている先を一覧で表示します。セルの塗り色による管理を、日付にもとづく管理に置き換えます。 |

## 4. 導入の進め方

**1. サンプルのご確認（無料）：** 弊社にて、販売図面の生成と検算、営業数値の統合のサンプルを作成します。8月5日のMTGでご提示します。ここまでに費用はいただきません。

**2. ご契約：** サンプルの内容にご満足いただけた場合に、月額の伴走契約へ移行します。契約期間の縛りは設けません。

**3. 業務のヒアリングと優先順位づけ：** 自動化する業務を弊社と御社で洗い出し、着手する順番を決めます。御社にお願いするのは業務フローのご説明のみで、エンジニアの方をご用意いただく必要はありません。

**4. 1〜2週間で1つずつ自動化する：** 1つの業務につき1〜2週間で動くものを作り、実際の業務でお使いいただきます。使ってみて出たご要望は、次の1〜2週間で反映します。

**5. 対象業務を広げる：** 販売図面と営業数値が実運用に乗ったあと、次のテーマへ順次広げます。初回MTGでは、ポータルサイトへの投稿、プロジェクト表の作成、メール・SMSの下書きなどが挙がっています。

## 5. システム構成

**開発形態**

**プラットフォーム：** ブラウザベースのWebアプリケーション

**対応デバイス：** PC・スマートフォン・タブレット（レスポンシブデザイン）

**モバイルアプリ：** 初期フェーズでは不要（Webで完結）

**推奨技術スタック**

**フロントエンド：** React（Next.js）を想定しています。ソフトのインストールが不要で、ブラウザだけでお使いいただけるためです。

**バックエンド：** Pythonを想定しています。Excelの読み書き、PDFの生成、検算の処理を扱うライブラリが揃っているためです。

**データの保管：** 扱う件数と参照の仕方が決まった段階で選定します。最初の2つの自動化では、既存のExcelをそのまま入力として扱う想定です。

**インフラ：** クラウド（Vercel・Google Cloud）の利用を想定しています。専用サーバーの購入や設置が不要で、利用量に応じた費用で運用できるためです。

上記は現時点の想定です。最初のタスクの要件が固まった段階で確定し、あらためてご報告します。

**セキュリティ対策**

- 通信はすべてHTTPSで暗号化します。物件情報・顧客情報を平文でやり取りしません。
- 利用はIDとパスワードによる認証制とし、御社の関係者以外はアクセスできない状態にします。
- 生成AIには、送信したデータを学習に使わない設定のAPIを利用します。個人情報は送信の対象から除外します。

## 6. 開発スケジュール

1〜2週間で1つの業務を自動化し、動くものをご確認いただきながら進めます。以下は最初の3ヶ月間の想定です。この期間で6〜10件の自動化を目安としています。

| フェーズ | 期間 | 主な作業内容 |
| --- | --- | --- |
| Phase 1 | 2026年7月29日〜8月5日（契約前・無料） | 販売図面の生成と検算、営業数値の統合のサンプルを作成し、8月5日のMTGでご提示します。 |
| Phase 2 | ご契約後1〜2週間 | 販売図面の自動生成と自動検算を実運用に載せます。現在お使いのレイアウトを再現し、過去の物件で検算結果を突き合わせます。 |
| Phase 3 | ご契約後3〜6週間 | 営業数値の3ファイルを統合し、媒体別・担当者別の集計と、業者訪問のフォロー一覧を作成します。 |
| Phase 4 | ご契約後7週間〜3ヶ月 | ポータルサイトへの投稿、プロジェクト表の作成、メール・SMSの下書きなど、次のテーマへ順次着手します。 |
