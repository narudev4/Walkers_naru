** 1. 提案概要**

**本提案の目的**

本提案の目的は、Phase1（MVP）の構築です。飲食店とナノインフルエンサー層をつなぐプラットフォームを、稼働上限40時間の範囲内で作ります。決済連携は持たず、軽量な仕組みに絞り込みます。まず秋冬に無料で検証し、10月の展示会でお披露目します。

**ターゲット：** 飲食店（既存取引先含む）、ナノインフルエンサー層

**特徴：** 閲覧課金型のリリース配信（100円/200円プラン）が中心です。マッチング機能は本番導入時に実装予定です。決済連携のない軽量なMVPとして、まず秋冬に無料で検証します。

**ローンチ目標：** 2026年10月の展示会でお披露目します。秋冬に無料で約100店舗へ試験導入予定です。

** 2. 現状整理**

**業界・市場の現状**

御社は、従来型のプレスリリースでは反応が薄く、飲食店様の情報が十分に届いていないという課題を抱えています。また、大規模なインフルエンサー基盤をお持ちの一方、フォロワー数千〜1万台の層は金額換算がしづらく、活用できていません。この層を閲覧課金型の仕組みで活用することが、本提案の狙いです。

| 課題 | 詳細・現状 |
| --- | --- |
| リリースが届かない | 御社が支援する飲食店様の情報が、従来型のプレスリリースでは十分に届いていません |
| PRの機会が少ない | 飲食店様がPRする機会自体が少なく、御社の送客支援がしにくい状況です |
| 未活用の層がある | 御社が抱える大規模なインフルエンサー基盤の中でも、フォロワー数千〜1万台の層は金額換算がしづらく、御社としても活用できていません |

** 3. 提案ソリューション**

**支援コンセプト**

**支援内容：MVP開発（要件定義〜実装、準委任）**

「閲覧するだけで報酬が発生する」シンプルな仕組みです。飲食店のリリースをナノインフルエンサー層に届けます。決済連携は持たず、閲覧ログの記録だけで報酬を計算します。

**主要機能一覧**

| 機能カテゴリ | 概要 |
| --- | --- |
| 飲食店会員登録・店舗管理 | 会員登録、店舗登録（最大100店舗）、広告予算の課金設定 |
| リリース作成 | テキスト・画像・動画によるリリース作成、配信予約 |
| 広告予算管理 | 残高表示、閲覧ごとの自動減額（決済連携なし） |
| インフルエンサー会員登録・リリース閲覧 | 登録審査、リリース一覧のエリア/業態絞込、閲覧報酬の獲得 |
| 運営管理画面 | 会員管理、リリース承認、報酬管理、不正監視 |

** 4. 利用フロー**

**1. リリース作成：** 飲食店が広告予算を設定し、リリースを作成します

**2. リリース閲覧：** インフルエンサーがリリース一覧から気になる情報を閲覧します

**3. 報酬獲得：** 閲覧条件を満たすと、ポップアップで報酬を獲得します

**4. 興味あり表示：** インフルエンサーが「興味あり」を表示します（Phase1はUI表示のみ）

**5. PR依頼：** 飲食店が閲覧ログから、相性の良いインフルエンサーへ直接PRを依頼します

** 5. システム構成**

**開発形態**

**プラットフォーム：** ブラウザベースのWebアプリケーション

**対応デバイス：** PC・スマートフォン・タブレット（レスポンシブデザイン）

**モバイルアプリ：** 初期フェーズでは不要（Webで完結）

**推奨技術スタック**

**フロントエンド： React（AI駆動開発との相性がよく、開発速度を優先するため）**

**バックエンド： Node.js（フロントエンドと言語を統一し、開発速度を優先するため）**

**データベース： PostgreSQL（ログベースの集計処理に適しているため）**

**インフラ： Vercel（デプロイが速く、展示会までのスケジュールに合うため）**

**セキュリティ対策**

SSL通信による暗号化

パスワードのハッシュ化

メール認証による本人確認（SMS認証は要件定義時に追加要否を確認します）
