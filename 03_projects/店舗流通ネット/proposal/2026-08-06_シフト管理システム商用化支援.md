## 1. 提案概要

**本提案の目的**

本提案の目的は、荻田様がBoltで構築されたシフト管理システムを、自社サーバーで商用運用できる状態にするまでのご支援です。機能の追加ではなく、公開と運用に必要な作業に絞っています。契約形態は準委任契約（稼働時間に応じたご契約）を想定しています。

- **対象範囲**: 現在稼働しているシフト管理システム一式です。管理本部・店長・アルバイトの3アカウントと、その全画面を対象とします。
- **ご支援の形**: 弊社が公開まで代行する形と、御社内で公開・運用できるようにする研修を加える形の2案をご用意しました。後者は、今後同じ仕組みを社内で育てていく前提のご支援です。
- **将来の統合について**: 仲西様からご要望いただいた「管理本部から見て、シフト・人事評価・キャリアマップが全部接続されている状態」は、本提案で仕上げるシフト管理システムをそのまま土台にできます。同じアカウントでログインし、権限で画面を出し分ける形です。
- **完成目標**: 2026年9月末。10月からの下期スタートに間に合う形で組んでいます。
- **本提案に含まないもの**: 人事評価制度とキャリアマップのシステム化は、本提案の対象外です。人事評価制度については、現在お使いの資料一式をご提供いただければ、弊社でモックアップを作成してあらためてご提案します（費用はいただきません）。キャリアマップは、制度の形が固まった段階でご相談ください。

## 2. 現状整理

**現行システムの調査結果**

ご共有いただいたURLから、実際にシステムを操作して確認しました。管理本部・店長・アルバイトの3アカウントすべてでログインし、全画面の動作と通信内容を調べています。所定休日の超過判定や有給の扱いといった労務まわりまで丁寧に作り込まれており、そのまま活かせる状態でした。また、複数の企業様でのご利用を想定した会社識別の仕組みが、データベースの設計に既に組み込まれていました。コンサルティング先の企業様へ展開するご構想の土台になる状態です。一方で、対応や確認をお勧めする点も見つかりましたので、主なものを3点記載します。

| 課題 | 詳細・現状 |
|---|---|
| カレンダーの曜日のずれ | 管理本部の「全店シフト編集」と、アルバイトの「希望シフト提出」で、日付と曜日がずれています。店長画面のみ正常でした。 |
| AI一括自動承認の動作 | 実行したところ、5段階ある承認パターンのうち、最も避けたい「第五承認パターン（最終手段）」の結果になりました。人員が足りない分を他の店舗へ応援依頼する「ヘルプ要請」が810件発生し、それでも必要な人員の13%しか確保できない状態です。デモ用データにシフト希望がほとんど入っていないことが主な原因ですが、応援依頼の件数を抑える仕組みが現在はないため、実データでも大量の応援依頼が出るおそれがあります。公開前の調整が必要です。 |
| 企業ごとのデータ分離（複数社への展開時） | 荻田様のご構想どおりコンサルティング先の企業様へ展開する際は、企業間で互いのデータが見えない仕組みが必要です。現在は画面側の指定でデータを絞り込んでおり、データベース側のアクセス制限は御社の管理画面でしか確認できないため未確認です。御社単独でお使いの間は影響しませんが、展開の前に設定の確認と検証をお勧めします。 |

## 3. 提案ソリューション

**支援内容：準委任契約による伴走支援**

弊社では、稼働時間に応じてご契約いただく準委任契約でのご支援を想定しています。準委任契約とは、完成した成果物ではなく、作業した時間に対してお支払いいただく形です。現在のシステムはすでに動いており、残るのが仕上げの作業であるため、必要な分だけ稼働するこの形が適していると判断しました。請負契約をご希望の場合は、作業範囲を確定したうえで別途お見積りいたします。

**作業項目と内容**

| 作業項目 | 概要 |
|---|---|
| コードの書き出しと仕様のドキュメント化 | Boltから現在のコードを書き出し、画面と機能を文書に起こしてシステムの全体像を見える形にします。 |
| 要件の確定とドキュメントでの合意 | 足りない画面・機能や未定義の細かな挙動を洗い出し、あるべき動きを御社と決めて、実装の前に文書でご確認いただきます。 |
| 実装（不具合の修正を含む） | 合意した仕様どおりにコードを完成させます。調査で判明した不具合（カレンダーの曜日、AI自動承認の動作、画面ごとに数値が食い違っている箇所など）の修正と、データベース側のアクセス制限の確認もここで行います。 |
| 自社サーバーへの移行と公開前の動作確認 | 完成したコードを御社が管理されるサーバーへ移します（移行先は情報システム部門のご確認を経て確定します）。想定される操作を一覧に起こし、各画面が意図どおりに動くかを確認してから公開します。 |
| 規約類の整備のご支援と運用の引き継ぎ | プライバシーポリシーと利用規約の作成をご支援し、日常の運用手順をお渡しします。従業員の方の氏名・時給・勤怠を扱うため、公開前に必要になります。 |
| 企業ごとのデータ分離（複数社への展開時） | コンサルティング先の企業様へ展開する際に、データベース側で企業ごとのアクセス制限を設定し、別の企業のデータが取得できないことを実際に試して検証します。御社単独でのご利用の間は必須ではありません。 |

## 4. 公開までのステップ

1. **コードの書き出し**: Boltから現在のシステムのコードを書き出し、内容とデータ構成を弊社で確認します。
2. **仕様のドキュメント化**: 現在の画面と機能を文書に起こし、システムの全体像を見える形にします。
3. **要件の確定**: 足りない画面・機能や未定義の細かな挙動を洗い出し、あるべき動きを御社と決めます。
4. **ドキュメントでの合意**: 実装に入る前に、確定した仕様を文書で御社にご確認いただきます。
5. **実装**: 合意した仕様どおりにコードを完成させます。調査で判明した不具合の修正と、データベース側のアクセス制限の確認もここで行います（企業ごとのデータ分離の設定と検証は、複数の企業様への展開前に行います）。
6. **移行と公開**: 決定した構成へ移行し、公開します。移行先（サーバーの構成とデータベースの扱い）は情報システム部門のご確認が必要なため、ステップ1〜4と並行して早めの確定をお願いします。
7. **運用の引き継ぎと規約類の整備**: プライバシーポリシーと利用規約を整え、日常の運用手順をお渡しして御社で運用できる状態にします。研修を含むご支援をお選びいただいた場合は、この段階を厚くします。

## 5. システム構成

- プラットフォーム: ブラウザベースのWebアプリケーション
- 対応デバイス: PC・スマートフォン・タブレット（レスポンシブデザイン）

**推奨技術スタック**

- **フロントエンド**: Boltが生成したコードを引き継いで使用します。作り直しはしませんが、同じ機能が画面ごとに重複している箇所（カレンダー等）は、不具合の修正とあわせて整理します。書き出したコードの状態は、Phase 1の引き継ぎ時に確認します。
- **バックエンド**: 現在ご利用のSupabaseを継続する案と、御社サーバーへ移す案の2通りがあります。情報システム部門のご確認を経て決定します。
- **データベース**: 現在は、Boltが標準で連携するSupabaseというサービスにデータが保存されています。継続するか御社サーバーへ移すかは、上記バックエンドと同時に決定します。月額費用は、データ容量・通信量に応じた従量課金です。
- **インフラ**: 御社が管理されるサーバーへ配置します。Boltのサーバーをそのまま本番に使うことは、規模の大きい企業では一般的ではありません。

**セキュリティ対策**

- データベース側のアクセス制限の設定状況を確認します。企業ごとのデータ分離の設定と検証は、複数の企業様への展開前に行います。
- 通信の暗号化と、ログイン情報の保護状況を確認します。
- 従業員の方の個人情報の取り扱いについて、御社の社内規程との整合を確認します。

### 金額を【要入力】にした理由

MTGで古谷が口頭提示した数字は「時間単価 1.3〜1.8万円」「30〜40時間」「40〜80万円」。
一方、実機調査に基づく積み上げは **34〜56時間**で、提示済みの工数を上回る。

- 単価 1.3万円 × 34時間 = 442,000円
- 単価 1.8万円 × 56時間 = 1,008,000円

下限は提示レンジ内に収まるが、上限は 80万円を超える。どう提示するかは naru の判断が必要なため、金額欄は【要入力】のままにしている。

### スケジュール・見積もりの表について

初回はテンプレートの表を箇条書きに置き換えていたが、naru の FB により表へ戻した（2026-08-04）。

テンプレートの表は各行のプレースホルダーが同一文字列（[期間]・[金額]等）で、一括置換すると全行が同じ値になる（NG-3）。解決策として、旧表を削除して `insert_table` で空表を作り直し、**空表のセル位置を計算して後ろのセルから `insert_text` で埋める**手順を確立した。

空表（rows×cols）のセル位置の計算式は次のとおり（実測で検証済み）。

```
セルの挿入位置 = table.start_index + 3 + row*(2*cols + 1) + col*2
```

後ろのセルから挿入すれば前方の index はずれない。次回以降、テンプレートの表を埋めるときはこの手順を使う。

### NDA の位置づけ（2026-08-04 naru 質問への回答）

NDA は**人事評価制度の資料一式を共有いただくため**に出てきた話であり、シフト管理システムの見積もりには不要。

- 発端は古谷の発言（42:52）「営業の範疇でモックアップをうちで作っている。費用をいただかずに作って『こんな感じのシステムを作ったらいいですか』というコミュニケーションをしているので、**もし必要だったら NDA を締結した後で大丈夫なので、使っている資料一式をいただけたら**、それをもとにこちら側から作って提案させていただくことも可能です」
- 仲西様（47:40）「うちの雛形を投げさせていただいて、**でもろもろお見積もりいただいていきましょう**」→ NDA と見積もりは並行
- 荻田様（43:20）「その NDA をいただきながら、**先のシフトのやつはもう早く作ってあげたい**」

当初「NDA締結後に着手し」と書いていたが、着手条件を実態より厳しくしていたため「ご発注後すみやかに着手し」へ修正した。
