# 【馬場一彰様】無人よもぎ蒸しサロン 運営システム開発のご提案

株式会社Walkers ／ 2026年6月4日

---

## 1. 提案概要

無人よもぎ蒸しサロンの運営に必要な「予約・決済・スマートロック・通知・サブスク管理」を、**コードによる独自開発**で一本につなぎ、無人でも安定して回る運営システムを構築します。

- 当初ご想定のノーコード（Make）連携ではなく、独自開発により**拡張性が高く、ランニングコストを抑えた**構成にします
- 複雑な予約制御（駐車場2枠の事前予約、会員ランク別の予約件数・解禁時期）にも対応します
- 2026年8〜9月のオープンに向け、まずは**ミニマムかつ壊れにくい**構成で構築します
- 画面イメージは**モックアップ**でご確認いただけます：〔本番URL：デプロイ後に記載〕

## 2. 現状整理

| 項目 | 現状・課題 |
|---|---|
| 無人運営 | 予約 → 決済 → 鍵発行 → 通知 → サブスク管理を、人手を介さず一連で処理する必要がある |
| 複雑な予約制御 | 4部屋に対し駐車場2台の事前予約、会員ランク別（通常／プレミアム）の予約件数・解禁時期の制御は、既存の予約ツールやノーコード連携では実現が難しい |
| 処理の確実性 | サブスク更新失敗時に「会員ランク変更 → 予約取消 → 鍵削除 → 通知」を確実に連鎖実行する必要がある（無人運営の肝） |

## 3. 提案ソリューション

| 機能 | 内容 |
|---|---|
| 予約管理 | 会員ランク別の予約件数制限・解禁時期、駐車場2枠の事前予約 |
| 決済（Stripe） | 予約・決済のWebhook連携、サブスクリプション課金の管理 |
| 部屋自動割当 | 開始時刻に応じた自動割当（00分開始 → 1・2号室／30分開始 → 3・4号室） |
| スマートロック | RemoteLock API で PIN を自動発行、利用時間のみ有効化、終了・取消時は自動失効／削除 |
| LINE通知 | 予約確定・鍵案内・サブスク通知を自動送信（送信数を考慮し最適設計） |
| サブスク自動処理 | 更新失敗時の連鎖処理（タグ削除 → 予約取消 → 鍵削除 → 通知）を1トランザクションで確実に実行 |

これらの画面・体験は、提出済みのモックアップで実際に操作してご確認いただけます。

## 4. 利用フロー（お客様）

1. スマホで予約（メニュー・日時・駐車場を選択）
2. Stripe でお支払い
3. お部屋が自動割当され、入室PINが自動発行
4. LINE で予約詳細・部屋番号・PINが届く
5. ご利用時間にPINで入室（終了後、PINは自動で失効）

## 5. システム構成

- **開発形態**：コードによる独自開発（ノーコード／Make は不採用）
- **外部連携**：Stripe（決済・サブスク）／ RemoteLock（スマートロック）／ LINE Messaging API（通知）
- **ランニングコスト**：サーバー・データベースを中心に構成。ノーコードの「サービスごとの月額積み上げ」を回避し、トータルコストを抑制（外部APIの従量分は別途）
- **セキュリティ**：PINは利用時間のみ有効化・自動失効。カード情報は Stripe 側で暗号化処理
