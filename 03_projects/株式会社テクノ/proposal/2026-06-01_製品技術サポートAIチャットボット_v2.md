## 1. 提案概要

貴社の製品技術サポートを、製品マニュアルを学習したAIが支援するご提案です。ご相談の中で、対象とする顧客フェーズによって**用途の異なる2つのプロダクト**に分かれることが明確になりました。

- **Bot（検討・問い合わせ段階の顧客対応）**: 製品の採用を検討中・問い合わせ段階の顧客に、マニュアルを参照した一次回答を提供
- **Agent（導入後の技術サポート）**: 製品導入後（CV後）の顧客に、図やコード生成まで踏み込んだ技術サポートを提供
- **目的**: いずれもベテラン技術者の対応工数を削減し、本来の設計開発業務に集中できる状態をつくる
- **進め方**: 先行して要件定義・技術検証（準委任契約）で回答精度とAPIコストを実測 → 確定スコープで本見積り
- **資金面**: 規模の大きいAgentは、デジタル化・AI導入補助金の活用余地あり

→ Bot・Agentは**目的が異なる別プロダクト**のため、「Botを作る場合」「Agentを作る場合」「両方を作る場合」で個別にお見積りします。

## 2. 現状の課題

| 課題 | 詳細 |
|---|---|
| マニュアル探索の負荷 | SLM／PLMC／RTMC／RTPL／SPX の5シリーズ・10機種超、各機種にハードウェア編・導入編・仕様書など複数のPDFが存在。会員（装置メーカー様）が必要な情報へ辿り着くのが難しい |
| 技術者工数の逼迫 | 「意図した位置・速度でモーターを動かす方法」「APIの使い方」など深い技術問い合わせや電話対応に、ベテラン技術者の時間が奪われ、本業の設計開発を圧迫している |
| 内製運用の難しさ | 技術者はベテラン中心かつ多忙で、ツールの内製運用・継続メンテナンスに手が回らない（受託型での構築・運用が現実的） |
| 回答の正確性リスク | 配線など誤った回答は顧客の機器破損（ショート等）に直結しかねない。AIの回答を100%正解として扱わせない設計が必須 |

## 3. 提案ソリューション

**コンセプト: マニュアルを「探す」から「聞く」へ — 技術者の対応をAIが支援**

用途は顧客フェーズで2つに棲み分かれます。**段階的な拡張ではなく、目的に応じて選ぶ2プロダクト**です。

### Bot：検討・問い合わせ段階の顧客対応（CV前）
- 製品マニュアルを参照し、仕様確認・基本的な使い方に出典付きで一次回答
- 比較的軽量なモデルでコストを抑制
- 「採用するか」を検討中の顧客の自己解決を支援し、問い合わせ工数を削減

### Agent：導入後の顧客の技術サポート（CV後）
- 図・配線図の生成、APIサンプルコード生成、競合比較、現場写真からの判断など、踏み込んだ技術サポート
- 高性能モデル＋マルチモーダルを使用
- 既存の「有償サポート契約」と連動させ、提供レベルを分離

### 2プロダクトの関係（重要）
- **Agentの開発はBotの構築工数を内包**します（Agentの方が上位機能）。
- ただし**用途・公開先が異なるため、テスト・公開作業はBot／Agentで独立**して必要です。
- → **両方を別プロダクトとして公開する場合**は、Agent費用に加えてBot分の独立したテスト・公開工数を加算します。

### 回答の責任設計（共通の必須要件）
- 回答は**「あくまで参考情報」**と明示し、最終確認は技術者へ誘導（配線ミス等の物理リスク回避）
- 購入者／未購入者で提供レベルを分離
- Bot と Agent は**別システムとして構築**（プロンプトインジェクション対策）

## 4. 利用イメージ

**Bot（CV前）**
1. 検討中の顧客がHP上のAIに質問 → マニュアルを検索し出典付きで一次回答 → 必要なら問い合わせ・技術者へ

**Agent（CV後）**
2. 導入済み顧客が現場の課題（写真・競合比較・組み込み等）を相談 → 図・配線図・サンプルコードを生成 → 「参考情報」と明示し技術者へ誘導 → 有償サポートと連動

---

## 5. システム構成

- **RAG基盤**＋**従量課金API（LLM）**。Agentは図・写真等の**マルチモーダル処理**を含む
- 最適な基盤・モデルの組み合わせは**技術検証フェーズで実測のうえ確定**（特定の製品・ツールに依存しない設計）
- **Bot と Agent は別システムとして構築**（責任分界・プロンプトインジェクション対策）
- セキュリティ：会員領域マニュアルの取り扱い、未購入者への提供範囲の制御を設計に含める

| 作るもの | 構築期間（目安） | テスト・公開 |

補助金を活用する場合は「要件定義（自費）→ 申請 → 交付決定後に構築」の順。

## 7. 補助金活用

- **デジタル化・AI導入補助金**（旧IT導入補助金）の活用余地があります。特に規模の大きい**Agentの場合に有効**です。毎月募集
- **補助率は 1/2〜2/3**（申請区分・賃上げ要件等により変動）
- **留意点**：本補助金は事務局に登録された既製ITツールの導入費＋導入関連役務が中心の制度です。フルオーダー開発がどの費目で対象になるかは、費目設計を補助金担当と精査のうえご提案します（「構築費がそのまま補助対象」と断定はいたしません）
- **着手の順序**：交付決定前の発注・支払いは対象外のため、要件定義（自費先行）→ 申請 → 交付決定後に構築、という順序になります
- **当社の補助金サポート**：着手金 5万円 ＋ 成果報酬（採択額の 8〜15%）

## 8. 概算見積もり

> すべて**たたき台レンジ**です（古谷／naru 確定前提）。要件定義完了後に、確定スコープに基づく正式な本見積りをご提示します。capabilityは取捨選択できます。

**共通（いずれも先行）**：要件定義・技術検証（準委任） **30〜60万円**

### A. Botを作る場合（検討・問い合わせ段階の顧客対応）

| 項目 | 概算（たたき台） |
|---|---|
| Bot構築（マニュアルRAG＋HP設置＋回答調整。テスト・公開込み） | 100〜200万円 |
| **小計（要件定義込み）** | **約130〜260万円** |

### B. Agentを作る場合（導入後の技術サポート）

Agentは上記Bot相当の構築を内包し、さらに以下の機能を実装します。capabilityごとに増減します。

| 項目 | 概算（たたき台） |
|---|---|
| エージェント基盤＋Bot相当機能（RAG・別システム化・責任設計） | 200〜350万円 |
| ① 配線図・図解の生成出力 | 120〜200万円 |
| ② APIサンプルコード生成（C#連携等） | 100〜180万円 |
| ③ 競合製品の機能読み替え・比較 | 60〜120万円 |
| ④ 現場写真からの状況判断（マルチモーダル） | 120〜200万円 |
| ⑤ マニュアル横断の応用回答 | 60〜100万円 |
| **小計（要件定義込み・全capability実装時）** | **約690〜1,210万円** |

※全capabilityを入れると補助金活用前提の規模。capabilityを絞れば費用は抑制できます。

### C. Bot と Agent 両方を別プロダクトとして公開する場合

B（Agent費用）に、**Bot独立分のテスト・公開工数 ＋30〜60万円** を加算します。

ランニングコスト（API従量＋保守）は別途、技術検証で実測します。
