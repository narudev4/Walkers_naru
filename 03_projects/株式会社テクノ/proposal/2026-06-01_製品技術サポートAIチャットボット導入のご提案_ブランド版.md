## 1. 提案概要

**本提案の目的**: 貴社の製品技術サポートにおいて、ベテラン技術者が問い合わせ・電話対応に多くの時間を割かれている現状を、製品マニュアルを学習したAIが一次対応を担うことで改善します。いきなり大規模に作らず、検討フェーズの顧客向け「Bot」から小さく始め、効果を確認しながら導入済み顧客向け「エージェント」へ段階的に拡張します。

- **ターゲット**: 貴社製品（SLM／PLMC／RTMC／RTPL／SPX 等）を検討・導入されている装置メーカー様、および製品技術サポートを担うベテラン技術者の皆様
- **特徴**: ①段階導入（検討顧客向けBot → 導入済み顧客向けエージェント）で小さく始める ②回答は「あくまで参考情報」と明示し、誤回答リスクを設計で抑制 ③購入者／未購入者で提供レベルを分離
- **ローンチ目標**: まず Phase 1（Bot）の早期公開を目標とし、具体的な時期は要件定義・技術検証フェーズの完了後に確定
- **期待効果**: ベテラン技術者がマニュアル探索・一次問い合わせ対応から解放され、本来の設計開発業務に集中できる状態を目指す

## 2. 現状整理

貴社では5シリーズ・10機種を超える製品群について、ハードウェア編・導入編・仕様書など多数のマニュアルPDFが存在し、製品技術サポートの現場で以下の課題が生じています。

| 課題 | 詳細・現状 |
|---|---|
| マニュアル探索の負荷 | SLM／PLMC／RTMC／RTPL／SPX の5シリーズ・10機種超、各機種に複数PDF。会員が必要な情報へ辿り着くのが難しい |
| 技術者工数の逼迫 | 深い技術問い合わせ・電話対応にベテラン技術者の時間が奪われ、本業の設計開発を圧迫 |
| 内製運用の難しさ | 技術者は多忙で内製運用・継続メンテに手が回らない（受託型での構築・運用が現実的） |
| 回答の正確性リスク | 配線など誤った回答は顧客の機器破損（ショート等）に直結しかねない。AI回答を100%正解として扱わせない設計が必須 |

## 3. 提案ソリューション

**コンセプト**: マニュアルを「探す」から「聞く」へ。用途が「検討フェーズ顧客向け」「導入済み顧客向け」の2層に分かれるため、対立2案ではなく段階的に上る階段として構成。

| 機能 | 概要 |
|---|---|
| Phase 1：Bot（検討フェーズ顧客向け） | マニュアル参照で仕様確認・基本的な使い方に回答。軽量モデルでコスト抑制 |
| Phase 2：エージェント（導入済み顧客向け） | 図・配線図生成、APIサンプルコード（C#等）生成、競合比較。高性能モデル |
| 回答の責任設計 | AIをキャラクター化し「参考情報」と明示。最終確認は技術者へ誘導 |
| 提供レベルの分離 | 購入者／未購入者で提供レベル分離（有償サポート契約の線引きと同じ） |
| Bot とエージェントの分離構築 | 別システムで構築（プロンプト制御方式はインジェクションで未購入者が高度機能を引き出すリスク） |

## 4. 利用イメージ
1. 質問入力：顧客が貴社HP上のAIサポートに質問入力
2. マニュアル検索・一次回答：出典を示しながら一次回答
3. 図・コード生成（Phase 2）：図・配線図やサンプルコード生成
4. 技術者への誘導：「参考情報」と明示、確実性が必要なら技術者へ
5. 有償サポート連動：購入済み顧客は応用的支援まで

## 5. システム構成
- フロントエンド：貴社HPに組み込むWebチャットUI
- バックエンド：RAG基盤（マニュアルPDFを検索可能化）＋従量課金API（LLM）
- データベース：マニュアルを検索可能にするベクトル基盤（構成は技術検証で確定）
- インフラ：特定製品・ツールに依存しない構成。最適な基盤・モデルは技術検証で実測のうえ確定
- セキュリティ：会員領域マニュアルの認可制御／未購入者への提供範囲制御／誤回答リスク対策

## 6. 開発スケジュール
| フェーズ | 期間 | 主な作業内容 |

| 要件定義・技術検証（準委任） | 約2〜4週間 | 回答精度検証、APIコスト実測、要件確定 |

## 7. 補助金活用戦略
- 活用予定：デジタル化・AI導入補助金（旧IT導入補助金）
- 補助上限：公募回・申請区分により変動（補助率 1/2〜2/3）
- 活用イメージ：要件定義（自費先行）→ 申請 → 交付決定後に構築。交付決定前の発注・支払いは対象外
- 費目設計の精査：既製ITツール導入費＋導入関連役務が中心。費目は補助金担当と精査（「構築費＝当然対象」と断定しない）
- 当社サポート：着手金5万円＋成果報酬（採択額の8〜15%）
- 募集回の調整：6/15締切の二次募集には間に合わず、後続回を想定
