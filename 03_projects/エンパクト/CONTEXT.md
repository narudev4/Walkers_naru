## 1. プロジェクト概要

エンパクトインターナショナル様向けに、**保険営業のロープレ研修システム**＋**営業部長 AI コーチング**を提供する。
完全オンプレ動作（ASUS GX10 サーバー上、インターネット非接続）が絶対条件。

- 仮称: 「営業 AI エージェント / 営業ロープレ AI」
- 想定エンドユーザー: エンパクト様の保険営業社員（中国人比率高）
- 提案バリュー: 「先輩・上司の代わりにいつでも質問できる環境」「社内営業ノウハウの属人化解消」
- 横展開: 日本語ベースだが Qwen3 系のため中国語横展開が容易（今井様の最重要要望）

## 4. 既存プロトタイプ（実装済み）

リポ: [output/deploy/enpact-ai-roleplay/](../../output/deploy/enpact-ai-roleplay/)

### スタック

| レイヤ | 技術 |
|---|---|
| フロント | Next.js 16.2.6 (App Router, Turbopack) + React 19.2.4 + TS 5 + Tailwind 4 |
| API | Next.js API Routes / SSE ストリーミング / Node ランタイム |
| LLM | Ollama + Qwen3:14B (`think: false`, `num_predict` 制限) |
| TTS | Aivis Cloud（プロト）→ AivisSpeech OSS（本番） |
| STT | Web Speech API（プロト）→ whisper.cpp / faster-whisper（本番） |
| DB | プロト=メモリのみ → 本番 PostgreSQL（履歴・ペルソナ・監査） |

### 主要エンドポイント

- `/api/chat` — ロープレ会話（営業部長が山田社長を演じる）
- `/api/coach` — `mode: review | advice` でコーチング2系統
- `/api/tts` — Aivis 音声合成プロキシ
- 共通: [src/lib/ollama-sse.ts](../../output/deploy/enpact-ai-roleplay/src/lib/ollama-sse.ts) で Ollama NDJSON → OpenAI 互換 SSE 変換

### 設計コア（[src/lib/persona.ts](../../output/deploy/enpact-ai-roleplay/src/lib/persona.ts)）

- **AI アイデンティティ = 営業部長 1人**。シナリオごとに山田社長などを「演じる」構造。
- `CoachIdentity`（営業部長）と `ClientScenario`（シナリオ）を分離。
- 山田社長プロフィール: 58歳、金属加工業二代目、従業員45名、年商8億円、家族経営40年。
- hidden worries: 事業承継・退職金・資金繰り・取引先依存・従業員リスク。
- 言語ルール厳格化済み: 標準語固定、関西弁/方言/老人風禁止、フィラー50%混入、相対引用30〜50%、hiddenWorries の遠回し漏らし（信頼成立後）など。

### 既に実装済みの主要機能

- 山田社長ペルソナ（強がり→本音遷移）
- 音声ロープレ（マイク → LLM → 並列 TTS → 音声出力）
- Barge-in（AI発話中に話し始めると即停止）
- 対話モード（ChatGPT音声モード相当、沈黙1.8s自動送信）
- 振り返り FB（良かった点／惜しかった点／次の一手の3部構成、プレーン出力済み）
- 営業部長相談サイドパネル（履歴維持、Cmd/Ctrl+Enter、誤送信時の中断ボタン）
- キャラクター持続性（「AIですか？」に山田として惚ける）
- ハルシネーション抑止（部長は履歴の実発言のみを根拠化）

## 5. 録画 demo 用「シナリオ制御モード」プラン（最新）

5/21 失敗を受け、**`/roleplay?demo=1` で動く録画専用ルート**を追加する。LLM 任せの自由会話だと録画中に破綻するため、ステージ制 + 自然な複数候補返答 + 検品/固定 fallback に寄せる。

### 設計

- 新ファイル想定: `src/lib/demo-scenario.ts`
- `DemoStage`: `opening → identity → purpose → relevance → pointExplanation → taxAccountant → hiddenConcern → adviceResume → softClose`
- `DemoScenarioState`: stage / 既出論点 / 直前返答ID / 相談回数
- `DemoResponseCandidate`: stage ごとに山田社長返答 2〜3 候補（直前と同じものは出さない）
- `CoachAdviceCandidate`: stage ごとの部長ヒント/相談/具体例（決定論的、demoモードでは LLM fallback 使わない）
- LLM は「表現ゆらぎ」だけに限定し、検品 NG なら候補文へ fallback

### 録画フロー（2〜4分目安）

1. 山田社長が電話に出る（auto opening）
2. 営業が名乗る
3. 山田社長が用件を聞く
4. 営業が事業承継・退職金を切り出す
5. 山田社長が「うちに何が関係するのか」
6. 営業が要点説明
7. 山田社長が税理士確認と息子の不安をにじませる
8. 営業部長に相談（深掘り方針）
9. 営業が再開、相続税/後継者不安を深掘り
10. 振り返り FB を受ける

### 受け入れ条件

- `/roleplay?demo=1` で録画ルートを通せる
- 山田社長が同じ返答を連続しない／営業部長役にならない
- 営業部長が山田社長役にならない
- 「うちはまだ早い」が不必要に出ない
- ヒント/相談が同じ内容を連打しない
- 振り返り FB が出る
- `npm run lint` / `npm run build` 通過
- demo 用テスト + 既存テスト緑

### テスト観点

- ステージ遷移: 想定営業発話で正しい DemoStage に遷移／返答重複なし／役割混線なし
- 相談: ヒント・相談・具体例・振り返りが別文面／同じ助言を繰り返さない
- 音声: 録画に出る全返答を事前 TTS 確認、数字/記号/括弧は読み上げ用に正規化
- 画面: `http://localhost:3001/roleplay?demo=1` で表示崩れ・遅延・重複返答なし

### 方針メモ

- 通常モード（自由会話）の挙動を壊さない
- 完全固定台本ではなく複数候補から選び自然さを保つが、会話進行は必ずシステム側が制御
- 先方には「実運用では会話設計と AI を組み合わせる」とだけ伝え、内部の固定/半固定は明示しない
- 録画で直接共有 URL は渡さない（操作させない）

## 6. 録画運用ルール

- 録画ツールはシステム音声＋マイクを同時収録できるもの（QuickTime+BlackHole / Loom / OBS / ScreenStudio など）
- **ヘッドホン必須**（TTS をマイクが拾って対話モード暴走するのを防止）
- 事前に30秒テスト録画で AI 音声・自分の声両方が入っているか確認
- ブラウザは Chrome（Web Speech API）
- `ollama serve` 起動 + 録画前チェックリストを全消化
- 詳細: [output/deploy/enpact-ai-roleplay/DEMO_SCRIPT.md](../../output/deploy/enpact-ai-roleplay/DEMO_SCRIPT.md)
