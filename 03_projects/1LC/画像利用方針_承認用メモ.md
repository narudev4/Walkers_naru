# 物件画像のメール配信利用について（承認のお願い）

> 作成: 2026-06-15 / naru（細谷）
> 宛先: （上司名）
> 関連: マッチングメールの HTML 化（6/4 定例 決定事項4・クリック率0.9%改善の柱）

---

## 1. やりたいこと（結論）

マッチングメールを HTML 化するにあたり、**物件の外観写真・間取り図をメール内に表示**したい。
現状はテキストリンクのみ。写真付き「物件カード」にすることで、開封後のクリック率改善（現状 0.9% → 目標 8%）を狙う。

→ そのために **物件画像をどう取得し、メールに載せるか**の方針について承認をいただきたい。

---

## 2. 画像の取得方法（技術検証は完了）

| 論点 | 検証結果 |
|---|---|
| 土地大臣の「公式 API」で画像は取れるか | **取れない**（池田の指摘どおり） |
| では取得経路は無いのか | **ある**。土地大臣の物件公開ページ（daijin.cc）が、物件画像を**規則的な公開 URL で配信**している |
| 取得に認証・トークンは要るか | **不要**。物件番号さえあれば外部から画像ファイルを取得できることを実機で確認済み（HTTP 200・実画像を取得） |
| 運用方法 | 取得画像を **1LC 側ストレージに再ホスト**し、メールには自社 URL を埋め込む（daijin.cc へ直リンクしない＝相手サーバーに負荷をかけず、掲載終了でも画像が消えない） |

> 補足: 「API が無い」と「画像が取れない」は別。公式 API は無いが、公開ページの画像配信 URL から取得する方式（実質スクレイピング）であれば技術的には可能。

## 2.5 実際にどれだけ画像が出るか（2026-06-15 実測）

「画像が取れるか」は**物件ごと**で、頭文字（出所）だけでは決まらない。URL を生成して**叩いて確認**するしかない（404 ならフォールバック）。配信対象＝**新着 100 件**で実測した結果：

| 物件系統 | 画像あり率 | 備考 |
|---|---|---|
| **全体（新着100件）** | **42%** | 残り 58% はテキストカードでフォールバック |
| A 系（ATBB） | **100%（8/8）** | 新着はほぼ確実 |
| F 系（楽待ち系） | **93%（13/14）** | 新着はほぼ確実 |
| R 系（レインズ系） | **27%（21/78）** | 出にくい。新着の多数を占める |

- **古い物件は掲載終了で画像が消える**ため、配信対象（新着）で測るのが正。新着なら A/F 系はほぼ画像あり。
- **画像のある物件を優先配信** or 画像有無でカードを出し分ければ、見栄えする割合をさらに上げられる。

### 技術構成（確定）
- **A 方式（URL 直生成）＋ 存在確認（叩いて 200 なら採用）＋ 404 はフォールバック（テキストカード）**
- **Airtable Script の `fetch` は CORS で daijin.cc に届かない** → 画像取得は**外部バッチ**で実行（物件番号は Airtable から取得）

---

## 3. 承認の本丸：使ってよいか（規約・著作権）★要判断

**「技術的に取れる」＝「使ってよい」ではありません。** 以下は経営・規約判断が必要で、ここを確認しないまま配信するのはリスクです。

| # | 論点 | 懸念 |
|---|---|---|
| (a) | **レインズ規約** | テキストの 1 対 1 パーソナライズ配信はセーフという整理。ただし**外観写真は物件特定性が高く**、メール添付がグレーゾーンに当たらないか要確認（過去、自社サイト表示が 1 万→589 件に減らされた経緯あり） |
| (b) | **画像の著作権** | 物件写真の権利者（売主／元付業者／チタン）。1LC がメール配信に二次利用する権利があるか |
| (c) | **チタン／daijin.cc の利用規約** | 画像の取得・再利用が先方規約上 OK か（チタンとの関係に影響しないか） |

---

## 4. 承認いただきたいこと

1. **取得方式**（公開ページの画像 → 自社再ホスト → メール埋め込み）で進めてよいか
2. **規約・著作権 (a)(b)(c)** を、誰がどう確認するか
   - 例: レインズ規約は岩下様経由で確認／チタン利用規約は次回チタン MTG で確認
3. 上記がクリアできた前提で、**限定的なテスト配信**まで進めてよいか

---

## 5. 代替案（承認が降りない／規約 NG の場合）

- 画像を使わず、物件カードを**テキスト＋アイコン＋利回り強調**で構成（規約リスクを完全回避してもデザイン改善は可能）
- 物件を特定させない**イメージ画像**（エリアの雰囲気写真等）に留める

---

## 付録: 技術的な裏付け（参考）

- 画像配信 URL は物件番号から機械的に生成可能（例: 物件番号 → `…/gp/A/286/<番号>_3.jpg`）。連番で複数枚（外観・室内・間取り）取得可。
- 規則の全物件一般化は 2〜3 物件で裏取りすれば確実。
- メール側は外部 Web フォント・flex レイアウト等が主要メーラー（Gmail/Outlook）で崩れるため、デザインを保ったまま `table`＋インライン CSS でコーディングし直す前提。
