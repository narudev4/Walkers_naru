# Airtable 削除作業手順（naru 用・手動実施）

> 対象ベース: `appksEWIuKl7N2ftS`（CRM）
> 承認済み削除: ★物件紹介履歴 紹介日時<2026/3/1（約45,049）／チタン物件一覧 更新日<2025/12 かつ 紹介なし（約31,010）
> **大原則**: ①バックアップ → ②件数確認 → ③削除 → ④結果確認。順番は ★物件紹介履歴 → チタン物件一覧。

---

## 0. 始める前に
- **順番厳守**: ①★物件紹介履歴 → ②チタン物件一覧（逆だと物件削除で履歴が孤児化する）。
- **時間帯**: 自動処理を避ける。物件取得＝6時間ごと、マッチング＝毎朝9時(JST)。日中の落ち着いた時間に。
- 削除は元に戻しにくい → **バックアップ必須**。

---

## 1. バックアップ（削除前・必須）

### 1-1. CSVエクスポート（最低限）
対象: **★物件紹介履歴(全件)** と **チタン物件一覧(全件)**。＋念のため 希望条件(個人投資家)・不動産業者一覧(企業) も。

手順（Airtable）:
1. バックアップするテーブルで、**フィルタなしのビュー**を開く（フィルタ済みビューだと一部しかエクスポートされない）。隠しフィールドはCSVに出ないので、**全フィールドを表示**してから。
2. ビュー名の右の「**…**（ビューメニュー）」→「**Download CSV**」。
3. ダウンロードしたCSVの**行数 ＝ そのテーブルの総件数**になっているか確認。
4. 保存先: `03_projects/1LC/source_docs/backup_YYYYMMDD/` など安全な場所。

注意: CSVはリンク（投資家・物件のひも付け）を「名前の羅列」でしか保存しない＝関係の完全復元はできない。あくまで中身の控え。

### 1-2. ベーススナップショット（強く推奨・復元の保険）
- Airtable 右上の **履歴アイコン（時計）** → スナップショット、または base の「**…**」→「**Duplicate base**」で複製を1部。
- 万一のとき**まるごと戻せる**。CSVより上の安全網。**最低でもこれは取っておく。**

## 2. 削除（バックアップ完了を確認してから）

### ステップ① ★物件紹介履歴（先に）
1. 個人ビュー **`viwMmHjysYqs0ZkAb`**（紹介日時<2026/3/1）を開く。フッター件数 **約45,049** を確認。

4. 完了後、★物件紹介履歴の**総件数が約45,049件 減った**か確認。

## 3. 大量削除のコツ（重要）
- 数万件をUIで一度に選択・削除すると**重い/固まる/失敗**することがある。
- **安全策＝日付を区切って数回に分割**。例（★物件紹介履歴）:
  1. まず 紹介日時<2025/9（約2,042件）を削除
  2. 次に カットオフを 2025/12 に（約+16,001件）
  3. 次に 2026/3 に（約+27,006件）
  各回ごとに件数を確認しながら進める。チタンも同様に段階削除。
- **代替（確実）**: Airtable の **Scripting拡張**で `deleteRecordsAsync` を50件ずつバッチ削除する使い捨てスクリプト。「手動」ではないが大量削除に強い。**希望があれば作成します**（テスト→本番の順、naru承認後）。
