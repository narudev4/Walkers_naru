## ゴール（このタスクのスコープ）

1LCのAirtableベースが**レコード上限（125,000件）を超過（約140,000件）**しており、自動処理が止まる/止まりかけている。**古いデータを削除してレコード数とランニングコスト（月2万円超）を下げる**。

**naru の今回の担当 = 「削除候補の洗い出しと報告」**（実削除ではない）:
- どのテーブルの、どの基準（新規登録日 or 更新日）の、何件が削除可能かを調べる。
- 目標削減量は **7万〜10万件**。
- **翌日のMTG**で「この基準でここまで消せます」と報告→合意後に実削除（実削除は別ステップ）。

> ⚠️ **このセッションでは実削除しない。** 候補の特定・件数試算・リスク洗い出しまで。削除基準（新規登録日/更新日）はMTGで合意してから。

### データがどう溜まるか（=「使用済み/不要」判断の材料）
- **物件取得 Automation** (`wflqREpmCKeVl0oQz`): チタンAPI（`https://www.1lcinc.com/syuuekibukken/php/json_output.php`）へ`物件エリア`単位でPOST→`チタン物件一覧`へ格納。**毎日増加の主因**。
- **toCマッチング Automation** (`wflu54U87Lag1xNLV`): 毎朝8時、`チタン物件一覧`ビュー`viwPDkWFB8zHPraRL`から希望条件で最大5件抽出→`★物件紹介履歴`にレコード生成。**履歴増加の主因**。
- toB は Interface 手動なので増加ペースは低い。

### 削除時のリスク（要チェック）
- `★物件紹介履歴` は `★個人投資家` と `物件紹介_投資家`(物件) への **リンク（linked record）** を持つ。→ `チタン物件一覧` の古い物件を消すと、履歴側のリンクが**孤児（orphan）化**する恐れ。どちらを先に/どの範囲で消すか要設計。
- 「配信紹介履歴の自動更新」はスクリプトでコメントアウトされ**未稼働**（重複除外が効いていない既知の穴）。履歴の意味づけが曖昧な点に注意。
- データの**用途・重要度が不明な項目がある**（池田氏も「何のために保存してるか分からない」状態）。消す前に用途確認。

## 調査の進め方（推奨）

**Airtable MCPは無い。** ベース所有はクライアント（岩下氏）なのでPAT発行は避け、**既存ログインのまま使えるブラウザ操作／CSVを優先**する。

- **(主) Claude in Chrome でAirtable UIを操作** … 新しい認証情報ゼロ。Airtableは**ビューにフィルタをかけるとフッターに該当件数が正確に出る**ので、「更新日 < 2025-01-01 → ◯件」をフィルタで読むだけで件数把握できる。スキーマ（フィールド名）も画面で確認。
- **(重い集計時) CSVエクスポート → ローカルpandas** … 大きいテーブル（チタン物件一覧・★物件紹介履歴）をグリッドビューからCSVダウンロード → `03_projects/1LC/source_docs/` 等に置いてローカルで日付分布・重複・リレーションを正確かつ高速に集計。トークン不要。
- **(任意フォールバック) Airtable REST API + PAT** … naru が読み取りPAT（`data.records:read`+`schema.bases:read`、base=`appksEWIuKl7N2ftS`）を発行してよいと判断した場合のみ。PATはnaru自身のアクセス範囲・読み取り限定でクライアント課金や権限には影響しないが、所有がクライアントのため**無理に使わなくてよい**。

### 調査ステップ
1. ベースのテーブル一覧とフィールド（特に**日付系: 新規登録日 / 更新日**の正式フィールド名）をスキーマ取得で確認。
2. `チタン物件一覧` と `★物件紹介履歴` の**総件数**を確定。
3. 各テーブルで **日付カットオフ別の件数分布**を出す（例: 〜2024末 / 〜2025-06 / 〜2025-12 で各何件）。新規登録日・更新日の両軸で。
4. **リンク関係**を確認し、孤児化リスクの無い削除セットを設計（例: 「売却済み/紹介済みで1年以上更新なし」など）。
5. 「使用済み・不要」と判断できる項目（売却済みフラグ、重複、古い紹介履歴）を特定。
6. **削除候補レポート**作成: テーブル別「基準＝○○、カットオフ＝○○、削除可能件数＝N件」、合計削減見込み vs 7-10万件目標、孤児化リスクと回避策、推奨実行順。

### 報告アウトプット（MTG用）
- 「`★物件紹介履歴`: 更新日2025-06以前 = X件削除可」「`チタン物件一覧`: 売却済み/1年以上前 = Y件削除可」→ 合計 Z件（目標7-10万に対し充足/不足）。
- 推奨削除基準（新規登録日 or 更新日）とその理由。
- 実削除時の手順案（バックアップ→CSVエクスポート→削除、孤児化を避ける順序）。

## 留意

- 別件だが要対応: 引き継ぎコードに**Postmark APIトークンが平文露出**（ローテーション推奨）。本タスクとは分離。
