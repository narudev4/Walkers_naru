# 物件マッチング 現行 vs 改善版 比較（2026-07-25）

## 0. これは何か / どう読むか

毎朝9時、Airtable が個人投資家ごとに物件を5件選んでメール配信している。その「選び方」を
変えると配信内容がどう変わるかを、**今朝の実データ**で並べたもの。

- **掲載状態は推測ではなく実測**。チタン（1lcinc.com）の物件ページを1件ずつ開いて確認した。
  「❌掲載終了」= ページに「この物件は掲載を終了致しました」と表示される、または404。
- 「現行」列は**今朝ほんとうに送られた物件そのもの**（紹介履歴テーブルから取得）。
- 「改善版」列は、同じ投資家・同じ物件データで新ロジックを走らせたシミュレーション。
- 現行ロジックを Python で再実装したところ、今朝の配信 **85人・401件を100%（401/401）再現**できた。
  つまりシミュレータの挙動は本番と一致していることが確認済み。

### 改善版で変えたのはこの4点だけ

マッチング条件（エリア・種目・構造・価格・利回り・築年・URL有無・過去紹介済みの除外）は
**現行とまったく同じ**。変えたのは選び方の周辺だけ。

1. 物件を探す順番を「レコードID順（＝実質ランダムな固定順）」から**新規登録日の新しい順**に変更
2. **掲載終了と判定された物件を除外**（チタンのページを実際に見て判定）
3. 「過去紹介済｜成約済」フラグが立っている物件を除外
4. 希望条件の数値が空欄・「こだわらない」の場合は**その条件を無視**（現行は空欄だと全物件が不一致になる）

## 2. なぜ現行はこうなるのか（原因と規模）

1. **掲載終了を見ていない**。物件テーブル自体が古く、判定済み13,153件のうち
   **7,050件（54%）が既に掲載終了**。
   何も対策しなければ配信の半分近くが死んだ物件になるのは当然の結果。
2. **走査順が「レコードID昇順」で固定**。これは物件の新しさとも古さとも無関係な並び順で、
   毎朝この順で先頭から探して5件で打ち切るため、**毎日ほぼ同じ顔ぶれ（＝長く残っている＝
   売れた可能性が高い物件）が上位に来る**。改善版は新規登録日の新しい順に変えた。
3. **希望条件の空欄が「全部不一致」になる**。価格・利回りの上下限のどれかが空欄の投資家は
   74人いて、うち74人は現行ロジックで永久に0件になる（空欄→数値比較が成立せず全条件不成立）。
4. **築年の希望値が 9999 の投資家が 81人**（新しい入力フォームが「こだわらない」を
   9999 で書き込むのに、現行の条件式は「築年数 > 9999」を要求する）。
   このうち81人は**何をしても1件も選ばれない**。旧フォームは同じ意味で -1 を入れており、
   そちらは正しく「全物件OK」になる。数字ひとつで結果が真逆になっている。

### 補足: Airtable の「更新日」は鮮度の判断に使えない

今朝配信された物件289件（実配信401件のユニーク数）は、**全件が「更新日 = 2026-07-25」**になっている。
Airtable 上で今日更新された物件も同じ289件で完全一致した。つまり
**メール配信して紹介履歴を作った副作用で、その物件の更新日が今日に書き換わっている**。
「更新日が新しいから生きている物件」という判断はできない（今朝送った掲載終了物件も更新日は今日）。
そのため本比較表の日付列には、サイトに物件が載った日である「新規登録日」を使っている。

## 4. 築年の不等号を逆にした場合（仕様が未確定なので両方出す）

現行の条件式は「物件の築年数 **>** 投資家の希望値」。素直に読むと
「希望より古い物件だけ送る」という意味になり、日本語の希望（築○年以内）とは逆。
そこで不等号を逆（築年数 **<** 希望値）にした場合も出した。

- 改善版の配信内容が変わる投資家: **85人 / 85人**（物件単位では238件が入れ替わる。改善版396件 → 逆239件）
- 今朝配信された85人のうち、逆にすると配信0件になる人: **29人**
  （現行の書き方のままなら 1人）。
  理由: 旧フォームの「こだわらない = -1」が、逆にすると「築年数 < -1」＝全物件アウトになるため。
- 紹介許可ON 322人で見た0件の人: 改善版 94人 → 逆にすると 64人
  （9999 の81人が救われる一方で、-1 の人が全滅する）
- **結論として、不等号を逆にするだけでは解決しない。「こだわらない」を数値の魔法（-1 / 9999）で
  表さず、明示的に『指定なし』として扱うのが正しい直し方**。

## 5. 注意点（この表の限界）

- **未判定（⚠️）の扱い**: 物件ページの読み取りが500エラー等で確定できなかったものは
  「未判定」とし、掲載終了率の分母から外している（現行側0件 / 改善版0件）。
- **改善版は「選んだ5件をその場で実チェックして掲載中のものだけ残した」結果**。
  本番で同じ品質を出すには、毎朝の配信前に掲載終了チェック（今回作ったのと同じ仕組み）を回す必要がある。
- **物件データは今日19時台に取得したもの**。今朝9時時点と価格・利回りが変わっている物件が
  数件あり、その分だけ現行側の再現に誤差が出る可能性がある（今朝の配信は401/401一致したので実害なし）。
- **「成約済」フラグはほぼ機能していない**。物件25,739件のうちフラグが立っているのは2件だけで、除外条件としては効果がない。
- **今朝の配信は9:04〜14:12（JST）にわたって発生**しており、9時に一斉配信されていない。
  また紹介許可ONの322人に対し履歴が残ったのは85人分だけで、
  残りが「条件に合う物件が無かった」のか「処理が途中で止まった/履歴作成が失敗した」のかは
  この表では判別できない（別途調査が必要）。
- 氏名は伏せているが、社内テスト用アカウント（ワンエルシーテスト等）も配信対象に混ざっている。
