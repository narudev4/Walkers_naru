## 議論の骨子

### 1. 定期削除スクリプトと物件データ管理（00:13〜04:56）

GitHub Actions から**2日に1回**実行される定期削除スクリプトが稼働中。バックアップ失敗時はメール通知が送信される仕組み。削除条件は「90日以上前の更新」OR「5,000万未満」で、物件情報は **89,396件 → 21,000件** に削減済み。

ただし Airtable 全体のレコード数は依然約9万件。次のプラン（5万件上限）への降格にはまだ遠い。**物件情報以外の約7万件**が何のデータか不明で調査が必要。

マッチングロジックは「条件合致確認」と「紹介済みフラグ」だけを参照するため、物件本体が削除済みの紹介履歴は削除しても影響なし。過去に物件削除されたが履歴だけ残っている「孤児データ」が相当量ある可能性。

### 5. API 連携と物件データ取得の課題（16:21〜33:44）

#### 5-1. 物件取りこぼし問題

チタン API の**1回あたりの取得上限を超えると後続の取得が遮断される**仕様が原因で、Airtable に入力されていない物件が判明。取得を細分化して対応予定（今日明日中に完了見込み）。別視点からも同様の取りこぼしが判明しており、対応方法はほぼ同じ。

#### 5-2. 土地権利

所有権以外（借地権等）は融資対象にならず売却対象にもならないため、**所有権のみを取得**する方針。安い物件には借地権が多く含まれ、おすすめ物件に表示されると問題。Airtable に「土地権利」フィールドを設け、表示は全て「所有権」で固定。API で取得可能かはチタンに確認中（未回答）。

#### 5-3. 取引対応

取引対応（売主側仲介等）は API で取得可能なはずだが、Airtable に項目が未設定。チタン作成の Airtable 連携 API が正しく送信しているか要確認。**レインズから取得可能であることは確認済み**で、Airtable に項目を追加して物件取得時に入力する設定に変更予定。

#### 5-4. API 仕様書

チタンの API 仕様書がスプレッドシートの「API要求」シートに整理されている。確実に取得可能: 物件名、画像、売主側情報、取引対応。**利回り・積算価格の妥当性・土地比率・建物比率はエンドポイントは存在するが空の値が返る状態**。シンプルな API 仕様書を作成し、随時更新する方針。
