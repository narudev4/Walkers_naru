## 2. 現行システムの全体像

物件データの取得 → 顧客マッチング → メール配信、までを **ほぼ全自動** で回している。手動作業はほぼ無い。

```
チタン(物件データ元/API) ──API──▶ Airtable(中核DB) ──▶ Postmark(メール配信) ──▶ 顧客
                                      ▲
                          Airtable内スクリプト/Automationで
                          取得・マッチング・配信トリガーを制御
```

### 構成要素

| 要素 | 詳細 |
|---|---|
| **物件データ取得元** | 「チタン」社経由（Century21のデータをAPIで取得）。Airtable上のスクリプトからAPIリクエスト（地域・価格帯等のパラメータでフィルタ）。**1日4回**実行、200〜300件/回取得（約191件/日確認済み）。取得管理（チタン側）は1LC社では非把握。 |
| **中核DB** | **Airtable**（Business Plan / 13テーブル）。取得後の物件管理・配信先リスト管理をすべてここで実施。**レコード上限を既に超過**。所有者: 岩下様。 |
| **メール配信** | **Postmark**。物件紹介メールを配信。月100〜200通。**メールテンプレートは1種類のみ**。配信先はAirtableで管理。所有者: 岩下様（mi@1lc.com）。 |
| **マッチング** | 「AIおすすめ物件一覧」機能あり。毎日10〜30件をマッチング（状況により変動）。 |
| **日報** | 稼働状況の確認に使用。 |
| 営業代行Interface | 機能は存在するが営業代行は現在利用なし。 |

## 4. Walkers の提案ソリューション

### 主要施策
1. **会員制パーソナライズマイページ** … ログインユーザーごとに本人専用物件を表示（レインズ規制対応の肝）。メール・LINEと同期。
2. **マッチングエンジンの再設計** … 属性・物件条件・購買履歴・行動データ＋AIレコメンド。
3. **マルチチャネル配信（メール＋LINE）** … LINE公式のプッシュ配信を追加。開封率・クリック率・応答率を可視化。
4. **YouTube・SNSでのリスト醸成** … 岩下様が苦手な領域をWalkersが代行・伴走。楽待ち経由だけでなく自社メディアで信頼獲得→商談化。
5. **経営パートナーとしての継続伴走** … 月次レビュー、四半期戦略アップデート。

### 個人投資家の体験フロー（想定）
集客（YouTube/SNS/楽待ち）→ 会員登録（投資条件入力）→ マイページで本人専用おすすめ物件が日次更新 → メール＋LINEでリアルタイム通知 → 岩下様が直接コンタクトし商談・成約。

### 推奨技術スタック（案）
- フロント: **Next.js (React) + Tailwind CSS**
- バック: Node.js / Python（チタンAPI連携・マッチング・配信トリガー）
- DB: **Airtable（現行継続）＋ Supabase（行動ログ・履歴用）**
- インフラ: Vercel / Render or AWS / Amazon SES or Resend / LINE Messaging API
- セキュリティ: チタンAPIへの認証設定追加をチタン社に要請（最優先）、会員情報暗号化、宅建業法・レインズ整合性検証、配信パーミッション/オプトアウト整備

### スケジュール（提案時点）
| Phase | 期間 | 内容 |
|---|---|---|
| 1 要件定義（準委任） | 2〜3週 | ゼロベースヒアリング、レインズ規約精査、現行データ構造分析、KPI設計、本見積確定 |
| 2 設計 | 1〜2週 | 画面設計（マイページ/管理画面）、マッチングロジック設計、配信フロー、チタン社連携仕様調整 |
| 3 開発 | 4〜6週 | マイページ構築、マッチングエンジン実装、メール・LINE配信実装、Airtable移行、並行運用テスト |

→ **2026年5月 要件定義着手、6月〜10月 段階的リリース** が目標。

### ②' 旧版：成果報酬に関する覚書（料率逓減方式 / たたき台）
v2 以前の構成。料率を**運用開始からの経過期間で逓減**させる方式。協議用たたき台として3シナリオ：
- 標準: 1-12ヶ月 12% → 13-24ヶ月 10% → 25-36ヶ月 8%
- 保守的: 8% → 6% → 5%
- 強気: 15% → 12% → 10%

**料率設定の考え方（重要な交渉ロジック）**:
- Walkers が直接動かせるのは「到達率／開封率／クリック率」の3段まで。
- 問合せ率以降は岩下様の営業力・市況に依存するため寄与は限定的。
- 本システム経由接触の顧客の成約にのみ料率適用（独自開拓は除外）。
- 逓減構造＝初期はWalkersの投下回収を優先、後期は1LCの利益確保を優先。

**成果連動契約 修正2 の追加・変更点（先方修正反映）**:
- **独自開拓のみなし規定（第8条2(2)）**: 本システム非経由の独自開拓取引でも、**事前通知が無ければ「対象に含む」とみなす**（甲が独自開拓と立証した場合のみ除外）。← Walkers有利の防御条項。

## 10. システム実態（過去MTGで解析した一次情報）

提案書の「システム構成案」は将来像。**現行の実態**は以下（2026-04-08引継ぎMTG・04-10調査報告で判明）:

```
レインズ/楽待ち/アットホーム（物件元）
   ↓ スクレイピング
チタン（物件DBを持つ会社/SaaS。土地大臣の提供元）
   ↓ 認証なしAPI（むき出し / 1lc.com ドメイン）
岩下オフィスのノートPC 2台（自作APIサーバー的に常時稼働。ここがデータ取得の心臓部）
   ├→ 土地大臣（=チタン提供SaaS。1lc.com公開サイト＆顧客マイページの実体。Salesforce相当のCRM/配信機能あるが岩下はほぼ未活用）
   └→ Airtable「戦闘グループCRM」（13テーブル/Businessプラン/125,000件上限）
          ↓ オートメーション
       Postmark（メール配信）
```

**重要な実態**:
- **チタンAPIが認証なし（むき出し）** … URLを知れば誰でも物件取得可。ただし稼働は岩下のローカルPCのためサーバー代爆発リスクは低い（4/27確認）。レインズ情報を抜かれる懸念から、チタンに認証/暗号化を依頼済み（池田氏がメール送付、チタン対応予定。最悪Walkersが対応可）。→工程表「スクレイピングの通信暗号化」。
- **Airtableがレコード上限超過**（125,000件上限に約140,000件）。なぜか稼働継続しているが要対処。「10万件到達で2万件をCSVエクスポート→削除」の自動アーカイブを組む方針（一括5〜10万円見積）。Enterpriseで25万件まで上げる選択肢もあるが2〜3年で再発。→工程表「エアテーブルのデータ移行」。
- **Airtableオートメーション6本**: ①チタンから物件取得（6時間ごと・稼働中）②個人投資家向けマッチング配信（毎朝・Postmark経由・稼働中）③配信履歴作成（稼働中）④⑤企業向けマッチング/物件紹介（稼働中だがDB超過リスク）⑥**企業へのメール配信＝Googleアカウント連携未設定でOFF（2025年8月頃から放置・動いていない）**。営業がインターフェースから物件登録→自動メール、を意図した機能だが未稼働。
- **利回りフィールドの大規模データ欠落** → マッチング不発 → 一部の配信が出ていない（池田氏が原因特定・対応中。5/7 Chatwork報告分）。
- **岩下氏の二重稼働** … 上記システムとは別に、岩下氏自身がClaude CodeでAirtable/チタンのAPIからデータ取得→スプレッドシートでマッチング→営業事務が手動メール送信、を並行で回している。
- **レインズ規約問題の核心**（4/10で岩下氏が詳説）: レインズ独占掲載物件を「ログインで閲覧できる状態」で出すと規約違反（業者が会員登録して通報してくる）。2025年春のクレームで自社サイト表示が1万件→589件（広告可物件のみ）に激減。**メール/DMでの1対1パーソナライズ配信はセーフ**（希望条件マッチ送付）。→「会員制マイページに各人パーソナライズ物件のみ表示」ならメールボックスと実質同じでグレーOK、と岩下氏同意。ただし物件特定を避ける表記（エリア・価格帯・利回り・築年数をアバウトに）が要検討。要件定義でレインズ契約/規約を精査。
- **土地大臣のリプレイス方針**: 土地大臣はカスタマイズにチタン許可要（おそらく不可）＋UXが古く分かりにくい（ユーザーは登録した記憶なくログイン要求され離脱）。チタンAPIから物件は取れるので、**同等以上の会員制マイページをWalkersが自作**する方向。→工程表「土地大臣のリプレイス」。
