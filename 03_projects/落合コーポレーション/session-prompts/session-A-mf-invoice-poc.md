### 背景（このセッションだけで完結するための要点）
- 落合コーポは会計・請求書をマネーフォワードで運用中（本番は**ビジネスプラン**）。今回は naru が**トライアル口座を新規作成**してAPI実験する。
- B2B請求書には3つの支払区分がある:
  - ①かけ払い20日締め（締め日23:59にバッチで対象期間のフルフィルメント注文を集計→下書き作成→人が確認送付）
  - ②かけ払い末締め（同上、末日締め）
  - **③都度払い（注文を受け次第、下書きでなく即時で自動送付）** ← **今回実証するのはこれ**
- なぜ③か: 最もシンプル（1注文→1請求書、即時、集計・cron不要）で、**「MF請求書APIが叩けるか」のコア配線の検証に最適**。③が動けば、①②は「cron＋期間集計＋下書き保存」を足すだけの応用に落ちる（①②自体は今回スコープ外）。

### 接続契約（Track B と繋ぐ・必読）
- `session-prompts/integration-contract.md` を**必ず読む**。Track B（ストアモック）と最後に一気通貫で繋ぐため、**入力は「正規化注文データ JSON」固定**。
- 段2（A単体）: B が `output/last-order.json` に書き出すJSONを読んで請求書発行。
- 段3（一気通貫）: `draftOrderId` から Shopify Admin API で直接引いて発行（両方動いたら）。
- A が MF 取引先を新規作成したら、その `mfPartnerId` を後で Shopify 顧客へ書き戻せるよう結果に含める。
- **勝手な入力形式で作らない**（契約を外すと B と繋がらない）。

### スコープ（やること）
1. リポジトリに **`moneyforward/`** ディレクトリを新規作成（Node.js >= 20, `"type":"module"`）。
2. **OAuth2**: 認可フロー実装 → アクセストークン取得 → リフレッシュ対応。
3. **請求書発行**: Shopify注文1件分のデータ（取引先・品目・数量・単価=掛け率適用後の卸価格・税）を入力に、MFクラウド請求書APIで**請求書を1枚作成**。③相当なので「即時発行」想定。
4. 作成結果（請求書ID/番号/閲覧URL等）を取得して表示し、**MF管理画面で目視確認**できる状態にする。
5. 入力の注文データは、まずは**サンプルJSON 1件**でよい（Shopify→MF変換ロジックを1本通す）。余力があれば既存デモストアの実注文1件を `shopify/src/shopifyClient.js` 経由で取得して使う。

### スコープ外（やらない・時間を使わない）
- ①②（締め日cronバッチ・期間集計・下書き保存→人確認送付）の実装。← `README` か設計メモに「③の応用で実装可」と数行残すだけ。
- Shopify Webhook の常駐サーバー配線（本番のリアルタイム発火）。今回は手元で1回叩ければよい。
- 会計（仕訳）連携。今回は**請求書APIのみ**。
- 掛け率の計算（それは Track B / 既存 `shopify/src/discountEngine.js` の領分。卸価格は入力として与える）。
