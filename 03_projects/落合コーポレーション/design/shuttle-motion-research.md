## 3. 本命（鼓動・躍動感）に応える方向性

「羽が線に沿って飛ぶ」は §1-2 の最小形にすぎない。本命は §1-1 の「メインビジュアルで鼓動・軌道・スピード感・躍動感」。取り得る方向は3つある。

### 方向1: メインビジュアルを動画にする — 本命に最も近い

ぽぽ様が Kling で作ろうとしていたものの正体はこれ。Web 実装としては素直に成立する。

- **ミュート動画の自動再生はブラウザで常に許可されている**（Chrome 公式に "Muted autoplay is always allowed." と明記）。`<video autoplay muted loop playsinline poster="...">` で、操作なしにヒーローが動く。音だけが制約対象（§7）。
- Shopify 側: **Dawn に背景動画セクションは標準では無い**ため、カスタムセクションを1つ作る。動画は Shopify Files にアップロードして配信できる（YouTube/Vimeo 埋め込みも可だが、ヒーロー背景ならセルフホストのほうが UI が邪魔にならない）。テーマコード編集は Basic プランで可能なので**プラン制約なし**。
- 素材の入手経路が3つある。
  1. **実写撮影**。落合コーポレーション様は年間20大会規模のイベントを開催しており（7/22 逐語・決済の議論で言及）、撮影機会がある。スマッシュの瞬間・シャトルが飛ぶ軌道は数秒あれば足りる。最も「本物」に近く、権利問題も無い。
  2. **ライセンス動画素材**。即日入手できるが、他社と被る・自社製品ではないという弱点がある。
  3. **AI 生成（Kling 等）を Walkers 側でやる**。ぽぽ様が断念した工程を引き取るかたち。受領済みの実写シャトル（`design/assets/` に6点、白背景・高解像度）が image-to-video の入力に使える。ただし製品の形状が崩れるリスクがあり、**メーカーの主力商品の描写としては検証が必要**。
- ⚠️ **注意点**: 動画はヒーローの LCP を悪化させる。`poster` に静止画を必ず置き、動画本体は遅延読み込み、モバイルでは通信量を考えて静止画にフォールバックする設計が前提。

### 方向2: 軌道線を「心拍波形」に描き直す — キャッチコピーとの整合が最も高い　★7/28 に出すならこれ

現在の軌道線はなめらかな弧だが、これを**心拍計の波形（急峻なピークを持つ線）に寄せた軌道**として描き直し、そこをシャトルが走り、パルスが線上を走る。

- 「鼓動（HEARTBEAT）」と「軌道」を**1つの表現で同時に満たせる**。キャッチコピー「FEEL THE HEARTBEAT」＝「シャトルとプレーヤーの鼓動がシンクロする」という由来の説明に、絵として直接答える形になる。
- 既存 SVG の `d` 属性を差し替え、§4 の A＋C をかけるだけ。**追加素材が一切不要で、明日のMTGに確実に間に合う**。
- 弧のままにするか波形に寄せるかは 2案作って見せて選んでもらうのが早い。

### 方向3: 静止画に躍動感を足す — 最小コストの保険

`hero-action.jpg` にゆっくりズーム（Ken Burns）をかけ、シャトルまわりに鼓動のパルス発光を重ねる。既存素材のままで 30分程度。ただし本命からは最も遠く、これ単体を「要望に応えた」と出すのは弱い。

### 推奨

**方向2 を 7/28 に出し、方向1 を方向性の提案として並べる。** 方向2 は素材の意思決定を伴わないので確実に間に合い、コンセプト整合が最も高い。方向1 は撮影・ライセンス・AI 生成のどれを選ぶかという**先方の意思決定が必要**なため、明日は「動画にもできます。素材はこの3経路です」と選択肢を提示して合意を取る材料にするのが筋。

## 4. 【最小形】軌道アニメーションの実現方式

### 方式A: SVG `<animateMotion>` + `<mpath>`（SMIL）　★推奨

既存の `<path>` に `id` を付け、シャトルを同じ SVG 内に置いて `<mpath href="#trail">` で参照する。

```html
<svg viewBox="0 0 1200 700" preserveAspectRatio="xMidYMid slice">
  <path id="trail" d="M -50 620 C 250 620, 320 120, 620 90 S 1050 300, 1260 40"
        fill="none" stroke="#245BFF" stroke-width="2.5"/>
  <g>
    <!-- シャトルのベクター図形をここに -->
    <animateMotion dur="6s" repeatCount="indefinite" rotate="auto" keyPoints="0;1"
                   keyTimes="0;1" calcMode="spline" keySplines="0.4 0 0.2 1">
      <mpath href="#trail"/>
    </animateMotion>
  </g>
</svg>
```

- **利点（これが決め手）**: `viewBox` の座標系をそのまま共有するため、**レスポンシブでズレない**。`preserveAspectRatio="xMidYMid slice"` で拡大縮小されても軌道と羽が常に一致する。
- `rotate="auto"` で進行方向に自動で機首を向ける（羽が軌道に沿って傾く）。
- 対応状況: `<animateMotion>` は 2020年1月以降、`<mpath>` は 2018年10月以降 Baseline（MDN）。IE 以外は問題なし。

### 方式B: CSS Motion Path（`offset-path` / `offset-distance`）

```css
.shuttle {
  offset-path: path("M -50 620 C 250 620, 320 120, 620 90 S 1050 300, 1260 40");
  offset-rotate: auto;
  animation: fly 6s cubic-bezier(.4,0,.2,1) infinite;
}
@keyframes fly { from { offset-distance: 0% } to { offset-distance: 100% } }
```

- 対応状況: CSS Motion Path は **global 95.19%**（Can I use）。Chrome 46+ / Firefox 72+ / **Safari 16.0+**（2022年）/ Edge 79+。Baseline "Widely available"。実用上は問題なし。
- **⚠️ 落とし穴**: `path()` の座標は **SVG の viewBox ではなく、要素の包含ブロックの CSS ピクセル**で解釈される。ヒーローの SVG は `slice` で可変スケールするため、**このままでは画面幅を変えると羽と線がズレる**。合わせるにはブレークポイントごとに path を再計算するか JS でスケールを当てる必要があり、方式Aより手間が増える。
- `offset-path: url(#trail)` で SVG を参照する書き方もあるが、MDN が「Safari は SVG 図形参照に一部制限あり」と明記しており、確実性で方式Aに劣る。
- → **HTML 要素（`<img>` のシャトル）を飛ばしたい場合の選択肢**。SVG 内で完結するなら方式Aでよい。

### 方式C: `stroke-dasharray` / `stroke-dashoffset`（線が伸びる）

```css
#trail { stroke-dasharray: 2000; stroke-dashoffset: 2000; animation: draw 3s ease-out forwards; }
@keyframes draw { to { stroke-dashoffset: 0 } }
```

- 「ライン自体が飛跡として描かれる」表現。ぽぽ様の「軌道っぽい感じ」に効く。単体では羽は飛ばない。
- **方式A（羽が飛ぶ）＋方式C（羽の後ろから線が伸びる）を同時にかけるのが完成形**。羽の先端に線が追従するので「シャトルが飛んで軌跡を残す」絵になる。

### 推奨構成

**A＋C の合わせ技。** 既存 SVG に `id` を足し、シャトルのベクター図形を入れ、`animateMotion` と `stroke-dashoffset` を同じ duration で回す。追加ライブラリは不要。

## 5. Shopify で載せられるか → **載せられる。プラン制約なし**

- テーマコード編集（`Actions → Edit code`）は Basic プランで利用可能。カスタムセクションの新規追加も可。制限がかかるのは**チェックアウト画面**のみで、そちらは `checkout.liquid` 自体が 2026年に完全廃止され Checkout Extensibility に移行済み（本件のヒーローとは無関係）。
- 実装形態: `shopify-theme/sections/` に `hp-hero.liquid` を既に自作しているので、その中にインライン SVG ＋ `{% style %}` を書くだけ。アプリ導入も外部 JS も不要。
- 既存の自作セクション（`hp-hero.liquid` / `hp-cta.liquid`）と同じ手順の延長で移植できる。

## 6. 素材の課題（着手前に潰す必要あり）

受領済みのシャトル画像 7点（`design/assets/`）を確認したところ、**全ファイルにアルファチャンネルが無い**（`hasAlpha: no`）。白背景の上に白いシャトルが写った不透明な矩形画像。

| ファイル | 寸法 | アルファ |
|---|---|---|
| 落合様シャトル1.jpg / 2.jpg | 2506×1672 | なし |
| 落合様シャトル3.png | 1672×2508 | なし |
| 落合様シャトル4.png | 1745×1593 | なし |
| 落合様シャトル5.png | 1769×1401 | なし |
| 落合様シャトル6.png | 1801×1733 | なし |

そのまま飛ばすと**黒背景のヒーローに白い四角が飛ぶ**ことになる。対応は2択。

1. **ベクターのシャトルを描き起こす（推奨）**。飛ぶサイズは 40〜60px 程度で写真の質感は出ない。青・白・黒のミニマルな線基調（線幅 2.5px の軌道線）とも整合し、拡大縮小で劣化せず、色も自由に当てられる。ファイルサイズもほぼゼロ。
2. **写真を切り抜いて透過 PNG/WebP 化する**。背景が均一な白なので切り抜き自体は可能だが、**白い羽と白背景の境界**があるため単純な輝度キーでは羽が溶ける。被写体抽出（Photoshop・remove.bg 等）が必要。実写の質感を出したい場合のみ。

## 7. 音（宏樹様案）について — 実装可能だが自動再生は不可

- ブラウザの自動再生ポリシーにより、**ユーザー操作なしに音を鳴らすことはできない**。Chrome は Media Engagement Index、Safari はユーザー操作履歴で判定し、操作前の `play()` は `NotAllowedError` で拒否される。`autoplay` 属性も無視される。
- したがって「ページを開いた瞬間にシャトルの打球音」は**技術的に不可**。取り得る形は次のいずれか。
  - ヒーローのボタンやシャトルをクリック/タップしたときに鳴らす（ユーザー操作が起点なので確実に鳴る）。
  - 音量オンのトグルを置き、ユーザーが有効化したときだけループさせる。
- BGM 的な常時再生は EC サイトでは離脱要因になりやすく、実装可否とは別に**推奨しない**。7/28 の場では「ページを開いた瞬間に鳴らすのはブラウザ側の制約でできない、操作起点なら鳴らせる」と説明するのが正確。

## 8. その他の実装上の注意

- **`prefers-reduced-motion`**: OS で「視差効果を減らす」を有効にしている利用者にはアニメーションを止める（`@media (prefers-reduced-motion: reduce)`）。アクセシビリティの標準対応。
- **ループ回数**: 無限ループは目障りになりやすい。初回表示で1〜2回飛ばして静止（`fill="freeze"`）が上品。ぽぽ様が案Bを選んだ理由に「ホバーエフェクトの動きが上品」を挙げているので、過剰にしないほうが選定意図に沿う。
- **LCP への影響**: SVG インラインなので画像リクエストは増えない。ヒーロー背景写真のほうが支配的で、アニメーション追加による速度劣化はほぼ無い。
- **モバイル**: `slice` で切り取られる範囲が変わるため、軌道の端が画面外に出る。方式Aなら座標系が共通なので破綻はしないが、狭い画面用に軌道を短くした別 path を用意するとより整う。
