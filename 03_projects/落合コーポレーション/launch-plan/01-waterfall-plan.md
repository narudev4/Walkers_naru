## 進行原則

1. **ウォーターフォール**: 各フェーズは前フェーズの成果物承認をゲートとする。ゲート判定者 = naru。
2. **技術トラックとデザイントラックを分離**: トンマナ（ひろき様待ち）は技術ローンチをブロックしない。デザイン未確定でも「機能的に完成した状態」を7月末に納品可能にする。
3. プロセス: 洗い出し（済）→ 工程表承認 → 調査・技術検証 → 仕様凍結 → 実装プラン設計 → **Haiku レビュー** → 実装 → システムテスト（99ケース）→ UAT → 公開。
4. 確定した事実のみスプシへ昇格。本ドラフトは naru 承認後に「作業一覧」タブへ反映。

## リスクと逃げ道

| リスク | 発生時の逃げ道 |
|---|---|
| 本番プラン契約が遅れる（P-8） | dev store のままレクチャー実施は可能。ただし決済系テストが後ろ倒し → 公開日リスケの早期警告を 7/18 に判断 |
| Shopify Payments 審査が間に合わない | 銀行振込+代引きのみで公開 → クレカは後日有効化 |
| 後払い/PayPay 審査が間に合わない | Phase2 送り（先方合意を P0-1 で取る） |
| 掛率実値が来ない（P-1） | demo 値のまま公開せず、B2B のみ非公開で B2C 先行公開 or 掛率入手まで B2B 招待を送らない運用 |
| 商品マスタが来ない（P-3） | 現サンプル+画像なし非公開で公開し、後日一括入替 |
| トンマナが決まらない（DT-4） | 現行デザインのまま機能公開 → デザインは公開後アップデート（先方合意前提） |
| 佐川連携の工数が想定超 | Phase1 は「注文CSV手動エクスポート→e飛伝手動」の暫定運用で納品要件を満たす |
