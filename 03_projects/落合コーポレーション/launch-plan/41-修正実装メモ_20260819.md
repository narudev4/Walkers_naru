# 修正実装メモ（2026-08-19 デプロイ前レビュー用）

Cloudflare Workers の修正2件を実装し、テストまで完了した。**デプロイ・コミット・push は一切していない**（全て `ochiai-integrations/workers/` の working tree に未コミット変更として残している）。ochiai-hq への SendMessage は到達しなかったため、本メモを報告とする。

## 修正1（High）: findAlreadySettled の D1 bind 上限

- `src/lib/d1Store.js`: `findAlreadySettled(orderGids)` が全 GID を 1 つの `IN (...)` に bind しており、101 件以上で D1 のパラメータ上限に当たり締めバッチ全体が失敗する問題を修正した。
- 100 件ずつのチャンクに分割して SELECT し、結果の Set を統合する。戻り値契約（`Set<string>`）は不変。上限値は定数 `D1_MAX_BIND_PARAMS = 100` として定義。空配列時はクエリを発行しない（従来と同じ挙動）。

## 修正2（Medium）: 都度払いの MF 請求書の支払期日を +7 日に

- 仕様の正: 質問事項 No.16/35「③都度払い: 請求日から 1 週間以内」。従来は `payment_term_days` がどこからも渡らず、`mapOrder.js` の既定値 30 日で全件計算されていた。
- `src/lib/pipeline.js`: ステップ4（③都度払いの請求書即時作成）で `createInvoiceFromOrder(mf, { ...order, payment_term_days: IMMEDIATE_DUE_DAYS })` とし、定数 `IMMEDIATE_DUE_DAYS = 7` を付与（根拠コメントに質問事項 No.16/35 を明記）。指示どおり呼び出し側での付与を採用し、order 自体は変異させずスプレッドコピーとした。
- **かけ払いへの非影響の根拠**: `settleBatch.js:253` が統合注文に `due_at`（翌月20日／翌月末）を明示しており、`mapOrder.js:77` で `toDate(order.due_at)` が `payment_term_days` より優先されるため、締めバッチの期日計算には一切影響しない。これをテストで固定した（下記）。

## 懸念点・共有事項

1. **ws3-review エージェントと `npm test` が競合する**。両者が同じローカル D1（`.wrangler/state` の SQLite）を共有するため、並行実行すると SQLITE_BUSY と beforeEach の DELETE 干渉で無関係なテストが落ちる（実際に一度発生し、単独再実行で解消を確認）。レビュー時に fail が出たら、まず並行実行を疑うこと。
2. ベースライン検証で一時的に `git stash` を使った（すぐ pop 済み、現状は全変更が working tree にある）。同一 working tree で他エージェントが作業中のため、以後 stash は使わない。
