# 本番ストア移管 手順書（E-4）

作成 2026-08-06（細谷）。土台: launch-plan/13-移行前チェックリスト_20260803.md ＋ 8/4〜8/6 の実測結果。
対象工程: E-2〜E-7・A-8。**移管は Client transfer（同一ストアの所有権移転）のため、商品・顧客・テーマ等のデータ移行作業は発生しない。**「データ移行の実機確認」は本書の【C. 移管直後の生存確認】が該当する。

## A. 移管前（実施順）

1. **E-5: 新 Custom App の作成とトークン発行**（担当: 細谷・所要 約30分）
   - スコープ: 旧アプリの16スコープ ＋ `write_orders`（A-8: 入金確認自動化）＋ `read_payment_gateways` ＋ `write_content` ＋ **`read_shipping`・`write_shipping`（2026-08-06 追加: D-3 の送料プロファイル設定を API で行うため。現トークンには無い）**。不要スコープは付与しない。付与一覧を控える。
   - トークンは Cloudflare Workers の env にのみ保存（平文ファイル禁止）。
   - Workers の env 差し替え → デプロイ → Webhook 購読を新アプリで再登録（orders/create。向き先 https://ochiai-integrations.ochiai-corp.workers.dev/api/webhook）。
   - 通し確認: テスト注文 → Webhook 受信 → Draft Order/請求書パイプライン動作（実発行はしない）。
   - 旧アプリのトークン失効・購読解除は**移管後**に実施（切り戻し先として残す）。
2. **テーマの保全**（約10分）
   - dev ブランチと公開テーマの差分ゼロを確認（直近コミットが反映されていること）。
   - テーマ ZIP をエクスポートして保管（GitHub 連携が切れた場合の復元元）。
   - `ochiai-theme` リポジトリの GitHub Organization 移管を古谷さんと検討（個人リポのままだと先方側で再接続不可）。
3. **記録を控える**（約10分）
   - Webhook 購読一覧（トピック・URL）。
   - 新旧アプリの API スコープ一覧・アプリ名。
   - メタオブジェクト定義一覧（customerclass・itemtype・announcement）。
4. **ストア設定の確認**（約10分・古谷さんと分担）
   - 請求通貨が JPY であること。
   - 先方の会社住所がストア設定に入力されていること（不一致だと先方がカード登録できず受諾不能）。
5. **先方への事前案内**（落合様・宏樹様宛）
   - 受諾メールが届くこと／受諾期限は7日／受諾時に Basic プランを選択いただくこと／無料トライアル対象外のため課金が始まること。

## B. 移管の実施

1. Dev Dashboard > Stores > Client transfer タブ > 対象ストア > **Transfer store**。
2. 先方メールアドレスを入力して送信（アドレスは事前に宏樹様に確認）。
3. 先方が受諾 → プラン選択（Basic）→ 移管完了。所要時間は公式記載なし（受諾後は即時想定・当日中に C を実施）。

## 未確認のまま残る点（当日まで解消不能・安全側で準備済み）

- legacy custom app のトークンが移管で失効するか（C-3 で確認。新アプリで保険）。
