## A. すでに答えられる質問（実装記録ベース・根拠あり）

### Q1. B2Bの注文はどこまで動いているのか？
**A**: カートの「法人価格で注文する」ボタン → 掛率適用の Draft Order 自動作成 → 請求書URLへリダイレクト、まで動作。6/18 に実機で Draft Order #D28 → 注文 #1012（銀行振込・PENDING → 支払い済みマーク → PAID）を通しで実証済み。
**根拠**: スプシ「請求書フロー現状」§6、decisions-implementation.md D-1

### Q2. マネフォ請求書連携はどこまで動いているのか？
**A**: 注文 webhook → 支払区分判定（都度/かけ）→ MF請求書下書き自動作成まで本番相当で動作（Vercel 稼働中）。Shopify 合計とMF請求書合計の1円単位一致を実証済み（¥34,221）。締めバッチ（20日/末日）は実装済み・cron 未設定。
**根拠**: スプシ「作業一覧」Phase 2/4、「B2C+B2B完全実装工程表」C-1〜C-7

### Q3. なぜ Shopify Plus じゃなくて Basic でできるのか？
**A**: 掛率は Draft Order の priceOverride 方式で実現しており、Plus 限定の Functions を使っていない。銀行振込は Manual Payment で決済手数料ゼロ。規約面も調査済みで問題なし（第3回MTGで先方承認済み）。
**根拠**: スプシ「作業一覧」0-1/0-2、CONTEXT.md 2026-06-03 更新

### Q4. デザインはどうなっている？
**A**: B2C は6案提示済み（黒基調・カラー基調が好評、ひろき様の最終決定待ち）。B2B 案はこれから作成し今週共有（NA-20260706-001）。デザイン決定を待たず機能開発は並行で進む。決定が遅れても「機能先行で公開 → デザイン後反映」の逃げ道がある。
**根拠**: 第4回MTG議事録 決定1-3、CONTEXT.md §13

### Q5. 画像はどうする？

**根拠**: 第3回MTG議事録 決定9、第4回MTG議事録 決定4

## B. 調査反映待ちの質問（3本の調査で埋める）

### Q9. 本契約は具体的にどうやる？何が引き継がれる？ ✅調査済み【重要な訂正あり】
**A（手順）**: Dev Dashboard → Stores → Client transfer タブ → Transfer store → クライアントのメールアドレス入力。ひろき様側は通知メール →「Accept store」→ プラン選択・支払い登録。Basic は**月払い ¥4,850/月（年払い換算 ¥3,650/月）**。移譲後は無料トライアル対象外で即課金開始。
**⚠️ 重要1（工程の前提修正）**: 2026年現行の Dev Dashboard 体系では、**移譲できるのは「client transfer store」種別のみで、通常の開発ストア（dev store）は移譲不可**。手元の落合デモストアがどちらの種別かの確認が最優先タスク（Dev Dashboard の Stores 画面で確認）。旧型 development store → client transfer store への変換可否は公式に明記なし＝未確認。
**⚠️ 重要2（工程の前提修正）**: **カスタムアプリは移譲前のストアにインストール不可が公式仕様**（「Custom and draft apps can't be installed」）。つまり MF 連携用のカスタムアプリ・Admin API トークン・webhook 購読は**移譲後に本番ストアで作り直し（トークン再発行・webhook 再登録・Vercel 環境変数更新）が公式前提**。工数は小さいがゼロではなく、テストも移譲後に再実施が必要。
**その他**: クライアントの支払い通貨とストアの請求通貨が一致していないと移譲受諾できない（日本円ストアなのでリスク低いが確認）。テーマ・商品・メタデータの引き継ぎは「同一ストアの所有権変更」なので実務上残るはずだが、公式の明示一覧は未確認。
**根拠**: [shopify.dev: Dev Dashboard stores](https://shopify.dev/docs/apps/build/dev-dashboard/stores) / [client transfer stores](https://shopify.dev/docs/apps/build/dev-dashboard/stores/client-transfer-stores) / [Shopify Help: hand-off](https://help.shopify.com/en/partners/manage-clients-stores/client-transfer-stores/hand-off-stores) / [料金](https://www.shopify.com/jp/pricing)

### Q10. クレカ決済はすぐ使える？審査は？ ✅調査済み
**A**: Shopify Payments（日本・法人）の要件は、代表者情報＋**法人番号13桁**＋本人確認書類（免許証等をカメラで原本撮影、スキャン不可）＋登記謄本 or 印鑑登録証明書。**特商法ページの掲載が事前に必須**。日本の普通預金口座（円建て）必須。Visa/MC/Amex は審査所要時間の公式明記なし（不備時に延びる）。**JCB のみ手動審査で最大3週間** → 8月末公開から逆算すると、移譲後すぐ（8月上旬）に Shopify Payments を申請すべき。手数料は Basic で国内カード・JCB 3.55%、Amex・海外 3.9%。
**根拠**: [日本の要件](https://help.shopify.com/ja/manual/payments/shopify-payments/supported-countries/japan/requirements) / [対応決済](https://help.shopify.com/ja/manual/payments/shopify-payments/supported-countries/japan/payment-methods) / [手数料](https://www.shopify.com/jp/pricing)
**先方への含意**: 特商法情報（お願い#7）と登記謄本の準備が Shopify Payments 申請の前提になる → お願い事項の優先度が上がる。

### Q11. 銀行振込は本番で本当に動く？ ✅調査済み
**A**: 手動決済（銀行振込）にプラン制限・本番動作の制約は公式に存在しない。開発ストアで動かなかったのは「移譲前ストアは実取引がサポートされない」という種別由来の一般制約であり、本番の有料プランでは通常機能。取引手数料なし。「注文は未払いで確保 → 入金確認後に支払い済みマーク」という運用も公式記載どおりで、現在の実装と一致。
**根拠**: [手動決済](https://help.shopify.com/ja/manual/payments/manual-payments) / [client transfer stores の制約記載](https://shopify.dev/docs/apps/build/dev-dashboard/stores/client-transfer-stores)

### Q12. 佐川の送り状はどうやって自動化する？費用は？ ✅調査済み【前提の訂正あり】
**A（前提の訂正）**: **e飛伝IIは2024年3月末でサービス終了済み**。現行は e飛伝III（無料・クラウド型、要佐川運賃契約+スマートクラブ登録）。内部工程表の「e飛伝II CSV」表記は古かった。
**A（選択肢と推奨）**:
- **Ship&co（アプリ・本命）**: 佐川と API 連携し CSV 不要。追跡番号の Shopify 自動書き戻し＋フルフィルメント自動完了＋発送通知メール自動送信まで一気通貫。月額1,100円〜＋1件10〜22円。30日無料トライアル。**前提: 佐川との運賃契約（お客様コード）が必要** → 落合社は既存事業で出荷しているため既存契約がある可能性が高い。要確認。
- **プラスシッピング（次点）**: 佐川と個別契約なしで特別運賃を使える月額0円アプリ（60サイズ499円税別〜）。佐川契約がない/運賃が高い場合の代替。
- **e飛伝III CSV 運用（無料だが非推奨）**: 送り状は出せるが追跡番号の Shopify 書き戻しが手動になり、毎回の作業負荷が残る。
- **佐川 API 直接開発（非推奨）**: 仕様書が申込後にしか提供されず、商談〜開発の期間が読めない。
**推奨**: 佐川の既存運賃契約があれば **Ship&co**、なければ**プラスシッピング**。どちらも8月中の導入に間に合う見込み（Ship&co の佐川 API キー発行日数のみ未確認）。
**根拠**: [e飛伝III](https://www.sagawa-exp.co.jp/service/okurijyou-support/e-hiden3/) / [Ship&co 料金](https://www.shipandco.com/ja/pricing/) / [Ship&co×佐川×Shopify](https://www.shipandco.com/ja/integration/shopify/sagawa-express) / [プラスシッピング](https://apps.shopify.com/plusshipping) / [佐川スマートAPI](https://www.sagawa-exp.co.jp/service/smart-api/)
**先方への確認事項（追加）**: 佐川急便との運賃契約（お客様コード）の有無。

### Q13. 後払い・PayPay は入れられる？いつまでに決めればいい？ ✅調査済み
**A（推奨案）**:
- **PayPay**: Shopify Payments は PayPay 非対応（2026年時点）。**KOMOJU 経由**が最有力 — 初期・月額無料、手数料3.5%〜、審査2〜3営業日で8月末に確実に間に合う。8/15頃までの申請で十分。同じ契約でコンビニ払い（2.75%）も同時有効化可能。
- **後払い**: 本命は **Paidy**（初期・月額0円、公式アプリ）。ただし加盟店審査が約10〜14日なので、初回公開に含めるなら8/8頃までに申請。公開後の追加に制約はないため、「公開と並行申請→9月導入」でもリスクなし。
- **見送り推奨**: NP後払い（取引ごとの成約サポート手数料124〜252円が低単価商材に重い）、atone（直接契約が必要でリードタイム不明）。
- **注意**: KOMOJU/Paidy は Shopify Payments 外のため、サードパーティ取引手数料（公式ブログ記載 0.2〜2.0%）が上乗せ。Basic での正確な率は未確認 → 管理画面かサポートで確認要。
**根拠**: [Shopify公式 決済一覧](https://www.shopify.com/jp/blog/payments-list) / [KOMOJU料金](https://ja.komoju.com/pricing/) / [Paidy Shopifyマニュアル](https://download.paidy.com/shopify/shopify_paidy_manual.pdf) / [NP後払い料金](http://www.netprotections.com/price/) / [atone料金](https://atone.be/business/price/) / [Shopify Help: Additional payment methods](https://help.shopify.com/en/manual/payments/additional-payment-methods)
**未確認（正直に言う）**: Basic のサードパーティ手数料の正確な率、Paidy の正式料率（申込時個別提示）、KOMOJU 経由 PayPay の PayPay 側個別審査の有無。
