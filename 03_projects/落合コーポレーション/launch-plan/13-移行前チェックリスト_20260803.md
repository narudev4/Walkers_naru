# 本番ストア移行 事前調査（2026-08-03）

調査主体: migration-spike（公式ドキュメントベースの調査。実機未確認項目は明記）。
対象工程: E-2〜E-7（移管 8/4〜8/6 予定）。

## 結論（最重要リスク2点）

1. **ストア種別**: Dev Dashboard 上で対象ストアが「Client transfer store」に分類されているかが未確認。「Dev store」の場合は公式に移管不可（Transferable to a merchant: No）。旧 Partner Dashboard 由来の開発ストアがどちらに分類されるかは公式に記載なし。**8/4 作業の最初に Dev Dashboard > Stores > Client transfer タブでの目視確認が必須。**（E-1 の 7/29 確認「プラン画面に『ストアを移行』があった」と併せて突合する。）
2. **Custom App の所在**: 2026-01-01 以降、管理画面での custom app 新規作成（legacy）は不可。現アプリが Dev Dashboard 由来の場合、**アプリは移管されず Walkers 組織に残り、移管後の Walkers はコラボレーターのため Dev Dashboard に入れない** → Cloudflare Workers 連携が管理不能になるリスク。判定方法: ストア管理画面「設定 > アプリと販売チャネル > アプリを開発」に表示されれば legacy、表示されなければ Dev Dashboard 由来。

## 1. 移管後の Walkers アクセス（E-6）

- **コラボレーターアクセスは移管後も自動で維持される**（公式: "You keep collaborator access, so you can continue to work on the store after the transfer."）。再申請不要。
- ただしコラボレーターは Dev Dashboard に入れない（組織権限なし）。POS 不可・Administrator ロール付与不可。
- 出典: https://shopify.dev/docs/apps/build/dev-dashboard/stores/client-transfer-stores ／ https://help.shopify.com/en/manual/your-account/users/security/collaborator-accounts

## 2. GitHub 連携の維持（E-7）

- 移管後に連携が維持されるかは**公式に記載なし。実機検証が必要。**
- 確定事項: 一度切れたら同一テーマへの再接続は不可。再接続すると**新テーマとして追加**され、テーマ ID が変わる（"You can't reconnect a branch to a theme after it has been disconnected."）。
- GitHub 側: Organization 外のコラボレーターはブランチ接続不可。個人リポジトリのままだと先方側で再接続できない。
- 対処: 移管前に dev と本番テーマの差分ゼロ確認＋テーマ ZIP バックアップ取得。`ochiai-theme` の Organization 移管を検討。
- 注: フォーラムの Shopify スタッフ回答（disconnect→reconnect で新テーマ不要）とドキュメントが矛盾。安全側（新テーマになる前提）で準備する。
- 出典: https://shopify.dev/docs/storefronts/themes/tools/github ／ https://community.shopify.dev/t/shopify-theme-lost-access-to-github-repo/25767

## 3. Custom App・Webhook の生存（E-5）

- legacy custom app は認証情報のローテーション不可。**削除すると同方式では二度と作り直せない**（2026-01-01 以降の新規作成廃止）。→ **現アプリは絶対に削除しない。**
- Dev Dashboard 由来アプリは移管不可（公式回答: "Apps that are in your dev dashboard org cannot be transferred … we recommend using merchant custom apps which are still enabled on client transfer shops."）→ 移管後に先方組織側でアプリを作成し、Workers のトークンを差し替える段取りが必要。
- Webhook はアプリにスコープされ、トークンが変われば再登録必須。
- 出典: https://changelog.shopify.com/posts/legacy-custom-apps-can-t-be-created-after-january-1-2026 ／ https://community.shopify.dev/t/dev-dashboard-with-client-transfer-shop/28769

## 4. 移管の手順と所要時間（E-2・E-3）

- 手順: Dev Dashboard > Client transfer タブ > Transfer store → 先方メールアドレス入力 → 先方が受諾（**プラン選択は受諾フロー内で行う**）。
- 受諾期限は 7 日（期限切れで失効）。移管は**不可逆**。
- 移管後ストアは無料トライアル・プロモーション対象外（先方への費用説明に注意）。
- 移管前に: 請求通貨が JPY であること・先方住所の入力を確認（不一致だと先方がカード登録できず受諾不能）。
- 所要時間（受諾→利用可能まで）は公式記載なし。
- 出典: https://help.shopify.com/en/partners/manage-clients-stores/client-transfer-stores ／ https://help.shopify.com/en/manual/your-account/manage-orgs-and-stores/change-transfer-ownership

## 移行前チェックリスト（8/4 実施）

1. Dev Dashboard で対象ストアが Client transfer タブにあることを確認する（最優先）。
2. 「設定 > アプリを開発」で Custom App の所在（legacy か Dev Dashboard 由来か）を判定する（最優先）。
3. Dev Dashboard 由来の場合、先方組織でのアプリ再作成＋Workers トークン差し替えの段取りを組む。
4. 請求通貨が JPY であることを確認する。
5. 先方の住所・会社情報をストア設定に入力する。
6. テーマ ZIP エクスポートを取得し、dev ブランチと本番テーマの差分ゼロを確認する。
7. `ochiai-theme` の GitHub Organization 移管を検討し、Shopify GitHub App の権限をリポジトリ単位で付与する。
8. 現在の Webhook 購読一覧（トピック・URL）を控える。
9. Custom App の API スコープ一覧とアプリ名を控える。アプリは削除しない。
10. 先方へ事前連絡: 受諾期限 7 日・受諾時にプラン選択・無料トライアル対象外。
