# B2B／B2C 送料設計 叩き台（K-1）

作成 2026-08-06（細谷）。古谷さんレビュー用。決定後に K-2（仕様ドキュメント）→ D-2/D-3（設定・実装）→ D-10（境界テスト）へ進む。

## 1. 確定している要件（再掲・出典つき）

| 対象 | ルール | 出典 |
|---|---|---|
| 一般のお客様向け（B2C） | 本州・四国・九州: 8,000円以上 無料／未満 550円。沖縄・北海道: 一律 1,500円。 | D-2（要件定義書） |
| 業者様向け（B2B） | 本州・四国: 税抜2万円以上 無料。九州・北海道: 3万円以上。沖縄: 5万円以上（質問 No.4 回答済み）。未満は 550円。 | D-3・質問 No.4 |
| 導線 | B2C＝通常チェックアウト。B2B＝Draft Order の invoice checkout（御社価格で注文する）。 | S-1〜S-3 実装済み |

## 2. 実測で分かっている仕組み（D-9・2026-08-06）

- Draft Order のチェックアウトには**配送プロファイルの送料が自動で表示・適用される**（配送先住所でのゾーン判定も動作）。
- ただし Shopify の配送プロファイルは**「商品」単位**で、顧客や販路では切り替えられない。B2C と B2B は同一商品を販売するため、**プロファイルだけでは B2C と B2B の料率を分けられない**。ここが本設計の核心。
- 補足: 工程表 D-9 の「プロファイル設定だけで成立」は「送料機構が Draft Order に効く」ことの確認。料率の分離には本書のいずれかの案が必要。

## 2-2. 公式ドキュメント調査の結果（2026-08-06・独立2系統で実施）

「案A より良い手はないか」を、Shopify ネイティブ機能側とアプリ・代替アーキ側の2方向から公式ドキュメントで調べた。**両方が独立に案A（Draft Order の shippingLine を自前で計算して直接指定）を推奨**する結論になった。

| 手法 | 判定 | 根拠（一次情報） |
|---|---|---|
| 配送プロファイルの分岐軸を増やす | ❌ 不可能と断定 | 分岐軸は商品／発送元／ゾーン／サブスクのみ。かつ「1つの商品は同時に1つのプロファイルにしか属せない」と公式明記。 |
| Carrier Service API（配送料の外部計算） | ❌ Basic では新規利用不可 | 2023-01-01 以降、Starter/Basic はアクセス申請自体ができない（公式 changelog）。 |
| Shopify Functions（Delivery customization） | ❌ 要件を満たさない | 2024-12 のアップデートで Draft Order 決済にも適用されるようになったが、**できるのは非表示・名称変更・並べ替えのみで金額は変えられない**。なお自社カスタムアプリで Functions を使うには Plus が必要（アプリストア経由の公開アプリなら Basic 可）。 |
| Shopify の B2B 機能（Companies・支払条件） | ❌ 前提と非整合 | 機能自体は **Basic でも利用可能**（公式）。ただし会社アカウントでログインするネイティブ B2B チェックアウトが前提で、本案件の Draft Order 請求書決済とは別動線。配送料への効果も公式記載なし。 |
| 配送料アプリ（App Store） | △ 検証しないと分からない | 顧客タグ別の出し分け対応アプリは複数あるが、**どのアプリも「Draft Order の請求書決済で効くか」を公表していない**。全アプリ英語UIのみ。導入するならトライアルで実機検証が前提。 |
| 送料を明細行（custom line item）として積む | ❌ 非推奨 | 公式に「カスタム明細行は自動フルフィルメント・配送アプリと併用不可」と明記。加えて Shopify のレポート上は商品売上に計上されるため、**マネーフォワード連携が送料を拾えなくなる**（連携側の改修が必須になる）。 |
| **案A: shippingLine を直接指定** | ✅ 推奨 | `DraftOrderInput.shippingLine` は正規の API フィールド。B2C は標準プロファイル、B2B はこの経路のみを通るため、**同一商品のまま料率を分離できる唯一の現実解**。追加課金なし。 |

### ★最優先の要検証 → ✅ 実機検証済み（2026-08-06 PM・#D60 で実測・削除済み）

検証用 Draft Order（shippingLine「業者様配送（検証用）550円」を API で直接設定）の請求書決済画面で確認した。

1. **配送欄には設定した shippingLine の1件だけが表示される**。配送プロファイルの料金（通常配送550円／北海道・沖縄1,500円）は並ばない → 業者様が B2C 料率を見る・選ぶ余地はない。
2. **配送先住所を北海道に変更しても shippingLine は保持される**（550円のまま・合計不変）。プロファイルへのフォールバック・再計算は発生しない。

→ **案A は成立**。ただし2の裏返しとして「住所を変えても送料が変わらない」ため、東京の住所で作った注文の配送先を業者様が北海道に変えると本州料率のまま出荷することになる。対策は運用側で選ぶ: ①お届け先はご登録住所に限る（注文メール・お取引条件に明記）②Workers が注文完了 webhook で配送先とゾーンの不一致を検知して通知（自動再計算はせず人が判断）。おすすめは①＋②の併用。

## 3. 案の比較（当初案・上記調査で裏付け済み）

### 案A（本命）: B2B 送料は Workers が Draft Order に shippingLine を直接設定する

- createDraftOrder 時に、顧客住所 → ゾーン判定（本州四国／九州北海道／沖縄）→ B2B 料率で送料を計算し、Draft Order の shippingLine に設定する。
- Shopify のプロファイルは B2C 専用にできる → D-2 をそのまま既定プロファイルに設定して完結。
- 長所: 料率を完全制御・B2C と干渉ゼロ・Basic プランで成立・アプリ追加不要。
- 短所: 実装1〜2日（旧 No.10b の再登板）。チェックアウトで配送先を変更された場合に追随しない可能性。
- **着工前の要検証（30分・Draft Order 作成→確認→削除で可能）**:
  1. shippingLine 設定済み Draft Order のチェックアウトで、送料がその1件に固定されるか（プロファイル料金が並ばないか）。
  2. チェックアウトで配送先住所を変更したとき送料がどうなるか（固定のままなら「お届け先はご登録住所」の運用と併せる）。

### 案B: プロファイル1本に B2C・B2B 両レートを併記して選ばせる

- 実装ゼロだが、B2C のお客様にも「業者様向け送料（2万円以上無料）」等のレートが見えてしまう。
- 選び間違いが起きる・B2B の存在と価格体系を示唆する → **「B2C と B2B は繋げない」方針（2026-05-26 決定）に反するため非推奨**。

### 案C: B2B 専用に商品を複製して専用プロファイルに所属させる

- 商品・在庫・実データ入稿がすべて二重管理になる。送料目的だけでは割に合わない → 非推奨（掲載を分ける議論自体は No.71 で先方判断待ち）。

## 4. 推奨と進め方

**案A を推奨。**ただし着工判断の前に上記の要検証2点を実機で確認する（手順は B-13 と同じ: 検証用 Draft Order を作成 → チェックアウト表示を確認 → 削除）。

進め方: 要検証2点 → 古谷さん合意 → Workers 実装（ゾーン判定＋料率表。判定基準は K-2 でドキュメント化）→ テーマ側は変更なし → D-2 を既定プロファイルへ設定（Admin UI）→ D-10 境界テスト（19,999／20,000・29,999／30,000・49,999／50,000 の8パターン）。
