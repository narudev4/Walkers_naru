## 実行結果

### 1. EX-C-1-04 二重押下（冪等キー無しの実挙動確定）— 期待どおり

- リクエスト: 同一ペイロード `{"customerId":9681061183789,"items":[{"variantId":51910940197165,"quantity":10}]}` を POST /api/create-draft-order へ 2 回連続送信。
- 結果: **2 回とも 200 で、別々の Draft Order が 2 件できた**（#D69 → #D70。金額は同一 133,760 円）。Workers に冪等キーが無い現状の実挙動を実 HTTP で確定。
- 証跡: 1 回目 `draftOrderId: gid://shopify/DraftOrder/1253513822509 (#D69)`、2 回目 `gid://shopify/DraftOrder/1253513855277 (#D70)`。いずれも `"ok":true`・total 133,760 JPY。
- 補足: テーマ側のボタン disabled（`b2b-cart-checkout.liquid:114-118`）は今回未検証（ブラウザ操作禁止のため）。サーバ側に防波堤が無いことの確定が本ケースの成果。

### 2. EX-C-1-02 不正数量（実 HTTP での再確認）— 期待どおり

- リクエスト: quantity を 0／-1／1.5／"abc" に変えて 4 回 POST（顧客・バリアントは上と同じ）。
- 結果: **4 パターンすべて HTTP 400**・本文 `{"error":"数量が正しく指定されていない商品があります。カートで数量をご確認ください。"}`。ユニットテスト（`workers/test/createDraftOrder.test.js`）と同挙動を実 HTTP で確認。
- 後片付け: 何も作成されないため不要。

### 3. EX-A-3-01 削除済み商品（実在しない variantId）— 期待どおり（2 挙動とも）

- (a) 混在: 有効バリアント＋実在しない `variantId: 99999999999999` の 2 行を POST → **HTTP 200**。不正行は黙って除外され、有効 1 行だけの Draft Order #D71（`gid://shopify/DraftOrder/1253513953581`）が作成された。レスポンスの lineItems はラケット 1 行のみで、除外の警告・通知は一切なし。
- (b) 全部不正: `99999999999999`・`88888888888888` の 2 行のみ → **HTTP 400** `{"error":"有効なバリアントが見つかりません"}`。
- 39 の期待結果（`createDraftOrder.js:239-244,250-252` の `if (!variant) continue;`）どおり。「業者様に理由が示されない」問題も実挙動として確定。カート表示側（Shopify がカートから自動除去するか）は本テストの範囲外で未検証のまま。

### 4. EX-B-1-02 相当の読み確認（かけ払いのタグ・属性付与）— 期待どおり
