## 1. 現行実装の設定箇所（3 点セット）

レート決定式: `custom_overrides[category] ?? discount_matrix[group][category] ?? 1.0（正価）`。

| # | データ | 場所 | 設定内容 |
|---|---|---|---|
| A | 掛率マトリクス | Admin → コンテンツ → メタオブジェクト → **Discount Matrix** | group × category × discount_rate（0<x≦1 の小数。0.60 = 上代の 60%）。行追加のみで新グループ・新カテゴリ対応（コード変更不要・実証済み）。 |
| B | 顧客側 | Admin → 顧客 → 対象顧客 → メタフィールド | `b2b.customer_type`=corporate（必須ガード）／`b2b.discount_group`=A 等／個別条件は `b2b.custom_overrides`（JSON 例 `{"racket": 0.55}`）。運用上は `payment_terms`・`corporate_name`・`customer_code` も併設。 |
| C | 商品側 | Admin → 商品 → 対象商品 → メタフィールド | `b2b.category`=racket 等。掛率計算に使うのは category のみ（sport はコレクション分類用）。 |

適用経路は 2 つ: 表示＝テーマ Liquid（`b2b-wholesale-price.liquid` ほか）がログイン法人のみに御社価格を描画。決済＝発注フォーム → Vercel API / `createDraftOrder.js` → Draft Order の priceOverride（Basic ではセルフカートのチェックアウトが正価に戻るため）。

一括投入スクリプト: `shopify/src/setup.js`（メタオブジェクト定義・マトリクス・商品 category・テスト顧客）／`shopify/src/create-test-customer.js`（顧客 + metafield + 有効化 URL）。

## 2. 【環境変化】ネイティブ B2B が Basic に開放（2026-04-02）

6/1 検証・6/8 決定メモの前提「ネイティブ B2B・セルフカート卸価格決済は Plus 限定」は、**2026-04-02 の Shopify 発表で変わった**。Company・カタログ（価格表）・B2B チェックアウト・支払条件・数量ルールが Basic/Grow/Advanced でも追加費用なしで利用可能。

- 出典: https://help.shopify.com/en/manual/b2b/getting-started/plan-features ／ https://shopify.com/news/b2b-for-all ／ https://changelog.shopify.com/posts/key-b2b-features-now-available-on-non-plus-plans
- カタログは「全体 % 調整」+「商品別固定価格（% を上書き）」の併用可: https://help.shopify.com/en/manual/b2b/catalogs/creating-catalogs

### Basic での制約（落合要件との突き合わせ）

| 項目 | ネイティブ B2B（Basic） | 現行 Draft Order 方式 |
|---|---|---|
| セルフ決済で卸価格 | ○（B2B チェックアウト） | ×（発注フォーム → Draft Order の Invoice） |
| 掛率グループ数 | **アクティブカタログ 3 個まで**（≒3 グループ） | 無制限（マトリクス行） |
| カテゴリ別掛率 | カタログの % は 1 つ → カテゴリ別は**固定価格を CSV で計算投入**（掛率変更・値上げ時に再投入） | マトリクス行の編集のみ |
| 業者個別×区分の上書き（custom_overrides 相当） | 3 カタログ枠では実質不可 | ○（JSON 1 個） |
| カタログの割当 | 会社への直接割当は Plus のみ。Basic は B2B マーケット経由 | 顧客 metafield のみで完結 |

なお Functions の自作（カスタムアプリ）が Plus 限定である点は 2026-08 時点でも変わらず（https://shopify.dev/docs/apps/build/functions ）。

## 3. 選択肢（判断は naru・古谷さん）

1. **現行 Draft Order 方式の続行**（推し）。2 軸マトリクス + 個別カスタムに完全対応・実装済み・実機 PASS。9/1 試験運用が目前でリスク最小。ネイティブ移行は Phase 2 の検討事項として質問事項 or 工程表に積む。
2. **ネイティブ B2B カタログへ乗り換え**。グループが 3 つ以内に収まるなら、セルフ決済・支払条件までネイティブで賄え保守物が減る。ただしカテゴリ別掛率の CSV 運用・個別カスタム不可・作り直し工数。
3. **公開アプリ**（BSS: B2B & Wholesale Solution＝日本語 UI・無料プランあり／Wholesale Pricing Discount B2B＝日本語 UI $24.99〜／Regios＝Functions 方式・英語）。顧客タグ×商品/コレクション別 % 掛率に対応。月額と外部依存が増える。

### アプリ・方式共通の落とし穴（導入検証時のチェック 4 点）

割引コード併用可否（Draft Order 経由は割引コード不可）／動的チェックアウトボタンの挙動／割引後価格の商品ページ表示／**JSON-LD 経由で卸価格が Google に露出する事故**（2026-05 に報告あり。`seo.hidden` での noindex 等で対策）。
