# Shopify 通知メールテンプレート仕様調査（2026-08-03）

調査主体: mail-spike（公式ヘルプ・shopify.dev・スタッフ回答ベース）。
対象工程: C-9・F-10・S-4・F-5。

## 1. 支払区分分岐に使えるデータ経路

| 経路 | 可否 | 根拠 |
|---|---|---|
| `customer.metafields` | **不可の公算大** | customer オブジェクトのプロパティ一覧（25個）に metafields が無い。Shopify スタッフ回答（2024-11-25）「Only product and variant metafields are supported on email notifications currently」。 |
| 注文 metafield（`metafields.NAMESPACE.KEY`） | **矛盾・要実機** | ヘルプセンターは記載あり、スタッフ回答は否定。2026-02 のフォーラムでも「動かない」報告が継続。記法（order. を付けない）の問題の可能性もあり。 |
| `attributes`（注文属性） | **可（公式明記）** | "Any attributes which were attached to the order. Example: {{ attributes.gift-note }}"。 |
| 注文 `tags` | **可（公式明記）** | Order properties に tags あり。`{% if tags contains '...' %}` で分岐可。 |

**推奨**: 分岐はタグ or attributes を本線にする。文面案（launch-plan/11）の本命（customer.metafields）は降格し、フォールバック（customer.tags／attributes）を昇格。

**要実機検証**: Draft Order の `customAttributes`・tags が完成後の注文の `attributes`・`tags` に引き継がれるか（公式に明記なし）。

## 2. 発送通知への明細表示（S-4 案A）

**可。分納にも対応。**

- 発送通知は fulfillment 単位で発火し、`fulfillment.fulfillment_line_items` はその回に発送した行だけを返す（`fulfillment_line.line_item`・`quantity`、`line.title`・`line.variant.sku`・`line.price`・`line.pre_tax_price` で表を組める）。
- **注意1**: `tax_price`／`shipping_price`／`total_price` は注文全体の金額。分納回の金額ではないため、納品書代替では金額合計欄を載せない。
- **注意2**: テンプレートをカスタムすると注文状況ページへの自動リンクが消える。`{{ order_status_url }}` を手動挿入する。

## 3. 新しい顧客アカウントの通知への影響

- **6桁確認コードメールは文面カスタム不可**（公式明記。2026-03 時点でも変わらず）。
- **アカウント招待メール（customerSendAccountInviteEmail）は旧方式（legacy）専用**。新方式では成立しない。
- パスワードリセットは概念ごと消滅（パスワードレス）。
- 注文確認・発送通知のテンプレート編集には影響なし。
- **Shopify の B2B 機能（Companies・支払条件）は Basic でも利用可能で、新しい顧客アカウントが必須**（旧方式では B2B 不可）。通知変数に `payment_terms`・`b2b?`・`company`・`payment_schedule.due_at` 等がある。将来 Shopify 標準 B2B へ寄せる選択肢を残すなら新方式維持が有利（F-5 の判断材料）。

## 実機検証リスト

1. 注文 metafield（`metafields.NAMESPACE.KEY`）が注文確認メールで値を返すか。
2. Draft Order の customAttributes → 注文 attributes の引き継ぎ。
3. Draft Order のタグ → 注文タグの引き継ぎ。
4. `customer.tags` が通知テンプレートで参照できるか。
5. 「20日締め翌月末払い」を Shopify 支払条件テンプレートで表現できるか・`payment_schedule.due_at` の実挙動。
6. Flow での注文後タグ付けと通知送信の順序（競合の懸念があるため採用しない前提の確認）。
7. `b2b?` の実挙動（同一テンプレートで B2B/B2C 分岐する前提の確認）。
