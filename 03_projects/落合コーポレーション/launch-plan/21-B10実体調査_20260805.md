# B-10 実体調査 結果（2026-08-05・Admin API実測）

> 実測方法: Admin GraphQL（scratchpad/probe-b10.mjs）。metafieldDefinitions／metaobjectDefinitions／metaobjects／customers の生レスポンスに基づく。

## 1. 「定義が2つある疑い」→ 重複ではなかった（解消）

| 画面で見えた名前 | 実体 | ID |
|---|---|---|
| 顧客区分(f) | **メタオブジェクト定義**の名前（type: `customerclass`） | MetaobjectDefinition/15240233261 |
| 顧客区分2(f) | **顧客メタフィールド定義**の名前（`custom.2_f`、metaobject_reference → 上記を参照） | MetafieldDefinition/176756850989 |

顧客側の custom 系メタフィールド定義は `custom.2_f`・`custom.itemA/B/CdiscountRate` の4つだけで、**重複定義は存在しない**。8/4 に古谷さんが「なんで2個あるんだ」と言ったのは、メタオブジェクト定義名とメタフィールド定義名が似ているための見間違い。**B-14 の「統合」作業は不要**。紛らわしさの解消には顧客メタフィールド定義名を「顧客区分」等へ改名するだけでよい（任意・古谷さん確認）。

## 2. 実体マップ（コードが参照すべきキー）

- メタオブジェクト `customerclass`（displayNameKey=name）: fields = `name`／`typeA`／`typeB`／`typeC`（number_integer・割引率%）／`typeCustom`（boolean）。エントリー handle: `cutomertypea`／`cutomertypeb`／`cutomertypec`／`cutomertypecustom`（"cutomer" は古谷さんの typo だが実害なし・変更しない）。
- メタオブジェクト `itemtype`: fields = `name` のみ。handle: `a`／`b`／`c`。
- 顧客: `custom.2_f`（→customerclass）、`custom.itemAdiscountRate`／`itemBdiscountRate`／`itemCdiscountRate`（number_integer）。
- 商品: `custom.itemType`（metaobject_reference → itemtype）。
- カスタム区分エントリーの typeA/B/C は **null**（値を持たない）。カスタム顧客の率は顧客側の itemXdiscountRate が正、という設計が実データでも裏付けられた。

## 3. 取得方法の確定

- **Workers（Admin GraphQL）**: `metafield(namespace:"custom", key:"2_f") { reference { ... on Metaobject { fields { key value } } } }` で顧客→区分→typeA/B/C まで一発で展開できることを実測（デモ法人Aで確認）。metafields 一覧の平読み（現行実装）では reference の中身は取れない → alias 指定＋reference 展開へ変更が必要。
- **Liquid（テーマ）**: key `2_f` は数字始まりのため dot 記法不可。**bracket 記法 `customer.metafields.custom['2_f']` が必須**（Liquid の識別子規則。実機の最終確認は B-13 のプレビューで実施）。metaobject reference は `.value` でメタオブジェクトが返り、`x.typeA.value` 等でフィールドを読む。商品側は `product.metafields.custom.itemType` で dot 可。

## 5. 異常時の期待値（推奨案。最終確認は B-15 ③で古谷さんへ）

| ケース | 推奨挙動 | 理由 |
|---|---|---|
| 顧客区分（custom.2_f）未設定 | 正価（割引なし）。 | 高く出る分には過小請求にならず、顧客からの指摘で設定漏れに気づける。 |
| 商品区分（custom.itemType）未設定 | 正価。 | 現行エンジンの no-category と同じ安全側。 |
| カスタム区分だが個別値が未入力 | 該当商品区分は正価。 | 上と同じ原則。 |
| 割引率 0% | 有効値として正価。 | 「割引しない」の明示指定と解釈。 |
| 割引率 100%・負・100超・非数 | 無効値として正価へフォールバック。 | 100%＝無料は入力ミスの公算大。事故防止。 |
| 区分A/B/C顧客に個別値が残存 | 無視（仕様どおり）。 | 8/4 古谷さん明言。 |
