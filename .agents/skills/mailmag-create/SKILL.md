# メルマガ作成・配信（Benchmark Email / 山口流）

トリガー: 「メルマガ作って」「メルマガ配信」「Benchmark」「mailmag-create」

## 概要

YouTube 動画の更新に合わせて、Benchmark Email でメルマガを作成・配信するワークフロー。山口鳳太さんがレクチャーした手順（録画: `output/manuals/mailmag-automation/`）をスキル化したもの。

「**過去のメルマガを複製 → サムネイル / 本文タイトル / 動画 URL の3箇所だけ差し替え → 件名差し替え → 12:00 PM JST で配信予約**」を一連で実行する固定パターン。新規デザインは作らない。

## 戦略的意図

- メルマガは「YouTube 更新時にサムネとリンクだけ送る」最小構成（[00:16]）
- 内容のアップデートは将来検討。**今は時間を割きたくない**（[00:25]）
- だから「YouTube 動画が更新されるたびに自動でメルマガが配信される」状態を作る（[00:38]）
- 既存メルマガをテンプレ流用するので、**変えるのは3箇所だけ**（サムネ / 本文タイトル / URL）

> 「これを YouTube の動画が更新されるたびにやりたいと」（山口、[00:38]）

> 「この3つさえ変えるら OK。多分自動化できる、絶対できる」（山口、[01:23]）

> 「ほとんど固定作業やから」（山口、[02:43]）

## ツール構成

| 役割 | ツール |
|------|--------|
| メルマガ配信プラットフォーム | **Benchmark Email**（`ui.benchmarkemail.com`） |
| 送信元アカウント | 株式会社 Walkers / `account@walker-s.co.jp` |
| 配信対象（顧客リスト） | テスト / 名刺リスト / HP のお役立ち情報希望リスト（合計 241 件） |
| トリガー元 | YouTube チャンネル更新 |
| ブラウザ自動化（推奨） | Codex in Chrome MCP（`mcp__Claude_in_Chrome__*`） |
| ブラウザ自動化（代替） | Playwright MCP / 手動実行 |

## ワークフロー全体像

```
YouTube 動画更新（または手動入力）
    │
    ▼
[Phase 0] 前提条件チェック（Chrome 拡張接続 / Benchmark ログイン）
    │
    ▼
[Phase 1] ヒアリング & 入力素材確定
    │   ├─ 動画タイトル（【】等のプレフィックス込み・全文）
    │   ├─ 動画 URL（短縮形 youtu.be/XXX）
    │   ├─ サムネイル画像（最高解像度）→ ローカル DL
    │   └─ 配信日（当日 = 動画公開日）
    ▼
[Phase 2] 既存メルマガ複製（テンプレ流用）
    │
    ▼
[Phase 3] デザイン編集 - 3箇所だけ差し替え
    │   ├─ サムネイル画像（ローカルファイル → アップロード）
    │   ├─ 本文中のタイトル（テキストブロック内）
    │   └─ 動画 URL（本文末尾リンク）
    ▼
[Phase 4] 配信先 - 現状リストのまま固定（要すり合わせ）
    │
    ▼
[Phase 5] 送信元 - 変更なし（株式会社 Walkers）
    │
    ▼
[Phase 6] 件名 - YouTube タイトル全文を差し込む
    │   ├─ 件名: お役立ち動画の紹介｜{タイトル}
    │   └─ プレヘッダー: 「{タイトル}」という動画を公開しました。
    ▼
[Phase 7] テストメール送信（任意）→ 表示確認
    │
    ▼
[Phase 8] 配信前最終確認（ユーザーに明示承認を取る）
    │
    ▼
[Phase 9] 配信設定 - 12:00 PM JST で予約
    │
    ▼
[Phase 10] 完了報告
```

## 実行フロー

### Phase 0: 前提条件チェック

**配信は不可逆操作**（241 件にメール送信）。**必ず先に環境を確認する**。

#### 0-1. Chrome 拡張の接続確認

`mcp__Claude_in_Chrome__list_connected_browsers` で接続済みブラウザを確認。

- 接続済み → そのまま Phase 1 へ
- 未接続 → ユーザーに「Chrome 拡張をインストールして接続してください」と案内 → 接続後に再開
- 拡張自体が利用不可 → Phase 2 以降は手動実行モード（後述「手動実行（代替）」節）に切り替え、ユーザーに通知

#### 0-2. Benchmark Email へのログイン状態確認

`mcp__Claude_in_Chrome__navigate` で `https://ui.benchmarkemail.com/` にアクセス → スクリーンショットでログイン済みか確認。

- ログイン済み（メール一覧が見える） → Phase 1 へ
- 未ログイン（ログイン画面が出る） → **ユーザーに「Benchmark Email にログインしてください」と依頼**。Codex はパスワード入力をしない（プロハイブされている）

### Phase 1: ヒアリング & 入力素材確定

#### ヒアリング原則

- **「足りない情報だけ」を、1メッセージ1質問で聞く**。標準値が決まっている項目は確認しない。
- 必須項目が未確定なら、その質問だけして待つ。
- 発話から自明に読み取れる項目（例: ユーザーが YouTube URL を貼った）は暫定確定して進める。

#### 必須項目

| 項目 | 区分 | 取得方法 | 確認質問 |
|------|------|---------|----------|
| **動画タイトル** | 必須 | YouTube URL から `mcp__youtube__getVideoDetails` で取得、または貼付。**【】等のプレフィックスを含む全文** をそのまま使う（例: `【対策まで解説】バイブコーディング（AI駆動開発）の失敗事例7選`） | 「対象動画の URL またはタイトルを教えてください」 |
| **動画 URL** | 必須 | 短縮形 `https://youtu.be/XXX` に正規化 | 上と同時 |
| **サムネイル画像** | 必須 | `https://i.ytimg.com/vi/{ID}/maxresdefault.jpg` を取得し、**ローカル一時ファイルに保存**（例: `/tmp/yt-thumbnail-{ID}.jpg`）。Phase 3-1 でアップロードに使う | 自動取得（失敗時のみ確認） |
| **配信日** | 必須 | **デフォルト = 動画公開日 当日に固定**（未確定事項に逃がす運用、§未確定参照）。ユーザーが別日を指定した場合のみ上書き | 質問しない（自明確定）。ユーザーから別日指定があれば受け取る |
| **複製元メルマガ** | 任意 | デフォルト「直近の送信済みメルマガ」（暫定値、未確定事項参照） | 指定があれば受け取る |

#### サムネイルのローカル保存（実装メモ）

```bash
curl -L -o /tmp/yt-thumbnail-{VIDEO_ID}.jpg "https://i.ytimg.com/vi/{VIDEO_ID}/maxresdefault.jpg"
# 失敗時 (404) は hqdefault.jpg にフォールバック
curl -L -o /tmp/yt-thumbnail-{VIDEO_ID}.jpg "https://i.ytimg.com/vi/{VIDEO_ID}/hqdefault.jpg"
```

このローカルファイルパスを Phase 3-1 のアップロードで使う。

#### 標準値（聞かない）

| 項目 | 標準値 |
|------|--------|
| 配信時刻 | **12:00 PM**（正午、JST） |
| タイムゾーン | Japan Standard (+0900) |
| 件名プレフィックス | `お役立ち動画の紹介｜` |
| プレヘッダーテンプレ | `「{タイトル}」という動画を公開しました。` |
| 送信元 | 株式会社 Walkers / `account@walker-s.co.jp` |
| 配信先 | テスト / 名刺リスト / HP のお役立ち情報希望リスト（現状のまま） |

### Phase 2: 既存メルマガを複製

ブラウザで Benchmark Email にアクセス。複製操作はブラウザ UI で行う（API でできるか未調査、§自動化実装の候補参照）。

#### Codex in Chrome MCP 経由（推奨）

1. `mcp__Claude_in_Chrome__navigate` で `https://ui.benchmarkemail.com/` を開く
2. 左サイドバー「**メール**」を `mcp__Claude_in_Chrome__find` で取得 → クリック
3. メール一覧から、雛形にしたいメルマガ（直近の送信済み）の右端「**…**」メニューを開く
4. 「**複製**」をクリック

#### 手動実行（代替）

1. Benchmark Email にログイン → 左サイドバー「メール」を開く
2. メール一覧から雛形メルマガの右端「…」メニュー → 「複製」

> 「まずこの既存のやつを複製しますと」（山口、[00:45]）

### Phase 3: デザイン編集 - 3箇所だけ差し替え

複製後にメール作成ウィザード（4カード構成: デザイン / 配信先 / 送信元 / 件名）が開く。**デザインカードの右上「編集」**をクリックしてエディタへ。

**変更するのは次の3箇所のみ**:

| # | 変更箇所 | 取得元 |
|---|---------|--------|
| 1 | サムネイル画像 | YouTube 動画の最高解像度サムネイル |
| 2 | 本文中のタイトル（「【○○】タイトル」） | YouTube 動画タイトル |
| 3 | 動画 URL（本文末尾「動画はこちら: https://youtu.be/XXX」） | YouTube 動画 URL（短縮形） |

#### 3-1. サムネイル差し替え

1. 本文プレビュー上のサムネイル画像を `mcp__Claude_in_Chrome__find` で取得 → クリック
2. 左ペインに「画像ブロック」設定が出る
3. 「**画像変更**」タブをクリック → ファイル input 要素が出る
4. `mcp__Claude_in_Chrome__file_upload` で **Phase 1-1 でローカル DL したサムネイルファイル**（例: `/tmp/yt-thumbnail-{ID}.jpg`）を input 要素にアップロード
5. アップロード完了後、本文プレビューでサムネが切り替わったことをスクリーンショットで確認

**注意**: Benchmark Email の画像アップロードは「ローカルファイル → file input」経由のみ。URL 直貼り入力は対応していない（Phase 0 で確認済みでないなら追加調査が必要）。

#### 3-2. 本文タイトル差し替え

1. 本文中の「【○○】タイトル」ブロックをクリック → 左ペインに「テキストブロック」設定
2. テキストを新しい YouTube タイトルに置換

#### 3-3. URL 差し替え

1. 本文末尾「**動画はこちら: https://youtu.be/...**」のリンク文字列を選択
2. 新しい YouTube URL に置換（**プレーンテキストとリンク先 URL の両方**を更新する）

#### 3-4. 保存

右下「**保存 & 次へ**」をクリック。

### Phase 4: 配信先

「**配信先**」カードで顧客リストを選択。

**現状の前提**: テスト / 名刺リスト / HP のお役立ち情報希望リスト（合計 241 件）。本マニュアルでは「現状のリスト構成のまま固定」を一旦の前提とする。

> 「これ配信先ちょっとまた変えなあかんな。…ここは俺が調整が必要」（山口、[02:00] 付近）

**最新版の配信先構成は山口とすり合わせ必須**（§未確定事項参照）。設定後「**保存**」（青ボタン）。

### Phase 5: 送信元 - 変更なし

「**送信元**」カードはそのまま通過。

| 項目 | 値 |
|------|-----|
| 会社名 | 株式会社 Walkers |
| 送信元メール | account@walker-s.co.jp |

> 「送信元は OK」（山口、[02:18]）

自動化でも触らない。

### Phase 6: 件名 - YouTube タイトルだけ差し替え

「**件名**」カードで「編集」をクリック。**「件名」と「プレヘッダー」の両方に、Phase 1 で確定した YouTube タイトル全文（【】等のプレフィックスを含む）をテンプレに差し込む**。

#### テンプレート（固定）

```
件名:           お役立ち動画の紹介｜{YouTube タイトル全文}
プレヘッダー:   「{YouTube タイトル全文}」という動画を公開しました。
```

`{YouTube タイトル全文}` は **Phase 1-1 で取得した動画タイトル**（角括弧プレフィックス込み）をそのまま使う。Phase 3-2 の本文タイトル差し替えと同じ文字列。

#### 例

入力: `【対策まで解説】バイブコーディング（AI駆動開発）の失敗事例7選`

| 項目 | 値 |
|------|-----|
| 件名 | `お役立ち動画の紹介｜【対策まで解説】バイブコーディング（AI駆動開発）の失敗事例7選` |
| プレヘッダー | `「【対策まで解説】バイブコーディング（AI駆動開発）の失敗事例7選」という動画を公開しました。` |

> 「件名も変えなあかん。基本的にお役立ち動画の紹介、紹介は同じで、あとはここタイトル変えるだけ」（山口、[02:24]）
> （※ 文字起こしでは「親父動画」と聞き取られているが、正しくは「お役立ち動画」）

### Phase 7: テストメール送信（任意）

配信前に表示崩れを確認したい場合のみ実施。スキップ可。

1. メール作成ウィザード上部または右ペインの「**テスト送信**」ボタンを `mcp__Claude_in_Chrome__find` で取得 → クリック
2. 送信先メールアドレス入力欄に、Walkers の確認用アドレス（デフォルト: `account@walker-s.co.jp`）を入力
3. 送信
4. ユーザーに「テストメールを `{宛先}` に送信した。受信ボックスで表示確認してください」と案内
5. ユーザーから OK が出るまで Phase 8 に進まない

スキップする場合: ユーザーから「テストはいい」「飛ばして」等の明示があれば直接 Phase 8 へ。

### Phase 8: 配信前最終確認（CRITICAL）

**配信は不可逆操作**（241 件にメール送信）。**配信ボタンを押す前に、必ずユーザーに最終承認を取る**。

ユーザーに以下のサマリを提示し、明示承認（「OK」「はい」「配信して」等）を待つ:

```
配信予約の最終確認をお願いします:

- 件名: お役立ち動画の紹介｜{タイトル}
- プレヘッダー: 「{タイトル}」という動画を公開しました。
- 配信日時: YYYY-MM-DD 12:00 PM (JST)
- 配信先: テスト / 名刺リスト / HP のお役立ち情報希望リスト（合計 約 241 件）
- 送信元: 株式会社 Walkers <account@walker-s.co.jp>
- サムネ・本文タイトル・動画 URL: 差し替え済み

このまま予約を確定してよろしいですか？
```

承認なしで Phase 9 に進まない。「修正」と言われたら該当 Phase に戻る。

### Phase 9: 配信設定 - 昼 12 時で予約

右上「**配信設定**」（青ボタン）→ モーダル「**配信スケジュールの設定**」が出る。

| 項目 | 値 |
|------|-----|
| 日付 | 配信したい日（**デフォルト: 動画公開日当日**、未確定事項参照） |
| **配信時間** | **12 : 00 PM**（正午） |
| タイムゾーン | Japan Standard (+0900) |

**重要**: モーダル冒頭に「正午にする場合は、"12:00 PM" と設定してください。」と明示されている。AM/PM の取り違えに注意。

「**配信設定**」（青ボタン）で予約確定。

### Phase 10: 完了報告

ユーザーに以下を報告:

- 配信予約済みメルマガの件名
- 配信日時（YYYY-MM-DD 12:00 PM JST）
- 配信先リスト
- Benchmark Email 上の編集 URL（取得できれば）

## チェックリスト（配信前に確認）

- [ ] 既存の最新メルマガを複製した
- [ ] サムネイル画像を新動画のものに差し替えた
- [ ] 本文中のタイトルを新動画タイトルに差し替えた
- [ ] 本文末尾の動画 URL を差し替えた（**テキストとリンク先の両方**）
- [ ] 配信先リストが意図通りになっている（テスト / 名刺リスト / HP のお役立ち情報希望リスト）
- [ ] 送信元が `株式会社 Walkers / account@walker-s.co.jp` のまま
- [ ] 件名 = `お役立ち動画の紹介｜{タイトル}` になっている
- [ ] プレヘッダー = `「{タイトル}」という動画を公開しました。` になっている
- [ ] 配信設定: 日付 = **動画公開日当日**（暫定固定、未確定）、時刻 = **12:00 PM**、タイムゾーン = Japan Standard
- [ ] テストメール送信で表示崩れがないか確認した（任意、Phase 7 でスキップ可）
- [ ] **Phase 8 でユーザーから配信予約の明示承認を得た**

## 自動化実装の候補（Phase 11: 将来）

現時点はブラウザ操作（Codex in Chrome / Playwright）で実装。将来的に以下を検討:

- **Benchmark Email REST API**（[公式ドキュメント](https://www.benchmarkemail.com/jp/help-FAQ/answer/API-Information)）
  - 複製・テンプレ更新・スケジュール送信が API でできるか要確認
- **YouTube → メルマガ完全自動化**
  - YouTube Data API ポーリング or PubSubHubbub で新規動画検知
  - 検知 → このスキルを起動 → 配信予約まで完了
- **Zapier / n8n**: ノーコード連携。Benchmark Email コネクタの提供範囲を確認

→ **後続タスクで Benchmark Email API の対応範囲を細谷側で調査する**。
