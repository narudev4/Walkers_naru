# 「〇〇 作り方」系記事リライト

トリガー: 「作り方記事」「〇〇 作り方」「howto-article」「アプリ作り方記事リライト」

## 概要

Walkersメディアにすでに公開されている **「〇〇 作り方」系（＝開発方法系）の記事** を、見本記事「マッチングアプリ 作り方 完全ガイド」と同じ構成にそろえ直すリライト量産スキル。

- 見本記事: <https://walker-s.co.jp/media/matchingapp-development/>
- 想定実行者: Codex（細谷の手元で実行）
- 元マニュアル: `output/manuals/howto-article/manual.md`（録画 2026-04-30 / 山口 鳳太レクチャー）

リライトの肝は **「手順10ステップの差し替え」＋「STEP1〜5への実演動画の埋め込み」** の2点。残りはタイトル調整と AI による言い回し変換でコピペ判定を避ける作業。

## 戦略的意図

| なぜ | 内容 |
|------|------|
| AI時代の差別化 | テキストだけの記事は AI で量産できる。**実演動画が入っている記事**こそ Google・読者から選ばれる |
| AI記事のリスク回避 | 同一文言は Google から「他記事と同じ」と判定されてマイナス評価。**言い回しを変える**ことでオリジナリティを保つ |
| 既存記事のテコ入れ | 既存「作り方」シリーズが見本記事比で構成省略されている。**手順10ステップ＋実演動画を流し込んで底上げ** |

> 「結局AI時代とかやと、実演みたいなのがすごい大事になってくるのよな」（山口・[01:22]）
> 「Google側からすると、完全に同じだったら『こいつこの記事と全く同じこと言ってるな』ってなって、マイナス評価食らったりする」（山口・[03:09]）

## ツール構成

| 役割 | ツール |
|------|--------|
| 見本記事の参照 | Walkersメディア（matchingapp-development） |
| 元記事の管理／タスク台帳 | Notion（"優先施策" ビュー、ステータス管理） |
| 連絡・依頼受領 | Google Chat（依頼スレッド「お願い：作り方系の記事リライト」） |
| 文章書き換え | AI（ChatGPT 等／言い回し変換） |
| 実演動画 | 画面録画（ローカル）→ 記事に埋め込み |

## ワークフロー全体像

```
[Phase 1] タスク受領（Google Chat 依頼スレッド → Notion 進行中に変更）
        ↓
[Phase 2] 差分把握（見本記事と元記事を見比べる：タイトル／手順10ステップ／実演動画の3点）
        ↓
[Phase 3] タイトル差し替え（必要なら見本フォーマットに揃える）
        ↓
[Phase 4] 「手順10ステップ」セクション挿入（見本から構成ごとコピー）
        ↓
[Phase 5] AI 言い回し変換（自記事テーマに合わせて文言を置換、コピペ判定回避）
        ↓
[Phase 6] 実演録画（STEP1〜5 のみ画面録画、6以降は動画なし）
        ↓
[Phase 7] 動画埋め込み（見本と同位置に貼る）
        ↓
[Phase 8] Notion 更新・提出（下書きで貯めて一括提出 → 完了）
```

## 実行フロー

### Phase 1: タスク受領 ― Google Chat と Notion で対象記事を特定

- Google Chat の依頼スレッド「お願い：作り方系の記事リライト」を開く
- そこに記載された **対象記事リスト** だけが今回の作業対象
- **「全部やる」ではない**。Walkersメディアの "作り方" 検索に出る全記事を対象にしない
- Notion の **"優先施策" ビュー** から該当タスクを開き、ステータスを **「進行中」** に変更
- 作業順は **山口さんが頼んでいる順** を守る（並行で勝手に並べ替えない）

> 「これ全部というよりかは、さっきチャットで送った内容だけやってもらう感じで」（[00:36]）
> 「順番は俺が頼んでる順でお願い」（[05:14]）

### Phase 2: 差分把握 ― 見本記事と元記事を見比べる

見本記事 <https://walker-s.co.jp/media/matchingapp-development/> と元記事を並べて、**変更が必要な箇所3つ**を特定する。

| 差分ポイント | 内容 |
|------|------|
| 1. タイトル | 「〇〇 作り方 完全ガイド｜AIを用いた開発方法まで解説」のような形 |
| 2. 手順10ステップ セクション | 既存記事だと省略されていることが多い。ここがメインの差分 |
| 3. STEP1〜5 直下の実演動画 | 6以降は動画なし（見本記事もそうなっている） |

> 「主にどこが変わってるかっていうと、まずタイトル変わってます」（[00:45]）
> 「メインで変わってるのが、このマッチングアプリ開発の手順10ステップってところ」（[00:51]）

### Phase 3: タイトル差し替え

「タイトル差し替え」とは、**見本記事のタイトル形式にそろえる**こと。

- 見本のフレーム（「〇〇 作り方 完全ガイド｜AIを用いた開発方法まで解説」）を踏襲
- 元記事のテーマ語（マッチングアプリ／チャットアプリ／フリマアプリ等）を **そのまま自記事の主題語に置換**
- **タイトル変更が不要な記事もある** ので、依頼スレッドを必ず確認してから判断
- 既存記事のタイトルがすでに見本フォーマットに沿っている場合はそのまま

### Phase 4: 「手順10ステップ」セクション挿入

「10ステップ手順挿入」とは、**見本記事の手順表＋各 STEP 解説を構成ごとコピーして元記事に貼ること**。手順の中身（10項目それぞれ）は **見本のままでOK・書き換え不要**。書き換えるのは Phase 5 で言い回しのみ。

- 既存記事に「流れ」見出しがあれば **「手順」見出しに差し替え**（見出し文言を変える）
- 見本記事の手順表＋各 STEP 解説をそのまま貼る
- **手順自体（10ステップの中身）は書き換えない**

> 「手順自体はもうこの手順でOK。あとは色を付け加えるって話」（山口・[03:25]）
> 「ここ手順に変えて、この手順のところを修正していくだけ」（[02:39]）

#### 10ステップの全体像（見本記事より）

| # | ステップ |
|---|---------|
| 1 | 企画立案 |
| 2 | 要件定義 |
| 3 | 設計（UI／UX 設計、画面のデザインを詳細に決める） |
| 4 | 内部設計（システム構成を決める） |
| 5 | 開発 |
| 6 | テスト（エラーの修正を行う） |
| 7 | リリース準備（App Store などのストア申請を行う） |
| 8 | リリース（ユーザーへアプリ提供を開始する） |
| 9 | 保守・運用（ユーザーの声をもとにバグ修正や機能追加を行う） |
| 10 | （見本記事の表記に従う） |

#### 章タイトル例（見本記事より）

- 「【手順①】企画立案：どのようなアプリを作りたいのか明確にする」
- 「【手順②】開発会社の選定：相見積もりを行い最適な会社を見つける」
- 「【手順⑦】リリース準備：App Storeなどのストア申請を行う」
- 「【手順⑧】リリース：ユーザーへアプリ提供を開始する」
- 「【手順⑨】保守・運用：ユーザーの声をもとにバグ修正や機能追加を行う」

### Phase 5: AI 言い回し変換 ― 自記事テーマに置換

「AI言い回し変換」とは、**見本記事のマッチングアプリ前提の文言を、自記事のテーマに合わせて AI に書き換えさせる工程**。コピペ判定（Google からのマイナス評価）回避が目的。

- 手順構造（10ステップの並び・各 STEP の章立て）は変えない
- 言い回しと固有名詞だけ自記事テーマに調整
- AI（ChatGPT など）に下記プロンプトを投げる

#### プロンプトテンプレート

```
以下の文章の「マッチングアプリ」の部分を「〇〇アプリ」に置き換えてください。
あわせて言い回しを少しだけ変えて、まったく同じ文章にならないようにしてください。
意味と手順は変えないでください。

---
（見本記事から該当セクションを貼る）
---
```

> 「これAIでやるというよりも、『この内容を言い回しを変えてください』ってAIに送るだけでOK」（山口・[04:22]）
> 「この文言を、ちょっとアプリバージョンに置き換えて、っていう」（[04:34]）

ポイント:
- **手順構造は変えない**
- **言い回しと固有名詞だけ調整**
- **STEP6 以降も文言は全部修正する**（動画はないが、文言の言い換えだけは入れる）

### Phase 6: 実演録画 ― STEP1〜5 のみ画面録画

「実演録画」とは、**見本記事で動画が貼られている STEP1〜5 と同じ操作を、自記事のテーマで画面録画して差し替える工程**。

- 見本記事を見て、STEP1〜5 の **どんな操作を録画しているか** を確認する
- 自記事のテーマに合わせて **同じような操作を画面録画**
  - 例: マッチングアプリ → AI へのヒアリング画面
  - 例: チャットアプリ → チャットアプリ前提でのヒアリング画面
- **STEP6 以降は実演動画なし**（見本記事もそうなっている）

> 「結局機種（記事）とかってこういう実演とかが鍵になるから、めんどくさいけどやる」（[02:14]）
> 「実演動画は6個以降はついてないけど、この文言自体は全部修正する」（[04:58]）

#### 録画範囲のヒント

- 1動画 1〜2分程度（見本記事は約 2:05）
- 操作の手元を見せる（カーソル動き＋画面遷移）
- ナレーション無しでも成立するように、UI を順に追っていく

### Phase 7: 動画埋め込み ― STEP 直下に貼る

- 見本記事と **同じ位置**（各 STEP の解説直下、「※下記のように AI にヒアリングしてもらうのがおすすめです」のあと）に動画を貼る
- 見本記事の埋め込み方を **そのまま真似る**（プレーヤーサイズ、配置）

### Phase 8: Notion 更新・提出

- 1記事終わるたびに、いったん **下書き保存**
- リスト全部終わってから **一括で山口さんに提出**（個別に都度送らない）
- 提出後、Notion の対象タスクを **「完了」** に更新
- 提出物は記事だけでなく実演動画（YouTube 化想定）も含む。「まずYouTubeを貯めておいて、あとはノートやね」（[05:27]）の指示どおり、動画は YouTube で先行ストックする運用

1. 作業着手前に Google Chat の依頼スレッドを必ず開いて対象リストを取得する
2. リスト外の記事に手を出さない（「全部やる」ではない）
3. 作業順は依頼スレッド記載の順（山口さんが頼んでいる順）
