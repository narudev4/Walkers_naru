## 2026-05-15: 「競争優位性は秒でパクられる」記事

元素材: https://note.com/app_dev_lab/n/n634db073e3c8

### FB の届き方
鳳汰から修正版が直接送られてきた（chat にて貼付）。

### 私の draft → 鳳汰修正版 の差分

**1. タイトルの冠言削除と助数詞**
- 「Claude Codeで誰でもアプリが作れる時代、競争優位性は『秒でパクられる』。生き残る会社の3戦略」→「Claude Codeによって競争優位性は『秒でパクられる』。生き残る会社の3つの戦略」
- 前半の「〜誰でもアプリが作れる時代、」を削除（リード冒頭で同じ説明をしているので重複）
- 「3戦略」→「3つの戦略」（助数詞「つの」を入れる）

**2. H2「Claude Code 時代に〜」→「Claude Codeによって〜」**
- 「〜時代に競争優位性は秒で消えるのか」→「〜によって競争優位性は秒で消えるのか」
- 抽象的な「時代」より、Claude Code の具体作用「によって」の方が因果が明確

**3. 「ツール固有」と「AIカテゴリ」の使い分け（重要）**
私のdraftは「Claude Code 時代の市場変化」「Claude Code 自身の手で起きる」のように、市場/外部環境の話まで Claude Code で書いていた。鳳汰修正版では：
- H3「技術と市場の変化が "Claude Code 自身" の手で起きる」→「AIによって技術と市場の大変革が起きる」
- 「これが Claude Code 時代の市場変化の本質だ」→「これがAI時代の市場変化の本質だ」
- 「原則は Claude Code 時代の個人や小チームの開発でも〜」→「原則はAI時代の個人や小チームの開発でも〜」
- 例示の「Google で検索 → ChatGPTで〜」→「Google で検索 → AIで〜」

→ **ツール（Claude Code）で「作る・模倣する」具体行為は Claude Code、市場変化やカテゴリ置換のような外部環境変化は AI** と書き分ける。混在させない。

**4. 箇条書きの「- 」記号を使わずプレーン段落で並べる**
- 私: `- Google で検索 → ...` のリスト
- 鳳汰: 「- 」を外してプレーン段落で4行並べる

→ 過去FBの「装飾の点記号は冗長になりがち」と一貫。リストでさえ点記号を嫌う。

**5. 戦略③のデファクト例から ChatGPT を削除**
- 私:「『フリマアプリと言えばメルカリ』『検索と言えば Google』『AIエンジンと言ったら ChatGPT』」
- 鳳汰:「『フリマアプリと言えばメルカリ』『検索と言えば Google』」（ChatGPT 例削除）

→ 推測: ネットワーク効果でデファクトを取った例として ChatGPT は時期尚早 or 議論のある対象なので外したか。あるいは「AIの市場変化」を語った直後に「AIエンジンと言ったら ChatGPT」が出ると論旨が混線するため。判断軸としては弱いので**様子見**。

### 抽出した判断軸（yamaguchi-style.md に反映予定）
- ツール固有の話（Claude Code で作る・模倣する）と AI カテゴリの話（市場変化・カテゴリ置換）を書き分ける。市場/外部環境変化は AI、開発行為は Claude Code
- リスト箇条書きの「- 」記号は使わない。プレーン段落で改行して並べる
- タイトルに「〜時代」の冠言を入れない。リードで同じ説明を書いている場合は重複なので削除。具体作用「〜によって」の方を選ぶ
- 「3戦略」のような体言止めの数字+カテゴリ語より「3つの戦略」と助数詞を入れる方が好まれる

### 追加FB（Phase 4 後・naru から、鳳汰確認済み）: 強調装飾の `"..."` 撤去

naru から「`"` は削除します。多分ルールにも書いてる（鳳汰確認済み）」との指示。私（Claude）は draft / 最終版で強調装飾としてダブルクォート囲みを4箇所使っていた:
