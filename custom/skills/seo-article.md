# SEO記事制作

トリガー: 「SEO記事」「SEO記事書いて」「SEO記事作って」

## 概要
キーワード設計 → 競合調査 → 構成案 → 本文執筆 → メタ情報生成まで、SEOを意識した記事を一貫して制作する。

## 実行フロー

### Phase 1: ヒアリング
以下をユーザーに確認する（未指定の項目のみ聞く）:

| 項目 | 必須 | 例 |
|------|------|-----|
| メインキーワード | ✅ | 「DX 中小企業」 |
| ターゲット読者 | ✅ | 「DX推進担当者・経営者」 |
| 目標文字数 | - | 3000〜5000字（デフォルト） |
| 記事の目的 | - | 認知獲得 / リード獲得 / 購買促進 |
| サイト・媒体名 | - | 自社ブログ、note など |
| トーン | - | 専門的・丁寧（デフォルト） |

### Phase 2: キーワード設計
Web検索でメインKWの関連情報を収集し、以下を設計する:

- **メインKW**: ユーザー指定のキーワード
- **サブKW**: 共起語・関連語を5〜10個列挙
- **検索意図分析**: このKWで検索するユーザーが「何を知りたいか」を整理
- **競合タイトル調査**: 上位表示されている記事のタイトルを確認し、傾向を把握

### Phase 3: 構成案の作成・確認
SEO最適化された記事構成を作成し、ユーザーに確認を取る。

**構成案フォーマット:**
```
# [SEOタイトル案（32文字以内）]

## リード文の方針
[検索意図に応えるリード文の方向性]

## H2: [大見出し1]
- H3: [小見出し1-1]
- H3: [小見出し1-2]

## H2: [大見出し2]
...

## まとめ
[CTAの方針]

---
メタディスクリプション案（120文字以内）:
[内容]
```

### Phase 4: 本文執筆
構成案が承認されたら本文を執筆する。

**執筆ルール:**
- リード文でメインKWを自然に含める
- H2/H3 見出しにサブKWを適切に配置
- 1000文字あたり2〜3回メインKWが出現する密度を目安にする
- 箇条書き・表・数字を活用し、スキャナビリティを高める
- 根拠のある情報には出典元を明示する
- **出典はH3見出しセクションの一番下にまとめて配置する**（本文中にインラインで散らさない）。1つのH3セクション内で複数の出典がある場合は、セクション末尾に `»出典：` を並べて記載する
  - 書式: `»出典：[サイト名](URL)`
  - 配置位置: H3セクションの最終コンテンツの直後、次の見出しの直前
- E-E-A-T（経験・専門性・権威性・信頼性）を意識した記述にする
- 結論を先に書く「逆ピラミッド構造」を意識する

### Phase 5: メタ情報・仕上げ
```
【SEOタイトル】（32文字以内）
[タイトル]

【メタディスクリプション】（120文字以内）
[内容]

【スラッグ案】（英数字・ハイフン）
[slug-example]

【内部リンク候補】
- [関連記事テーマ1]
- [関連記事テーマ2]

【SNS拡散用リード文】（X/Twitter向け、140字以内）
[内容]
```

## 出力先
`output/articles/YYYY-MM-DD_[メインKW].md`

### Phase 6: 保存・ファイルを開く
記事の執筆が完了したら、以下を必ず実行する:
1. `output/articles/YYYY-MM-DD_[メインKW].md` に保存する
2. `open output/articles/YYYY-MM-DD_[メインKW].md` でファイルをブラウザ/エディタで開く
3. ユーザーに「開きました。確認してください」と伝える

## 文体・表記ルール

### AIっぽい表現の禁止
- 「---」（水平線・区切り線）を本文中に使わない → セクション間の区切りは見出し（## / ###）だけで表現する
- 「——」（emダッシュ）を使わない → 括弧（）で補足する
  - ❌ `72,000件の個人情報が丸見えに —— Tea社データ漏洩事件`
  - ✅ `72,000件の個人情報が丸見えに（Tea社データ漏洩事件）`
- **出典の書式は `»出典：` を使う**（`（出典: ）` は括弧＋半角コロンでAIっぽいため禁止）
  - ❌ `（出典: [サイト名](URL)）`
  - ✅ `»出典：[サイト名](URL)`

### 見出しの書式ルール
- **番号付き見出しには【】をつける**
  - ❌ `失敗事例①`、`対策①`、`原因①`
  - ✅ `【失敗事例①】`、`【対策①】`、`【原因①】`
- **見出し内の小見出しは #### を使う**（太字 `**` ではなく h4 タグ）
  - ❌ `**何が起きたか:**`
  - ✅ `#### 何が起きたか`
- **見出しの数と内容を一致させる**（「3つの原因」と書いたら中身も3つにする）

### 呼称ルール
- 記事の書き手を指す場合は「著者」ではなく「**筆者**」を使う
- 「教訓」「意見」セクションには「（筆者の意見）」を明記する
  - ✅ `#### この失敗から学べる教訓（筆者の意見）`

### 特定ターゲット向け表現の回避
- 小見出しでターゲットを限定しすぎない
  - ❌ `非エンジニアへのポイント`（読者を限定しすぎる）
  - ✅ `この失敗から学べる教訓（筆者の意見）`（汎用的）
