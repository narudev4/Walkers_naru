# note転載

トリガー: 「note転載」「noteに載せて」「noteに転載」

## 概要
自社メディア記事をnote.comに転載する。重複コンテンツにならないよう文章をリライトし、note向けに最適化して投稿する。

## 戦略的意図
- 自社ドメインの品質を維持しつつ、noteプラットフォームからの追加集客を獲得
- 低品質コンテンツを自社ドメインに載せるリスクを回避
- 複数プラットフォームでの露出によりPV最大化

## 実行フロー

### Phase 1: 記事選択
ユーザーに転載する記事を確認する。

**記事の指定方法:**
- ファイルパスを直接指定（例: `output/articles/2026-02-26_AI駆動開発とは.md`）
- テーマやキーワードで検索（`output/articles/` 配下をGlobで探索）
- 「最新の記事」など相対指定

記事が見つかったら内容を読み込み、ユーザーに確認する。

### Phase 2: note向けリライト
元記事を以下のルールでリライトする。**元記事のSEO価値を損なわず、かつ重複コンテンツにならない**ことが目標。

#### リライトルール

1. **タイトル変更**
   - 元記事とは異なるタイトルに変更
   - note読者に刺さるカジュアルなトーンに（疑問形・会話調OK）
   - 例: 「AI駆動開発の全貌」→「AI駆動開発って実際どうなの？現場のリアルをまとめてみた」

2. **リード文を完全書き換え**
   - note特有の「個人の語り」トーンに変更
   - 「〜だと思います」「〜してみました」のような一人称視点
   - 自社の経験や視点を織り交ぜる

3. **本文のリライト（30%以上変更）**
   - セクション順序の入れ替え
   - 見出し文言の変更
   - 表現の言い換え（専門的→平易に）
   - 個人的な見解・コメントの追加
   - noteでは表(テーブル)が使えないため、箇条書きに変換
   - 具体例やエピソードの追加・差し替え

4. **note向け最適化**
   - 冒頭に「この記事で分かること」を3行程度で追加
   - 末尾にCTA（自社サイト誘導 or フォロー促進）を追加
   - ハッシュタグを5〜10個提案
   - 目を引く見出し構成（noteはH2/H3のみ推奨）
   - 画像alt等のメタは除去（noteでは不要）

5. **canonical / 出典の明記**
   - 末尾に「この記事は [自社メディア名] の記事をベースに、note向けにリライトしたものです」と明記
   - 元記事URLがあれば記載（自社サイトへの誘導にもなる）

### Phase 3: リライト記事の確認
リライトした記事をユーザーに提示し、以下を確認する:
- タイトルの方向性
- トーン・文体
- 追加・削除したい内容
- ハッシュタグ

### Phase 4: 保存・投稿

#### 4a: ファイル保存（必須）
`output/articles/note/` 配下にMarkdownで保存する。

**ファイル名規則:** `YYYY-MM-DD_note_[テーマ].md`

**YAMLフロントマター:**
```yaml
---
title: [noteタイトル]
original_file: [元記事のパス]
tags: [ハッシュタグ1, ハッシュタグ2, ...]
status: draft | published
date: YYYY-MM-DD
platform: note
---
```

#### 4b: note投稿（MCP連携がある場合）
`note-post-mcp` がインストールされている場合:
1. 保存したMarkdownファイルを指定して投稿ツールを呼び出す
2. まず「下書き保存」で投稿し、ユーザーにnote上で最終確認を促す
3. ユーザーの確認後、公開する

MCP連携がない場合:
1. 「Markdownファイルを保存しました」と報告
2. 「note.comのエディタに貼り付けてください」と案内
3. note-post-mcpの導入を提案する

#### 4c: Playwright経由の投稿（MCPがない場合の代替）
Playwright MCPが利用可能な場合、ブラウザ操作で直接投稿も可能:
1. note.comにナビゲート
2. ログイン状態を確認
3. 新規記事作成画面を開く
4. タイトル・本文を入力
5. ハッシュタグを設定
6. 下書き保存
※ この方法はユーザーの明示的な許可を得てから実行する

## 出力先
`output/articles/note/YYYY-MM-DD_note_[テーマ].md`

## 出力テンプレート

```markdown
---
title: [noteタイトル]
original_file: [元記事パス]
tags: [tag1, tag2, tag3]
status: draft
date: YYYY-MM-DD
platform: note
---

# [タイトル]

> **この記事で分かること**
> - [ポイント1]
> - [ポイント2]
> - [ポイント3]

## [リード文の見出し（任意）]
[一人称視点のリード文]

## [H2見出し1]
[リライトされた本文]

## [H2見出し2]
[リライトされた本文]

...

## まとめ
[要点 + CTA]

---

*この記事は [Walkersメディア](元記事URL) の記事をベースに、note向けにリライトしたものです。*

*[Walkersのnoteアカウント]をフォローすると、最新記事の通知が届きます。*
```

## note-post-mcp セットアップガイド

note投稿を自動化したい場合、以下の手順でMCPサーバーを導入する:

```bash
# .mcp.json に追加
{
  "mcpServers": {
    "note-post": {
      "command": "npx",
      "args": ["@gonuts555/note-post-mcp@latest"],
      "env": {}
    }
  }
}
```

初回実行時にブラウザが開くので、noteにログインする。認証状態は `~/.note-state.json` に保存される。
