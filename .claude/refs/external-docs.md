# 対外文書ルール（提案書・議事録・メール文面）

CLAUDE.md の外部参照ルールから飛んでくるファイル。対外文書を書く前に全文を適用すること。

## 帰属の明示（メタ認知チェック）

書く前に「これは誰の発言・判断か」を自問する。答えられない断定文は書かない。

- 先方からのヒアリング内容 → 「〜様には〜とお伺いしました」
- Walkers 側の提案・判断 → 「弊社では〜をご提案します」
- 「貴社は〜です」のような、AI が勝手に決めつけた断定は禁止

## 構造

- 機能・作業内容を並べる前に、提案の軸（構造）を最初にシンプルに言い切る
- 議事録の情報を網羅しない。提案の軸に沿った情報だけを厳選する（軸がブレる最大の原因は、関係のないコンテキストの盛り込み）

## 文末は句点「。」（CRITICAL）

文になっている限り、**すべての文末に「。」を付ける**。naru から繰り返し指摘されている項目。

- 対象: 本文・箇条書きの各項目・表のセル内・見出し直下のリード文・図表キャプション
- 箇条書きが最頻出の抜け漏れ箇所。「〜します」「〜です」「〜ます」で終わる項目に句点が無い状態を放置しない
- 体言止め（「月額300,000円」「未着手」等）と単語だけの項目は句点不要。文かどうかで判断する
- **naru に見せるチャット応答・報告文にも適用する**（対外文書だけのルールではない）
- 書き終えたら、箇条書き行と表セルを machine 的に見直して抜けを潰してから提出する

## 言葉選び

- 比喩的な標語・キャッチーな言い回し（「組織のAI知能」「精鋭部隊」等）は避け、直接的で平易な言葉を使う。凝った表現は分かりやすさより AI っぽさを強めるだけ
- 相手が使った言葉（「事業継承」「知識武装」等）でも、そのまま見出しや標語に転用しない。文脈が変わると伝わらない
- 情報の正確性より読み手の平易さを優先する。「11社のディーラー」「PSIデータ」のような社内的に正確な表現は、最初から「ディーラー」「データ」に平易化する。細かい数字・略称を出さなくても伝わる
