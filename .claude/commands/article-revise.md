# 記事修正（コメント反映）

トリガー: 記事本文にHTMLコメント（`<!-- ... -->`）が含まれた状態で送られてきたとき

## 概要
ユーザーが記事の本文中に `<!-- コメント -->` 形式でフィードバックを埋め込んで送ってくる。
そのコメントの指示に従って記事を修正し、修正後の記事を保存・表示する。

## 実行フロー

### Step 1: コメント抽出
記事本文から `<!-- ... -->` 形式のコメントをすべて抽出し、一覧化する。

**抽出フォーマット:**
```
【コメント一覧】
1. (位置: リード文の直後) 「---」はAIっぽすぎるからすべて削除。
2. (位置: H3「なぜAIだけ〜」の直後) 「なぜダメなのか」ではなく「なぜ良いのか」にして。
...
```

### Step 2: 修正方針の報告
コメント一覧をユーザーに見せ、修正方針を簡潔に報告する。
ユーザーの承認を待たず、そのまま修正に進む（70点で上げるスタイル）。

### Step 3: 記事修正
各コメントの指示に従って記事を修正する。

**修正ルール:**
- コメントの指示をそのまま反映する（勝手に解釈を広げない）
- 修正箇所の前後の文脈・トーンと整合性を取る
- `seo-article.md` の文体・表記ルールに従う（ですます調、---禁止、emダッシュ禁止など）
- 修正完了後、すべての `<!-- ... -->` コメントを本文から削除する
- 修正によって見出し構成が変わる場合は、前後のセクションとの整合性も確認する

### Step 4: 保存・表示
- 元のファイルパスに上書き保存する（ファイルパスはfront matterや既存ファイルから特定）
- ファイルパスが不明な場合は `output/articles/` 配下に保存する
- `open` コマンドでファイルを開いてユーザーに確認してもらう

### Step 5: 修正サマリー
修正内容を簡潔に報告する。

**報告フォーマット:**
```
【修正完了】
1. ✅ (コメント内容の要約) → (どう修正したか)
2. ✅ (コメント内容の要約) → (どう修正したか)
...
```

## 注意事項
- コメントがない場合は「コメントが見つかりません」と伝えて終了
- コメントの意図が不明確な場合のみユーザーに確認する
- 記事全体の品質（thinking-dna基準）も併せてチェックし、明らかな問題があれば修正サマリーで指摘する
