# 毎朝の定例業務（自動実行対応）

トリガー: launchdによる毎朝03:00自動実行 / 「朝の定例」「モーニングルーティン」

## 概要
毎朝自動で実行される定例業務。5部門の部長AIが並列で動き、朝起きたときには全て完了している状態を目指す。

## 実行フロー

### Phase 1: 情報収集（全部門並列）

以下を **Taskツールで5つ並列実行** する:

```
Task 1 [コンテンツ部長]:
  - X/Twitterの業界トレンドを確認
  - 今日のX投稿の草案を1本作成
  - output/articles/YYYY-MM-DD_x-morning.md に保存

Task 2 [営業部長]:
  - 今日のMTGスケジュールをGoogle Calendarから取得
  - 各MTGの簡易ブリーフィングを作成
  - 未返信の重要メールを3件まで抽出

Task 3 [BO部長]:
  - 直近のKPI（GA4 / GSC / Clarity）をスナップショット取得
  - 異常値があればアラート作成
  - 昨日と比較して大きな変化があれば報告

Task 4 [戦略部長]:
  - 業界ニュースを3件ピックアップ
  - 競合の動き（新サービス・プレスリリース等）があれば報告

Task 5 [管理部長]:
  - GitHub Issueの未完了タスクを確認
  - 期限切れ・期限間近のタスクをリストアップ
```

### Phase 2: 統合レポート作成

5部門の結果を統合し、以下のフォーマットで朝のブリーフィングを作成する:

```markdown
# 朝のブリーフィング: YYYY-MM-DD（曜日）

## 今日のスケジュール
| 時間 | 内容 | 準備状況 |
|------|------|---------|
| HH:MM | {MTG/タスク} | {ブリーフィング済/未準備} |

## 要対応（今日中）
1. {重要度順にリスト}
2.
3.

## KPIスナップショット
- PV: {数値}（前日比 {+/-}%）
- GSCクリック: {数値}
- 異常値: {あれば記載}

## 業界トピック
- {ニュース1}
- {ニュース2}

## X投稿草案
> {投稿文}

---
自動生成: YYYY-MM-DD 03:00
```

### Phase 3: 保存

1. ブリーフィングを `output/digest/YYYY-MM-DD_morning.md` に保存
2. DAILY.mdの当日セクションに概要を追記
3. 重要なアラートがあれば `00_context/memories/facts.md` にも記録

## エラーハンドリング
- 外部API（Gmail, Calendar等）が応答しない場合 → その部分をスキップして「取得失敗」と記載
- 全体の実行時間が5分を超える場合 → 未完了のタスクを記載して終了
- ネットワークエラー → ローカルデータのみで可能な範囲のレポートを生成

## 出力先
- メインレポート: `output/digest/YYYY-MM-DD_morning.md`
- X投稿草案: `output/articles/YYYY-MM-DD_x-morning.md`
- DAILY.md: 当日セクションに追記
