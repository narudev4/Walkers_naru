# 記事執筆チーム起動

トリガー: 「記事執筆チーム」

## 概要
6エージェントが5フェーズで連携して高品質な記事を執筆する。

## 利用するツール

| フェーズ | ツール | 用途 |
|---------|--------|------|
| リサーチ | `WebSearch` | テーマに関する最新情報・データを収集 |
| リサーチ | `WebFetch` | 参考記事の詳細コンテンツを取得 |
| リサーチ | `Glob` + `Grep` | ローカルの関連資料（`06_learning/`, `output/articles/`）を検索 |
| リサーチ | `google_drive_search` + `google_docs_get` | Google Drive上の関連ドキュメントを検索・取得 |
| 保存 | `Write` ツール | 完成原稿を `output/articles/` に保存 |

## エージェント構成

| エージェント | 役割 |
|:-----------|:-----|
| リサーチャーA | テーゼ・アンチテーゼ・ジンテーゼの論考分析 |
| リサーチャーB | 技術・産業の事実ベースの調査 |
| リサーチャーC | 批判的思考（Devil's Advocate） |
| 構成エージェント | 3本のリサーチを統合し、記事の構成案を設計 |
| 編集長 | 4軸（洞察の深さ・論理の明快さ・So What?の強さ・構成の完成度）でレビュー |
| ライター | 編集長のフィードバックを反映した原稿を執筆 |

## 実行フロー

1. **ヒアリング**: テーマ・ターゲット読者・文字数・トーンを確認
2. **リサーチ（並列）**: リサーチャーA/B/Cが同時にリサーチ実行
   - 各リサーチャーは `WebSearch` で複数クエリ実行、`WebFetch` で有用な記事の詳細を取得
   - ローカル資料は `Glob` + `Grep` で検索、Google Driveは `google_drive_search` で検索
3. **構成設計**: 構成エージェントが3本のリサーチを統合し構成案を作成
4. **初回レビュー**: 編集長が構成案をレビュー
5. **執筆**: ライターが原稿を執筆
6. **最終レビュー**: 編集長が最終レビュー → 修正指示 → 完成

## 出力先
`output/articles/YYYY-MM-DD_[テーマ].md`
