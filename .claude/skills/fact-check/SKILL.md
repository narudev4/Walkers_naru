# ファクトチェック

トリガー: 「ファクトチェック」「事実確認」「fact-check」「裏取り」

## 入力
$ARGUMENTS

## 概要
出力に含まれる客観的事実（固有名詞・数値・日付・連絡先・制度情報等）を一次ソースで照合し、事実と相違がないことを保証する。AIが生成した情報もユーザーが提供した情報も等しく検証する。

## 利用ツール

| ツール | 用途 |
|--------|------|
| Read (built-in) | `00_context/profile.md`, `memories/` 参照 |
| Glob (built-in) | `03_projects/` 内ドキュメント検索 |
| `google_drive_search` / `google_docs_get` | Google Drive/Docs内ドキュメント照合 |
| `API-post-search` (Notion) | Notion案件情報照合 |
| `gmail_search_messages` / `gmail_read_message` | メール照合 |
| `gcal_list_events` | カレンダー日程照合 |
| WebSearch | 外部事実の裏取り（補助金制度・企業情報等） |

## 実行手順

### Phase 1: チェック対象の特定

$ARGUMENTS が指定されていれば、そのテキストを対象とする。
指定がなければ、直前のスキル出力・回答を対象とする。

対象テキストから**検証可能な事実主張**をすべて抽出する:
- 固有名詞（会社名・人名・サービス名・プロダクト名）
- 連絡先情報（メールアドレス・電話番号・住所・URL）
- 日付・日時（MTG日程・納期・設立日・契約日・申請期限）
- 数値（金額・見積額・補助率・上限額・統計データ）
- 役職・肩書き（代表取締役・担当者の役職・部署名）
- ID・コード（Google DocsのID・Notion ID等）
- 制度・法規情報（補助金名・補助率・法律名・条文番号・制度要件）

> **対象外**: 主観的記述・定性的評価・戦略提案の妥当性

### Phase 2: ソース照合（並列実行）

抽出した事実主張を以下の優先順で照合する。**可能な限り並列**で実行:

1. **ローカルファイル**（最優先）
   - `00_context/profile.md` — 自社情報（会社名・代表者・住所・設立日等）
   - `memories/` — クライアント情報・案件メモ・過去の意思決定
   - `03_projects/{案件名}/` — 案件固有の資料・議事録

2. **Google Drive / Docs**
   - `google_drive_search(query="{キーワード}")` でドキュメント検索
   - `google_docs_get(document_id="{ID}")` で本文取得・照合

3. **Notion**
   - `API-post-search(query="{キーワード}")` で案件情報照合

4. **Gmail**
   - `gmail_search_messages(q="{キーワード}")` でメール照合
   - 特に日付・約束・合意事項の裏取りに有効

5. **Google Calendar**
   - `gcal_list_events(q="{キーワード}")` で日程照合

6. **Web検索**（外部事実のみ）
   - 補助金制度・企業の公開情報・統計データ等
   - 公式サイト・官公庁サイトを優先

### Phase 3: 結果分類・報告

照合結果を以下のフォーマットで報告する:

```
## ファクトチェック結果

### ❌ 不一致（要修正）
| # | 該当箇所 | 記載値 | 正しい値 | ソース |
|---|---------|--------|---------|--------|
| 1 | {箇所} | {記載値} | {正しい値} | {ソース名・パス} |

### ⚠️ 要確認（ソース不明）
| # | 該当箇所 | 記載値 | 状況 |
|---|---------|--------|------|
| 1 | {箇所} | {記載値} | {なぜ確認不可か} |

### ✅ 確認済み（{N}件）
すべてソースと一致。
```

### Phase 4: 修正対応

- **❌ 不一致**: 正しい値に自動修正する（修正前にユーザーに提示）
- **⚠️ 要確認**: ユーザーに確認を求める（「この値は正しいですか？」）
- **すべて ✅**: 「ファクトチェック完了」と報告

## ルール（厳守）

1. **推測で「正しい」と判断しない**: ソースで確認できない場合は ⚠️
2. **ユーザーの入力も検証する**: 情報ソースに関係なく事実正確性を担保
3. **修正は根拠付き**: ❌ の修正案には必ずソースを明記
4. **チェック対象外は判定しない**: 主観的記述にはコメントしない
5. **効率的に実行**: 照合は可能な限り並列で実行
6. **過去の事故を繰り返さない**: 特に会社概要（代表者名・住所）、クライアント名・メールアドレスは重点チェック
