Walkers メディアの「〇〇 作り方 完全ガイド」系（＝開発方法系）記事を、**まだ記事が無いアプリについて 0→1 で新規執筆**するスキル。見本記事「マッチングアプリ開発方法 完全ガイド」と同じ構成・**予約システムv2ルール（鳳汰OK済）**に準拠して全文を生成し、最後は **Claude in Chrome** で WordPress 下書きを作る。

- 見本記事: <https://walker-s.co.jp/media/matchingapp-development/>
- v2ルール集約（必読）: `references/howto-v2-rules.md`
- 想定実行者: Claude Code（細谷の手元で実行）
- 元依頼: `output/manuals/howto-article-brief/manual.md`（録画 2026-05-29 / 鳳汰レクチャー）

> **このスキルが立つ前提（naru が誤りを正せるよう明記）**: 「対象アプリは**開発費用系**記事が完成済みで、**作り方系**記事の空きを埋める」という解釈に立つ。鳳汰さんが"別の新シリーズ"を意図していた場合はここを修正する。

### Phase 4: WordPress 下書き化（Claude in Chrome）

**夜間バッチの第一候補＝REST 方式（2026-06-11 実証・台帳「確立済みパイプライン」参照）**: rest-nonce 取得 → REST GET 7240 raw → ブラウザ内で区間差し替え・swap・検証 → POST 空draft → PUT content → REST 再検証。Yoast「新規下書き」複製（下記）は UI 操作が必要な場合の代替。検証項目・draft 厳守は両経路共通。

**主経路＝テンプレ複製 + テキスト差し替え（確定）。**
理由: v2ルールの装飾（オレンジリスト・各手順の太字・AIヒアリングライン・動画埋込位置）はすべて Gutenberg **ブロック**。空投稿に markdown を貼ると全部壊れる。**公開済みの作り方記事**を複製し、内側テキストだけ差し替えると全ブロックを保全できる。これは `howto-article`（リライト）のブロック編集と**同一技術**で、違いは元ネタ（テンプレ複製 vs 既存記事）だけ。

**テンプレ記事（2026-06-01 確定）**:
- **既定＝見本「マッチングアプリ開発方法 完全ガイド」post=7240 を複製**（naru 指示で確定）。構成: 〇〇とは？ → 機能一覧 → **手順10ステップ** → 注意点2つ → **作り方2選（手順の後）** → 費用・期間 → 安く抑える4つ → 選び方5つ。**「9割のケース」H2は無い**。
- ⚠️ 予約システム(post=7307・9ステップ・9割先頭・作り方4選・とは/注意点なし)は**別構成**。見本と揃えたいので**原則 7240 を使う**。9ステップ型にするのは naru が明示確認したときだけ。
- ※ batch-complete の `10813/108xx` は Yoast「書き換え&再公開」の一時複製IDで現存しない。**公開ID（7xxx）が正**。

手順（`mcp__Claude_in_Chrome__*`、naru のログイン済み Chrome を使用）:

1. wp-admin 投稿一覧（`/media/wp-admin/edit.php`）でテンプレ記事の行 →「**新規下書き**」（Yoast Duplicate Post の New Draft）でブロック保全コピーを作る。
2. **タイトル**を所定形式に変更。
3. 各ブロックの**テキストのみ**を対象アプリ用に差し替え（ブロック種別＝H2/H3/段落/番号リスト/オレンジリスト/YouTube枠 は保持）。テーマ別カスタマイズ語彙を適用。
4. **status = draft 維持（publish は絶対にしない）**。保存後の **post ID／編集URL** を控える。

**ブロックのテキスト差し替えの実装（実証済・2026-06-01）**: 編集画面で `wp.data.select('core/editor').getEditedPostContent()` を取得 → **テンプレ固有語→対象アプリ語の find→replace**（`split().join()`）をブラウザ内で適用（本文をコンテキストに載せず差し替え）。残存語は `(c.match(/語/g)||[]).length` を 0 になるまで反復検証（テーマ別の固有語＝マッチング/予約/出会い/App Store/アプリ等を網羅）。

> **必須の後処理ペア（共通アセットを汎用に戻す・鳳汰FB 2026-06-05）**: global swap 後に必ず適用する。
> - `"{app}開発費用シミュレーター" → "アプリ開発費用シミュレーター"`（シミュレーター名はテーマ名を入れず汎用に）
> - シミュレーターのリンク href を **`https://simulation.walker-s.co.jp/`** に統一（テンプレの app 固有ページURLを残さない）。`c = c.replace(/href="[^"]*"([^>]*>[^<]*開発費用シミュレーター)/, 'href="https://simulation.walker-s.co.jp/"$1')` 等で。
> - **`loos/post-link` のシミュレーターカード2枚も対象**（a href の置換だけでは漏れる・SaaS実測 2026-06-11）: `linkData.url` の `/matching-app/` 等の固有パスを除去してトップに統一し、**`utm_campaign={対象記事スラッグ}`** に書き換える（テンプレの `matching-app-development-cost`／`sns-development-cost` が残ると計測が他記事に混ざる）。あわせて `"isNewTab":true,"rel":"noopener noreferrer"` を JSON 属性に付与（チェックリスト「新しいタブで開く」対応）。
> - **tech-studio の Bubble 記事カード**: テンプレは `bubble-dating-apps`（マッチング用チュートリアル）を指すが、対象アプリ版の tech-studio 記事は**存在しないことが多い**（2026-06-11 確認: SaaS 版なし）。**汎用の `bubble-how-to-use`（Bubble使い方完全ガイド）に差し替え**、直前の本文宣言も「〜で{app}を開発する方法をすべて解説」→「〜**の使い方**をすべて解説」へ直す（存在しない記事を宣言したままにしない）。

> ⚠️ **確定反映は `resetBlocks` を使う（重要・実証済の落とし穴）**: 編集を反映する最終手段は
> `wp.data.dispatch('core/block-editor').resetBlocks(wp.blocks.parse(c))` →（タイトルは別途 `editPost({title})`）→ `savePost()`。
> **`editPost({content})` と `updateBlockAttributes`（ブロックAPI）を混在させない**こと。混ぜると後続の `editPost({content})` がブロック側に反映されず**巻き戻る**（2026-06-01 に実測）。テーブルのセル等を個別に直したい場合も、最終的に全文を `resetBlocks` で入れ直すのが安全。
> 保存後 `getCurrentPost().content.raw` で実保存本文（マッチング=0・App Store=0 等）と `status==='draft'` を再検証する。

> ⚠️ **複製元から引き継ぐ＝要・人手差し替え項目**（テンプレ複製の宿命。テキスト差し替えだけでは直らない）:
> - **冒頭の YouTube embed → 削除する**（鳳汰FB 2026-06-04: 新規記事は実演動画がまだ無いので冒頭動画は消す。Phase 4 で `c.replace(/<!-- wp:embed[\s\S]*?<!-- \/wp:embed -->\s*/,'')` で先頭embedを除去）
