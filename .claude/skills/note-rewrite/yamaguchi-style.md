# 鳳汰スタイルガイド（note-rewrite）

このファイルは山口鳳汰さんの編集判断軸を蓄積する。`note-rewrite` SKILL.md のフロー骨格から分離した「判断系」の中身。
ゴールは「鳳汰さんを呼ばずに鳳汰さんレベルの成果物が出せる状態」。FBごとに即追記。

## 判断軸（明文ルール）

### 文体・トーン
- noteは「だである調」（自分の主張を出す場）
- 切り口を変えた瞬間に刺さる（AI→Claude Code 等）
- **誇張ワードを避ける**（例: 「Claude Code革命」→「Claude Codeによって」「Claude Code登場以降」。「衝撃」「激震」「○○の終焉」のような煽り語も同様。タイトル・H2・本文すべてで淡々とした表現を優先する。2026-05-15 UX×営業力FBより）

### 構成
- H2配下の並列項目はH3に揃える（目次が綺麗・YouTube流用しやすい）
- **見出しは主題を1つに絞る**（"AとB" の複合見出しを避ける。例: 「アイデアのコモディティ化とClaude Codeの進化」→「ClaudeCodeによる開発ハードルの低下」。副次論点は本文で展開する。2026-05-15 UX×営業力FBより）
- **イントロも論点を1つに絞る**（冒頭で「AとB」の複合論点を提示せず、副次論点は本文後段で自然に展開する流れにする。2026-05-15 UX×営業力FBより）
- アイキャッチは「最低限見やすければOK」。凝りすぎない
- 末尾は CTA だけ残し、蛇足な「まとめ」は削る

### 表現の冗長性カット
- 装飾の点記号は冗長になりがち。極力使わない
- **リスト記号 `*` `-` は使わず、太字 + コロン + 段落で項目を並べる**（H2配下の論点列挙も H3配下の手法列挙も同じ。例: `* **ユーザビリティテストの徹底**: ...` ではなく `**ユーザビリティテストの徹底**: ...` と書く。点記号を消してプレーン段落に。2026-05-15 UX×営業力FBより）
- **同じ修飾語を 2 回目に出すときは省く**（例: 「LP + デモ動画」→「LP + デモ」、「Claude Code・ノーコード」→「ノーコード」。直前のパラグラフで説明済み or 記事全体の文脈で明らかな修飾語は冗長になる）
- **並列技術名は切り口に集中**（例: 「ノーコードやClaude Code」→「Claude Code」。切り口の焦点をぼかす並列技術名は初出でも削る。記事全体の角度を1点に絞る。2026-05-15 UX×営業力FBより）
- **既知の技術解説段落は削除**（例: 「Claude Codeのような自然言語駆動の生成AIエージェントは...」のような読者が既知の前提解説段落は冗長。読者は切り口の技術を知っている前提で書く。2026-05-15 UX×営業力FBより）
- **強調装飾としての `"..."`（半角ダブルクォート囲み）は使わない**（鳳汰確認済み、2026-05-15 競争優位性FB）。語句を浮かせて強調したくなる場面でも、そのまま地の文に流し込む。見出しに使っていた場合は助詞・空白を詰めて自然な日本語に整形する（例: `"持続" しない` → `持続しない`、`"やるべきこと" 3選` → `やるべきこと3選`、`"優位性を作り続ける仕組み" を持っている` → `優位性を作り続ける仕組みを持っている`）
- **「〜時代」のような冠言は避ける**。リードで同じ説明を書いている場合は重複（2026-05-15 競争優位性FBより）
- **具体作用「〜によって」を選ぶ**（「Claude Code 時代に」より「Claude Codeによって」）
- **数字+カテゴリ語の体言止めには助数詞を入れる**（「3戦略」より「3つの戦略」）

### 切り口語の使い分け（Claude Code 切り口の場合）
- **ツール固有の話 = Claude Code**（作る・模倣する・MVP を1日で出す等の開発行為）
- **AIカテゴリの話 = AI**（市場変化、カテゴリ置換、技術変革、外部環境の変化）
- 混在させない。例: 「Claude Code 自身の手で市場が変わる」は不自然 → 「AIによって技術と市場の大変革が起きる」（2026-05-15 競争優位性FBより）

### 切り口リライト時の論点再評価（重要）
- **切り口で前提が変わる論点は削除/書き換える**（元記事/元動画の論点を盲目的に踏襲せず、Phase 2 初稿生成で毎章チェック）
- **論点を削ったら本文・末尾ステップの残響も削除**（章だけ消しても文中・まとめに残ると整合性が崩れる）
- **ただし上記2項目は Phase 2 初稿生成の段階で適用する**。Phase 3 で鳳汰の修正版が届いたら、その内容を **そのまま** 採用する。Claude が判断軸の整合性のために追加で本文を削る/書き換えるのは **禁止**。整合性が気になる箇所は naru/鳳汰に申し送り、指示を待つ（2026-05-13 越権事案より）
