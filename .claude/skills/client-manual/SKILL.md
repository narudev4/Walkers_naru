# 顧客向け操作マニュアル作成（HTML→PDF）

トリガー: 「操作マニュアル作って」「マニュアルPDF」「手順書を先方向けに」「client-manual」

## 概要

md→pandoc ではなく **手書き HTML（1ページ=1 section）→ Chrome headless で PDF** にする方式。落合コーポレーション操作マニュアル v3（2026-08-19・47ページ・古谷さんOK）で確立した。参照実装は `03_projects/落合コーポレーション/launch-plan/manual-v3/`。

読者は「PCが得意でない顧客」を想定する。**業務の流れ（ビジネスフロー）を章立てにし、画面の機能一覧では構成しない**。

## パイプライン

1. **ビジネスフロー一覧を先に作る**（誰が・いつ・何をするか。落合の例: `launch-plan/37-ビジネスフロー一覧_*.md`）。章＝フローの束、節＝1業務、STEP＝1操作画面。
2. **スクショを撮る**: Claude in Chrome で実画面を zoom 撮影（`save_to_disk: true`）→ アセットフォルダに連番コピー。要点だけをトリミング（sips -c H W --cropOffset y x）。管理画面のメニュー文字が読めるサイズが合格ライン。撮れないドメイン（例: moneyforward はマニフェストレベル不可）は naru に手動スクショを依頼。
3. **セクション HTML を書く**: 参照実装の `m1-sections.html` の `<style>` とページ構造（下記）をそのまま流用。分量が多ければ m1/m2 に分割し fixer サブエージェントに委任。
4. **結合とページ番号**: `assemble.py`（ページ抽出・節参照 `P.<span class="pref" data-ref="sec-xx"></span>` の自動解決・フッター採番）→ `inject.py`（表紙・目次を secmap から生成）。ページの増減に参照が自動追従する。
5. **PDF 化**: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf=final.pdf "file://…/final.html"`
6. **視覚QAループ（必須）**: 生成 PDF を Read ツールで**全ページ画像として目視**→修正→再レンダリング、問題ゼロまで。チェック観点: はみ出し／フッター衝突／不自然な折返し／画像の可読性／丸数字の中心。
7. **納品**: `cp final.pdf ../NN-操作マニュアル_vX_YYYYMMDD.pdf` して naru に開いて見せる。

## ページの型（CSS クラス）

- `.page`（210mm×296mm・overflow:hidden）+ `.foot`（絶対配置フッター、`<span class="pnum"></span>` は結合時採番）
- `.band`＝紺帯タイトル＋赤丸 STEP 数字（`.num`）＋担当ピル（`.who`＝顧客の操作／`.who.w`＝自社対応）
- `.lead`＝青の要旨ボックス、`ol.ops`＝丸数字手順、`.note`＝黄注意、`.ok`＝緑確認、`.tbd`＝赤「確定後に記入」タグ
- `.shots > .shot > img + .cap`＝スクショ（max-height はページ個別に style 上書き。単独 105〜110mm・2枚積み 88〜92mm 目安）
- 丸数字の光学中央: 数字は Helvetica・line-height:1・帯は padding-bottom:2px、ops は padding-top:1.25px（画素実測済み。触らない）

## 文章ルール（naru 指摘の蓄積・必ず守る）

- 文末は句点「。」。日本語と英数字の間に半角スペースを入れない。
- 章は数字（1章〜）。本文の節参照は「P.◯◯」（pref で自動解決）。「A-3」等の内部記号を読者に見せない。
- **選択肢の列挙（例: payment:prepaid／20th／eom）は ／ 区切りにせず `<br/>` で1行1項目**。
- note/ok ボックスはタイトル `<span class="t">` の直後に `<br/>` を入れ、本文は文単位の行に割る（3文以上は必須）。
- UI の文言は**実画面のラベルに一致させる**（例: 実UIが「入金済」なら「入金済み」と書かない）。書く前に実画面で裏を取る。
- 「画面の地図」のような AI 臭い比喩は使わない（→「画面一覧」等の普通の語）。
- 定常業務に「自社へ報告してください」を入れない（自走できる本にする）。報告が要るのは例外時だけ。
- 未確定事項は `.tbd`「確定後に記入」タグで明示し、確定後に差し替える。
- 消える予定のページ（付録等）は編集せず、結合スクリプト側で除外する。

## 品質保証の型

fixer サブエージェント（実装+単体PDF視覚QA）→ codex 監査（旧参照・未解決参照・採番の機械チェック）→ 司令塔の全ページ目視、の三重。最後に naru の「マニュアルだけ見て操作できるか」網羅テスト（チェックリスト例: `launch-plan/45-マニュアル網羅テスト_20260819.md`）。
