# 記事自動更新モニター

トリガー: 「記事モニター」「記事チェック」「記事登録」「記事更新」「article monitor」

## 入力
$ARGUMENTS

## 概要
公開済み記事URLをGoogle Sheetsで管理し、業界トレンドの変化に基づいて更新が必要な記事を検出・Google Chat通知・リライトドラフト生成まで行うモニタリングシステム。

## 利用するMCPツール

| ツール | 用途 |
|--------|------|
| `google_sheets_read` / `google_sheets_write` / `google_sheets_append` / `google_sheets_create` | 記事DB（スプレッドシート）の読み書き |
| `google_docs_create` / `google_docs_append` / `google_docs_get` | リライトドラフトの保存・共有 |
| `google_drive_search` | シート・ドキュメントの検索 |
| Google Chat MCP（`google-chat`） | 更新レコメンドの通知 |
| `gmail_create_draft` | メール下書き通知（Chat代替としても利用可） |
| WebSearch | Google検索によるトレンド調査 |
| `mcp__twitter__search_tweets` | X(Twitter)のSNSトレンド調査（**未導入**: `WebSearch(query="site:x.com ...")` で代替） |
| WebFetch / Playwright | 記事本文のスクレイピング |

## 設定情報

スキル初回実行時にセットアップを行い、以下を `00_context/memories/facts.md` に保存する:
- `article_monitor_sheet_id`: 記事管理スプレッドシートのID
- `article_monitor_chat_space`: Google Chat通知先スペース
- `article_monitor_notify_email`: 更新通知の送信先メールアドレス（Chat未設定時の代替）

## モード判定

`$ARGUMENTS` の内容から実行モードを自動判定する:

| 入力パターン | モード | 実行内容 |
|-------------|--------|---------|
| 「セットアップ」「初期設定」 | セットアップ | Sheet確認/作成・Chat通知先設定 |
| URL文字列を含む / 「登録」 | 記事登録 | URLから記事取得→KW抽出→Sheet追加 |
| 「チェック」「確認」「モニター」/ 引数なし | トレンドチェック | 全記事のトレンド照合→レコメンド通知 |
| 「リライト」「書き直し」+ 記事指定 | リライト生成 | 指定記事のリライトドラフト作成 |
| 「ダッシュボード」「一覧」「GUI」 | ダッシュボード | GUI表示 |

---

## Phase 1: セットアップ（初回のみ）

### 1-1: Google Sheets確認・作成
1. `google_drive_search` で記事管理シートの存在を確認
2. 存在する場合 → シートIDを記録して次へ
3. 存在しない場合 → `google_sheets_create` で新規スプレッドシートを作成:
   - タイトル: `記事モニター管理DB`
   - ヘッダー行: URL | タイトル | キーワード | 最終チェック日 | 最終更新日 | ステータス | 優先度 | リライトDoc | メモ

### 1-2: 通知先の確認
1. ユーザーに通知方法を確認:
   - Google Chat通知（推奨）
   - Gmail下書き作成（`gmail_create_draft`）
   - ローカルレポートのみ（通知なし）
2. 通知先を記録

### 1-3: 設定保存
- `00_context/memories/facts.md` にシートIDと通知設定を追記
- `00_context/memories/decisions.md` に設定決定を記録

---

## Phase 2: 記事登録

### 2-1: 記事コンテンツの取得
1. ユーザーからURLを受け取る（$ARGUMENTS またはヒアリング）
2. WebFetch でURL本文を取得（prompt: 「記事のタイトル、本文テキスト、公開日を抽出してください」）
   - 取得失敗の場合 → Playwright `browser_navigate` → `browser_snapshot`
3. 取得したコンテンツから以下を抽出:
   - **タイトル**: `<title>` または `<h1>`
   - **公開日**: metaタグまたは本文から推定
   - **本文テキスト**: 記事の主要コンテンツ

### 2-2: キーワード抽出（AI分析）
取得した本文からキーワードを5〜10個抽出する:
- **主要テーマKW**: 記事の中核トピック（3-5個）
- **業界・技術KW**: トレンド変化を検知しやすいもの（2-3個）
- **固有名詞**: 製品名・サービス名・法制度名など（該当する場合）

### 2-3: ユーザー確認
抽出結果をユーザーに提示:
```
📝 記事登録プレビュー
タイトル: {title}
URL: {url}
抽出キーワード: {kw1}, {kw2}, {kw3}, ...
```
- キーワードの追加・修正をヒアリング
- 確定後に次のステップへ

### 2-4: Google Sheetへの追加
`google_sheets_append` でシートの末尾行に以下のデータを追加する:
- URL, タイトル, キーワード(カンマ区切り), 今日の日付, 空欄, 「アクティブ」, 「未チェック」, 空欄, 空欄

### 2-5: 登録完了通知
```
✅ 記事登録完了
タイトル: {title}
キーワード: {keywords}
```

---

## Phase 3: トレンドチェック（メイン機能）

### 3-1: 記事データ取得
1. `google_sheets_read` で記事管理シートの全データを取得
2. ステータスが「アクティブ」の記事を抽出

### 3-2: キーワード別トレンド調査
各記事のキーワードについて以下を**並列実行**:

**Web検索（WebSearch）**:
- クエリ例: `"{キーワード}" 最新 2026` / `"{キーワード}" 動向 変化`
- 直近1週間〜1ヶ月のニュース・変化を収集
- 抽出する情報:
  - 新しい事実・統計データ
  - 法改正・制度変更
  - 新製品・サービスのリリース
  - 業界の動向変化

**SNS調査（Twitter MCP）**:
- `search_tweets` で各キーワード検索（count: 15）
- バズっているトピック・新しい議論を検出

### 3-3: 更新必要性の判定
各記事について以下の基準でスコアリング:

| 判定基準 | 優先度 | 例 |
|---------|--------|-----|
| 事実の陳腐化 | HIGH | 記事内の統計・データが古くなった |
| 法制度・規制変更 | HIGH | 前提となる法律・制度が変わった |
| 新技術・サービス登場 | MEDIUM | 記事で言及すべき新選択肢が出た |
| 業界トレンド変化 | MEDIUM | 市場の方向性が変わった |
| SNS話題性のみ | LOW | ソーシャルで関連話題が盛り上がっている |
| 変化なし | NONE | 更新不要 |

### 3-4: 通知（HIGH/MEDIUMのみ）
Google Chat MCPで通知（未設定の場合は `gmail_create_draft` で代替）:

```
📰 記事更新レコメンド（YYYY-MM-DD）

🔴 要更新: {N}件 / 🟡 更新検討: {N}件 / 🟢 変更なし: {N}件

━━━━━━━━━━━━━━━━━━

🔴 【要更新】{記事タイトル}
URL: {url}
検出された変化:
• {変化内容1}
• {変化内容2}
推奨: {具体的な更新内容}

━━━━━━━━━━━━━━━━━━

🟡 【更新検討】{記事タイトル}
URL: {url}
検出された変化:
• {変化内容}

━━━━━━━━━━━━━━━━━━

💬 リライト開始:「記事モニター リライト {タイトル}」
📊 ダッシュボード:「記事モニター ダッシュボード」
```

### 3-5: Sheetデータ更新
`google_sheets_write` で以下を更新:
- 各記事の「最終チェック日」を今日に更新
- 「優先度」フィールドを判定結果で更新
- 「メモ」フィールドに検出された変化の概要を記載

### 3-6: ローカルレポート保存
`output/article-monitor/YYYY-MM-DD_check-report.md` に保存:

```markdown
# 記事モニター チェックレポート
実行日: YYYY-MM-DD

## サマリー
- 対象記事数: {N}件
- 要更新（HIGH）: {N}件
- 更新検討（MEDIUM）: {N}件
- 変更なし: {N}件

## 要更新記事

### 1. {記事タイトル}
- URL: {url}
- キーワード: {keywords}
- 検出された変化:
  - {変化}: {詳細}（ソース: {url}）
- 推奨更新内容: {具体的な更新ポイント}

## 更新検討記事
{同様のフォーマット}

## 情報ソース
- {URL/出典リスト}
```

## Phase 4: リライトドラフト生成

### 4-1: 対象記事の特定
1. ユーザーが指定した記事（タイトル or URL or 番号）を特定
2. Sheetから該当記事のデータを取得
3. 直近のチェックレポートから変化情報を取得

### 4-2: 現行記事の取得
1. WebFetch / Playwright で記事の最新版を取得
2. 本文テキストを抽出・構造化

### 4-3: トレンド情報の補完調査
1. チェックレポートの変化情報をもとに追加Web検索
2. リライトに必要な最新データ・事実を収集
3. 信頼できるソースの情報を優先

### 4-4: リライトドラフト作成
1. **差分分析**: 現行記事と最新トレンドの差分を整理
2. **構成案**: 更新すべきセクション・追加セクションを設計
3. **ドラフト執筆**: 既存の文体・トーンを維持しつつ内容を更新

### 4-5: Google Docsに保存
- `google_docs_create` でドキュメントを作成、`google_docs_append` で本文を書き込む
- タイトル: `【リライト】{記事タイトル}_YYYY-MM-DD`
- ローカルにもバックアップ: `output/article-monitor/YYYY-MM-DD_rewrite-draft_{slug}.md`
- 内容:

```markdown
# リライトドラフト: {記事タイトル}

> このドキュメントはAIが自動生成したリライトドラフトです。
> 公開前に必ず内容を確認してください。

## 更新メタ情報
| 項目 | 内容 |
|------|------|
| 元記事URL | {url} |
| リライト理由 | {変化の概要} |
| 生成日 | YYYY-MM-DD |
| ステータス | ドラフト（レビュー待ち） |

## 変更サマリー
| セクション | 変更種別 | 変更内容 | 根拠 |
|-----------|---------|---------|------|
| {セクション名} | 改訂/追加/削除 | {内容} | {ソース} |

## リライト本文

{記事全文のリライト版}

## 参考ソース
- [{ソース名}]({URL})

---
生成: Claude AI (article-monitor)
```

### 4-6: Sheet更新 + 通知
- `google_sheets_write`: 「最終更新日」更新、「リライトDoc」にDocsリンクを記録、「ステータス」を「リライト済み」に
- Google Chat MCP（または `gmail_create_draft`）で通知:
```
✅ リライトドラフト完了

📝 {記事タイトル}
📄 Google Docs: {リンク}

変更ポイント:
• {変更点1}
• {変更点2}

レビューして問題なければ公開してください。
```

## Phase 5: ダッシュボードGUI

`/gui` スキルのパターンに従い `output/gui/article-monitor.html` を生成する。

### GUI構成
- **メトリクスバー（上部）**: 総記事数 / HIGH件数 / MEDIUM件数 / 最終チェック日
- **テーブル（メイン）**: 全記事一覧（ソート可能、優先度バッジ色分け）
- **HIGHカード**: 要更新記事をハイライト表示

### 生成ルール
1. gui-core.js / gui-style.css の Read は不要（外部参照で読み込み）
2. Sheetから取得したデータをJSON化し `const DATA = {...}` で埋め込む
3. `output/gui/article-monitor.html` に Write で保存
4. **ブラウザは自動で開かない**。ファイルパスをテキストで伝える

---

## ルール
- 記事のスクレイピングは分析目的のみに使用し著作権に配慮する
- トレンド判定は事実ベースで行い、推測で「要更新」にしない
- リライトは元記事の文体・トーンを尊重する
- 金額・契約情報など機密データは含めない
- Google Chatへの通知はHIGH/MEDIUMのみ（LOWは通知しない）
- チェック結果は毎回Sheetとローカルに記録しトレース可能にする
- リライトドラフトは必ずユーザーのレビューを経てから公開する
- 情報ソースを必ず明記する
