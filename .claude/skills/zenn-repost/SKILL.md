# Zenn 転載リライト（山口流）

トリガー: 「Zenn 転載」「Zenn にも載せて」「zenn-repost」「Zennリライト」

## 概要

すでに note 等で公開済みの記事を **Zenn に横展開** するワークフロー。
山口鳳太さんがレクチャーした手順（録画: `output/manuals/zenn-repost/`）をスキル化したもの。

新規執筆ではなく**転載リライト**。ただし「同じ文章を機械的に複製」してはいけない。**ペナルティ回避のためのリライト** と **Zenn の流儀（営業 NG・CTA は末尾だけ）** を守ったうえで貼り付けるのが必須。

## 戦略的意図

- 執筆した記事は **すべての該当プラットフォームに転載していく** のが基本方針
- ただし完全コピペは検索エンジンのペナルティ懸念があるため、**内容は同じでも文章は変える**
- Zenn は **エンジニア有志のプラットフォーム**。営業っぽさが出ると嫌われる文化
- ハードルはあるが、勝てれば強い → リスク認識した上でやってみる

> 「内容は同じでも絶対に文章は変える。」（山口 [00:19]）
> 「営業っぽさが出ると、あんまり良くなくて。」（山口 [01:50]）

## ツール構成

| 役割 | ツール / 場所 |
|------|--------------|
| 元記事（参照元） | note の公開済み記事（URL or `output/articles/note/` 配下） |
| 投稿先 | Zenn の記事エディタ |
| マークダウン仕様 | Zenn 独自仕様（note とは別物） |
| AI 補助（要確認） | Zenn MCP（存在するかもしれない・未確認） |
| AI 学習素材 | フォータ（執筆 AI）とのやり取りログ → 山口さんの修正パターンを学習させる |
| 画像 | YouTube サムネと共通でOK（Zenn 冒頭にそのまま流用可） |

## ワークフロー全体像

```
[1] note の元記事を取得（URL or ファイル）
        ↓
[Phase 1] ヒアリング & 元記事読み込み
        ↓
[Phase 2] 言い回しレベルでリライト（内容は同じ／文章は別物）
        ↓
[Phase 3] Zenn 独自マークダウンに整形
        ↓
[Phase 4] サムネイル + CTA 配置（CTA は末尾だけ）
        ↓
[Phase 5] コメント指示 ⇄ 修正のループ（山口流の核）
        ↓
[Phase 6] Zenn 貼付用最終版を出力 + フォータ学習素材として保存
```

## 実行フロー

### Phase 1: ヒアリング & 元記事読み込み

#### ヒアリング原則

- **「足りない情報だけ」を、1メッセージ1質問で聞く**
- 標準値が決まっている項目は確認しない
- 発話から自明に読み取れる項目は暫定確定して進める

#### 必須項目を聞く順番

1. **元記事**（note URL or ファイルパス）
2. **末尾 CTA の誘導先**（リライト直前。元記事を読んでから聞いた方がユーザーも答えやすい）

#### 項目一覧

| 項目 | 区分 | 標準値（未指定時の挙動） | 確認質問（必須項目のみ） |
|------|------|----------|---------|
| 元記事 | **必須** | なし | 「元記事の URL／ファイルパス／本文をください」 |
| 末尾 CTA 誘導先 | **必須** | なし | 「末尾 CTA は何に誘導しますか？（URL があれば一緒に）」 |
| サムネ画像 | 任意 | YouTube サムネと共通でOK。指定なければプレースホルダー | 聞かない |
| 文体 | 任意 | 元記事に合わせる（Zenn は技術記事寄りなので **ですます調** が無難） | 聞かない |
| 冒頭 CTA | 自動拒否 | **絶対に置かない**（Zenn 流儀） | 聞かない |
| Zenn MCP の有無 | 任意 | 未確認のため、まず無し前提で進める | 聞かない（後述の未確定事項） |

#### CTA URL が未指定の場合

末尾 CTA の誘導先は聞くが、**URL 自体が未指定**の場合は本文中に `[#]` プレースホルダーで残す。Claude は URL を捏造しない。

#### 元記事の受け取り方

| 渡され方 | 読み込み方 |
|---------|----------|
| URL（例: `https://note.com/...`） | `WebFetch` で本文取得 |
| ファイルパス（例: `output/articles/note/...md`） | `Read` ツール |
| 本文ベタ貼り | そのまま使う |
| 記事タイトルだけ | `output/articles/note/` を `Glob` で検索 → 候補が複数あればユーザー確認 |

### Phase 2: 言い回しレベルでリライト

機械翻訳的な単純置換ではなく、**人が読んだときに別の文章だと認識できる** レベルでリライトする。

#### リライトルール

1. **内容（主張・結論・例示）は変えない**
2. **段落の入れ替えは可**
3. **語尾・接続詞の変更は可**
4. **リード文・見出しも書き換え対象**（特に検索インデックス対象になりやすい部分）
5. **同じ文・同じフレーズを残さない**（コピペ感の排除）

> 「文章は変えること、言い回して変えること」（山口 [00:19]）

ペナルティ回避の確証はないが、**怖いので絶対にやる** という運用ルール。

> 「正直これはちょっと怖い部分はある、ぶっちゃけ。」（山口 [00:31]）

### Phase 3: Zenn 独自マークダウンに整形

Zenn のマークダウンは note や一般 Markdown と微妙に違う。**note 記法をそのまま貼ると崩れる**。

#### Zenn 独自記法（主要）

| 要素 | Zenn 記法 |
|------|----------|
| メッセージブロック（info） | `:::message` ... `:::` |
| メッセージブロック（alert） | `:::message alert` ... `:::` |
| 詳細折りたたみ | `:::details タイトル` ... `:::` |
| コードブロックにファイル名 | ` ```ts:filename.ts ` |
| 数式 | `$$ ... $$`（KaTeX） |
| 目次 | 自動生成（記法不要） |
| Twitter / YouTube 埋め込み | `@[tweet](URL)` / `@[youtube](videoId)` |

> 「Zenn の場合、これちょっと独特なよな、マークダウンとかが。」（山口 [01:00]）

#### Zenn MCP（未確認）

> 「Zenn、MCP あった気がする。」（山口 [01:11]）

存在の確証なし。**まずは Zenn 公式 Markdown ガイドベースで整形** し、Zenn MCP の存在が確認できたら以後はそれに乗せる。

### Phase 4: サムネイル + CTA 配置

#### 冒頭サムネ

YouTube のサムネと共通で OK。Zenn は冒頭に大きいビジュアルがあっても自然。

> 「Zenn の場合は、これは YouTube 冒頭にあって OK と、サムネイル側にあるし。」（山口 [00:48]）

#### CTA 配置（最重要）

**Zenn 転載で最も note と異なるポイント**。

- **冒頭 CTA は絶対に置かない**
- **CTA は記事末尾の 1 箇所だけ**
- 本文中のサービス言及も「営業っぽさ」を出さない

> 「最初の方には絶対に CTA は設置しない。」（山口 [01:54]）
> 「最後にやるだけ。最後に載せるだけにしたいな。」（山口 [02:06]）

理由: Zenn 文化では営業っぽさが嫌われるため、冒頭から営業すると読まれずに離脱される。

### Phase 5: コメント指示 ⇄ 修正のループ

`note-rewrite` と同じく、**ユーザーが Markdown 上にコメント `<!-- -->` を埋めて返す → Claude が反映 → 繰り返す** のループ。

#### Claude の動作

ユーザーが**コメント入り Markdown 全文**を貼ってきたら:

1. すべての `<!-- -->` を読む
2. 各コメントの指示を反映
3. **コメント自体は削除して**修正版 MD を返す
4. 「ここを変えました」とサマリも合わせて返す
5. ユーザーがさらにコメントを追加して投げてきたら、また反映

このループを **山口さんが「OK」と言うレベルまで** 繰り返す。最終版発火シグナルは `note-rewrite` と同じ（「OK」「完成」「Zenn 用に出して」等の明示指示）。

#### draft の上書きポリシー

毎回**同じ draft ファイルパスに上書き保存**する。過去の履歴は残さない（会話ログに残るので十分）。

**保存先（draft）:** `output/articles/zenn/draft/YYYY-MM-DD_[テーマ].md`

### Phase 6: Zenn 貼付用最終版 + フォータ学習素材

#### 最終版保存先

`output/articles/zenn/YYYY-MM-DD_[テーマ].md`（draft/ を含まない）

#### YAML フロントマター

```yaml
---
title: [Zenn タイトル]
original_url: [元記事の note URL もしくはファイルパス]
type: tech | idea
topics: [topic1, topic2, topic3, topic4, topic5]  # Zenn は最大5個
published: false  # 最終確認まで false
emoji: "📝"  # Zenn 必須
status: draft | published
date: YYYY-MM-DD
platform: zenn
cta_url: [末尾CTAの誘導先URL or "[#]"]
---
```

#### フォータ学習素材として保存

転載作業はフォータ（執筆 AI）に文章リライトを任せていく方針。**山口さんが修正したパターンを AI に学習させていく**ループを回すため、Phase 5 のやり取りログを残す。

> 「フォータとのやり取りで俺の修正をスキンで学ばせてって（やる）。どんどん良くなっていく。」（山口 [02:19]）

**学習ログ保存先:** `output/articles/zenn/feedback/YYYY-MM-DD_[テーマ]_feedback.md`

中身は「Claude が出した版 → 山口さんのコメント → 反映後」の差分が分かる形式。具体フォーマットは未確定（後述の未確定事項）。

#### 人間最終調整の依頼

> 完成版を Zenn エディタに貼り付けてください。プレビューで Zenn 独自マークダウン（メッセージブロック等）の表示崩れがないか目視確認をお願いします。
