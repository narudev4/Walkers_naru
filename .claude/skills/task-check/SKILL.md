# タスク残確認（クイック版）

トリガー: 「やり残し」「残タスク」「今日やること」「やばいことある？」「タスク確認」

## 目的
今日やるべきこと・やり残しを**実態ベースで**素早く確認する。
DAILY.mdやTaskGodの情報を鵜呑みにせず、必ずGmail送信履歴で照合してから提示する。

## `/task-organize` との違い
- `/task-organize`: 全タスクの棚卸し（30分〜）。1件ずつユーザー確認。
- `/task-check`: 今日〜直近のやり残しをサクッと確認（5分）。実態照合だけして報告。

## 利用ツール

| フェーズ | ツール | 用途 |
|---------|--------|------|
| Phase 1 | `gcal_list_events` (Google Calendar MCP) | 今日の仕事カレンダー予定取得 |
| Phase 1 | `gcal_list_events` (Google Calendar MCP) | 今日の個人カレンダー予定取得 |
| Phase 1 | Read (built-in) | DAILY.md の持ち越しタスク取得 |
| Phase 1 | `list_tasks` (TaskGod MCP) | doing / planned ステータスのタスク取得 |
| Phase 2 | `gmail_search_messages` (Gmail MCP) | **送信済みメール全件取得**（直近3日） |
| Phase 2 | `gmail_search_messages` (Gmail MCP) | 持ち越しタスクの相手先ごとに送信済み確認 |
| Phase 3 | なし（判定ロジック） | 照合・フィルタリング |

## 実行手順

### Phase 1: 情報収集（並列実行）
以下を**すべて並列で**取得する:

1. **今日のカレンダー（仕事）**: `gcal_list_events` — walker-s.co.jp
2. **今日のカレンダー（個人）**: `gcal_list_events` — CLAUDE_LOCAL.md「個人カレンダーID」参照
3. **DAILY.md**: Read — 最新日付のエントリから持ち越しタスクを抽出
4. **TaskGod doing タスク**: `list_tasks(status="doing")`
5. **TaskGod planned タスク**: `list_tasks(status="planned")`

### Phase 2: 送信メール照合（CRITICAL — 絶対省略禁止）

#### Step 2-1: 直近の送信メール一括取得
```
Gmail: gmail_search_messages
  q: "from:<仕事メール> after:YYYY/M/D"  ← 3日前の日付（※ 仕事メールは CLAUDE_LOCAL.md「個人設定」参照）
  maxResults: 20
```

#### Step 2-2: 持ち越しタスクごとの個別照合
Phase 1 で見つかった持ち越しタスクの**各相手先名**で送信メール検索:
```
Gmail: gmail_search_messages
  q: "from:<仕事メール> {相手名 or 会社名} after:YYYY/M/D"  ← 1週間前
  maxResults: 5
```

**全件チェック完了するまで Phase 3 に進まない。**

#### Step 2-3: 照合結果の判定
各タスクを以下に分類する:
- ✅ **対応済み**: 送信メールに該当する返信・送付の痕跡あり
- ⏳ **未対応**: 送信メールに痕跡なし
- 📅 **本日予定**: カレンダーに予定あり（時刻付きで表示）
- ⏰ **期限接近**: 期限が今日〜3日以内

### Phase 3: 結果報告

以下のフォーマットで報告する。**対応済みのタスクは「済」と明記し、未対応のものだけ強調する。**

```
📋 タスク残確認（実態照合済み）

━━ 🔴 今日やらないとまずいもの ━━
（期限が今日 or カレンダーに予定ありで未実施）
1. [タスク名] — [理由]

━━ 🟡 今週中に対応が必要 ━━
（期限が今週内 or 相手を待たせている）
2. [タスク名] — [期限/状況]

━━ 🟢 急ぎではない ━━
3. [タスク名] — [期限/状況]

━━ ✅ DAILY.md上は未完了だが実は対応済み ━━
（送信メールで確認）
4. [タスク名] — [いつ対応済み]
```

## ルール
- **Phase 2 は絶対に省略しない**: これがこのスキルの存在意義。省略したら手動確認と同じミスを繰り返す
- **DAILY.mdの持ち越しタスクを照合なしで提示することは禁止**: 1件でも照合漏れがあったらスキルの目的を果たしていない
- **対応済みのものを「未対応」と報告しない**: 送信メールで対応済みが確認できたら、必ず「対応済み」として報告する
- **カレンダーの予定は時刻を明記する**: 「今日MTGがある」ではなく「17:00にMTG」と具体的に
- **判断はしない、事実だけ報告する**: 「やばい」「急いで」等の主観的な判断はユーザーに委ねる
