# タスク整理

トリガー: 「タスク整理」「タスク棚卸し」「タスククリーンアップ」「タスク見直し」

## 利用ツール

| フェーズ | ツール | 用途 |
|---------|--------|------|
| Phase 0 | `gmail_search_messages` (Gmail MCP) | 送信・受信メールからコミットメント抽出 |
| Phase 0 | `gmail_read_message` (Gmail MCP) | メール本文の詳細取得 |
| Phase 0 | Glob + Read (built-in) | `03_projects/` 配下の議事録・MTGメモ確認 |
| Phase 0 | `google_drive_search` (自作Google MCP) | Google Docs上の議事録検索 |
| Phase 0 | `google_docs_get` (自作Google MCP) | 議事録本文のアクションアイテム抽出 |
| Phase 1 | `list_tasks` (TaskGod MCP) | 全タスク取得（todo/doing/done） |
| Phase 1 | `list_projects` (TaskGod MCP) | 全プロジェクト取得 |
| Phase 5 | `update_task` (TaskGod MCP) | ステータス・期限・説明の更新 |
| Phase 5 | `delete_task` (TaskGod MCP) | タスク削除 |
| Phase 5 | `complete_task` (TaskGod MCP) | タスク完了 |
| Phase 3 | Skill: `/task-register` | 漏れタスクの新規登録（重複チェック込み） |
| Phase 6 | `list_tasks` (TaskGod MCP) | 整理後の全タスク再取得 |
| 却下記録 | Edit (built-in) | `00_context/memories/rejected_tasks.md` に追記 |

## 目的
TaskGodのタスク情報を現実と一致させる。
「TaskGodを見れば今やるべきことが正確にわかる」状態をゴールとする。

## ゴール定義
整理完了時、TaskGodが以下の状態になっていること:
- **doing**: 今まさに取り組んでいるタスクだけ（上限3件目安）
- **todo**: 近日中に着手するタスクだけ（やらないものは消す）
- **done**: 実際に完了したタスク
- **重複ゼロ**: 同じ内容のタスクが2つ以上存在しない
- **全タスクがプロジェクトに紐づいている**（汎用タスクを除く）
- **説明・期限が最新**: 古い情報のまま放置されていない
- **メール・議事録で約束したことがすべてタスク化されている**

## 実行手順

### Phase 0: 実態の把握（CRITICAL — 省略不可）
TaskGodの情報だけでは実態はわからない。整理の前に**外部ソースから現実を把握**する。

#### 0-1. 送信済みメールの確認
```
Gmail: gmail_search_messages
  q: "from:me" （直近1〜2週間）
```
以下を抽出する:
- **「○○します」「対応します」「送ります」「確認します」等のコミットメント**
- 相手に期限を切った約束（「今週中に」「○日までに」等）
- 見積書・提案書・資料の送付約束

#### 0-2. 受信メールの確認
```
Gmail: gmail_search_messages
  q: "is:inbox" （直近1〜2週間の重要なもの）
```
以下を抽出する:
- 相手から依頼されたが未対応のもの
- 返信待ちの状態で放置されているもの

#### 0-3. 直近の議事録の確認
以下を確認する:
- Glob + Read で `03_projects/` 配下の直近の議事録・MTGメモを確認
- `google_drive_search(query="議事録 OR MTGメモ")` でGoogle Docs上の直近の議事録を検索し、`google_docs_get` で本文取得
- 特に「次回までに○○」「○○を確認する」「○○を送る」等のアクションアイテムを抽出

#### 0-4. 抽出結果の提示
Phase 0 で見つけた「約束・コミットメント」を一覧で提示する:
```
📧 メール・議事録から抽出したコミットメント

━━ 送信メールからの約束 ━━
1. [日付] → [相手]: 「○○します」（対応状況: 不明）
2. [日付] → [相手]: 「○○を送ります」（対応状況: 不明）

━━ 受信メールからの依頼 ━━
3. [日付] ← [相手]: 「○○をお願いします」（対応状況: 不明）

━━ 議事録からのアクションアイテム ━━
4. [日付] [MTG名]: 「次回までに○○を準備」（対応状況: 不明）
```
この一覧は Phase 2 のタスク確認時に照合に使う。

### Phase 1: TaskGod現状取得
1. TaskGod MCP `list_tasks` で全タスク（todo / doing / done）を取得
2. TaskGod MCP `list_projects` で全プロジェクトを取得
3. 全タスクを一覧で提示する（ステータス別）

### Phase 2: ユーザーと1件ずつ確認
全タスクを**ステータス別に1件ずつ**ユーザーに確認する。AIが勝手に判断しない。

**Phase 0 の抽出結果と照合しながら確認する。**
- タスクの完了判断に送信メールの情報を活用する（例: 「見積書送付」タスク → 送信メールに見積書送付の痕跡があれば「送信済みのようですが、done にしますか？」と補足）
- 逆に、doing/todo だが実はメールで対応済みのタスクがあれば指摘する

#### doing タスクの確認
doing のタスクを1件ずつ提示し、以下を聞く:
```
📌 [タスク名]（doing / 作成: ○日前）
   プロジェクト: ○○ / 期限: ○○
   💡 関連情報: [Phase 0で見つけた関連メール・議事録があれば表示]

→ このタスクの状態は？
  1. doing のまま（進行中）
  2. done にする（完了した）
  3. todo に戻す（まだ着手していない・中断）
  4. 削除する（もうやらない）
  5. 内容を修正する（タスク名・説明・期限を更新）
```

#### todo タスクの確認
todo のタスクを1件ずつ提示し、以下を聞く:
```
📋 [タスク名]（todo / 作成: ○日前）
   プロジェクト: ○○ / 期限: ○○
   💡 関連情報: [Phase 0で見つけた関連メール・議事録があれば表示]

→ このタスクの状態は？
  1. todo のまま（やる予定）
  2. doing にする（今取り組んでいる）
  3. done にする（もう終わった）
  4. 削除する（もうやらない・不要）
  5. 内容を修正する（タスク名・説明・期限を更新）
```

#### done タスクの確認（簡易）
done タスクは一覧表示のみ。明らかな重複や誤りがあればユーザーに指摘する。
全件確認は不要（量が多いため）。

### Phase 3: 漏れタスクの登録提案
Phase 0 で抽出したコミットメントのうち、**Phase 2 で該当するタスクが見つからなかったもの**を提示する:
```
⚠️ TaskGodに未登録のコミットメントが見つかりました

1. [日付] → [相手]: 「○○します」
   → タスク登録しますか？

2. [日付] [MTG名]: 「次回までに○○を準備」
   → タスク登録しますか？
```
ユーザーが登録を希望したら、**`/task-register` スキルを使って登録する**（重複チェック込み）。

### Phase 4: 重複・類似チェック
Phase 2 の確認と並行して、以下を検出したら都度指摘する:
- タスク名のキーワードが70%以上一致するペア
- 同一プロジェクト内で内容が重複するタスク
- 検出したら「これとこれは同じ内容に見えますが、統合しますか？」と聞く

### Phase 5: 一括実行
Phase 2〜3 で確認した変更を、TaskGod MCPで一括反映する:
- `update_task`: ステータス変更、期限設定、説明更新、プロジェクト紐づけ
- `delete_task`: 削除
- `complete_task`: 完了
- 新規登録は `/task-register` 経由で実行（重複・却下チェック込み）

**変更はすべてユーザーが指示したものだけ。AIの独自判断で追加変更しない。**

### Phase 6: 整理後の確認
1. `list_tasks` で整理後の全タスクを再取得
2. before/after を比較して報告:

```
✅ タスク整理完了 — TaskGodは最新の状態です

📊 変更サマリー
- ステータス変更: ○件
- 削除: ○件
- 内容更新: ○件
- 統合: ○件
- 新規登録（漏れ補完）: ○件

📋 整理後の状態
- doing: ○件（整理前: ○件）
- todo: ○件（整理前: ○件）
- 合計アクティブ: ○件

🎯 現在の doing タスク
1. [タスク名]
2. [タスク名]
3. [タスク名]
```

## 却下タスクの記録（CRITICAL）
Phase 2 または Phase 5 でタスクを**削除**した場合、必ず `00_context/memories/rejected_tasks.md` に追記する:
```
- YYYY-MM-DD | タスク名 | 却下理由（ユーザーの言葉をそのまま記録）
```
これにより `/task-register` が同じタスクを再登録するのを防止する。

## ルール
- **Phase 0 は絶対に省略しない**: TaskGodだけ見て整理を始めることは禁止。メール・議事録から実態を把握してからタスクの確認に入る
- **AIが勝手にステータスを変更しない**: 全てユーザーの指示に基づく
- **Phase 2 の1件ずつ確認を省略しない**: まとめて「全部OKですか？」は禁止
- **ただし効率化は許容**: 明らかに同じ判断が続く場合（例: done が大量にある場合）、「残りの done タスク○件もそのままでよいですか？」とまとめてよい
- **doing の上限目安は3件**: 整理後に4件以上残る場合は「doing が多めです。優先順位をつけますか？」と提案する
- **新規タスクの追加は `/task-register` 経由**: Phase 3 の漏れ補完も含め、直接 `create_task` を叩かない
